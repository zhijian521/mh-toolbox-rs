# 全项目细节统一补充

基于上一轮已收口的工作区继续做静态审查。下文保留初次发现，实施状态见文末；本轮没有运行测试、构建或视觉探针，也没有操作真实账本。

## 建议优先处理

### 1. 偏好设置的写入失败统一处理（P2）

- 位置：`src/composables/use-font-scale.ts:74`、`use-dev-mode.ts:51`；对照 `use-theme.ts:56`。
- 现状：三者读取均有异常保护，但字号监听与开发者模式 setter 仍直接调用 `localStorage.setItem`。访问受限或写入失败时，状态已改变，异常仍向 Vue 回调传播；主题写入则捕获异常并保留本次选择。
- 建议：偏好复用轻量写入边界，统一“本次生效、记忆失败有简短回执”。偏好不套用业务账本的损坏后拒绝写入规则，不为切主题弹确认。

### 2. 错误按原因与作用范围展示，减少重复（P2）

- 位置：`src/services/persist.ts` 的 `canWrite()`、`src/components/SaveNotice.vue:9`、`src/composables/save-feedback.ts:7`；`src/views/overview/OverviewView.vue:153`、`TeamCard.vue:69`。
- 现状：读取失败后尝试保存，`canWrite()` 会把读取错误同时复制到 `writeError`；页面可能同时出现读取错误和带“重试保存”的同文提示。保存失败还可能同时显示页内、弹窗内和浮动通知。首页按每个角色重复显示同一数据源读取失败，并为多张卡分别挂 `role="alert"`。
- 建议：读取失败、保存失败、字段填写错误分开处理。读取错误不展示无效的保存重试；弹窗操作失败以当前弹窗为主，页级保留待保存状态；首页集中说明数据源问题，卡片保留安静的“未读取”占位。后端诊断仍留日志。
- 不把所有错误一律改为强制播报；需要保留信息的状态和需要立即提示的错误分别决定播报方式。

### 3. 按钮与控件的字号缩放规则追齐（P2）

- 位置：`src/components/SlotButton.vue:94`、`:108`；对照 `PressButton.vue:89`、`src/styles/base.css:839`。
- 现状：普通槽按钮默认高度固定为 `26px`，主按钮与输入框则使用 `calc(26px * var(--fs-scale))`。默认字号同高，放大字号后同档控件不再遵守同一高度规则。
- 建议：统一默认高度与内边距的缩放口径，同时保留父级 `--slot-h` / `--slot-w` 的明确覆写；不要为了修复默认档而覆盖侧栏等已有定制尺寸。
- 槽按钮、凸起按钮保留各自材质，统一的是几何和使用场景。

### 4. 自绘控件的禁用与保存锁形成完整契约（P2）

- 位置：`src/views/accounts/AccountEditor.vue:167`、`src/views/income/OnlineDialog.vue:191`；对照目标和物价表单；`src/components/SelectField.vue:173`、`DateField.vue:207`。
- 现状：有的表单同时设置 `disabled` 与 `inert`，有的只禁用 fieldset。SelectField 有整项禁用属性，但选择函数未再次判断禁用；DateField 当前只有日期范围的禁用逻辑，没有整控件禁用属性。自绘列表、键盘处理及 Teleport 月历不能仅凭 fieldset 推定完全锁定。
- 建议：统一保存期间和失败待重试期间的锁定；控件禁用时拒绝选择并收起已打开的浮层。错误文本和重试按钮留在锁定范围之外。
- 这是静态发现的交互契约缺口，是否存在可触发的绕过路径尚未运行复现，不作为已复现的数据错误报告。

## 样式与简化

### 5. 校验提示与输入框建立关联（P3）

- 位置：`src/components/PriceField.vue:178`、`:201`；`src/views/prices/PriceItemDialog.vue:145`；`src/views/tools/AlarmDialog.vue:167`。
- 现状：价格格有错误颜色和说明文字，但输入框没有对应的 `aria-invalid`、`aria-describedby`；多处表单也只是把错误段落放在字段旁边。
- 建议：先完善确实承载字段校验的公共控件，让文字与控件关联，使用现有 danger 主题色；统一错误行字号、行距和位置。普通无校验文本框无需新增一整套封装。

### 6. 历史窗口筛选与空态再追齐（P3）

- 位置：`src/views/accounts/AccountRecords.vue:152`、`:287`；`src/views/income/OnlineRecords.vue:134`、`:232`；`IncomeHistoryDialog.vue:172`；`src/views/overview/OverviewView.vue:814`。
- 现状：历史记录已共用表格、分页及滚动区，但搜索仍有不同的局部宽度规则；首页图表空态还单独维护一套居中、文字灰阶与间距。上一轮统一的是部分页面级筛选和图标空态，并未覆盖所有业务容器。
- 建议：给搜索、筛选清除入口、无结果提示建立同一使用口径；保留历史窗口与主页面合理的宽度差异。只归并相同呈现，不把卡内空态和整页引导空态拉成同一高度。

### 7. 说明与回执文案继续减法（P3）

- 位置：`src/views/tools/AlarmView.vue:140`、`src/views/SettingsView.vue:40`、`src/views/tools/AssetView.vue:120`；`src/views/settings/DataSection.vue:216`；删除操作及成功通知分布于闹钟、收益和目标页。
- 现状：部分副标题重复下方功能或混入“随包分发、不联网、JSON”等实现说明；删除问句与成功回执仍混用“删掉 / 删除”“已删掉一条 / 已删除记录”等写法。
- 建议：同页上下文明确时统一为“新增、修改、保存、删除、已保存、已删除”；省掉重复说明。跨页入口保留对象名。覆盖范围、整份替换、无法撤回、跨日计算等会影响决定的信息保留；备份格式与技术信息可放到次级说明。

## 小范围功能回执

### 8. 浏览器预览的外链结果避免误报（P3）

- 位置：`src/services/desktop.ts:68` 的 `openExternal()`；调用处包括 `src/views/ToolsView.vue:56`、`src/views/overview/OverviewView.vue:101`。
- 现状：IPC 失败后会尝试 `window.open()`，随后仍无条件返回 `false`。纯浏览器预览即使打开了页面，调用方也会提示“没能打开浏览器”。
- 建议：明确区分桌面系统外链与浏览器预览降级，返回与实际路径一致的结果；不能把 `noopener` 模式下 `window.open()` 返回 `null` 简单等同于被拦截。桌面 IPC 故障仍应可诊断。

## 执行顺序与边界

先处理 1–4，完善失败回执、缩放和锁定；再处理 5–7 的样式与文案，最后处理预览外链回执。

这一轮不建议合并不同业务的数字输入组件、不统一所有弹窗宽度、不删除不同场景需要的两种按钮材质，也不新增 CSS 框架、全局状态管理库或大规模重命名。实际排版效果需在用户指定视觉验收时检查六主题、明暗和字号组合。
