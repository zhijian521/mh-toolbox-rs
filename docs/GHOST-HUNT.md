# 捉鬼助手

> 这份文件回答三个问题：**坐标从哪来、范围怎么算、图怎么画**。
> 分层与目录归属见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，视觉规范见 [`CONVENTIONS.md`](CONVENTIONS.md)。
>
> **状态**：P0 已实现（2026-10-31）。截屏、OCR、文本解析、双层范围渲染、三种模式都在真机链路上
> 跑通。标「已验证」的条目都有实测数据支撑；还没做的只有行走掩膜、命中记录与经验偏移分布（§7）。

## 1. 任务的文本格式（已验证）

捉鬼任务只从任务追踪面板读，不碰内存、不碰协议。实测原文（2026-10-31，角色归岚）：

```
捉鬼
钟馗抓鬼（第5个）：去大唐境外559,54附近抓巳时四刻偷尸鬼。

鬼王
降服千年厉鬼（第5个）：去海底迷宫一层的0，0附近
```

两条任务句式**不一样**，解析器必须分别处理：

|          | 小鬼（钟馗）       | 大鬼（鬼王）         |
| -------- | ------------------ | -------------------- |
| 句式     | `去{地图}{X},{Y}`  | `去{地图}的{X}，{Y}` |
| 地图名后 | 无「的」，紧贴坐标 | **有「的」**         |
| 坐标分隔 | **半角**逗号       | **全角**逗号         |
| 任务前缀 | `钟馗抓鬼`         | `降服千年厉鬼`       |

**句尾是免费的天眼状态信号**，四种，全部由「坐标后面跟着什么」直接读出：

| 读到           | 状态      | 含义                                                                                           |
| -------------- | --------- | ---------------------------------------------------------------------------------------------- |
| `附近`         | `nearby`  | 未开眼，画 ±50 范围                                                                            |
| （什么都没有） | `silent`  | **已开眼**：游戏把 `附近` 两个字直接删掉，不给替代字                                           |
| `处`           | `exact`   | 已开眼（另一种写法）                                                                           |
| （兜底句式）   | `unknown` | 句首整段走样、只能靠「抓鬼…去…坐标」兜底时走到这一档，那层**不捕获**句尾，无从判断，仍按范围画 |

`silent` 与 `unknown` 必须分开，混成一个会同时错两头：当成 `exact` 则每条兜底解析出来的任务都画成
一个点；当成 `unknown` 则开了天眼的任务永远停在 ±50 上，用户只能自己跑遍 100×100 格。2026-11-01
用户实测：**天眼之后「附近」是整段消失的**，不是被替换成「处」。

官方说明：大小鬼同领时，**一个天眼通符同时精确化两条任务**。所以状态可能一小鬼一大鬼，两种模式要
能并存，不能假设全局统一。

**自动折行是最大的实现陷阱。** 面板宽度固定，长句会被切成：

```
钟馗抓鬼（第1个          ← 括号被切开
）：去江南野外            ← 下一行从右括号开始
134,54附近抓亥           ← 鬼名被切开
时三刻偷尸鬼。
```

所以**必须先按任务块把所有行拼成一整串再跑正则**，任何逐行匹配都会漏。

## 2. 坐标映射（已验证）

场景地图是等距美术，但**坐标到像素是直角映射**，不是 45° 投影。实测两图：

| 图       | 图片尺寸  | 坐标值域  | kx px/格 | ky px/格 | 误差  |
| -------- | --------- | --------- | -------- | -------- | ----- |
| 江南野外 | 463 × 344 | 160 × 120 | 2.894    | 2.867    | 0.94% |
| 北俱芦洲 | 459 × 346 | 228 × 170 | 2.013    | 2.035    | 1.10% |

两向密度差在 1% 以内 → 图片精确框住 `(0,0)~(maxX,maxY)`，无留白、无偏移。
**坐标系：原点在左下角**，x 向右，y 向上，所有地图一致。

```
px = gx × W / maxX
py = H − gy × H / maxY      ← y 必须翻转
```

交叉验证（比数学更硬的证据）：把官方 NPC 坐标表映射到江南野外图上，卵二姐 (32,21) 落在左下小屋
旁、樵夫 (133,22) 在右下田地、罗纤纤 (22,90) 在左上葡萄园、江湖奸商 (103,95) 在右上河湾——四个
全部落在合理位置。

### 由此推出的两条硬规则

**① 几何计算必须在坐标空间里做完，最后一步才乘 kx/ky。** kx 与 ky 一般不严格相等，游戏坐标里的
正方形（如 ±50）画到图上是**矩形**。先映射再计算，热力形状会歪、偏移方向会错。

**② 每张图的值域必须独立配置，代码里不许写死 200 或 300。** 实测跨度极大：五庄观约 60×38、大唐
境外 maxX 到 640。值域决定「图有多大」，**不决定「坐标合不合法」**——越界只提示、不否决（§8-22）。

## 3. 范围计算

三层收敛，从外到内：**① 基础容差 ±50**（官方口径：「任务栏提示坐标 ±50 范围内，需自行寻找，
天眼通符给准确坐标」）。**② 地图边界裁剪**：`假坐标 + 50` 撞到边界时直接截断——实测江南野外
134,54：`134+50=184 > 160`，右侧砍掉 24 格，面积从 10000 降到 7600（−24%）；地图边界本身就是一条
精确信息。**③ 高概率区域**（社区经验，可开关，口径见 §6）：假坐标 ≤50 时真坐标一定更小、≥150 时一定
更大，两轴同时命中时面积只剩 1/4；中间带 51~149 没有方向，不给第二层。

| 图       | 假坐标 | 官方 ±50 | 高概率区 | 减少 |
| -------- | ------ | -------- | -------- | ---- |
| 大唐境外 | 200,60 | 10201 格 | 5151 格  | −50% |
| 宝象国   | 30,60  | 8181 格  | 3131 格  | −62% |
| 五庄观   | 40,30  | 6916 格  | 1271 格  | −82% |

**内框与外框重合时不画内框**，只留一层浅红——画一个重合的框会让人以为内框就是范围。开关关掉时同样
只有一层。

**假坐标可以越出值域。** ±50 是游戏按真实位置随机给的，**不按地图边界裁剪**，所以真身贴着右边时
提示坐标本身就会 > maxX（2026-11-01 普陀山 96×72 读到 100,66）。这种任务不能丢，只按贴边处理：
判边用原值（越界那条轴不窄，范围已经顶到边了），算框先把坐标夹回 `[0, max]`（否则 `600-50` 与
`min(95, 650)` 会给出 x0 > x1 的倒框），画的时候标记落在边界上、数字后面标「图外」。

## 4. 数据获取（已验证）

不读进程内存——那是内存挂，性质不同。走**截屏 + 离线 OCR**：窗口按标题匹配「梦幻西游」
（`mhtab` 进程，单窗口）；GDI BitBlt 截屏 4~10 ms/帧（215×400）；PP-OCRv4 单帧 420~660 ms。

### OCR 引擎：从系统 OCR 换成 PP-OCRv4（2026-11-01）

`Windows.Media.Ocr` 零依赖、离线、单帧 84 ms，看着划算，**但它读不了彩色描边字**：同一帧白字全对，
黄色高亮的「金钱镖」「金童子」「龙女妹妹」整段读不出来。根因是它面向文档扫描（白底黑字）训练，而
梦幻任务栏是暗底 + 黄绿白三色混排；它也不返回置信度，错得再离谱也没有信号。换 PP-OCRv4 后同一帧
11 行全对。代价是模型 16 MB + onnxruntime 12 MB，单帧 420~660 ms（约 6 倍）——但这一页的全部价值
就是「认得准」。

**两个坑必须记住，都是「界面看起来完全正常」那种：**

1. **字典格式**。`paddle-ocr-rs` 从模型元数据取字典时会自己补 `["#"] + keys + [" "]`，但这份 ONNX
   是 Paddle 转来的、不带 `character` 元数据，走元数据路径直接 panic
   `crnn_net character not initialized`；退回「传字典文件」时 crate 只做 `split('\n')`、一位不补，
   于是整体错开一格——「任务追踪」读成「潘指词喵」。必须由我们在 `prepared_dict()` 里补好首行 `#`
   与末行空格再喂进去。
2. **打包漏了字典 → 静默降级成系统 OCR**。`tauri.conf.json` 的 `resources` 曾只写 `models/*.onnx`，
   字典没进包；`locate_models()` 又以「DET 在就算可用」判定，于是选中这个**缺字典**的目录，
   `engine()` 报错后安静退回系统 OCR。界面上一切照跑、状态灯还是绿的，只是认出来的字全错——白查了
   一整天。现在两头收紧：`resources` 带上 `models/*.txt`，`locate_models()` 要求**四件齐全**，前端
   在 `engine === 'windows'` 时显式提示降级。

### 截屏方式的取舍（实测）

| 方式                      | 结果                 | 说明                                                                  |
| ------------------------- | -------------------- | --------------------------------------------------------------------- |
| PrintWindow               | **全黑**             | 梦幻是 DirectX 渲染，GDI 拿不到画面；带 `PW_RENDERFULLCONTENT` 也一样 |
| BitBlt from **window** DC | 可用，但**缺右边缘** | 不要求前台；实测右边缘整片返回纯黑                                    |
| BitBlt from **screen** DC | 可用，内容完整       | **默认走这条**；要求窗口在前台且不被本窗口遮住                        |
| Windows Graphics Capture  | 未验证               | 能截被遮挡窗口；单窗口场景暂不需要                                    |

**窗口 DC 会丢右边缘**（2026-10-31 真机撞出来的）：同一个 1295×1039 窗口、同一块区域（x 从 0.72W
起、363 宽），屏幕 DC 一路画到第 362 列都有内容，窗口 DC 到第 **207** 列就全黑——少掉的 156px 正好
是任务面板（正文 x 1092~1295）。后果是「任务栏明明在，界面却一直显示没读到任务」，而任何一层都不
报错。所以 `screen::grab` 是**屏幕 DC 优先、窗口 DC 兜底**（屏幕全黑时，比如自己的窗口压上去或锁屏，
再退回去试一次）。**前提：五开是多标签合并在一个窗口内的**（已确认）；将来若变成多个独立窗口、或
需要在本应用盖住游戏时也能读，必须换 WGC。

### DPI：不声明就整体错位 25%

临时脚本里有的 `SetProcessDPIAware()` 搬进 Rust 时漏了：未声明时读到 1036×831（= 1295×1039 ÷
1.25），per-monitor v2 才是 **1295×1039**。ROI 是按窗口比例算的，比例没错，但「按虚拟坐标算出的
位置」去截「物理像素」，两边差 25%；而任务面板只有 200 多像素宽，差 25% 就等于整个框空掉。现在
`screen::ensure_dpi_awareness()` 在 `list_windows` 与 `grab` 各调一次（`Once` 幂等）。

### 系统缩放：那组 ROI 像素是「标定值」，必须按 DPI 换算

**游戏分辨率**（窗口 640×480 → 1295×1039）**不影响**面板的物理尺寸——面板贴右边、宽固定，窗口拉大
只是露出更多地图，所以 ROI 用像素而不是比例。**系统显示缩放**会改变面板的物理像素（125% 下 205px，
150% 约 246px），所以四个 ROI 值只是**在 125%（120 DPI）下量的标定值**。不换算的后果不是「差一点」，
而是**整行被切掉**：

| 缩放 | 面板首行 y | 面板宽 | 旧 ROI（固定 215×400 @ top 200）  |
| ---- | ---------- | ------ | --------------------------------- |
| 125% | 210        | 205    | 正好                              |
| 150% | 240        | 246    | 左边缘切掉约 44px，每行开头都没了 |
| 100% | 160        | 164    | 上边界晚 40px，第一条任务整行没了 |

2026-11-01 实测（本机 150%、窗口 978×814）：补偿后 ROI 读作 `258×480 @ (713,240)`，正文行首 x≈19；
不补偿时左边界是 x=757、行首落在 −25——正是「钟馗抓鬼」被读成「道抓鬼」的来源。实现：
`screen::monitor_dpi(hwnd)` 取**显示器**的有效 DPI（不是 `GetDpiForWindow`——它对不感知 DPI 的窗口
返回 96，等于说「不用补偿」，恰好反了），`Roi::at_dpi(dpi)` 四个像素值乘 `dpi / 120`，放大倍数**只
往大调**（字变小才需要多放大）。每帧现问一次，不缓存：用户改完缩放不该重启应用。状态行会显示
「系统 150%」——识别突然变差时，第一件事是确认这个数和系统设置一致。

### OCR 的三个坑（系统 OCR 时代，留作兜底时的参照）

2026-10-31 在 `Windows.Media.Ocr` 上量的；换 PP-OCRv4 后同一帧全部不再出现，但 `ocr.rs` 还留作兜底
（模型缺失时退回），那时候下面这些规律仍成立，所以不删。

**① 数字与字母混淆是系统性的，不是随机噪声。** `559` 在 1×~6× 六个倍率下稳定读成 `55q`，`93` 稳定
读成 `q3`。纠错表：`q→9 O/o→0 l/I/|→1 Z→2 S→5 B→8 g→9`。纠错必须留日志，否则规则一变只看到热力区
画错、看不出原因。

**② 逗号会丢。** 5 帧里 `0，0` 有 1 帧变成 `000`，无法二分。这类单帧残缺不靠投票吸收，靠**保留最好
的一帧**（§8-6）。

**③ 系统 OCR 没有「干净的倍率」。** 1× 丢「第1个」的数字与「降服」首字；2× 读出「钟馗抓鬼」但把
`）：` 读成 `）的`；3× 吃掉首字「钟」；4× 首字与冒号都对、但把 `（` 读成 `口`。**别指望调倍率解决，
解析层要容忍这些系统性错字**。换成 PP-OCRv4 后倍率含义也变了：它自带检测分支，倍数只需「够框住
一行字」，2× 即够（单帧 420~460 ms）；再往上只变慢，×4 起开始丢行。

### 其他已知问题

- **面板有滚动条**：任务多时捉鬼条目可能滚出可视区，读不到，需要检测或提示。
- **任务栏会被战斗/对话界面遮挡**：必须检测 ROI 是否被覆盖并暂停更新，否则会拿旧坐标继续画。
- **`0，0` 是游戏真实显示的值**（海底迷宫一层实测，玩家确认），不是 OCR 错误，不能当噪声丢，但也
  没法直接画范围（§6）。

7.20），界面上「±50 搜索框」的像素尺寸从 150px 到 720px 不等；**有四张竖幅**（女儿村、波月洞、
碗子山、长寿村），布局不能只考虑横幅。

**迷宫那 4 张可以做**：TAB 图只画当前层，其他层只是出口标签（海底迷宫一层图上标着「三层 / 二层 /
东海龙宫 / 海誓阁」），按层各切一张即可。

### 高概率区域的判定口径（2026-11-01 定稿）

三条全部来自外部共识，不是本机实测：① **官方容差 ±50**（官网《抓鬼攻略·队长篇》「鬼的坐标误差在
正负 50 以内」）；② **假坐标 ≤50 → 真坐标一定更小；≥150 → 一定更大**（多来源措辞一致，有「100%
准确」这类强表述，也是「35 个鬼只用 20 个眼」的依据）；③ **51~149 没有方向**（原话「51-149 的没有
规律只能硬找」），所以中间带**不画深红**——给它一个方向就是编一条社区明确否认的规则。

由此得出几何：深红 = 官方 ±50 框 ∩「贴边那半边」，即 `[value, value+50]` 或 `[value-50, value]`；
两轴都命中时面积降到 1/4。

**为什么删掉「按比例 25%/75%」**：它不是另一种经验，而是把 50/150 除以「假设坐标域宽 200」的归一化
结果。坐标域不是 200 时两种口径分歧，而攻略原文给的是绝对值；实测 20 张图只有 3 张接近 200 宽。
代价要认：江南野外 160 宽、假坐标 134（占 84%，肉眼明显靠右）在绝对口径下落在中间带、不出深红——
这是忠于原话，不是漏判。

**「≥150」的适用范围**：这条与 ≤50 对称的前提是坐标域大致 0~200。实测 `maxY < 150` 有 **15/20**
张、`maxX < 150` 有 **7/20** 张（其中 6 张两轴都不到），这些图上「往大走」数学上不可达——属规则的
适用范围，不是判错（社区攻略主要在境外、建邺、长寿这类大图上用）。

**明确不采纳的两类说法**：「寻鬼图」（X<Y 走左下……，号称 70% 准确率、转载极广）其实是「真坐标就在
假坐标附近」的常识推论——X 小本来就是左边；单独作为第二套口径会与 50/150 打架且没有量化依据。
「五庄观、普陀山一律去左下角」在同一张图上鬼恒在某个角原理上说不通，更可能是刷点记忆。这两类要进
产品只能走 §7 的「命中记录」：累积 `(假坐标 → 真坐标)` 偏移，攒够 30 次样本再决定。

**`0，0` 已确认不是 bug**：含义是**该场景没有可用的坐标域**，不是 OCR 读错、也不是任务刚接未生成。

### 三种渲染模式（由任务文本自动决定）

| 任务文本                     | 模式     | 渲染                                                            |
| ---------------------------- | -------- | --------------------------------------------------------------- |
| `去X，Y`（「附近」已被删掉） | 精确点   | 十字圆心 + 朱红心（与范围模式同一枚标记）+ **写在地形上的**坐标 |
| `去X处`（另一种天眼写法）    | 精确点   | 同上                                                            |
| `去X，Y附近`，坐标有效       | 双层范围 | 官方 ±50 浅红 + 高概率区域深红                                  |
| `去X附近`，坐标为 `0，0`     | 全层热区 | 整幅描边（纸白 + 朱红虚线）+ 一句「整层都要找」                 |

精确点的坐标**不套任何底板或边框**，朱红数字直接压在地形上，靠一圈纸白描边（先 `strokeText` 再
`fillText`，净外扩 1px）从任何底色上择出来：范围是一块「区域」，需要边界；精确点是「一个位置」，再
套一个框就成了界面控件贴在地图上。这套标记的三个颜色（`--map-seal` / `--map-seal-ink` /
`--map-halo`）是**全站唯一不随主题翻面**的令牌：底图是游戏截图，主题切暗色时它一格不变，标记要对抗
的是地形而不是主题——跟着翻面的话 `--cinnabar-ink` 在暗色下成亮粉朱（`#b85b49`），压在**同一片**
绿地上反而比亮色更糊。

降级模式不是「没功能」：没坐标时唯一有价值的信息是**你以前在哪找到过鬼**——每次命中记一次绝对坐标，
累积成该层自己的热力分布，样本过 10 次就能指路，而这张图恰恰是全程唯一没有别的办法收敛的一张。

### 场景白名单（防止误判吞掉真坐标）

`0，0` 只允许出现在**已登记为无坐标域**的场景（当前：海底迷宫一层）：白名单外读到 `0，0` → 判识别
失败、重试而不是降级；白名单内读到非 `0，0` 的有效坐标 → **按有效处理**（说明游戏改了，立刻记日志）。

官方 NPC 坐标表里**海底迷宫只有 2~5 层、没有一层**，而地狱迷宫三层有数据（最大约 40,45）。所以
`0，0` 更可能是「一层这张图本身没有坐标域」，而不是「所有迷宫都不给坐标」。**不要提前把 4 张迷宫都
降级**，按实测逐张登记。需要玩家确认一次：**在海底迷宫一层开天眼**，看任务文本变成 `0，0处` 还是
出现真实坐标——这决定这张图连精确模式都没有，还是只是未开眼时没坐标。

**两层红的画法：填充只表示「这一片」，范围的边界交给 2px 线。** 第一版把填充给到 alpha 0.62 /
0.70，用户反馈「太遮挡地图」——玩家要做的是**照着地形走过去**（洞口、通道、水陆分界），范围只是
入口，盖死地形等于把唯一的收敛线索抹掉。现在压到 0.24 / 0.42（暗色 0.30 / 0.48），边框从 1px 加到
2px：填充只剩两成出头之后，**那圈线才是范围唯一的凭据**，1px 在树丛与山棱的线条里会被读成地图自带
的一格。不用斜纹 / 虚线替代填充：两者在写实地形上都会与树丛、小路的纹理打架。两层靠**明度差**区分。

几处实现上定下来的事，都是踩出来的：

1. **`upscale` 的定点采样必须用有符号数。** `dst = 0` 时源坐标是负的半个像素（放大 3 倍为 −0.333），
   用无符号减法当场溢出；就算不提溢出，`>> 16` 对负数也会给出错误的整数部分——表现是整块文字偏一
   截而 OCR 仍认得出，只有行的 y 坐标全错。`screen.rs` 的测试盯的就是这一点。
2. **canvas 里不能用 `getPropertyValue('--cinnabar')`。** `tokens.css` 的值是 `light-dark(...)`，变量
   存的是原始 token、不做函数求值；塞给 `ctx.strokeStyle` 是非法颜色，canvas **静默忽略**，于是所有
   框线都画成默认黑。要借一个探针元素把变量当 `color` 用一次再读 computed style。
3. **暗色下给框线打的白衬底要对固定浅色，不能跟 `--paper`。** 纸色随主题翻面、暗色下成了近黑，衬
   进去反而把线压得更糊。它对抗的是地形，不是主题色。
4. **两个范围框常常共用同一条上边**（某轴没被收窄时）。两个标签都放顶部必然重叠，而叠掉的恰好是
   「收窄多少」这个最该看见的数字。现在外框标签压到框内左下角。
5. **`0,0` 的降级不能静默。** 白名单外读到 `0,0` 判识别失败并显示原因，不切「全层铺底」——否则界面
   看起来完全正常，画的却是一片没有信息的底色。
6. **一帧糊掉不该覆盖前面读全的结果——大小鬼各留各的最好一份。** 游戏画面一直在动，同一行这一帧读
   得干净、下一帧就糊掉；「糊掉」不代表任务变了。早先是整帧替换，于是**一帧糊就把攒下的好结果冲没
   了**，界面上表现为地图反复消失又出现。现在 `small` / `big` 两个槽位各留一份，规则全在
   `ghost-hold.ts`——纯函数，`ghost-hold.test.ts` 直接喂**连续的帧序列**（这一层的错法全是时序的，
   截一张图看不出来）。

    **完整度按三段信息加权**：地名 1 + 句尾 2 / 1 / 0 + 坐标 4。句尾三档而不是两档：`附近` / `处` 得
    2 分（有字为凭）、`silent` 得 1 分（「附近」消失，大概率开了天眼，也可能漏读）、`unknown` 得 0 分
    ——**1 分这一档是为了让误判能自己退回去**。坐标必须最重：**丢了坐标的一帧不许顶掉只丢句尾的一帧**，
    否则 `去江南野外0,0附近` 会拿到比 `去江南野外134,54` 更高的分，画面就从真坐标当场跳成「识别
    失败」。

    - 新的更**完整** → 立刻换。好帧可能只出现一次，等确认等于把它丢掉；更**残缺** → 一律不动。
    - 同分但**换了图** → 立刻换：一条任务活着时地图不会变，图变了必然换了任务，晚三帧用户就跑错地图。
    - 同图同坐标、读到 `处` → 立刻换（多了一个明确的字，要马上看到那个点）。
    - 同图同坐标、`附近` 两个字**消失**（`silent`）→ **连续 2 帧**才换：这是**缺失**，而缺失比存在弱
      （OCR 漏读两个字比凭空多读常见得多），孤立一帧先当作遮挡（NPC 走过去通常一两秒）。真开眼之后
      「附近」永久不再出现，两帧后必然满足。
    - 反过来 `silent` / `处` → `附近` 是**降档**，不单设规则，交给分数：`nearby` 2 分 > `silent` 1 分，
      按「更完整立刻换」生效——这就是给 `silent` 定 1 分的全部用处。
    - **序号读得到、又没变，坐标却变了 → 判误读，永远不采纳。** 这个组合在游戏里不存在，只可能是认错
      一位。它比「连稳几帧」强，是因为遮挡会**持续**：人站在任务栏前不走，错读能连着十几帧一样。
      序号在那一行里最靠前、最少被挡，正好当这张否决票。
    - 其余（序号没读到、或序号变了）→ 连续 3 帧一致才换（约 3.3 秒）。序号变了**不能**当立刻换的
      依据：糊掉那帧整行都乱、序号一起错，那时它和真换了任务长得一模一样。
    - 这一帧压根没读到某条（折行变化、滚动、被挡住）→ 什么都不做，不是「任务没了」。

    旧结果长期没被刷新时，卡片头上标 `Ns 前`——既不说它还是新的，也不抹掉。**年龄按槽位各算各的**：
    两条任务独立读，大鬼那行常糊、小鬼每帧都干净是常态，取最大值会让一直在读的那条也标成「40s 前」，
    而用户正是靠这个数字判断「这条任务是不是没了」。

    夹具三档各盯一件事：`?m=flap` 三帧分别缺小鬼、缺大鬼、两条全缺，跑过两轮两条都得在；`?m=swap`
    换图必须**立刻**换过去（保留 ≠ 永不更新）；`?m=drift` 同图同序号被认错一位且一直错着，走多少帧
    都得还显示原坐标。

7. **两条任务画在同一张卡片里，上下分栏，不做切换。** 大小鬼是一起捉的，实际动作就是在两个地图之间
   来回跑；做成「点一下换一张」等于把并行的两件事串起来，每换一次都要重新定位。`plans` 每条一个
   `.map-item`：有一条就单张吃满，两条各占一半——分栏是内容的结果，不是布局的默认。两张卡片是弯路：
   多一道边框、多一段间距，还多一层「这是两个物件」的错觉。
8. **卡片高度由内容区撑满，不用 `100vh - N` 估。** 估出来是「大概」，撑满拿到的是「正好剩这么多」，
   窗口一改两边就差一截（早期 `100vh - 170` 实测底部空 76px）。做法：`.hunt { height: 100% }`
   （`.page-content` 是 `flex: 1` 且高度确定）+ `grid-template-rows: minmax(0, 1fr)`（行高确定，格子
   才会拉伸）。卡片是 flex 列，`.map-item` 与 `.map-stage` 都要 `min-height: 0`，否则子项按内容撑高、
   两张一起溢出。
9. **图上已经画了的东西，头上不再抄一遍。** 坐标、官方格数、收窄比例、判定依据全部画在 canvas 里
   （标签贴着自己的框），卡片头上只留「小鬼 / 大鬼 + 地图名」。第一版把这些又排了一遍，结果头上两行、
   图上两行，地图被挤矮一截，读的时候还要在两处对同一个数。
10. **标题与地图都靠左，共用一条竖线。** `MapCanvas` 的 `layout.left` 从居中改成 0，标题去掉
    `justify-content: center`。一屏两图上下时人扫的是左边缘；居中版本把「组」交给中线，标题与图各在
    各的位置上，中间空一大片。两块之间只留 9px，不画分隔线：再加一道横线等于把一张纸切成两格，而且
    线会把行高吃掉、把地图压矮。
11. **标题匹配不能写裸「梦幻」。** 本应用叫「梦幻养老助手」，裸「梦幻」会让自动挑选把自己选成靶子：
    一路 OCR 自己的界面文字（「霞鹜文楷 Screen」），而界面一切正常、只是任务列表永远空着。现在只认
    `梦幻西游` 与 `mhtab`。这个 bug 是真机冒烟测试第一次跑就抓到的，纯前端桩数据永远暴露不了。
12. **截到全黑帧必须报错，不能当成「读到 0 行」。** 锁屏、窗口被完全遮住、窗口不接受 `BitBlt` 三种
    情况长得一模一样，共同结果是「状态显示监听中、任务列表空着」——用户会以为鬼没刷。锁屏时
    `BitBlt` 对**任何**窗口都返回全黑（真机实测：解锁时非黑像素 100%，锁屏后 0%）。判据在
    `screen::Frame::is_blank`，`ghost_probe` 直接返回错误。
13. **必须声明 DPI 感知，否则坐标整体错位 25%**（§4）。症状极具误导性：两边都不报错，只是 ROI 截到
    的区域空着，看起来像「任务没刷」。
14. **窗口 DC 在梦幻上会丢右边缘，任务面板就在那一条上**（§4）。默认走屏幕 DC；用窗口 DC 是「看起来
    能用、只在真机上缺一块」的那类 bug。
15. **解析正则要容忍系统性错字，别靠调放大倍率。** 下面这批错字全部来自 `Windows.Media.Ocr`
    （2× 把 `）：` 读成 `）的`，3× 吃掉首字「钟」，4× 把 `（` 读成 `口`）。换引擎后同样 8 帧能全读对，
    **但容错规则一条都不删**——兜底引擎还在，而且这些是真机上真实发生过的错法，删掉等于把「见过的
    最坏情况」忘掉。2026-11-01 用户从页面抄回 8 帧连读输出后又补了四条（都是**必须**改，不改整条
    解析不出来）：**「降」会整个消失**（`服千年厉鬼`，改成 `降?服?千年厉鬼`，靠「千年厉鬼」当锚点）；
    **「去」前面的字符没有形状约束**（`）《去`、`）．昊建邺城`，允许 0~2 个非数字字符，`去` 本身也可
    读成 `昊`）；**括号可能变成 `〈`**；**坐标分隔符两侧都可能多字符**（`36，一145`、`36，，45`，分隔符
    后允许 1 个非数字，但**分隔符本身在正则里仍不可省**——写可选的话 `(\d{1,4})` 贪婪会给出 `1191` +
    `07` 这种看着合法的读法）。

    还有一层**兜底句式**（`LOOSE_SMALL` / `LOOSE_BIG`）：句首整个走样时（`中旭抓鬼`、`挚月艮千厉鬼`
    ——「降服」和「年」都不在），只认「抓鬼 / 厉鬼」锚点 + 一个「去或昊」+ 一对坐标，并约束锚点与
    坐标之间不许出现第二个「去」（`[^去]{0,12}?`）。**它只在严格正则一段都没命中时启用**。

    **第三层：分隔符整个消失（坐标粘连）。** 折行**正好落在逗号上**时逗号跟着行尾被裁掉，拼接后两段
    数字粘成一串（`去麒麟山的119107附近`）。这一层不靠正则切，靠**这张图的坐标值域**：枚举所有切分
    点，要求 `x ≤ maxX` 且 `y ≤ maxY`。20 张图 maxX 最大 640、maxY 最大 210，都是三位数，所以 6 位
    （`119107`）只有 3+3、5 位（`13454`）通常只剩 3+2、4 位（`1234`）取长度差最小的 2+2。两条附加
    约束：**前导零直接排除**（`12105` 不可能是 `121,5`）；值域筛不干净时（`12115` 可切 `12,115` 也可
    `121,15`）**判失败、不猜**——错几十格的坐标比没有坐标更坏；地名没对上底图时也没有值域可用，同样
    放弃。切成功的帧会在「识别原文」里留一句「坐标缺分隔符，已按值域切成 x,y」：这个坐标是**算出来
    的**，用户有权怀疑；而且这一层的句尾只在明确读到「附近 / 处」时才采纳，读不到一律 `unknown`——
    缺逗号本身就说明这帧不完整，不该再拿它判「附近消失 = 开了天眼」。

    这批原文已逐帧固化：`#/tools/ghost?m=live1` … `live8` 单帧复现，`?m=live` 是 8 帧连放；另有 4×/
    3× 两档 `real` / `real3`；分隔符丢失是 `?m=wrap`。逐帧的**解析结果**断言在 `ghost-parse.test.ts`
    （`npm run test`），上面那个 hash 档验的是界面上的时序与绘制，两者不重复。

16. **地名匹配要认「差一个字」「只读出两个字」和「形近字连错两个」。** OCR 对地名不是全对全错，而是
    稳定地错成某一形：「碗子山」被读成「碗孑山」（3 字对 2 字）、又被读成「腕孑山」（**两字同时错**，
    但错的是形近字），「建邺城」只读到「建邺」或「邺城」。所以 `findGhostMap` 走四档打分、取分数
    最高的一条（不是「第一个命中的」，那等于让清单顺序决定送去哪张图）：全等 / 别名全等；**形近字
    归一后全等**（`CONFUSABLE = ['碗腕', '子孑']`，把误读字换回组内第一个字再比——不引通用形近字库，
    那会归一掉正常地名里本来就有的字）；互相包含，短的一方至少 2 字；差一个字（双指针，替换 / 插入 /
    删除各算一处）。

    **这条放松有前提**：20 张图两两之间至少差 2 个字（都以「山」「村」「国」结尾的那几组，相同位置
    只有一个字重合），所以「改一个字就变成另一张图」的组合不存在。**新增地图时必须重新核一遍**（包括
    新增的形近字组会不会让两张图归一后撞车），否则这一档会把鬼送到隔壁地图上，而且不报错。坐标之间的
    分隔符也放宽成 `[,，、．.]`：逗号被读成顿号、句号都出现过。回归夹具：`#/tools/ghost?m=fuzzy`
    （建邺 + 碗孑山 + 顿号分隔），两条都必须落到正确底图，`.map-alert` 为空才算过。

17. **「目录可用」的判据必须等于「能跑」，降级必须自报家门。** 模型是四件套（det / cls / rec 三个
    onnx + 一个字典），`locate_models()` 起初只看 `det` 在不在，于是选中一个缺字典的目录（打包漏了
    `*.txt`），`engine()` 报错后静默退回系统 OCR——症状是「识别得很差」而不是「坏了」，因为链路每一步
    都成功了。现在两头堵：判据改成 `REQUIRED` 四件全在；`GhostHuntView` 在 `engine === 'windows'` 时
    于状态区摊开一句「模型没加载，正用系统 OCR 兜底」。**教训可以推广**：任何「用其中一个文件代表整
    组」的存在性判断，都会在缺件时把错误推迟到运行时、并且伪装成别的问题；任何带退路的降级都必须能
    让用户看见。
18. **游戏重开后必须自动重查窗口，不能一直抱着旧句柄。** 用户在下拉里选过窗口后句柄就存着不变，游戏
    一重开，之后每帧都返回「窗口已关闭」，而重试用的是同一次调用、同一份选择，**永远不会自愈**。现在
    `tick` 一旦识别到这句错误就清空选择、重新枚举，下一帧按标题重挑，并在状态区说「游戏窗口已重开，
    正在重新查找」。这也是只能按文本判的地方：`invoke` 把 `Err(String)` 原样抛给 JS，没有错误码，两边
    任何一边改这句话就得同步改 `WINDOW_GONE`（`use-ghost-watch.ts`）。
19. **放大倍数的上限只能有一个数。** `ghost.rs` 原先按 `clamp(1, 6)` 夹，`ocr_paddle` 内部按
    `clamp(1, 4)` 再夹一次——传 6 会被静默压成 4，耗时和结果都和「调用方以为传的值」不符，却什么都
    不报。现在只有 `ocr_paddle::MAX_SCALE` 一份，两处都读它。
20. **前端也有回归测试，而且接在 `check` 里。** `npm run test` 跑两组：真机 8 帧（用户从页面抄回的
    原样输出，逐帧断言两条任务的地图与坐标；帧 7 的大鬼**故意留在失败状态**（`36，，45`），那是「宁可
    这一帧不更新」的设计）；单条容错（缺字地名、形近字、字母纠错、分隔符夹噪声、假坐标越界、无底图，
    一条对一个，用例名就是这条规则存在的理由）。**没接进 `check` 的检查等于没写**（`lint:commits` 就
    自己红过半年没人发现）。反向验证过一次：把分隔符那条字符类放宽成 `[^\d]{0,1}`，3 条用例立刻变红。
    做反向验证时要 `grep` 确认破坏真的落到正则上——第一次就撞上了「把注释改成一样的字、正则没动」，
    差点得出「测试没用」的错误结论。
21. **ROI 的像素是「标定值」，必须按显示器 DPI 换算。** 2026-11-01 用户报「游戏分辨率怎么调都没事，
    改系统缩放就识别变差」，当时这台机器已是 **150%**，而四个数是 125% 下量的。四个数乘 `dpi / 120`
    之后，同一窗口从「每行开头被切掉」变成整块框住。别用 `GetDpiForWindow`：对不感知 DPI 的游戏窗口
    它返回 96，刚好把补偿关掉。配套观测是状态行的「系统 150%」——先确认这个数，再怀疑别的。实验台加
    了 `LAB_RAW_ROI=1` 跳过换算，用来同屏对照「补偿前后」。
22. **值域越界只能提示，不能否决。** 任务栏给的是假坐标，游戏按真实位置 ±50 随机、**不按地图边界
    裁剪**——真身贴着右边时提示值本身就会越过 maxX（2026-11-01 普陀山 96×72 读到 100,66）。早先按
    「OCR 认错一位」一律丢弃，等于把一条本来能用的任务判成没读到。现在的口径：**保留**，在「识别
    原文」里写一句越界，图上按贴边画。三处配套，少一处都是错：判边用**原值**（越界那条轴不窄——范围
    本来已经顶到边，再砍只剩一根 0 宽的线）；算框前把坐标**夹回** `[0, max]`；标记**夹在边界上**并
    给数字加「图外」，画到图外的裁掉。代价是「600 读错」那种帧也会被采纳，但它画出来只是贴着边的一条
    线、还标着「图外」，看一眼就知道不可信——比让它静默消失更容易判断。

### 真机冒烟测试（不进门，是一把尺子）

`ghost_probe` 这条链有半截只有真窗口能验：GDI 到底能不能从 DirectX 化的游戏窗口拿到像素、默认 ROI
框不框得住正文。所以留了一条**手动**测试：

```bash
cargo test --manifest-path src-tauri/Cargo.toml --lib -- --ignored --nocapture smoke_real_taskbar
```

跑之前：游戏开着、任务栏展开、窗口在前台、**屏幕别锁**。它枚举窗口 → 挑梦幻窗口（没有就逐个试别的
窗口，跳过截成全黑的透明浮层）→ 跑一次真 OCR → 把每行原样打出来。断言只保证「链路能跑」，认出来的
字对不对由人对着游戏看。不在 CI 里跑，因为上面四条前置条件 CI 一条都不成立。

### 不开游戏的验证入口：测试文字（2026-11-02）

页面右下角常驻一块「测试文字」面板：把任务栏原文粘进去（或点一条样例），图上立刻按这段文字画范围。
**走的是与真机完全相同的那条链**——`linesFromText` → `parseGhostTasks` → `planFor` → `map-paint`，
不是另写一套模拟器。测的若是模拟器，测出来的只是模拟器对不对。为什么值得有它：冒烟测试要开游戏、摆
前台、别锁屏，一天跑不了几次；而解析层全是纯函数，喂一段文字就能走完。五条约束：

- **样例本身会被断言**。`ghost-samples.ts` 六条样例覆盖范围 / 精确点 / 全角逗号 / 双任务 / 折行与
  字母误读 / 缺分隔符六种分支，测试把每一条断言到**具体坐标**。只断言「能解析出东西」挡不住「正则
  退化成乱配」；样例坏掉时界面上的表现是「点了没反应」，最难查。
- **生效期间停轮询**，否则 1.1 秒后真帧回来把结果盖掉，看起来像「点一下闪一下就没了」。
- **退出不自动重启轮询**：测试时多半没开游戏，重启只会立刻报「没找到梦幻西游窗口」。
- **点「开始」时测试要让位**：不清的话，「开始」还没读到第一帧那一两秒里，`recompute` 会把测试结果
  和真帧交替写进 `plans`，图来回跳；而且若这次没启动成功，状态行报「没找到窗口」而下面「识别原文」
  还列着测试文本，读起来像「其实读到了」。所以 `start()` 里连 `report` 一起清。
- **一条都没解析出来时灯是赭色的**（`statusKind` 在测试态按下 `plans.length` 判）。灰灯会读成
  「待命中」，而实际是「这段文字里没有任务」。
