# 捉鬼助手

只维护现行解析、坐标与渲染边界。测量、实验和早期方案见
[历史快照](archive/ghost-hunt-through-2026-11-15.md)，不作为当前待办。

## 1. 任务文本

只截屏并离线 OCR，不读取游戏内存或协议。大小鬼分别解析：

- 小鬼：钟馗抓鬼…去{地图}{X},{Y}附近…。
- 大鬼：降服千年厉鬼…去{地图}的{X}，{Y}附近…。

任务自动折行，必须先按任务块拼接再匹配。数字纠错不能丢掉句尾状态：

- nearby：坐标后有“附近”，画范围。
- silent：句尾为空，开天眼后“附近”消失，画精确点。
- exact：坐标后有“处”，画精确点。
- unknown：兜底匹配未捕获句尾，保留范围，不能推断为已开眼。

大小鬼各自保留状态，不假定两条任务同时被完整识别。

## 2. 坐标映射

原点在左下，x 向右、y 向上，采用直角映射：

```text
px = gx × W / maxX
py = H − gy × H / maxY
```

几何先在游戏坐标空间计算，最后映射到像素；两轴缩放不一定相等。
各地图值域从清单读取，不写死统一宽高，也不把值域当作提示坐标的合法性边界。

## 3. 范围计算

基础范围采用官方提示坐标 ±50，再裁剪到地图边界。提示坐标允许越界，不能因此丢弃任务；
按现有算法夹回值域计算范围，标记贴边并提示图外。越界轴不再经验收窄。
高概率区域是基础范围与经验方向的交集；关闭开关或内外框重合时不画第二层。
容差和阈值唯一真源为 public/game/data/gameplay.json。

## 4. 截屏与 OCR

主链路为随包 PaddleOCR，Windows 系统 OCR 仅作降级。系统中文识别依赖系统语言能力，
其可用性不代表 PaddleOCR 的识别效果。部署边界见 [发布说明](RELEASE.md)。
ROI 标定像素按显示器有效 DPI 换算，不能使用固定物理像素或不感知 DPI 的游戏窗口报告值。
识别行坐标回传前需除回预处理放大倍数。游戏窗口需可见；最小化、黑屏、遮挡和识别失败应显示状态，
不把旧坐标当作新结果。

## 5. 游戏事实与资源

地图、值域及无坐标域标记在 public/game/maps/，任务句式和玩法参数在 public/game/data/。
加载入口位于 src/services/，文档不重复维护像素与完整事实表。资源维护见 [资源规范](GAME-ASSETS.md)。

## 6. 范围与渲染口径

经验方向使用绝对阈值：≤50 向较小坐标收窄，≥150 向较大坐标收窄，51–149 不提供方向。
该规则来自社区经验，适用性有限，可关闭，不承诺命中率；不能与官方容差混为一谈。
来源与取舍见 [历史依据](archive/ghost-hunt-through-2026-11-15.md#6-范围与渲染口径)。

- exact：silent 或 exact 且坐标有效，画标记与坐标，不画范围底板。
- range：nearby 或 unknown 且坐标有效，画基础范围和可选高概率区域。
- whole：0,0 且地图登记为无坐标域，显示全层提示。
- invalid：无法生成以上方案时显示失败原因，已知地图仍保留底图。

0,0 只在地图 noCoord 白名单中降级，当前登记海底迷宫一层；其他场景按失败重试。
白名单场景读到有效非零坐标仍按有效处理，不把所有迷宫一律降级。
标记面对不随主题变化的游戏底图，沿用 --map-seal、--map-seal-ink、--map-halo；
这些动态取色令牌不随主题明暗翻转，也不能因 CSS 中看不到引用而删除。
