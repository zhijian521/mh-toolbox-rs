## 一、优先处理的数据问题

### 01 · P1 · 闹钟写入失败仍然返回成功

- 位置：`src/views/tools/alarm-store.ts:83`、`:143` 起的新增/修改/删除/启停；`src/views/tools/AlarmView.vue:99`；`src/views/tools/ActivityView.vue:60`。
- 现状：`write()` 已返回是否保存成功，但各操作忽略结果，仍返回 `ok: true`。存储配额不足或写入被拒绝时，页面会关闭表单、提示成功；内存里的闹钟仍有效，重启后却恢复旧数据。页面顶部虽然有错误文字，成功回执依然与它矛盾。
- 建议：本地同步存储也遵循“保存成功才回执成功”；写失败时保留草稿。可采用写入候选清单、成功后替换内存的简单方式，避免新增失败后重试又新增一份。活动加提醒、启停、删除同步处理。
- 后续断言：模拟 `setItem` 抛错，操作不得返回成功、不得出现重复新增，成功重试后内容正确。

### 02 · P1 · 导入校验与前端可读取的结构不一致

- 位置：`src-tauri/src/backup.rs:774`；`src-tauri/src/store.rs:1030`；`src/views/goals/goals.ts:550`。
- 现状：目标在备份中是 JSON 值，导入侧检查目标 ID、流水数组与流水 ID；前端还检查目标类型、目标值等必要字段。例如合法备份信封内的 `goals: [{ "id": "goal-x" }]` 可以通过这里的目标校验并被插入，前端 `parseGoal()` 却会丢弃该目标。
- 影响：不完整或不受支持的备份可能被报为导入成功，实际页面少记录；下一次整份保存还可能删除这些前端未接纳的条目。导入前自动备份提供恢复手段，但不能替代入口校验。
- 建议：导入前校验业务必需字段，使“可导入”至少意味着“当前版本可读取”。先补目标，再核对其他数据域；不认识的必需结构明确拒绝或报告，不能只靠读取时丢弃。保留原有事务与导入前备份。
- 后续断言：缺类型、非法目标值、非法流水的备份应在替换前被拒绝，原账本保持不变；正常备份往返后有效条数一致。

### 03 · P2 · 浏览器存储应统一区分空数据、损坏、访问失败

- 位置：`src/main.ts:47`；`src/views/accounts/accounts-store.ts:67`；`src/views/goals/goals-store.ts:66`；`src/views/income/income-store.ts:71`；`src/views/income/online-store.ts:57`；`src/views/characters/roster.ts:440`。
- 现状：一些 `getItem` 在 `try` 外，访问被策略拒绝时会令启动的 `Promise.all` 拒绝，挂载回调不执行。解析失败又有不同处理：空表、回种子等；部分路径已标记加载完成，允许后续写入覆盖原始坏数据。
- 范围：主要影响纯浏览器开发/预览，不等同于桌面 SQLite 路径有此问题。
- 建议：读本地数据返回“未保存过 / 正常 / 损坏或不可访问”三类结果；失败挂错误、拒绝覆盖；种子只用于明确未保存过的情况。启动端增加异常兜底，让错误可见，不只是白屏。
- 不必为此改变桌面账本存储方案。

## 二、主页面与工具页需要追齐的标准

### 04 · P2 · 日期校验应只有一套真实日期规则

- 位置：`src/views/prices/prices.ts:184`；`src/views/accounts/accounts.ts:116`；`src/views/accounts/accounts-store.ts:134`；`src/views/income/income.ts:115`；`src/views/goals/goals.ts:520`；`src/views/goals/goals-store.ts:224`；`src/views/tools/alarms.ts:140`。
- 现状：物价检查年月日能否真实成立；其他多处只认 `YYYY-MM-DD` 的格式，闹钟还明确允许不存在日期被自动进位。
- 建议：抽取共享的日期有效性函数，统一拒绝 `2026-02-31`、`2026-13-01`。展示、范围限制、是否允许未来日期仍由各业务决定；不能把这些不同规则一并合并。
- 边界不只在日历控件：保存函数、备份读取也需要遵守相同规则。

### 05 · P2 · 物价保存与删除流程追齐公共实现

- 位置：`src/views/prices/PricesView.vue:182`、`:235`、`:261`、`:297`；对照 `src/composables/use-persisted-submit.ts`、`use-confirmed-removal.ts`。
- 现状：物价用 `pending`、版本号、回填编辑目标处理保存，已等待真实落盘，也有失败重试基础；角色、账号、目标使用公共提交锁与重试流程。两种实现的关闭时机、失败后的可编辑状态和按钮状态仍不同。
- 建议：物价复用提交与删除骨架，统一“提交中锁定、失败保留、重试不重复执行内存新增、成功才关闭”。保留当前连续记价不自动打开历史的行为。
- 这是实现与行为收口，不应描述成物价当前所有保存都不可靠。

- 建议：日期换公共日期控件，监听窗口换公共选择控件。窗口句柄若需字符串适配，应在这一层明确转换，不能因换控件丢失“自动选择”和停止时才可切换的规则。
- 不将正常的名称、备注文本框强行组件化。

### 07 · P2 · 筛选条、空态和错误提示的呈现收口
