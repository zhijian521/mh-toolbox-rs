# 主题切换准备静态审阅

日期：2026-11-12。范围：前端全局样式、公共控件、业务配色、图标处理、Canvas、明暗状态与样式加载入口。
本次为静态审阅，未运行测试、构建或视觉验收。规范以 [CONVENTIONS.md §2.4](CONVENTIONS.md#24-样式) 为准。

## 已完成的前置

| 项目 | 结果 |
| --- | --- |
| 主色与业务语义 | 主色、危险、成功、提醒和账本正负分开，分类与门派保留独立调色板 |
| 公共材质 | 纸卡、压印块、输入槽、票面、数值槽、浮层、弹窗、通知、印面和导航集中配方 |

## 本轮探查发现并修复

- 收益图标、闹钟卡存在不完整的 scoped 全局选择器，可能把声明落到根元素，已修正或通过统一令牌移除。
- 活动卡和页面台面的暗色规则在 scoped 样式内无法正确命中，已修复；活动卡使用独有类名，避免全局误匹配。
- 授权页把百分比传给 `light-dark()`，背景声明无效，已改为两种完整颜色，并使用危险语义色。
- 开发页目录复制了侧栏的纸键配方，已复用同一来源；两张折线图的重复槽底纹理也已收拢。
- 原生删除按钮与按钮组件缺少统一危险入口，已接入；确认服务同步透传并在下一次普通确认时复位。
- 部分注释与规范仍指向搬迁前的配方位置，已同步校准。

## 进入主题功能时需要做

1. **增加独立风格状态**。保留现有 `system / light / dark` 明暗选项，另用风格 ID 与根属性管理账簿、青瓷；集中选项、默认值、持久化与未知值回落。入口在挂载前应用，避免先显示旧风格再换色。
2. **增加青瓷配方**。从全局调色板、语义色与共用材质覆写，不复制业务页面。依赖局部颜色的覆盖命中实际元素，悬停、按下、聚焦与禁用保持成套；浮层 Teleport 到 body 时也要继承全局风格。
3. **接入设置并验收组合**。风格、明暗、字号分别保存与恢复；覆盖角色门派染色、装备与召唤兽详情、两种按钮、选择器、弹窗、通知、图表与地图。相关断言已补的部分仍需实际执行，视觉对比按后续验收范围运行。

上述三项属于正式主题功能，当前未实现。静态层面未发现需要先重写布局、状态体系或业务组件的阻碍。

## 保留与后续关注

- 门派、装备分类、涨跌和账本正负色有业务含义，换风格时分别审定，不能通过一键替换朱红连带改变。
- 进度条、装备格选中边、表格线、总览账线等已消费令牌；它们目前属于各自组件结构，不为消除所有混色表达式继续拆分。
- OCR 预处理的白底服务识别算法，截图与游戏原图保留原始颜色，不跟随界面风格。
- 现有暗色弹窗遮罩取字色混合，新风格验收时需对比遮罩浓度；本轮保留其配色。
- 侧栏牌记按明暗选择纸色或墨色资源，当前有效；青瓷确实需要不同资源时再扩展。
- 全量静态搜索不能替代运行与观感验收，当前结论不表示各组合已经实测通过。
