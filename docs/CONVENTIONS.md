## 2. 规范条款

### 2.1 工程基线

工具链是旧仓验证过的组合，不需要重新选型。

| 用途      | 依赖                                                                               | 配置要点                                                                                            |
| --------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 静态检查  | `eslint` 10 + `@eslint/js` + `eslint-plugin-vue` + `typescript-eslint` + `globals` | flat config；`vue/flat/essential`（**不是** `recommended`，那套带 600+ 条格式化规则）；不开风格规则 |
| 格式化    | `prettier`                                                                         | `printWidth: 100`、`tabWidth: 4`、`singleQuote: true`、`trailingComma: "all"`、`semi: true`         |
| 编辑器    | `.editorconfig`                                                                    | 4 空格、`charset = utf-8`、`end_of_line = crlf`                                                     |
| Rust 格式 | `rustfmt.toml`                                                                     | `max_width = 100`、`edition = "2021"`                                                               |
| Rust 检查 | clippy                                                                             | `cargo clippy -- -D warnings`（`unwrap`/`expect` 人工把关，不靠 lint 全禁）                         |

**脚本约定**（与 `package.json` 一致）：

```json
"format":       "prettier --write .",
"format:check": "prettier --check .",
"lint":         "eslint . --max-warnings 0",
"lint:commits": "git log -20 --no-merges --format=%s | node scripts/check-commits.mjs",
"typecheck":    "vue-tsc --noEmit",
"test":         "vitest run",
"check":        "npm run format:check && npm run lint && npm run typecheck && npm run test && npm run check:version && npm run lint:commits"
```

`npm run check` 是前端唯一入口，CI 的 `web` job 跑的就是这一条——**本机绿 = CI 绿**。
另有两条**不在**里面：

| job         | 跑什么                        | 提示                                                                                           |
| ----------- | ----------------------------- | ---------------------------------------------------------------------------------------------- |
| `rust`      | `cargo fmt --check`           | 全量时单独跑                                                                                   |
| `rust-test` | `cargo test --lib`（windows） | 前置 `npm ci && npm run build`：`generate_context!` 读 `dist/`，目录不在直接 panic，而它不入库 |

- **`--max-warnings 0` 不能去掉**：警告不影响退出码，等于检查只打印不拦人。
- **检查必须接进唯一入口**：`lint:commits` 曾经只是独立脚本，于是它自己红了没人发现。
- **`check` 里没有 Rust**：`clippy` 依赖 MSVC 的 `LIB` 与 `PATH`（见 `AGENTS.md` §三），混进来会让
  「一条命令全绿」在这台机器上不成立。Rust 侧单独跑 `cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings`。

**功能交付同步补相应断言，编写与执行分开。** 默认日常不例行运行验证；必要排错可直接执行，
无需单独询问，边界见 `AGENTS.md` §一。只有用户明确要求
「全量检查」时运行整套检查，指定单项则只跑指定范围。功能完成、提交和 Review 不自动触发。
下面是断言的归属与编写要求，不是自动执行清单。三层各管一段，互不顶替：

| 层   | 跑什么                    | 管什么                                            | 写在哪                                     |
| ---- | ------------------------- | ------------------------------------------------- | ------------------------------------------ |
| 单元 | `npm run test`            | 纯逻辑 / composable / 数据层，不碰 DOM            | 模块旁 `*.test.ts`                         |
| 集成 | 同上 + `cargo test --lib` | 跨模块、**真存储**：真 SQLite、真信封、真整份替换 | Rust 模块内 `#[cfg(test)]`；前端用真存储桩 |
| e2e  | `npm run e2e`             | 真窗口真鼠标：点得动、写得进库、重载不丢          | `tools/e2e/smoke.mjs`                      |

**动了什么就补哪层**，不靠记：纯函数 / 归一 / 坐标换算 → 单元；数据层（store / persist / 写队列）
→ 单元 + 烟测里一次「写完重载还在」；新页面 / 弹窗 / 按钮组 → 烟测新开一节（`--only=页名` 单跑）；
存储 / 迁移 / 备份信封 → Rust 真临时库用例（**别 mock**）；导出 / 导入 / 清除 → 烟测
「数据」节（靠 `e2e-dialog.json` 跳过系统对话框）；排版的截图与几何检查仅在用户要求验证时执行。
**新增 IPC 命令**不用改测试：前端 service 加调用即可，`ipc-contract.test.ts` 自动对账。

**新增一条 IPC 命令的顺序**：Rust 写 `#[tauri::command]` **再加** `#[specta::specta]`（返回或接收的
结构体要 `#[derive(specta::Type)]`）→ **两张** `collect_commands!` 都加（`lib.rs` 按平台分了两份，
漏一份只有非 Windows 才炸）→ **起一次 debug 窗口**生成 `src/services/bindings.ts` → 前端调
`commands.xxx()`（**不要写 `invoke('名字')`**）。IPC 契约测试在用户要求验证时执行；
生成物落后、命令名写错、少注册、注册了没人用，四种都会被检出。
`bindings.ts` 是生成物，不要手改，也别把它加进 `prettier` / `eslint` 的检查范围。

烟测断言的硬要求（都是踩过的坑，理由见 `RECORD.md` 第 103/105 批）：**按 `aria-label` 或稳定类名
定位，不按文本**（文本是内容，改个价就点不到；也别写「列表第一个子元素」，空态会占位）；**点击用
真实鼠标事件**，不要 `el.click()`（合成事件绕过命中测试，视口外也「成功」）；**写库后必须重载一次
再断言**；**控制台报错计入失败**（chunk 404、Vue 渲染异常都只从这条通道出现，噪音写进
`allowConsoleErrors` 并写在调用处）；**断言数跟着功能长**（写在 `AGENTS.md` §五），删功能连断言一起删。
烟测读取页面 store 或替换命令时，用 `tools/e2e/cdp.mjs` 的 `importLoaded()` 导入页面已加载的模块 URL；
不要直接导入不带 Vite 时间戳的路径，否则会得到第二份单例，前置数据与故障注入都不会作用于真实页面。

验证触发与完整清单以 `AGENTS.md` §一为唯一依据：默认日常，只有用户明确要求全量检查才跑整套；
提交、Review 不自动跑，同一份代码的结果不重复跑。

**版本锁定**：`engines` 只在大版本上拦人，`.nvmrc` 写 `22.22.2`、CI 用 `node-version-file` 读它。

**行尾由仓库说了算**：`.gitattributes` 声明 `* text=auto eol=crlf`，`.editorconfig` 与它一致。
只给 `*.bat` / `*.cmd` 声明不够——源文件会赖本机的 `core.autocrlf`，那是用户级配置。症状不是乱码，
是**静默**：改一行而 `git status` 显示整篇 M、`git diff` 却是空的。

```toml
# src-tauri/rust-toolchain.toml
[toolchain]
channel = "stable"
components = ["rustfmt", "clippy"]
```

**大户资源必须可再生**。`assets/fonts/LXGWWenKaiScreen.woff2` 是裁过的（GB2312 全集，1.75MB），
别手改：改覆盖范围就改 `tools/font/subset-font.py` 再跑。同目录 `.full.woff2`（9.84MB 原件）**必须
留在库里**——没有它就再也裁不出第二版，而游戏更新一批生僻地名时一定得再裁。`public/game/maps/*.webp`
的切图现场已删，属于「不可再生但已定型」，不要再对成品做二次压缩。

**游戏资源集中在 `public/game/`，不进 `src/`**：`src/` 的资源会被打包器改名加哈希，而清单写的是
文件名，失败方式是「某张图静默不显示」。三层判据与命名见 [`GAME-ASSETS.md`](GAME-ASSETS.md)。
一句话分界：**游戏名录、选项与数值规则进 public/game/data，解析算法与展示策略留代码。** 游戏内已有的图**从游戏
截图切，不手画、不找素材包**。

**性能改动先量基线，量完再改**。`node tools/probe/startup.mjs --exe <路径> --runs 5` 分三段报数
（进程→导航 / 导航→FCP / 导航→字体就位）。三条纪律：**同一份 exe 做 A/B**（靠 `--browser-args`
传参，不改 Rust 重编）；**取中位不取单次**（同机方差能到 2 倍）；**报数字要报对是哪一段**
（`font-display: swap` 之后字体不阻塞首屏，裁字体提前的是「字长对了」那一刻，不是 FCP）。

**提交规范**：`<type>(<scope>):<中文摘要>`，**只要一行**。type 白名单
`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`。冒号后不加空格（中文摘要贴着冒号读
是一行）；校验器对两种写法都放行（`:\s*\S`），放宽的只是一个空格。

**不写正文**：提交信息是 `git log --oneline` 里扫过去的一行。为什么这么做、试过什么错路、量到哪些
数，写进 `RECORD.md` 那一批。一行装不下 → 这批改动该拆，而不是该写长正文。`npm run lint:commits`
只看最近 20 条；更早的是旧仓历史，不追溯、不改写。

### 2.2 命名

三条前缀规则，覆盖 `src/` 全部：

| 前缀 / 形态 | 含义                       | 例子                                                                            |
| ----------- | -------------------------- | ------------------------------------------------------------------------------- |
| `App*`      | 应用外壳的一部分，全局唯一 | `AppRail`、`AppIcon`                                                            |
| 功能名      | 通用控件，名字说明它画什么 | `PageHeader`、`PageShell`、`TitleBar`、`SlotButton`、`PressTile`、`PressButton` |
| 业务名      | 只服务于某一页/某一域      | `MapCanvas`、`LedgerSection`                                                    |

`Base*` 前缀**已停用**：新基元直接用功能名。这不是「改名计划」，是「不再往里加」——改名冲掉
git blame，收益低于成本。其余约定：

- 组件文件 `PascalCase.vue`，一个文件一个组件
- **一个 `.vue` 太大时，先拆「样子」和「纯计算」，不要先拆组件。** 同目录允许放 `kebab-case.css`
  （`<style scoped src="./x.css">`，含 `:deep()` 逐条等价）与纯函数模块（如 `map-paint.ts`：入参进、
  像素出、不碰 Vue）。判据是 §2.3-3——拆完每个文件只回答一个问题。拆子组件是最后一步，它同时
  引入 props 契约与插槽，而多数「太大」只是两件事混在一个文件里。
- composable `use-xxx.ts`，导出 `useXxx`；类型 / 接口 `PascalCase`，**不加 `I` 前缀**
- CSS 类名 `kebab-case`，BEM 不强制；**层级靠块前缀**（`.rail-item`）而不是嵌套选择器。
  **类名不要求等于组件名**（`.rail-mark`、`.vs-track` 都是块语义），找组件靠 grep 标签名。
- 设计令牌 `--<类别>-<语义>`：`--paper`、`--ink-2`、`--fs-base`、`--r-2`、`--t-quick`

### 2.3 组件分层

```
views/          页面 = 路由目标。只做编排：拉数据、拼区块、处理路由参数
components/     有视觉语义的 UI 单元。不引 @tauri-apps/*，不读路由
composables/    跨组件的状态与副作用。单例状态放模块作用域
services/       系统能力唯一出口，一个能力一个文件。页面与组件都不许绕过它调 invoke
types/          全局声明与模块增强（`router-meta.d.ts`、`vue-augment.d.ts`），不放业务类型
```

1. **组件不调 `invoke`**。只有 `services/` 能碰系统（`desktop.ts` 管窗口与「关于」，`ghost.ts` 管
   捉鬼读取通道）。ESLint 的 `no-restricted-imports` 把它变成可检查的约束，且必须用 `patterns`
   匹配 `@tauri-apps/*` 整族——只写 `paths: ['@tauri-apps/api/core']` 等于只管一个入口。
2. **质感在组件内，布局在父级**。`SlotButton` 只认 `--slot-h`/`--slot-w`，父级用
   `.rail-foot { --slot-h: calc(30px * var(--fs-scale)) }` 传；`VerticalSlider` 同理（五个 `--vs-*`）；
   图标一律走 `--icon-size`（§2.4-15）。原理：父组件 scoped 样式能命中子组件根元素。

    `SlotButton` 的 `seal` 变体是「印面常驻、字压在印上」，用于**主操作**——一屏只该有一枚；它变的
    是「印在不在」，与形态正交，所以不叫 `variant`、不改尺寸。`size`（`md` 26 / `lg` 31）是**变量
    之上的预设**：`lg` 只声明 `--slot-h` 与 `--icon-size`，`md` **故意不写规则**——不声明，默认高度
    才轮得到继承父级的 `--slot-h`；补一条会把那份继承盖掉，侧栏那格无声退回 26px。
    **页头动作只用 `md`，不用 `lg`**：`--page-head-h` 不是常数，是「padding 19 + 标题行高 + 1」算的
    （1 档 45.3、1.1 档 47.8），而页头是 `min-height`。要更大的按钮先改令牌——那叫「页头整体变高」，
    一通栏的账线都会跟着下移、与内容区错开一格。

    **按钮有两种材质，按「这块地方的语言」分**：`PressButton` 是**凸**（压印纸，按下去压回纸里），
    用于页面里的动作——页头、面板、表单；`SlotButton` 是**凹**（本体是槽，悬停落一枚朱印），用于
    开发页槽按钮、占位页、设置页数据区三枚（用户定稿）、物价页「清除筛选」。（左栏底部原来
    还有两枚——切日夜、开仓库，2026-11-06 删了：栏里只留牌记与目录。）

    **朱面不是另一套按钮，是同一块纸换成朱色**：传 `tone="seal"`（`PressTile` 提供）。朱面的棱必须
    自己一套——`PressTile` 的棱按纸调，亮色那条奶白顶线压在朱红上是塑料高光，底棱的暖黄棕也对朱红
    反向。所以 `tone-seal` 换了块面三态、四条棱、内容影，`PressButton` 只剩内层字色（`--on-seal`）。
    需要「一块朱红」的地方一律用它，不要再写一份 `box-shadow`；两份配方迟早变成两个朱。不可点的块
    一起传 `still`：悬停变亮、按下回弹是「按我」的承诺，长在点不动的块上是骗人去点。

    **读数有自己的一块凹格：`NumTag`**——纸带上挖出来的一小格，淡槽底（45% `--well`）、无边框、
    数居中，几何走 `--tag-w` / `--tag-h`，内容走默认插槽（「满 180」的「满」能单独上朱）。与
    `PressTile` 正相反：左端图标印是凸的印，右端等级是凹的格。三条约束：① **它是签，不是输入框**
    ——不接受点击、不给悬停与按下态（加深底色是「这里能填」的承诺）。要能填就**换器件**，不换几何：
    卡上属性那二十格在 `editable` 时（截图识别的预览）换成 `<input class="field num num-slot">`，
    宽高直接读行上的 `--tag-w` / `--tag-h`，落点与那枚签逐像素相同——「这枚签现在能填」是**状态**
    不是**位置**，所以不许因此把表挪一挪。也**不是** `NumberField`：那一格和编辑页同宽同材质，
    但值是自由文本（经验可能是 `3,777.2万`），`NumberField` 会把「万」抹掉；
    ② **材质在全局 `.num-slot`，不在组件里**——同一副「45% 槽底 + 上沿影 + 下沿亮线」只此一份，
    `NumTag`、两个 input、卡上属性读数都挂 `class="… num-slot"`；**必须用 `background` 简写**（它
    顺手清掉 `.field` 那层顶壁渐变，改回 `background-color` 会让同一个数在卡上与弹窗里深浅不同）；
    材质与交互分两层——`.num-slot` 只给静息态，悬停 68% 与聚焦转实槽挂在 `.field.num-slot` 上；
    ③ **字号、颜色不归它管**——等级由调用方给 `--fs-md + 3` 与 `--num`，组件只说「格」，不说「字」。

    两者三形态（只 `text` / `icon`+`text` / 只 `icon`）与 `md` / `lg` 两档尺寸逐像素同值，并排时基线齐。
    **同一行不要混用**（一凹一凸并排，读起来是两种器件），两枚都别手写 `<button class="...">`。

    `PressButton` 另有 **`sm` 20 一档**（2026-11-05）：字号降到 `--fs-mini`、左右内距 11→6、图标
    15→12，是**注脚级**——塞在说明文字右端、读数格边上（收益页速记卡的导出 / 导入是第一处）。
    它和 2026-11-02 删掉的那档 24 不是一回事：24 只比 `md` 小 2px、并排读不出区别，是「看起来能
    调小」的假入口；`sm` 差 6px 且字号与内距一起收，一眼是另一种份量。`SlotButton` 暂时没有这
    一档（槽按钮长在工具条与页头，没出现过注脚级用法），要用时按同值补。**尺寸归组件**：业务页
    写 `size="sm"`，别再就地覆写 `--tile-h` / `--icon-size`——散着覆写早晚出现 20 / 21 / 19
    三个值。

3. **一个组件要么管状态，要么管样子，不要两个都管**。`SegmentedPills` 管「选一个」，格子的质感
   交给全局 `.bevel-pill`——这是范本。**不包一层 `BevelPill` 组件**：那枚胶囊自带 `aria-pressed`，
   是「独立开关」的语义，放进互斥组会与 `aria-checked` 打架，而一组格子还需要 roving tabindex。
   判据的另一半见 §2.4-45：`scoped` 里也别复用全局组合类的名字。
4. **新增控件先进开发页的「原子组件」卡**（`views/dev/AtomsSection.vue`），再进业务页。那一页
   （三连击左上角标进入，见 §2.4-19）是这套语言的验收面，不是给用户看的演示页。卡里的 `.note` 只答
   「怎么用、踩过什么坑」——「当初为什么这么画」属于 `RECORD.md`；一段压在两行内（1024 单列 878
   实测），末行不留孤字。**组合件另开一张卡**（如 `SlipRowSection.vue`）：由原子拼成、还带业务语义
   （`level` / `cap` / `off`）的件不塞进原子卡——混进去之后，下一个人想「复用」会以为它只是排版件。
   判据是「它 props 里有没有业务字段」，不是行数。
5. **侧栏不滚动，窗口最小高度由它决定**。`AppRail.vue` 是 `overflow: hidden`——8 档一旦要滚，拇指
   就跑出视口，「第几档」的位置感失效。高度交给窗口兜底：`lib.rs` 的 `min_inner_size` 取「较大」
   字号（`--fs-scale: 1.1`）时的需求 → **848**（默认窗口 860）。加高侧栏里的东西必须同步抬这个数；
   想再压低只能动侧栏自己（格高 `--vs-cell` = 内容 + 上下内边距 × 2，或栏宽）。

    **「最小高度」不等于「默认档刚好填满」**：按 1.1 档定，默认档必然留一段空白；那段落在槽之下
    ——牌记与槽都是 `flex: none`，贴着栏顶往下排。（栏底原先有两枚 30px 按钮靠 `margin-top: auto`
    贴底，2026-11-06 删了，所以现在没有「底栏」这个东西。）

    **栏顶那块标是 48×48 的正方形，牌记区（它的外框）等于栏宽 72**。方块与目录槽同宽（都取
    `--rail-slot-w`），到左右栏边的距离本来就是栏内衬 12；2026-11-06 用户要求「外面距上下左右
    保持一致」，于是上下也只能留 12，区高 = 48 + 12 + 12。**这条等式是死的**：方块是方的、
    左右留白 = (栏宽 − 方块) / 2，要让上下也等于它，区高就必然等于栏宽——想矮一点只能缩方块或
    缩栏宽，缩留白缩不出来。**也因此牌记区不再与 `PageHeader` 等值**（那条对齐已经主动放弃，
    别再按页头去调这个数）。牌记不画下边框：那里是直接落在纸上的应用标。
    块是 `PressTile`，与工具页图标格同一块材质；只给三个变量：`--tile-w`、`--tile-r`
    （`--r-2`，与槽同心）、`--tile-drop: 1`（栏底色与块面同色，凸起几乎全靠这道影，缩到 0.6
    就只剩 1px 宽的一条）。图形占块的 **72%**（图自带 3% 透明边，满铺会贴到下沿厚度上）。

    **不可点的块传 `still`**（角色卡辅助技能那几格）：只关悬停与按下两态，材质一律照旧——它仍然
    是纸上的一块东西。圆角与棱厚**不乘** `--fs-scale`：它们是绝对曲率与绝对厚度，槽那边也没乘。

6. **给开发与验证用的入口，一律挂「开发者模式」（`useDevMode`）**，不在页面上直接摊着。开关在
   开发页第二张卡。判据是**「用户真会用的功能」vs「只在没有游戏、没有数据时才用的替身」**——后者
   属于这一层，现在只有一个：捉鬼页右下角的「测试文字」面板。关着时**不渲染**（`v-if` 而非
   `v-show`：后者只是 `display: none`，停靠点还在 DOM 里，tab 与读屏摸得到，截图里也会被当成真
   功能）。状态落 `localStorage`（`mh-dev-mode`）：它表达「我现在处在这个模式下」，刷新掉回关等于
   每次都要点一下；这与「高概率区域默认开且不记忆」不矛盾——那条的理由是「记住上次会把默认值变成
   上次」，而这里的默认值本来就该是关。

    **新增一个带持久化的功能，同一批里补它在开发页的模拟数据**（`views/dev/demo-data.ts`）。这个
    按钮回答「一屏有没有东西可看」：功能加了、数据没加，开发页只覆盖半张表，而缺的那半张恰恰要手填
    十行才验得出来。三条：**写死**可复现、**量级真实**（物价按万写、角色按同级号给）、**极端态齐全**
    （满 / 空 / 只有一条 / 一条没有）。界面上的条数读 `DEMO_COUNTS`，不要把 4 / 6 写进模板。

7. **页面自己的数据层放 `views/<页>/<名字>.ts`，读进来的对象一律先归一**。模块级 `ref` +
   `useXxx()`，与主题、字号同一套写法（分层里没有「store」这一层，也别为此引 Pinia）。放 `views/`
   而非 `services/`：它不是系统能力（不过 `invoke`），换存储时改的是它自己那两个读写函数。

    **读时清洗与保存时清洗是同一个函数**（如 `normalizeCharacter`）：它既把旧数据补成合法形状，也在
    点保存时跑一遍。两处各写一套「收尾」，迟早一处记得一处忘。兜底原则是**永不抛错、缺什么补什么、
    坏条目单条丢掉**：它失败的方式很特别，只在重启之后才出错，而那时页面已挂载完，一行
    `undefined is not iterable` 就是整页白屏。

8. **二次确认只有一个入口：`askConfirm()`**。页面不渲染 `<ConfirmDialog>`、也不自己拼遮罩：

    ```ts
    const ok = await askConfirm({ title: '清空所有角色与物价？', confirmText: '清除' });
    if (!ok) return;
    ```

    - 宿主是 `components/ConfirmHost.vue`，在 `App.vue` 里挂**一次**；状态与 `Promise` 在
      `composables/use-confirm.ts`（模块级单例）。页面拿不到、也不该拿到「这个窗开没开」。
    - **宽度、按钮位置、初始焦点都只有一份实现**：宽度是 `ConfirmDialog` 里的 `WIDTH` 常量，焦点
      固定落在「取消」上。「这处窄一点 / 那处不给取消」不是需求，是把同一个窗拆成两个的开始。
    - **叫 `askConfirm` 而不是 `confirm`**：浏览器全局 `window.confirm()` 返回 `boolean`，哪个文件
      忘了 import，`await confirm(...)` 会静静拿到 `undefined`——恒等于「取消」，动作永不执行，
      一条错都不报。换个名字，忘 import 就是 TS2304。
    - 问句带书名号或引号，`note` 写后果（会连带删掉什么、能不能撤回）。这两句由调用方给，因为只有
      它算得出「下面还有 8 条记录」。

9. **消息提示只有一个入口：`notify`**。做完一件事说一句，不等待、不阻塞：

    ```ts
    notify.success('已删除');
    notify.error(result.error);
    ```

    宿主 `NotifyHost.vue` 挂在 `App.vue` 一次，状态在 `use-notify.ts`；页面拿不到「屏幕上现在有几条」。

    - **它是「说」，`askConfirm` 是「问」**：问要等回答、后面那句不许跑；说没有返回值，写在动作
      函数末尾即可。混用会把「说一声」变成「多一次点击」。
    - **浮层 vs 行内 `.note` 的判据是「这句话要不要留着看」**，不是「重不重要」：带路径、要能复制
      的回执留在行内；「刚才那下成了没有」才用浮层。
    - 三秒自收、同时最多三条（超了挤掉最早那条）、悬停停表、点一下收走。颜色只在左侧竖条与图标上，
      **文字恒 `--ink`**——整句刷成朱红，13.5px 楷体在米白纸上会发糊。
    - 位置、尺寸、动画都在宿主里，一处可改。别在页面里再写一份 `position: fixed` 的提示。落在
      **嵌入槽**里而不是浮层：浮层要处理点击穿透与超时竞争。

10. **速记是「一格一动作」，不是一张表单**。收益页的入口是点物品格，不是「记一笔」按钮：

    - **点一下即记**：固定价按单价表直接入账，浮动价（兽决、内丹、金币）先弹一次单价窗。表单式的
      「选物品 → 填单价 → 选日期 → 保存」把一步拆成四步，而这一页一天要点十几次。
    - **「记给谁」常驻可见**（标题行右侧那排胶囊），不收进弹窗：藏起来就会出现「记了半天全记到
      上一个号头上」，事后只能逐条翻日期靠回忆对齐。**可以按几个**，所以走 `TogglePills`
      （`group` + 每枚 `aria-pressed`），不是 `SegmentedPills`（`radiogroup` 只能选一个）；也不要
      自己写一排按钮——读屏会念成九个独立开关，键盘要按九次 Tab 才穿过去。
    - **记完要能核对**：右侧是「一格一件物品 × 次数」，**这一格的 `title` 与读屏标签里要写这组记给
      了谁**。上面那排胶囊会**停在最后一次的选择上**，换号忘了切，后面几条就全进了上一个号——聚合
      之后，这是归属唯一说得出口的地方。「未指定」不写进去：一屏里多数有归属、少数没有，**差异本身
      就是信息**，每条都标只会把真异常淹掉。
    - **一格 = 一件物品 × 次数，点它撤最近一条**（用户 2026-11-04：「不要列表这种汇总，一个图标 ×
      20，一眼可以看清」）。速记是**连点**的动作，逐条列会出现二十行长得一模一样的「定魂珠 4.6
      万」，而二十行里数不出「二十」。四条规矩：①**点一格撤一条**，不是整格清空（清空把「多点了一
      下」与「点了二十下要全撤」当成同一件事，撤一条自己数得清）；②**与左栏要一眼分得开**——两边都
      是压印块，靠三样区分：右栏带 `×N`、块小一号（36 对 44）、`×N` 挂整格右侧而不是跟价格挤一行。
      早先靠「没有厚度、只有细边」区分，那条随「类似于左边」的要求作废；撤错代价很低（再点一下原
      物品就记回来），不值得另造一种材质；③**同名的一收一支不合并**（会抵消成 0）；④**按价分开**：
      浮动价每条一个价，只按名字合并时那一格只能印一个不代表组里任何一条的价。分组键是
      `kind|名字|金额`；固定价天然是一个大 `×N`，浮动价是几个 `×1`。
    - **多选 = 分账，不是翻倍**：按了几个号就写几条、金额**平分**（`splitAmount`，余数按币补给排在
      前面的人，总额一分不差）。不写成「一条记录挂多个角色 id」：那样按人合计要么翻 N 倍，要么把
      分摊规则搬进查询，而删一条时说不清撤的是谁的份。
    - **「不指定」是空数组，不是一枚值**：它在胶囊组里需要一个能按的格子，所以两边做转译。按它 =
      清空全部；「按着一个角色再按它」= 切到某一枚。判据是**按之前它亮不亮**——判错会让「点了不指定
      却还记给刚才那个号」，账面上看不出来。
    - **点完必须有回执**：那一格亮一枚朱点（1.6 秒）+ 一句 `notify`。连点两个物品时分不清哪下成了，
      而这一页的全部价值就是「点准」。
    - **单价是用户数据，物品清单是游戏事实**：单价进 SQLite（每人每区不同），物品名与图标进
      `public/game/`（换文件不改代码，见 `GAME-ASSETS.md` §1）。把单价写进代码、或把物品名写进库，
      都不对——前者改不了，后者要连数据一起改。**浮动价的单价不写回单价表**：兽决每天一个价，写回去
      等于让下一条默认用昨天的价，比空着更容易记错。
    - **格子里只有图标，价格落在块外面**（用户当日连收三道：去掉物品名 → 压印块只包图标 → 价格移到
      块外下面）。现在是「44 见方的压印块包住 32 的图标」+「块下面一枚淡槽价签」，一凸一凹：块是
      物件，签是读数。名字改走两处：`title`（悬停即见）与 `aria-label`（读屏念「60武器，单价
      1.2万」），`img` 的 `alt` 留空——否则读屏念两遍。**没定价的那一格不印价签**（整行不渲染，
      不留空位），整排图标仍在一条线上。代价写在明处：60/70/80 武器图标长得几乎一样，只能靠悬停认
      ——这是「用密度换一点辨识度」的有意取舍。
    - **历史收益是「按区间筛选 + 区间流水表」**，不是一张汇总。汇总（一天一行）压掉单条的 id，没有 id
      就改不了、删不掉，而速记点错是常态。所以：**起止两条日期 + 一个角色下拉**在上、区间里一条流水一行
      （时间 / 物品 / 角色 / 金额 / 改 / 删）、**改不确认、删确认**（改能再改，删不能撤回）。`updateEntry`
      只开放金额 / 物品名 / 记给谁，**日期与收/支方向不给改**——那两样等于「搬到另一天」或把整页
      收支翻过来，走「删了重记」更诚实。
    - **区间而不是「单日」，单日只是它的退化情形**（2026-11-11 用户「支持日期范围」）。核对很少只看
      一天：「这个月摆摊收了多少」「上周那三件记进去没有」都是跨天问法，单日选择器把人逼回一天一天
      翻着加。起 == 止 时就是原来那个界面，不另留一套。**两端互相约束**：改起点晚于终点就把终点顺过去
      （反之亦然）——不约束的后果不是报错，而是表格空着、两个日期都看着正常。区间过滤走
      `income.ts` 的 `entriesIn`（两端都含的区间口径只有这一份；统计条现在是 `entriesOn` 只算今天，
      2026-11-11 第 149 批把页顶的范围滑块删了，区间筛选只剩这个窗在用），不要在这里重写一遍
      `date >= from && date <= to`：两处一旦有一处改成开区间，同一个词就指两段不同的日子。
    - **跨天时时间列补上日期**。区间一跨天，「14:32」单独看分不出是哪一天的 14:32，而这一列正是给人
      对时间用的：`multiDay` 为真时格子里竖排「11-11 / 14:32」，列宽 56 → 68（56 装不下第二行）。
    - **角色筛选是「全部角色 / 未指定 / 各角色」三段**（与账号页、目标页同一条口径，见下条）。「未指定」
      是真实筛选目标而不是「不限」，合并之后「哪些账没记给人」就问不出来。`SelectField` 把空串当没有值，
      所以「全部」要一个哨兵值 `'__any__'`。
    - **表格是「一张纸」：外框 + 圆角 + 斑马纹**（2026-11-11 用户「表格最外边加边框」「斑马纹」）。边框与
      圆角画在 `table` 上（`border-collapse: separate`——`collapse` 下圆角不生效），不画在滚动容器上：
      挂在容器上时行会从框底下滚过去，上沿线看着像悬在表头上面。斑马纹用 `nth-child(even)` 的**底色**
      （12% 的 `--well`），不加隔行线——账本里一列列都是同一种纸，加线会把 20 行读成 20 个格子。
      **悬停必须压过斑马纹**：两者同为 0-1-1 时就靠注入顺序，悬停会被偶数行吃掉，读起来像「有时灵有时不灵」。
    - **窗宽 900、高度下限 600**（2026-11-11 用户「弹窗可以增大一点」）。筛选条从「一个日期」变成
      「两个日期 + 一个角色」之后 720 装不下，还让「物品」那列挤成一条缝。宽度照旧不写死：`max-width`
      会把它收进视口，写死就是「换个窗口尺寸必红」。
    - **总计与各号小计是表格顶上的一排 tag，总计排第一**（2026-11-11 用户「总共金额也放到表格顶部左上，
      和角色收益一排展示，做成 tag 标签类型，一个角色一个，总计也一个」）。顺序是「总计 → 各号」而不是
      反过来：总计是这一排的标题，后面每一枚都是它的拆解，从左往右正好读成「一共多少、分别是谁的」。
      总计因此重一档（赭底 + 赭框 + 700 读数），其余各枚只给淡槽底——它们并列，谁也不比谁重要。
      **笔数仍留在筛选行右端**（`.filters .sum .dim`，e2e 的 `todayCount()` 靠它）：它回答「这次筛出
      多少条」，和起止、角色是同一件事；钱在表格顶上，条数在筛选行上，各归各位。
    - **表头与数据行同高**（2026-11-11 用户「表头高度和列表保持一致」）。行高不是文字撑出来的：每行右侧
      两枚 26 高的操作按钮把行定成 `26 + 7×2 = 40`，而表头原先只有 `5 + 小字` 约 27，一条细带压在
      表身上读起来像「表还没画完」。把表头 `line-height` 钉成 `26 × --fs-scale`、上下内距对齐到 7，
      两处同高且**都跟着字号档走**——只写死一个像素高的话，1.1 档下按钮会先长过表头。
    - **物品图标 20**（2026-11-11 用户「列表里的物品图标增大一点」）。16 在 40 高的行里只占一小半，
      认不出是哪件东西；20 仍留得住四周纸面，行高不必跟着长（按钮 26 才是行的下限）。

11. **账号是两本账，不是一本账的两个币种**（第 112 批）。人民币按元、梦幻币按万，
    `accountStats(entries, currency)` 只数本币种，页面上并排两张卡——**绝不合成一个「总收支」**：
    元与万不是一个量级，加起来只是把两个数拼在一起，那个数不能回答任何问题。连带四条：
    - **圆角必须落到四角的单元格上**（2026-11-11 用户「表格上面的两个角上的边框好像因为圆角被
      切割了」）。表格自己的 `border-radius` **裁不掉**单元格：单元格是方盒子，纸色一路铺到角上，
      那道弧被压在纸色底下就成了「被切掉的角」。表头又不能改成半透明（`sticky` 时下面的行会透出来），
      所以正解是让四角那四格自己带内圆：`:first-child` / `:last-child` × `thead` / `tbody tr:last-child`。
      内圆写 `calc(var(--r-3) - var(--w-hair))` —— 外沿是 4px，单元格从 1px 边框内侧起算，直接抄 4px
      会比外沿鼓出来。别改成给 `table` 加 `overflow: hidden`：那会让 `sticky` 表头在部分浏览器里
      失去吸附（祖先建立滚动容器）。
    - **统计条与速记卡是同一张纸**（2026-11-11 用户「收益上面四个统计卡片和下面的卡片样式保持一致吧，
      看起来整齐」）。统计四格用 `PaperCard`（`.board`），与 `LedgerSection` 包着的速记两栏同一层材质，
      间距 16 与 `.income-stack` / `.split` 同数。2026-11-05 那版是四枚 `PressTile` 压印签——凸起的小块
      与台面上的纸并排，读起来像「上半页下半页不是一套」。**这一条管的是「一屏里的卡片只有一种厚度」**：
      同一页再出现第五张卡，也走 `PaperCard`，不要再借 `PressTile`。
    - **「没填」不是「填错」：提示只在真动过之后亮，不能挂在失焦上**（2026-11-11 用户实报：
      「点击一个物品，不输入价格，但是关闭弹窗时候还进行校验，点第一下「取消」的时候取消不掉」）。
      两个症状同因：`touched` 由 `@blur` 点亮，而**按下「取消」的那一刻输入格正好失焦** → 提示行插进来、
      窗变高、页脚在指针底下往下挪了半行 → `mouseup` 落在按钮外，那一下点击没有发生，要按第二次。
      所以 `ItemPriceDialog` 改由 `@update:modelValue` 点亮（真打过字、或按过加减才算动过）：
      打开窗直接关掉一句校验都不出，页脚也不会在指针底下跳。**结论可以推广**：凡「点取消时可能插进
      一行提示」的窗，触发条件都不能是 blur——它和「点按钮」是同一个动作的前半截。
    - **读数三档色：进账苔绿、出账朱红、不带方向留赭**（2026-11-11 用户「一般收益为绿色，花费为红色」）。
      `StatRow.tone` / `StatItem.tone` 是 `num | gain | loss`：收入与为正的净额走 `gain`（`--moss`），
      支出与为负的净额走 `loss`（`--cinnabar`），笔数走 `num`（`--num` 赭）——它数的是条数不是钱。
      没有进账时收入读数是「—」，那是「没赚也没花」，不给方向色；净额恰好为 0 同理。
      色号一律引令牌，**不写死十六进制**：`--moss` 在暗色翻成 #86ab86，写死的绿在暗色下会发闷。
    - **两张表，不是在 `income_entries` 上加列**。`account_entries` 多出 `currency` / `category` /
      `channel` 三列。共表之后每一行都要回答「这行的 amount 是万还是元、有没有渠道」，漏一次就是
      把某笔按错单位算——不报错，只是总数悄悄不对。
    - **`amount` 的单位跟着 `currency` 走**：`rmb` 存元、`cash` 存原值（万 × 10000，与收益页、
      物价同一条）。人民币收到**分**、梦幻币收到**整数**：浮点尾巴会让同额两笔在汇总时差一点点，
      而差值落在小数第 15 位时人只会看到「总数不对」。
    - **校验先换算、再判正**。反过来 `0.00001` 万会过关、落成 `0`，而 `0` 在归一里是「丢掉」——
      用户点了保存、提示说记上了、重启后那条不见了。同一个坑第 97 批在收益页踩过。
    - **「全部角色」与「未指定」是两个不同的筛选项**，不能合成一个。点卡这类账本来就不挂角色，
      合并之后「哪些账没记给人」这个问题再也问不出来。

12. **目标是「一张表、两种算法」，全员目标用快照**（第 115 批）。养成（读角色档案）与存钱 /
    装备（手记流水）共用一张 `goals` 表、一个汇总函数 `goalSummary`，区别只在「数从哪来」。
    连带六条：
    - **状态是推出来的，不存字段**。`current >= target` 即达成——装备买够件数就是完成，不需要
      再点一次「标记完成」。删掉最后一笔流水就自动回到进行中。旧仓那套 `status` + `doneAt` +
      「恢复进行」是为「提前结案」留的口子，这里没有那个需求；多一个可写字段，就多一条能被
      写坏的状态。
    - **「全部角色」是快照，不是实时名册**。建目标那一刻把成员 `{id, name}` 抄进 `members`。
      目标许的是「这些人练到多少」，后加的人不该让一个已达成的目标退回 99%；名字一起抄，
      是因为人删掉之后那行还得读得出是谁。
    - **角色删除要提前说**：删角色时若被 N 个目标引用，确认窗里把那些目标的标题列出来。
      删除之后成员行保留、标「已删除」、**不计入分母**——分母里留一个永远补不上的人，
      会让目标永远到不了 100%。
    - **超额封顶、未达成最多 99%**。`current = Σ min(target, value)`：一个人练到 40 不能替
      另一个的 10 抵账；只有全员达标才给 100。卡片上的每个数都从同一个 `goalSummary` 出。
    - **手动目标记增量**，`current = max(0, Σ delta)`；改一笔只影响那一笔。达成日期取「累计首次
      到线」的那笔流水的日期，不另存。
    - **存钱目标先不接账号账本**（用户 2026-11-05 定）。账本记的是「钱包进出」，目标问的是
      「攒够了没有」，两者口径还没对齐之前硬接，会出现「充值也算进攒钱」这种假进度。

### 2.4 样式

1. **颜色只能来自令牌**。禁止在令牌表外写 `#rrggbb`、`rgb()`、颜色名。界面按用途取色：
   主操作、选中、悬停、焦点用 `--accent`；错误、删除用 `--danger` / `--danger-ink`；
   成功用 `--success`；一般提醒用 `--warning`；账本正负数用 `--positive` / `--negative`。
   **填色控件一律用 `--seal` / `--seal-edge` / `--on-seal`**，这组由主色映射，保证面与字成套。
   新风格同时提供 `--accent` / `--accent-ink` / `--on-accent`，不通过替换 `--cinnabar` 把报错、
   支出、装备分类和涨跌一起改色。`--cinnabar` / `--moss` / `--ochre` 等继续作为业务分类调色板。
   `--paper` **暗色是深纸**，要
   纸白取 `--ink`；需要**不随主题翻面**的纸白（`color-mix()` 的提亮锚点、画在截图上的标记）取
   `--paper-base`，需要**恒定的暗**取 `--ink-base`——`--ink` 在暗色是纸白，拿它去压会让「背光」变成
   一条发光的线。这两枚是令牌表里唯一允许写绝对色值的地方。组件里若仍需暗色覆写，**必须整条写进
   `:global()`**：`:global(html.dark .sel)` 编出来是 `html.dark .sel`，而 `:global(html.dark) .sel`
   会被编译成只剩 `html.dark`。

   **风格与明暗分开**：`useTheme()` 目前只管理 `system / light / dark`，新风格不能塞进这个枚举。
   当前默认仍为账簿风格，尚未接入青瓷或风格切换入口。后续风格定义继续放 `src/styles/`，
   覆写令牌和共用材质，不复制页面样式、不更改布局。

   **共用材质在 `tokens.css`，结构在 `base.css` 与组件**：纸卡 `--board-texture/shadow`、
   压印块 `--press-color/image/shadow/ink/icon-filter`、输入槽 `--well-background/texture/shadow`、
   票面 `--slip-background/shadow`、数值槽 `--num-slot-background/shadow`。
   明暗与悬停、按下、聚焦配方统一在此；业务组件继续传 `--board-face`、`--tile-face*`、
   `--tile-drop`、`--slip-base`，不再另抄材质。**依赖局部变量的配方在实际元素上声明**，
   不提到 `:root`：自定义属性会在声明处求值，放到根上会丢失门派和局部染色。
   覆写材质也要命中对应元素与状态；普通色值和字体才从根继承。Canvas 先用浏览器求值颜色、字体，
   缓存包含实际令牌与 `color-scheme`，不以亮暗两态代替完整外观。
2. **字号只能来自 `--fs-*`**，每个令牌已经乘过 `--fs-scale`，禁止 `font-size: 14px`。六档
   `--fs-mini` / `--fs-xs` / `--fs-sm` / `--fs-base` / `--fs-md` / `--fs-xl`；另有 `--fs-amount`
   （`base × 1.4`）只给金额读数——它是**语义档**不是第七档，别拿它排正文。字号表在 `tokens.css`，
   `views/dev/tokens.ts` 运行时读它画阶梯。
3. **圆角优先用 `--r-1/2/3/pill`，落不进这四档的就地写 px**。账簿方向基本不用圆角。侧栏竖滑块
   外框、格、印**共用 `--vs-radius`（`--r-2`）**。胶囊（`--r-pill`）只留给三档滑块、分段胶囊这类
   横向控件。判据：**这个值会不会被第二个地方用到**——会就进令牌；不会（曲率由具体尺寸决定）就地写
   并注释它跟着谁走。为滚动条滑块的 10px、细线的 1px、圆形的 50% 各造一档，等于把「一个值一个
   令牌」摆回来。
4. **间距就地写 px，不做刻度**。`--sp-1…10` 已删：十档只用过 2 档，一套 80% 没人用的刻度比没有更
   糟——它让人以为「选令牌」比写 `gap: 8px` 更正确。**例外只有「等值契约」**（同一个值被三处以上
   引用）：① 页面留白 `--page-pad`（16px），页头左右 = 内容区四边，`.page-head`、`.page-content`、
   捉鬼页浮动面板都引它；② 区块内边距 `--block-pad`（15/18/18）与 `--block-pad-tight`
   （11/14/12）。四处分写四套差 1–2px，读者感受不到，维护时多四个数。
5. **结构靠层级，不靠描边**（2026-11-05 改写）。区分的两套语法按「它在哪一层」分：
    - **内容区的区块**是 `.board`（`PaperCard`）——台面上的一张纸，圆角 + 棱 + 3px 断面 + 落影，
      见 §2.4-47。同一页里不要再用文武线框，两套放一起互不相认。
    - **浮层**（角色编辑器、捉鬼测试面板）仍是 `.frame` 文武线：它们盖在纸上，是「压着的一张
      线稿」，不该有厚度。
    - 行分隔用 `border-bottom: var(--w-hair) solid var(--rule)`。

    **阴影只有一个用途：说明「这块东西比纸高」**。不叠第二层光晕、不做内发光、不拿它当装饰。
    **内衬那道细线只有一份定义**：`.frame` 自带，别处要同样的内衬就加 `dual-rule` 类
    （现在只有 `.gear-tip`；角色卡 2026-11-06 去掉了那圈线，用户说它读作「贴边的细边框」），
    小尺寸容器只覆写 `--dual-inset`。全局 `.ledger-lines` 已删：真要用
    「格子纸」，那是**某个列表**的私有样式，写在该组件 scoped 里。

6. **动效必须走 `--t-*` + `--ease-*`**，位移类统一带 `--ease-snap`（回弹）。时长按**距离**分七档，
   不按控件分：`--t-quick` 120（颜色、边框）、`--t-mid` 180（淡入淡出）、`--t-press` 200（印面内缩）、
   `--t-shape` 220（宽高形变）、`--t-thumb` 240（滑块走一格）、`--t-slide` 300（竖槽整格跳动）、
   `--t-tip` 90（浮层跟着指针出现）。**先问「它是哪种距离」，再选档，不要新拍一个数。**
7. **`prefers-reduced-motion` 必须有降级。**
8. **令牌只有一个真源**。`src/styles/` 三张表是全站唯一来源，全仓没有样式表副本。要做独立设计稿，
   **引同一份文件，不要复制**——需要「记得两边都改」的东西一定会漂。
9. **选中态只换「朱底」，不改字形**。`font-weight`、`font-size`、`letter-spacing`、
   `-webkit-text-stroke` 在选中与未选中之间**必须完全相同**（竖版滑块、三档滑块、分段胶囊三处一律
   400 / 同字距 / 0 描边）。全站没有任何 `600` / `700`：`base.css` 只有一条 `h1…h4 { 400 }`。理由两
   条：文楷本地只有 Regular，`600` 与任何 `text-stroke` 都是浏览器合成，会把撇捺糊成块；一枚灌朱、
   带内高光与投影的印本身已经说清「选中的是它」。0.25px 描边尤其要当心——它只把笔画外扩一圈，读到
   的就是「这格加粗了」，查的时候容易找错地方。
10. **一组「选一个」＝ 一个 Tab 停靠点**。`radiogroup` + `radio` + `aria-checked`；只有当前项
    `tabindex=0`；方向键换选项并**把焦点带走**，`Home` / `End` 跳首尾。四个控件（侧栏竖槽、三档
    滑块、两格开关、分段胶囊）统一走 `use-roving-focus.ts`；组里允许禁用项时用 `isDisabled`，方向键
    会跨过它而不是卡住。导航用 `<nav>` + `aria-current="page"`，**不用** `tablist`：全站没有
    tabpanel、也没有 `aria-controls`，读屏会宣布「标签页 1/8」然后找不到面板。
11. **凹与凸各只有一处定义：`.well` 与 `.stamp`**。凹槽是金边 + `--well` 底 + 上暗下亮渐变 + 上沿
    内影与下沿**亮**高光；印面是底色 + 顶边受光 + 上沿高光 + 落地线与朱色投影。两者都写在
    `base.css`，控件只写几何（宽高、内边距、圆角、排布），不重写厚度。竖起来的槽用 `.well.upright`；
    印面底色走 `--stamp-bg`，两格开关「灭灯」换的就是这一个变量。**受光一律写像素过渡带
    （`transparent 9px`），不写百分比**：百分比按元素自身高度解析，同一串数落在 23px 胶囊与 62px
    格上会得出两种宽度。
12. **令牌不留零引用**。零引用直接删，要用时再加。加一档只花一行，留着十档要一直维护假设。
    **这条同样管类和图标。**
13. **展示令牌的页面必须运行时读，不许手抄**。色板与字号阶梯走 `views/dev/tokens.ts` 的
    `declaredTokens` / `colorTokens` / `tokenFontSize`：名字从已加载的样式表里枚举，值挂到隐藏探针
    上让浏览器算（判断颜色用「套成 `background-color` 读回来」，不是 `CSS.supports`——后者只要值里含
    `var()` 就返回 true，会把 `--fs-*` 误判成颜色）。**任何「文档页」都不要抄代码里的数字。**
14. **一个控件的「皮」放哪里，只看一条：会不会被第二个组件用**。材质与厚度——`.well`、`.stamp`、
    `.bevel-pill`、`.board`、`.frame`、`.section-mark`、`.track-opt`、`.dual-rule`、`.field-label`、
    `.form-row`、`.chip`、`.meta`——留在全局表；只被一个组件用的写 scoped（`.slot-btn` 在
    `SlotButton`，`.map-stage` 在 `MapCanvas`，`.kit*` 在 `AtomsSection`）。判据不是「通用不通用」：
    再通用的东西，只要只有一个组件用，就该进 scoped。**已知例外**：`.cost-opt` / `.cost-thumb` /
    `.cost-switch` 只被 `CostSwitch` 用却是全局的——按判据该进 scoped，但迁移要连同类名一起改、收益
    低，谁动 `CostSwitch` 再顺手评估。
15. **尺寸只有一个入口：父级覆写变量，组件不认 prop**。图标是 `--icon-size`（默认
    `calc(14px * var(--fs-scale))`），槽按钮是 `--slot-h` / `--slot-w`，区块标是 `--mark-w` /
    `--mark-h`，竖槽是 `--vs-*`。判定一条就够：**这个值要不要跟着字号缩放？** 要，就必须是变量
    ——inline px 会顶掉默认值、也不跟 `--fs-scale` 一起缩放。
16. **轨道里的一格是 `.track-opt`**。两格开关与三档滑块的可点区域逐行相同（定位、圆角、字色、
    行高、过渡），只有内边距差 2px；选中字色由轨道的 `--opt-fg` 给（默认 `--on-seal`，灭灯时换
    `--ink`）。各写一份的结果是两处 `padding` 各自漂。
17. **区块标题前缀是 `.section-mark`（凸起短竖条），不是印章**。印章在账本语境里留给「已入账 /
    已达成」这类**状态**。标记是恒定的一竖、不带字：它只交代「一块从这里开始」，不参与叙事。材质走
    `--bevel-*`，与 `.well` / `.stamp` 同一光向——这是它读得出厚度的唯一原因。
18. **「标题 + 并排小字」的行不要用 `align-items: baseline`**。`h2` 自己也是 flex 容器，第一个
    item 是那枚**空的**标记；没有文字的 flex item 基线取自身底边，于是 `h2` 对外报出的基线是「标记
    底边」，11px 的说明文字被拉低 2.5px。用 `align-items: flex-end`：底边严格重合，`h2` 仍是 19 高。
    **也不要**把 `h2` 退回 inline 排版——18px 的标记会把行框撑到 20.6，每张卡高 1.6px。
19. **开发用的页面不进左栏**。`/dev` 在 `router.ts` 单独挂一条、不进 `NAV_ITEMS`，入口是**三连击
    左栏牌记**。三条约定：① 栏只发事件（`request-dev`），路由由 `App.vue` 决定——`AppRail` 不知道
    路由的存在；② 这类页面的 `current` 取不到导航项，外壳要给空串，让 `VerticalSlider` 的
    `hasActive` 收起朱印——`useRovingFocus` 的 `indexOf` 找不到值返回 0，照它画会把朱印停在「总览」
    上；③ 判据是**读者**而不是内容量：用户要动的东西留设置页（外观、关于），做界面时要查的东西
    （组件、色板、字号、图标）进开发页。
20. **一叠卡只剩两三张就并排，但断点由内容宽度算，不写 `@media`**。`.stack-pair` 是
    `repeat(auto-fit, minmax(420px, 1fr))`：既能给整页换轴（`.stack.stack-pair`），也能只包住该并排
    的那两张——规则是同一条，不写第二份。420 是「最宽那一行装得下」的下限（设置页是字号 + 三段
    滑块 + 说明）；写死 `1fr 1fr` 再配媒体查询，断点就和内容脱钩了。**同的是判断方法（按内容量），
    不是阈值**——卡内网格也用 420 只是巧合。并排时两卡的文武线要齐（grid 默认 `stretch`）：短的那张
    下面留白，比底边错开一截好看；退回一列时 `stretch` 自然失效。**高度差得远的卡不并**：开发页只
    并了色板与字号阶梯，组件演示与图标仍各占一行——并排会把短的那张拉出大片空白，而空白不是
    「留白」，是「这格没做完」。

    同一条也约束卡内网格：原子卡用 `repeat(auto-fit, minmax(420px, 1fr))`，1024 窗口就能排两列。
    **每格内部的演示行都要按「两列时也放得下」摆**：420 的格内容区约 432，最挤的是输入格那排
    （130 + 72 + 72 + 两处 gap = 288）；原先槽按钮四枚一行，432 会折——折了就看不出「图标带字 /
    纯文字」的形态差，所以拆成两行两枚。**不要用 `grid-column: 1 / -1` 让某一格吃满整行**：那会在
    奇数格处留下半行空洞，而空洞读起来是「这格没做完」。

    **工具列表的图标格是唯一两条都特殊的一处**：`repeat(auto-fill, 92px)`。空轨道用 `auto-fill`
    而不是 `auto-fit`：后者会把空轨道折叠掉、剩下的 `1fr` 长开，只有一件工具时那一枚被抻成横贯整行
    的长条，读起来像详情页。轨道又写死 92px、不给 `1fr`：宽度由 56 的图标块决定，拉伸出来的不是
    格子而是按钮。

21. **「按下即选值」与「拖动关过渡」不能同时生效**。两件事都写在 `pointerdown` 里时，点击是在过渡
    被关掉的那一刻选中的，朱印只能瞬移，点得越准越像没有动画。分两条路：**纯点击在 `pointerup` 才
    选值**（那时过渡还开着），指针越过 4px 阈值才认作拖动、此后选值跟随指针。阈值不是防抖的花样：
    它把「手抖 1px 的点击」留在点击那条路上。判据不是 CSS 里有没有 `transition`——真点击要能数出
    中间帧，拖动期间 `transitionDuration` 必须是 `0s`。
22. **焦点环全站只有两种：朱环与墨环**。`--ring`（`2px solid --cinnabar`）给纸底上的控件，
    `--ring-inv`（墨 45%）给朱底或紧邻朱色的控件——红底画红环等于没有环；默认偏移 `--ring-offset`
    （2px），**唯一的负值是 `VerticalSlider` 的 -2px**（34px 宽的槽上向外撑一圈会盖住邻格），那一处
    单写并注明理由。一律实线：虚线是浏览器的默认手感，而这张纸上所有记号都有厚度。焦点环画在
    **哪个元素**上也有一条：可点的容器里包着一块压印块时，环画在块上（跟随块的圆角），不在容器上
    ——`PressButton`、工具页图标格两处一致。装备格 2026-11-04 起不是压印块（换成凹槽，装备是
    「往里放」的东西），环就画在格子自己身上。
23. **说明文字只有三档，带框小签只有一枚**。按「读者要不要读它」分，不按字号分：

    **业务界面面向自用与梦幻老玩家**：不写游戏常识、操作教学、重复控件含义的提示，
    不向用户解释内部实现。空态只说当前状态；只保留错误、数据丢弃、覆盖或不可撤销等
    会影响操作判断的提醒。单位直接放在字段里，不另写换算示例。

    | 类      | 用途                 | 规格                                  |
    | ------- | -------------------- | ------------------------------------- |
    | `.note` | 块级说明，要读       | `--fs-xs` + 1.72 行高（`blocks.css`） |
    | `.hint` | 行内提示，扫一眼     | `--fs-sm`                             |
    | `.meta` | 元信息，找的时候才看 | `--fs-mini` + `--muted` + 1.6 行高    |

    `.meta` 不写 `margin`、不写 `letter-spacing`：前者属于父级节奏，后者取决于旁边站的是什么（标签
    0.14em、状态 0.04em）。小签（门派、技能等级、地图上的「小鬼」、测试样例）统一 `.chip`：
    `--rule-2` 描边 + `--r-1` + `--fs-mini` + `1px 5px`；**可点的另加 `.chip-action`**
    （`2px 6px` + 悬停洇一点朱），内边距大 1px 是为了让指针落在框内任意处都算命中。

24. **卡内页签是 `SteppedSlider` 的 `as="tab"`，不是一排胶囊，最多六格**。它们是一条轨道上的六个
    停靠点——换页签时视线跟着朱印走，比「哪一枚变红了」快。差别只在 ARIA：`as="tab"` + `prefix` 出
    `tablist` / `tab` / `aria-selected`，以及每格的 `id` 与 `aria-controls`
    （`${prefix}-tab-${值}` / `${prefix}-pane-${值}`）。**几何一行不改**——`N 格等分 + 印按格位移`
    只在一处实现，分头写会漏出那个 2px 的百分比基准。

    格宽 = `(卡宽 420 − 两侧外边距 40 − 轨道内边距 4) / 6 ≈ 62.7`；扣掉格内两侧 8 的留白后可用
    54.7，最长的「召唤兽」三字在 1.1 档占 46，余 8.7——这是**现在的下限**，卡宽再往下收
    先崩这里。**再加第七个就得改文案或改成两行**——这个数跟着卡宽与 `--card-pad-x` 走。
    高度不给 prop，走 `--step-pad-y`：默认 3（格子 23、整条 29，行内开关用），卡内页签条给 6
    （格子 30、整条 36；字号 `--fs-base` 13.5、行高 18）。21px 的格子读作一条分隔线，与下面的
    账页抢不出层级。
    **页签条宽度钉 `max-content`**（`CharacterEditor.vue` 的 `.ocr-tabs`）：窄页它是 `.ocr-bar`
    里的 flex 项、本来就按内容收；装备 / 召唤兽两页它被塞进 `upload-navigation` 的栅格，那一层
    默认 `stretch` 会把它拉到整列宽——同一条控件在六个分区里两种宽度。别去栅格那边写
    `justify-items: start`，那会把页签下面几行一起收缩成内容宽。

25. **锚定浮片的落位只有 `useAnchoredTip` 一处**。「贴右侧 → 放不下翻左侧 → 两边都放不下贴边，
    纵向再夹回视口」不要手写第二份。同一时刻最多一张浮片，**宽度统一 240**——一宽一窄读成两套东西。
26. **表单里的格子是全局 `.field`（凹的），数字格走 `NumberField`**。输入格与 `.well` 同一个光向：
    底取槽色（`--well`）而非纸色，加一道内侧上影，再加一圈细边——**只用细边的输入框在亮色下读作
    「贴在纸上的白方块」**。高度 `calc(26px * var(--fs-scale))`，与 `PressButton` 的 `md` 同一条
    算式：表单里「加一行 / 删一行」的按钮就挨着输入框，高差 2px 整行就是歪的。焦点**不画
    `outline`**，改换边色 + 复述内影——外框是方的，会压在 `--r-2` 的圆角上；这与按钮的焦点环是两件
    事。

    文本格子给固定宽度，不要 `flex: 1`**——一撑满，后面的数字就被推到行尾，读起来是「一列空白」。

    字号跟随普通 / `.sm` 票面；辅助行还要容纳删除按钮时使用 `.compact`，不再分区复制宽高与字色。

    输入时立即同步保存状态，不等失焦或 Enter；中文组词结束再提交，去首尾空白时保留光标位置。

27. **进度条不叫滑块，也不复用 `SteppedSlider`**。`MeterBar` 与它是同一套凹槽语言，但**没有落点、
    不能拖**——滑块说「选了哪一个」，进度条说「走到了多少」。① 分母未知时 `percent` 传 `null`，轨道
    空着且**不写 `aria-valuenow`**（写了就是「确定值 0%」）；② 填充**不挂 `.stamp`**：印面那套（外
    投影 + 9px 受光带）是给 23px 以上的块调的，压在 10–14px 的条上只剩一圈毛边；③ 高度只走
    `--meter-h`（默认 10，经验条 14），**不加 `size` prop**——与 §15 同一条。
28. **空数据上屏只有两种处理，「留一片白」不在其中**。判据是**这个标签自己有没有信息**：标签本身
    说明了这一格是什么（「气血」「特技」）→ **保留标签，值给一个淡「—」**（整行只剩点线和空档时，
    「没填」和「值恰好很短」读起来一样）；标签只是个容器（门派 `chip`、整行副题、分区注脚）→
    **整块不渲染**（空胶囊边框比没有更像「这里坏了」，空 `<p>` 会撑出一段说不清来源的留白）。

    **整块空时给一句居中灰字**。`.empty-note` 自 2026-11-10 起是 **`base.css` 里的全局类**
    （角色卡的分区、召唤兽页都在用）：`--fs-sm` + `--muted`、上下 26px、居中。牌里那一行
    （「尚未记录属性」）加 `.inline`——留白收成 5px、字号退到 `--fs-mini`、左对齐，它夹在读数与
    技能图之间，撑高会把牌拉长。**不给 `.inline` 另起类名**：两个名字会让下一个人不知道该抄哪个。

    这条推翻 2026-11-04 的旧口径（当时判「为合并这几份而改五处 padding 是净亏」）。改判的理由是
    `scoped` 那侧的代价一直没算进去：三份同名规则必须同步改，而 `scoped` 拦不住全局同名规则，
    真要合并本来就只能往上提。剩下四处**仍就地保留**，各自的留白由所在版面决定，不往全局搬：
    `.skill-empty`（技能编辑器）、`.note.blank`（历史收益）、`.empty`（今日速记）、
    `.hist-blank`（价格历史）。判断标准是**外观是否逐字节相同**：相同（师门 / 辅助 / 召唤兽三页
    的 `.empty-note`）就往上提，只是「看着像」的不提。

29. **游戏里固定的表，结构写进代码，表单只填值**。「属性」五组（资源 / 名望 / 战斗 / 加点 / 潜能）
    就是这种表：游戏面板长什么样是定死的，用户只需照抄数字。所以 `ATTR_GROUPS` 决定组名、行与顺序，
    `normalizeCharacter` 按它**重建**，表单里没有加行、删行、改标题。第五组「潜能」标 `wide: true`，
    是唯一占整行的组。判据是**数据是不是游戏给的**：是（属性、修炼项、装备格）→ 结构写进代码；不是
    （技能表、召唤兽名单，一个号练哪几项本来就不一样）→ 结构留给用户编辑。两种都做成「可编辑」的
    代价不是多几个按钮，而是**数据里可能出现一份结构不对的表**，界面照旧按它渲染——用户看得见错，
    却没处改。修炼是第二个实例：`TRAINING_GROUPS` 定两组十项；组名是我们改的（游戏里叫「角色自身
    修炼」「召唤兽控制修炼」，又长又不准），改完照样写进清单——写进数据就又要允许编辑。
    修炼界面只修改等级，上限取清单默认值，已有数据中的上限仍保留；不再提供上限输入框。
    快速修改遵循同一规则：忽略传入的上限，仅在已有上限缺失时补游戏默认值。
    三类「只改一个等级」的快速修改（师门技能 / 辅助 / 修炼）窗里画的东西逐字相同，
    由 `quickTarget.ts` 的 `levelPanel()` 一处生成，不要在 case 里各抄一份字段表。
30. **票的「凹」由四道棱与圆角给，不靠缝**。`.slip-row` 的 `box-shadow` 四笔（上左亮、下右暗）加
    一层落影就是全部，面直接画在行自己身上，没有伪元素。**已经删掉的「凸纸带」是另一套，别照着
    复活**：两条色带都凸，厚度全靠行间 2px 缝——贴住时上块的下暗棱正好压住下块的上亮棱，两笔抵消、
    整页退回一条平色带；1px 也不够，会粘成「色带 + 一条暗线」。那套判据随 `.paper-row` 一族一起删了
    （2026-11-04 四页统一）。票不需要「缝给的厚度」：行距按档给（md 6 / sm 4），圆角自己把相邻两张
    分开。「面铺满整列、不两端内收」那条也连带作废——票没有伪元素，不存在这个问题。
31. **统一编辑弹窗沿用 `ModalShell` 外框留白，分区自己负责内部滚动**。六页共用尺寸见 §26；
    左侧导航常驻，右侧卡片宽度共用 `--char-editor-w: 460px`，两栏间距 16px，左截图栏保留约 400px。
    名册卡宽仍由 `--char-w` 决定。卡内无溢出或滚到边缘时，滚轮继续传给页面，不截断名册滚动。
    正文使用 `fill` 与 `min-height: 0`，
    装备和召唤兽详情各在自己的内容区滚动，不随所选项目改变弹窗大小，不叠加外层滚动条。
    详情纸、身份区与名称框的几何共用 §26 的 `.character-detail`，业务字段的专属排布留在各自表单。
32. **多格的固定比例写成 grid 的等分列 + `span`，不用 flex + 一串定宽**。召唤兽基础与资质用
    `repeat(2, minmax(0, 1fr))`，名字跨两列；各行复用 `slip-row sm`，输入格吃掉标签后的剩余宽度。
    比例要求 N 份，轨道数就是 N，跨格按份数表达；每格用 `<label>` 包住，让点击标签也能聚焦输入。
33. **值由别处决定的字段，显示成文字，不要再画一个输入格**。门派技能名来自 `schools.json`，上限是
    同一份表里的 `cap`——两者都不该出现在输入框里。**凹槽的意思是「这里可以写」**：写不了却画成
    可以写，比少一个格子更糟——用户会去试，试完发现改不动，就开始怀疑整张表坏了。同一条也管
    「只读编号」「算出来的小计」：只显示，不上 `.field`。要保住的只有同一列的起点与同一行的基线，
    所以名字格仍是那 200 宽、一行高，只是没有边框与内影。
34. **下拉不用原生 `<select>`，用 `SelectField`**。原生那枚在 WebView2 上永远是系统外观，放进这张
    纸里像贴错的一块金属片——与「不做 `<input type="range">`」同一条理由。三段各有出处：触发条直接
    用全局 `.field`（与旁边输入格同一个凹槽，并排不打架）、纸片 `--paper` + `--shadow-lift`（与浮片
    同一枚影子）、当前项朱字 + 3px 朱色短竖条（与 `.section-mark` 一个说法，不另造一枚勾）。

    六条实现细节，改它之前先读：① **焦点始终留在触发条上**（`aria-activedescendant` 指当前高亮
    项），列表项不接管焦点——否则 Tab 会走进列表，弹窗的焦点环要重算；② `Esc` 收起列表时**必须
    `stopPropagation`**：它常长在弹窗里，而弹窗自己在 `document` 上听 `Esc`，不拦的话「关下拉」会把
    正在填的表单一起关掉；③ **浮层不许出裁剪容器**——纸片 `min-width: 168` 是按「别看省略号」定的，
    而触发条在门派那格只有 114，左对齐时右端必然伸出弹窗，`.editor` 的 `overflow: hidden` 会连边框
    影子一起切掉；做法是先量最近一个 `overflow != visible` 的祖先，左对齐放不下就右对齐到触发条
    （`shift = rect.width − listWidth`），再兜一次左端；④ **别用 `scrollIntoView` 滚列表项**：它的
    `inline` 默认也是 `nearest`，会把**所有**可滚祖先一起滚——包括 `overflow: hidden` 的弹窗（照样
    能被程序滚动），左侧「名字 / 区服」标签会整片被切；要滚就只滚列表自己（比 `offsetTop /
offsetHeight` 与 `scrollTop / clientHeight`，直接写 `scrollTop`）；⑤ **纵向也要找位置**：下方
    不够就翻到触发条上方（排在弹窗底部的行向下只剩二三十像素）；两侧都放得下时不翻——向下是默认；
    ⑥ **值来自固定名录的字段用下拉而不是输入框**：手敲只有错字、同音字、表里没有三种结果，而卡片按
    名字查图标——错一个字那一格就没图，还不报错。**表外的老数据保留一项**
    （`XX（不在表里）`），否则下拉显示成「未选择」，看着像值被清空，用户一保存就真没了。

    **这一套不共用 `useAnchoredTip`**：那个是给「贴着某个元素、宽度固定 240」的浮片，`SelectField`
    要的是「不出裁剪容器 + 纵向翻边」，判据不同（§25 说的是浮片，别混）。

38. **卡上的读数是「数值墨 + 跟票的档走」；朱只给强调与满级**。属性值、技能等级、修炼等级、经验数
    一律用 `--num`（赭）。字号只有两档，与票同源：md 页 `calc(--fs-md + 1px)` = 15.5，sm 页
    `--fs-sm` = 12，靠赭色与字重分开——属性 20 行挤在 493 里，数字再大就顶签。修炼只显示当前等级，
    不再带上限分母或满级色。三层不许混：**墨**（名目 / 说明）→ **赭**（读数）→ **朱**（满级、强调动作）。
    数值一律朱的话，三层压成一层，「伤害 1591」与「已满」会一样重。

    **卡上与编辑页的数字一律加粗**。文楷只装了 400，700 由浏览器合成：笔画描粗、**字宽不变**，所以
    定宽 52 的淡槽、60 宽的输入格都不会被顶出去（实测五位仍 41.2，无 `scrollWidth` 溢出）。作用域
    不同但同义：`character-card.css` 的 `.num` + `:deep(.slip-val)` / `:deep(.meter-text)`；
    `CharacterEditor.vue` 的 `.ocr :deep(.num)`。**`scoped` 够不着子组件的字**，所以跨组件同款
    样式都要留一条 `:deep()`；反过来，**改类名时要用 grep 找 `:deep()` 里的旧名字**——2026-11-04
    四页统一把 `.school-val` 并进 `.slip-val`，这一条漏改，师门的数就静默地不加粗了（辅助那几行走
    `.num` 仍然粗，于是同一张卡一半粗一半不粗）。**仍然不动全局 `.num`**：它还挂在浮片
    （`GearTip` / `PetTip`，`Teleport` 到 `body`，两条 scoped 都够不着）与别处零散小字上。
    **单位跟着粗、词不跟**：「136 级」「11/20」整串加粗，而「参战 65」只粗 `65`——「参战」是个词。
    装备摘要（版心那块，**两组六行**：特技 / 特效 / 套装 · 宝石 / 灵饰 / 玉魄）按同一条：**整串值不加粗、
    里面的数字加粗上赭**。2026-11-10 之前由 `GearPane` 的 `numParts()` 把值切成「文字 / 数字」两段，
    现在值本身已经拆成一格一格（`BriefItem{name,value}`），模板直接把 `name` 写普通文字、`value` 包进
    `<b>`，`numParts()` 随之删掉。所以「起死回生」「碎星诀」这些词保持常规，而「头5 · 项0」里的数
    一眼看得出。段数行**0 段也写 0 并退灰**（`--muted`，不压 opacity）：留白读作「漏了一行」，
    0 才是「这一件还没练」。套装件数是数出来的（按写了这套的装备数），不足三件退灰。摘要**没有一个字
    是另存的**，六行全从十二件装备的 `detail` 现算（`gear.ts` 的 `gearBrief`），录入选什么卡上就
    显示什么。测试与 `title` 用 `briefText(row)` 把一行压回一句（`头5 · 项0`）。
    **特效与特技同用一枚朱**（两者都是「蓝字效果」，本卡不造第四种颜色），套装赭。
    **读数三行都进等宽栅格**（`BriefRow.perRow` + `dd.cols` + `--brief-cols`）：宝石 3 列两行、
    灵饰 4 列、玉魄 2 列，格与格靠列距分开、不画「·」。

    灵饰一枚 28——同一种读数各长各的（2026-11-10 实测三种宽度，这是那块最显眼的不齐）。定宽之后

    效果三行（特技 / 特效 / 套装）**不套**：那些是词不是数，套进凹格读起来像「这里能填」，
    而版心擦不了任何一个字。判据是「这一格是数值还是词」，不是「这格短不短」。

    六行混成一张平铺的清单，一眼看不出「上面是词、下面是数」；而 `0/20` 那种矮块才怕被线切开。
    六行的**行高统一由签定**（`min-height: var(--brief-tag-h)`）：有签 18、没签 16.8 时六行不是等距带子。

    **字仍然只有墨 / 赭 / 朱三层，没有第四种**。苔不再灌任何技能进度：卡上只剩装备浮片的增益字
    （物价页的「跌」也是它）。修炼那条绿条与师门的九格都在 2026-11-04 撤掉，判据同一条：数字已经
    说了，别再画一遍。**没填 / 0 级 / 未学**退回 `--muted`——`0/20` 用赭会和「练了一半的 11/20」
    同样醒目。**编辑页那排数字格同一个赭**：那一页是照着卡上那张表逐格核对的，同一行数在卡上赭、
    弹窗里墨，对照时像两份记录。

    **属性里没有「标朱那一项」**（2026-11-04 删）：`AttrRow.strong` 字段、`.slip-row.strong`
    规则、`mock.ts` 四处标记一起删干净——原先朱标「这个角色吃饭的属性」，但那一行为什么染朱用户读不
    出来，读起来只像渲染出错。判据：**一页里只有一个「朱」**，朱要么说「满了」，要么说「这个动作不
    一般」。**签里数的大小只有一个来源**（2026-11-04 修）：`.slip-val .lv`（base.css）给 md 15.5、
    `.slip-row.sm` 给 sm 12。卡自己的 `character-card.css` 是 `scoped` 的，一条裸 `.lv` 编译成
    `.lv[data-v-…]` 后特异性从 0-1-0 涨到 **0-2-0**，与 `.slip-val .lv` 打平，于是听注入顺序——票里
    的数被压成 13，而师门那一列长在 `SkillRow` 作用域里、不匹配那个 `data-v`，仍是 15.5。同一张卡
    上「门派 15.5 / 辅助 13」就是这么来的。**scoped 样式里别写裸的单类选择器去覆盖全局器件**：加了
    `[data-v]` 之后它已经不是一个「弱选择器」了。卡上那条 `.lv` 现在只认 `.char-head` 与
    `.pet-row`。**组头右端不报总数**：那几行就在下面、十二个装备格也在下面，同一个数说两遍；要表达
    「都练满了」，让那几行的数自己转朱。

39. **外来图像进纸面前只过一层「暖化」，不盖纱**（2026-11-04 改）：
    `filter: sepia(.42) saturate(.72) contrast(.95) brightness(1.05)`，**没有遮罩层**。游戏图标是
    深底金纹（剧情那几项还是深蓝底）的方图，色相不在这套墨 / 朱 / 赭里：`sepia` 把它拉进褐调、
    `saturate` 收掉卡通色的艳、`contrast` 只压一点点（压多了边缘就糊，十几个图标会变成十几块色斑）。
    **纱是这次撤掉的**（用户：「我们用到的游戏的图标不加遮罩层了」）：那层 `::after` 原先亮色盖
    22% `--ink-base`、暗色 18% `--paper`，判据是「降存在感」，代价是**认不出画的是什么**——十几个
    图标糊成同一块暗斑，而这一栏恰恰要靠图案区分（太极 / 符 / 仙鹤 / 剑 / 星图）。真要压，改
    `--tile-face` 或滤镜里的 `brightness`，**别再加一层**：壳（`.shot`）留着只为给圆角与裁切，
    `<img>` 是替换元素、长不出伪元素。这一整套（压印块 + 壳 + 滤镜）收在
    `views/characters/IconTile.vue`：辅助（`AssistIcon` 只负责查图）与师门技能共用同一枚，23 的图配
    28 的块。**别在业务组件里再写一遍滤镜**——两批游戏图会漂成两种色。
40. **`grid-auto-rows: 1fr` 的轨道不会缩到比内容还小，要写 `minmax(0, 1fr)`**。`1fr` 的下限是
    min-content：七行加起来比这一页高时，轨道不肯缩，整块溢出（师门页当年用均分时实测 433 / 422）。
    同一族坑：`flex: 1` 的滚动容器还要配 `min-height: 0`，否则它按内容撑开、永远不滚。
41. **行距归容器，别让行自己带 `margin-top`**。`.slip-rows` 一行 `row-gap`（md 6 / sm 4）就够，行上
    再写 `+ row` 的边距会叠成两倍而不自知。**间距与厚度是两个意思**：相邻两张票之间那几像素是「一叠
    纸」的厚度（sm 档要的 4px），6px 是「各自成行」（md 档要的），别共用一个值——共用了，改厚度就
    顺手改了行距。sm 不是「越小越好」：贴到 2 时整页底下空出一截却看不出是排完了（§37 的实测）。
42. **辅助技能编辑页只放四样：图标 / 名字 / 等级 / 删**。上限卡上早就不写、辅助的上限本就随技能表
    来；已学未学在「逐个录已学」的页面上没意义，没学的直接删行。两个字段留在数据里，`cap` 仍参与
    满级判断、`off` 仍让那一格退灰。判据：**编辑页的每一格只放「回去之后还要看的东西」**——只在
    录入那一瞬有用、之后没有任何一屏会读它的字段，不该占半行。名字是**选**不是写（名录在
    `game/data/skills.json`），所以那一格是 `SelectField`；`flex: 1` + `min-width: 0` 必须给，否则
    长名字把等级格挤出去，覆盖规则要带 `.slip-row` 前缀（`SelectField` 的根自带 `flex: 1`，同特异性
    下不押注入顺序）。两列而不是一列：一列 17 项 × 42 = 714，卡上可用只有 493；两列各 **183**
    （420 − 左右各 20 − 滚动条占位 2 = 378，减 gap 12 再对半），生活 4 行、剧情 2 行。票面、行高、
    列距全走 §37 的 `.slip-row` / `.slip-rows.slip-cols`。
43. **修炼一项 = 一张票；卡与编辑页都是左右两列，一组一列**。卡上：`grid` 两列（各 184、间距 12，
    版心 420 − 40 = 380），
    行高走 §37 的 **42**（= 签 24 + 上下各 9），两组占 251（组头 17 + 五行 234），493 里空 242。
    **试过吃满版心**（`grid-auto-rows: 1fr`，每行 88），用户看完否了：「太松散了，下面留白没事」
    ——行是用来读一项的，撑高不会让它更清楚：留白说「这一页只有五行」，硬撑说「这里灌了点东西」。
    行内：名目 `flex: 1`（约 105）｜ 签 56 × 24；名目从前是定宽 78，那是单列时为塞进五字项名掰出来
    的紧身尺寸，两列之后有余量，`nowrap` + `ellipsis` 只当兜底。签的 24 与编辑页那两个数字格同高。
    **卡上不画进度条**（用户：「不要黄绿进度条」）：判据不是「条不好看」，是它把 `11/20` 又说了一遍
    ——两列之后名目与签之外只剩几十像素，5/20 与 11/20 相差个位数，读不出比例。满级仍靠**签里的
    等级转朱**。数值签里**只有等级是读数**：上限写成 `/20` 的淡字（`--muted`、`--fs-mini`）。修改时
    沿用卡片两列，只把等级换为输入框，上限仍为只读文字。定高弹窗中内容少时允许留白。
    这一页**没有自己的行与容器样式**：票、行高、行距
    全在 §37（原先 `.training-list` 下那三条覆盖随纸带一族一起删掉）。
44. **角色卡按门派浅染：一层斜向渐变，只有纸变色**（用户：「参考物价卡片的浅色背景，根据门派来
    区分不同颜色」→「做一个渐变会更好，从左上到右下」）。**卡底 = 门派色掺进纸，135° 斜向渐变，
    方向随主题反转**：亮色 **30% → 8%**（左上淡、右下浓），暗色 **76% → 16%**。跨度是试出来的——
    先用 33/17 两端差太小、整卡仍读作平涂，拉到 46/8 才看得出方向，随后浓端收回 **30**，中点 19%。
    方向不能照搬：亮色下纸本来就亮，左上再压浓会读成「左上脏了一块」，从淡往浓走才像「色在右下
    积住」；暗色反过来。变的是**彩度不是明度**（两端只差 2 个点），所以不跟全站「左上受光」的规矩
    打架。**二十一门派归七族**：朱（官府/火）、金（佛门/天界）、桃（胭脂）、青（水/符箓）、绿
    （林木）、紫（幽冥）、褐（土石/机关）。族间差 60° 一眼分得开，族内差半个明度档；**不做二十一
    种色相**（各差 17° 压到 92% 附近时相邻两个几乎同色，读起来像随机）。分族表在 `tokens.css` 的
    注释里。**色号在 `tokens.css`**（`--tint-<门派>` / `--tint-deep-<门派>`），`blocks.css` 共用
    `.character-theme[data-school='…']` 的映射；**与物价卡同名但不共用色号**（那边九类按货品材质取色，这边按
    门派气质），混用会让「这张卡是召唤兽还是龙宫」变成要记得「哪套色号」才答得上。**票面跟着卡底
    走**：`.slip-row` 的第二色读 `--slip-base`，卡上设成中点亮色（`--wash`）——不跟的话，卡一染色，
    一排票就成了「贴在一张彩纸上的白条」；票取**中点**、不跟渐变，否则同一张卡上五张票深浅不一。
    **门派签也染**（`--tint-deep` 做底，字仍赭）：底色在卡的四个角上，而这枚签就在名字旁边，是日常
    认人的地方。**空门派回落纸色**：不匹配任何 `[data-school]` 时 `--tint` 未定义，
    `var(--tint, var(--paper))` 回落成纸——新角色还没选门派时它必须还是纸。**暗色单给一档浓度**
    （76 → 16，对亮色 30 → 8）：暗纸本身极深，同一个百分比混出来几乎看不出（量过，龙宫那张只剩
    「还是黑的」）——这不是把亮色压暗，是另取一组低明度色号 + 另一组浓度，色相各自对得上。
    角色卡、角色修改、快速修改和截图识别弹窗通过 `character-theme` 与 `data-school` 共用配色，
    编辑和识别按当前草稿门派实时更新；`ModalShell` 将调用方属性透传到 Teleport 内的面板，覆盖正文及页脚。
    普通按钮（纯图标和图标加文字）复用 `--slip-base` 的门派浅染，悬停与按下保持同色系；
    三态通过 `PressTile` 的 `--tile-face*` 传入，朱色主操作和已有分类配色保留自身语义。
    **浅染只有一条，写在 `.character-theme` 上**（2026-11-10）：`--wash-a` / `--wash-b` / `--card-bg`
    原来是 `.char` 独占的，改到 `.character-theme` 之后**角色卡与修改窗里装备 / 召唤兽右侧那两张详情纸**
    共用同一条渐变；`.char` 与 `.gear-form` / `.pet-form` 各自只写 `background: var(--card-bg)`。
    两张详情纸写 `var(--card-bg, var(--board-face, var(--board-paper)))`：自定义属性算不出来时
    整条 `background` 会变透明（substitution 失败不会回落到 `.board` 那条），留个兜底。
    别再往某个组件里复制色号或另写一条渐变——那会让「改门派浓淡要改几处」重新变成谜。
    混色锚点用 `--character-paper`，不写 `--board-paper` 也不写 `--paper`：角色卡上它就是
    `.board`（`--board-paper` 当场有值），修改窗面板上没有这个变量时回落成同一个
    `light-dark(--paper-2, --paper)`——两处挂法本来就该是同一种纸。
    **纸上一律不要贴白条**：这两张详情纸内部的任何「底色」都写 `var(--slip-base)`，
    不写 `var(--paper-2)`——后者在染色纸上是一块白补丁。已改过的三处：
    `GearDetailForm` 的 `.inline-field:hover/:focus` 与 `.gear-add .press-btn` 的 `--tile-face*`
    三态、`pet-detail-form.css` 的 `.skill-add:hover`。新增控件时照这条查一遍。
45. **scoped 里不要复用全局组合类的名字**。`blocks.css` 的 `.stack` / `.stack-pair` / `.note` /
    `.kit` 是跨组件的组合级排版，带着自己的意图（`.stack` 的 `max-width: 1240px` 是给「说明文字
    页」写的：再宽只会让说明拖成一条长线）。在某个视图的 `<style scoped>` 里再写一个 `.stack`，
    **两个规则会合并生效**——scoped 只加属性选择器，拦不住同名的全局规则。实测后果：收益页用了
    `.stack`，1600 宽窗口里内容被 1240 卡住，右侧空出近 300。判据：**这个类名在 `src/styles/` 里
    有没有**——有就说明它已经有主，换一个自己页面的名字（`.income-stack`），或者动全局那一条并说明
    为什么所有使用方都该跟着变。
46. **日期不用原生 `<input type="date">`，用 `DateField`**。同 §34 的 `<select>`：系统月历弹层在
    WebView2 上自成一套外观，且它给的是一张**看不懂月份**的一行字——收益历史要「选一天翻一天」，
    手敲一个不存在的日期会得到「这一天没有记录」，与「真的没有记录」分不开（物价页的记价窗一天只
    记一笔，那里仍用文本格 + 校验，够用）。五条实现细节：① **整张月历只有一个 Tab 停靠点**
    （落点那天 `tabindex=0`，其余 -1），方向键换日、`PageUp/PageDown` 换月、`Home` 回今天；
    ② **翻月必须把落点挪进新月份**（同一天，超出月末取月末）——不挪的话 `tabindex=0` 落在一个不存在
    的格子上，键盘用户按 `PageDown` 后焦点掉到 `body`，整张月历从 Tab 顺序里消失；③ `Esc` 收起时
    `stopPropagation`（它长在弹窗里，弹窗自己也听 `Esc`）；④ **值按年月日三段构造 `Date`**，不要
    `new Date('2026-11-05')`——那种写法按 UTC 解析，东八区整体退一天。**「今天」与「选中的那天」是
    两件事**：今天只在格子底画一枚朱点，选中灌朱面；两者同时成立时收掉朱点（一枚点压在朱面上是脏的）。
    ⑤ **纸片 `Teleport` 到 body、`fixed` 定位**，不要长在触发条下面。它长在弹窗正文里时，
    `.modal-body` 的 `overflow-y: auto`（内容长的窗要滚）就是一道裁剪边界：实测历史窗只有两条流水
    时正文约 260 高、月历约 300，下三行连同「回到今天」整块消失，而界面看上去只是「月历很短」
    （2026-11-05 用户报「日期选择被切割了」）。靠要求宿主窗传 `scroll: false` 解决是错的——历史窗的
    内容确实会长。代价是三件事要一起做：位置按触发条的**视口坐标**算（`placePanel`，滚动 / resize
    重新量）、`z-index` 高过弹窗遮罩的 80（取 85，仍低于提示层 90）、`Tab` 时 `preventDefault` 并把
    焦点还给触发条（纸片已不在弹窗面板里，弹窗的焦点陷阱会把焦点拽回窗内第一个控件）。

47. **卡片 = 台面上的一张纸（`PaperCard`），内容区不再用文武线框**（2026-11-05，用户：「把我们所有
    的原本卡片全部优化为这个样式」）。外壳是 `components/PaperCard.vue` → 全局 `.board`，页面内容区由
    `PageShell` 的 `surface`（**默认开**）铺一层台面托住它。五条：
    - **材质只有一份**，写在 `base.css` 的 `.board`：圆角 6px、上亮下暗的棱、下沿 3px 的「纸的断面」
      （`--rule-2`，不是半透明黑）、3px 硬影 + 10px 软影、左上偏光 + 135° 斜向渐变。改厚度只改这一处；
      **使用方不准再抄一份 `box-shadow`**（角色卡只覆盖底色，厚度照旧借 `.board`）。
    - **卡片必须躺在台面上**。`.page-content.surface` 铺 `--well`（暗色 `color-mix(well 66%, --ink-base)`）。
      不做这一步，「纸色浮在纸色上」等于没有立体——`PressTile` 与 `tokens.css` 都记着这条：
      纸上没有比纸更亮的纸。
    - **卡面纸色只有一个开关**：`.board` 的 `--board-paper`——亮色 `--paper-2`（#f2ead6），暗色
      `--paper`。纯纸白压在台面上太白，一张张读作「打了灯的板子」；`--paper-2` 是「纸 → 台面」
      的中间档。**底色与渐变两端都引它**，所以换纸色只改这一行；要自己染色的卡（角色卡的门派浅染）
      覆盖 `--board-face`，混色锚点仍用 `--board-paper`，否则它会比别人白一档。
    - **斜差按主题分档**：亮色 3/9、暗色 4/4（三轮调下来的数：4/8 → 4/12 → 3/9，暗色 14/12 → 7/6
      → 4/4）。亮色的斜差只能靠暗端压深——纸已最亮，提亮没有余量；暗色 4% 是「看得出方向、说不出
      哪里不一样」的下限，再收就只剩偏光在撑。两档都写在 `.board` 的注释里，改数前先读那一段。
    - **`.frame` 只留给浮层**：角色编辑器、捉鬼测试面板这些「盖在纸上的东西」仍是线框；摆在台面上的
      内容卡一律 `.board`。两者不是同一类物件，别互相借样式，也别把 `.frame` 的 `::before` 内衬线
      带进纸片里。
    - **卡片间距 16**（不再用 12/14）：下沿断面 + 硬影 + 软影会探出卡外一圈，间距小了下一张的顶边
      就压在上一张的影子里，两张读作「粘在一起」。`.stack` / `.stack-pair` 已统一 16，新容器照此。

48. **压印块的斜向渐变只有暗色有，而且强度按 46 / 32 / 26**（2026-11-05，用户：「`PressTile` /
    `PressButton` 的斜对角背景渐变在暗色下差距太大」）。五条：
    - **亮色的小块不叠背景渐变**：块面留一整片干净纸色，「光从哪来」由四条棱说完（同 `.board` 那条
      「纸上没有比纸更亮的纸」）。`wide` 是例外——它的偏光按固定像素给，亮色下那三层一直在跑。
      原先靠 `color-mix(… 170%)` 这个非法值让整条 `background-image` 失效——**别再写这种隐式失效**，
      要什么就写什么。
    - **暗色三层：小块 46 / 32 / 26，`wide` 28 / 16 / 26**（依次是左上偏光、145° 高光、315° 暗部）。
      这三层只有暗色写，因为 `--bevel-hi` 暗色是 18% 白、`--bevel-lo` 是 55% 黑：两边拉满 100% 时
      对角差 85 阶，一块纸读作「一半打了光、一半在阴影里」。收到这一档后实测 17 阶。
    - **停点跟着收**（52/58/62 → 46/50/55）：光斑只占角落，不往中间铺。
    - **`PressButton` 没有自己的材质**，它只是 `PressTile` 加一层字色。改按钮的观感就改 `PressTile`，
      不要在按钮里补第二份 `box-shadow` / `background-image`。
    - 块的大小决定用不用 `wide`：**200px 以上的面必须传**（偏光按固定像素给），小方块不要传。

### 2.5 注释

注释是这个仓最重要的资产之一：写「为什么」和「踩过什么坑」，不写「这行做什么」。

1. **文件头写「这个文件解决什么问题」**，不写「这是 xx 组件」。
2. **反直觉的写法必须写原因**（`AppRail.vue` 的 `min-width: 0`、`use-theme.ts` 的单例）。
3. **不要写「改了什么」**——一行提交信息与 `git show` 已经说了，注释只留契约。
4. **不写废话注释**：`// 定义变量`、`// 循环` 一律不写。
5. **代码里留「契约」，历史留在这里**。「当初试过 A、某次截图指出 B、所以现在写 C」是 `RECORD.md`
   的素材，不是行内注释的素材。行内要留的是那句「不这么写会怎样」：「`--bevel-lo` 恒偏黑，用
   `--ink` 会在暗色主题翻成提亮带」是契约；「早先这里写的是 `--ink`」不是。
6. **中文注释，句号结尾**，不用「注意」「小心」这类空话开头——直接说事实和后果。
7. **模板里的中文文案不要手动断行**。Prettier 会按 `printWidth` 折行，而折行点在 HTML 里渲染成
   一个空格。要强制断句就用 `<br>` 或拆成多个 `<p>`；一段文案只有一两句时，宁可让它整行超过 100
   字符被折，也不要在两句话中间敲回车。

### 2.7 小共用函数：一件事只写一份

同一件小事在几个窗口里各写一遍，改一处另一处就静默落后。下面八条是已经收拢的那几件——
新增同类逻辑前先 grep，已经有家的就去改那一家（§2.6 同一条口径）。

- 下拉选项遇到名录之外的旧值，统一用 `src/components/select-options.ts` 的 `withCurrentOption` 保留当前值；不要在门派、装备属性等各写一份补选项逻辑。
- 属性与修炼按行名查找，统一用 `character.ts` 的 `findAttrRow` / `findTrainingRow`；OCR 草稿和快速修改不各自展开分组。
- 修改窗的初始输入聚焦统一用 `focus-input.ts`，保留各窗口自己的目标选择器。
- 已退役的固定技能空格不再由 `petDetailSlots` 维护；技能数量以实际记录为准。
- 字段契约只从**自己的模块**取：装备相关的类型与常量在 `gear.ts`、召唤兽在 `pets.ts`，`character.ts` **不再** `export *` 转出一份。同一个类型有两个入口时，改一处另一处静默落后，而类型是同一份所以编译也不报错。
- 卡内六分区的页签选项只有一处：`character.ts` 的 `PANE_OPTIONS`。卡片与编辑器不要在组件里各自 `PANES.map(...)`——那还会在每次渲染新建数组，把滑块的 `values()` 一起换掉。
- 装备部位格只有一个边长：`GearEditor.vue` 的 `--slot-block`（48px），图标与首字压印都读它。同一个 48 写两遍时，改大小只改一处会让没图的格子小一圈。
- 日期与时刻落成字符串只有两处：日期走 `services/format.ts` 的 `dateText`（收 `Date` 也收毫秒），时刻走 `services/clock.ts` 的 `timeText`（补零由同文件的 `pad2` 承担）。不要在窗口里再写一份 `padStart(2, '0')` 去拼 `YYYY-MM-DD` 或 `HH:mm`——这类函数改一处，另一处就静默落后，而它们都长得对。

## 5. 一句话总结

**设计语言与工程护栏都已成立，八页业务也齐了（最后补上的是目标页，第 115 批）。**
下一段的缺口不在「还差哪一页」，而在**同一套东西写了两遍**——这类形状问题，改一处的
成本会随第二处漂移而变贵。角色新建、修改与识别已共用一份草稿和窗口；单件装备与单只召唤兽
和全部修改共用详情表单。`.empty-note` 已提到 `base.css`（牌内那行用 `.inline`），
另四处空态仍就地保留。
规范的作用是把最值钱的东西（令牌、四件套、控件契约、注释质量）固化下来别再退回去。
单测覆盖纯逻辑、composable 与页面数据层，`ipc-contract.test.ts` 守住两端**的命令名与字段名**，
`cargo test --lib` 网住 SQLite 那一层；仍然只能靠真机验证的是截屏与 OCR 那半段。
