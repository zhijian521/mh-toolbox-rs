## 2. 规范条款

### 2.1 工程基线

**必须装**（全部是旧仓已验证过的组合，不需要重新选型）：

| 用途      | 依赖                                                                               | 配置要点                                                                                                                      |
| --------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 静态检查  | `eslint` 10 + `@eslint/js` + `eslint-plugin-vue` + `typescript-eslint` + `globals` | flat config；`vue/flat/essential`（**不是** `recommended`，那套带 600+ 条格式化规则）；不开风格类规则（交给 Prettier）        |
| 格式化    | `prettier`                                                                         | `printWidth: 100`、`tabWidth: 4`、`singleQuote: true`、`trailingComma: "all"`、`semi: true`、`vueIndentScriptAndStyle: false` |
| 编辑器    | `.editorconfig`                                                                    | `indent_style = space`、`indent_size = 4`、`end_of_line = crlf`（.bat）、`charset = utf-8`                                    |
| Rust 格式 | `rustfmt.toml`                                                                     | `max_width = 100`、`edition = "2021"`                                                                                         |
| Rust 检查 | clippy                                                                             | `cargo clippy -- -D warnings`（`unwrap`/`expect` 由人工把关，不靠 lint 全禁）                                                 |

**依据**：现有代码实测 31 个文件（20 `.vue` + 8 `.ts` + 3 `.css`）全是 4 空格缩进、0 个 2 空格；最长行 96 字符
（`src/components/icons.ts`）。`printWidth: 100` 这一档不会折任何一行，可以接受。

**脚本约定**（照搬旧仓的命名，肌肉记忆不用改）。下面这段是**已落地**的实际内容，
与 `package.json` 一致：

```json
"format":       "prettier --write .",
"format:check": "prettier --check .",
"lint":         "eslint . --max-warnings 0",
"lint:fix":     "eslint . --fix",
"lint:commits": "git log -20 --no-merges --format=%s | node scripts/check-commits.mjs",
"typecheck":    "vue-tsc --noEmit",
"test":         "vitest run",
"check":        "npm run format:check && npm run lint && npm run typecheck && npm run test && npm run check:version && npm run lint:commits"
```

`npm run check` 是前端的唯一入口，CI（`.github/workflows/check.yml`）的 `web` job 跑的就是
这一条——这个约定比规则本身重要，因为它意味着这一项「本机绿 = CI 绿」。

但 CI 还有两个 job，**不在** `npm run check` 里，别以为跑绿了就能安心推：

| job         | 跑什么                        | 提示                                 |
| ----------- | ----------------------------- | ------------------------------------ |
| `rust`      | `cargo fmt --check`           | 本机要单独跑                         |
| `rust-test` | `cargo test --lib`（windows） | 前置 `npm ci && npm run build`，见下 |

`rust-test` 必须先有前端产物：`tauri::generate_context!` 在 `custom-protocol` 开启（默认）时按
`frontendDist` 读 `dist/`，目录不存在是**直接 panic**；而 `dist/` 不入库（`.gitignore`）。所以
干净检出上那个 job 原本必定是红的，本机绿只是因为工作区里恰好留着 `dist/`。

两条都踩过，写在这里：

- **`--max-warnings 0`**：原先 `lint` 就是 `eslint .`，而 `attributes-order` /
  `define-macros-order` / `no-console` 三条是 `warn`。警告不影响退出码，等于这半条检查
  只打印不拦人。现在只要有噪音就是红的。
- **`lint:commits` 进 `check`**：它原先只作为独立脚本存在，于是「自己已经红了」这件事
  没人发现——正则要求冒号后带空格，而实际 8 条提交是紧贴写的。**没接进唯一入口的检查，
  等于没写。**

**一条原先写在「不做」里、现在已兑现的**：`check` 里曾经没有 `test`，理由是「vitest 要等
第三批才接，那时放 `vitest run` 只会失败，放 `exit 0` 的假通过更是骗人」。2026-11-01 起有了：
捉鬼的解析与范围计算是纯函数，8 帧真机原样输出就是它的回归用例，`npm run test` 已进 `check`。
**加测试别只测 happy path**：那 8 帧里有一帧的大鬼是**故意判失败**的（`36，，45` 硬救
会得到一个差 100 格的坐标），用例把它固定下来，才挡得住后来者「顺手把分隔符放宽一点」。

只剩一处刻意的「不做」：

- **`check` 里没有 Rust**。`cargo clippy` 依赖 MSVC 的 `LIB` 与 `PATH`（见 `AGENTS.md` §三），
  混进 `check` 会让「一条命令全绿」在这台机器上不成立。Rust 侧单独跑：

```bash
cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings
```

**版本锁定**：

```json
"engines": { "node": ">=22.0.0 <23", "npm": ">=10" },
"packageManager": "npm@10.9.7"
```

`.nvmrc` 写 `22.22.2`（本机实测版本）。CI 用 `node-version-file: .nvmrc` 读它——
`engines` 只在大版本上拦人，`.nvmrc` 才能让 CI 与本机跑同一档。

**行尾由仓库说了算**：`.gitattributes` 里 `* text=auto eol=crlf`（仓库存 LF、工作区 CRLF），
`.editorconfig` 的 `end_of_line = crlf` 与它一致。

原先只有 `*.bat` / `*.cmd` 有声明，源文件全赖本机的 `core.autocrlf=true`——那是**用户级**
配置，不随仓库走。实测当时 64 个文本文件里混着 3 个 LF（被脚本按 `\n` 写出来的那几个）。
症状不是乱码，是**静默**：改一行而 `git status` 显示整篇 M、`git diff` 却是空的，
或者反过来漏掉真正的改动。换台机器、或在 Linux 上 clone，整套行尾预期都会变一次。

规范化只做一次：`git add --renormalize .`（索引本来就是 LF，实测 0 处变更），
再 `rm` 掉那几个 LF 文件、`git checkout --` 让它们按新属性重新落地。

```toml
# src-tauri/rust-toolchain.toml
[toolchain]
channel = "stable"
components = ["rustfmt", "clippy"]
```

**大户资源必须可再生**。`assets/fonts/LXGWWenKaiScreen.woff2` 是**裁过**的（GB2312 全集，
1.75MB），别手改它：要改覆盖范围就改 `tools/font/subset-font.py` 再跑一遍。同目录的
`LXGWWenKaiScreen.full.woff2`（9.84MB 原件）**必须留在库里**——没有它就再也裁不出第二版，
而游戏更新一批生僻地名时一定得再裁。同理 `public/game/maps/*.webp` 的切图现场已经删了，
只剩成品，属于「不可再生但已定型」，别再对着成品做二次压缩。

**游戏资源集中在 `public/game/`，不进 `src/`**。凡是「梦幻西游本身长什么样、有什么东西」
——底图、门派图标、门派/技能/装备数据表——都放这一个目录：`src/` 里的资源会被打包器
**改名加哈希**，而资源清单里写的是文件名，改名后必然对不上，且失败方式是「某张图静默
不显示」而不是报错。目录里有三层（`maps/` / `icons/` / `data/`），每层旁边有 README；
判据、命名、以及**哪些「和游戏有关」的东西故意留在代码里**（ROI、窗口标题匹配、形近字组、
句式正则）见 `docs/GAME-ASSETS.md`。分界线一句话：**会整体替换的是资源，偶尔改一个数
且必须跑测试的是规则。** 游戏内已有的图（技能图标、特技图标）**从游戏截图切，不手画、
不找第三方素材包**——手画的在游戏改版后必然对不上，而截图就是当前版本的真值；切图脚本
与遇到过的三个坑见 `docs/GAME-ASSETS.md` §4.1。

**性能改动先量基线，量完再改**。`node tools/probe/startup.mjs --exe <路径> --runs 5`
分三段报数（进程→导航 / 导航→FCP / 导航→字体就位）。三条纪律：

- **同一份 exe 做 A/B**，靠 `--browser-args` 传参而不是改 Rust 重编。换二进制会让
  「启动变快」混进链接布局变化的干扰。
- **取中位不取单次**。同一台机器上机器有负载时的方差能到 2 倍（实测同版本 660ms 与 2100ms）。
- **报数字要报对是哪一段**。`font-display: swap` 之后字体不阻塞首屏，裁字体不会让 FCP 变快，
  提前的是「字长对了」那一刻——把两件事混成一句「启动快了 300ms」就是假话。

**提交规范**：`<type>(<scope>):<中文摘要>`，type 白名单
`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`。
**冒号后不加空格**——中文摘要贴着冒号读是一行，加空格反而多一个断点；
校验器 `scripts/check-commits.mjs` 对两种写法都放行（`:\s*\S`），因为现有 45 条提交里
8 条是紧贴写成的，改习惯的成本高于放宽正则，而放宽的只是「一个空格」，不是格式本身。
正文写「为什么」，不写「改了什么」——`git show` 已经能看到改了什么。
`npm run lint:commits` 只看最近 20 条；更早的 45 条是旧仓历史（`[feat][20241225][…]` 那种），
不追溯、不改写历史。

**不用 husky**（沿用旧仓的判断）：本机沙箱对带管道的子进程不稳定，钩子容易误报。
校验放 `npm run check` + CI。

### 2.2 命名

三条前缀规则，覆盖 `src/` 全部：

| 前缀 / 形态 | 含义                       | 例子                                                                            |
| ----------- | -------------------------- | ------------------------------------------------------------------------------- |
| `App*`      | 应用外壳的一部分，全局唯一 | `AppRail`、`AppIcon`                                                            |
| 功能名      | 通用控件，名字说明它画什么 | `PageHeader`、`PageShell`、`TitleBar`、`SlotButton`、`PressTile`、`PressButton` |
| 业务名      | 只服务于某一页/某一域      | `MapCanvas`、`LedgerSection`                                                    |

`Base*` 前缀**已停用**：最后一个 `BaseCheck`（勾选框）在 2026-11-01 的清理里随之删除——
全仓没有任何地方用到勾选框，`.check` 那套样式一起删了。新基元直接用功能名，
不再新增 `Base*`。这条不是「改名计划」，是「不再往里加」：改名冲掉 git blame，收益低于成本。

其余约定：

- 组件文件 `PascalCase.vue`，一个文件一个组件
- **一个 `.vue` 太大时，先拆「样子」和「纯计算」，不要先拆组件。** 同目录允许放
  `kebab-case.css`（`<style scoped src="./x.css">`：选择器与写在 `.vue` 里逐条等价，
  含 `:deep()`）与纯函数模块（如 `components/ghost/map-paint.ts`：入参进、像素出、不碰 Vue）。
  判据是 §2.3-3——**拆完之后每个文件只回答一个问题**：`CharacterCard.vue` 答「这张卡长什么样」，
  `character-card.css` 答「每一块怎么画」；`MapCanvas.vue` 答「什么时候画」，
  `map-paint.ts` 答「画成什么样」。拆成子组件是最后一步，因为它会同时引入 props 契约与
  插槽，而多数「太大」只是两件事混在一个文件里。
- composable `use-xxx.ts`，导出 `useXxx`
- 类型 / 接口 `PascalCase`，**不加 `I` 前缀**（现有 `AppInfo`、`RailPage` 已经是对的）
- CSS 类名 `kebab-case`，BEM 不强制；**层级靠块前缀**（`.rail-item`、`.rail-foot`）而不是嵌套选择器。
  **类名不要求等于组件名**：`.rail-mark`、`.size-slider`、`.vs-track` 都是块语义命名，与
  `AppRail` / `FontSizeSlider` / `VerticalSlider` 不同名。找组件靠 grep 模板里的标签名，不靠类名；
  反过来为了「对齐」而批量改名，会冲掉 git blame，收益低于成本。
- 设计令牌 `--<类别>-<语义>`：`--paper`、`--ink-2`、`--fs-base`、`--r-2`、`--t-quick`

### 2.3 组件分层

```
views/          页面 = 路由目标。只做编排：拉数据、拼区块、处理路由参数
components/     组件 = 有视觉语义的 UI 单元。不直接调 services/，不读路由
composables/    跨组件的状态与副作用。单例状态放模块作用域
services/       系统能力唯一出口，**一个能力一个文件**（desktop.ts、ghost.ts）。页面与组件都不许绕过它调 invoke
types/          （待建）跨组件共享的类型
```

六条硬规则：

1. **组件不调 `invoke`**。只有 `services/` 能碰系统（一个能力一个文件，现在有 `desktop.ts`
   管窗口与「关于」、`ghost.ts` 管捉鬼读取通道）——`desktop.ts` 头注释立了这条，
   ESLint 的 `no-restricted-imports` 把它变成可检查的约束：`components/`、`views/`、
   `composables/` 里出现 `@tauri-apps/api`、`@tauri-apps/api/*` 或 `@tauri-apps/*` 一律报错。
   早先只拦了 `@tauri-apps/api/core`（`paths` 只匹配一模一样的模块名），于是 `TitleBar.vue`
   直接引 `@tauri-apps/api/window` 管窗口按钮，lint 照样全绿——**规矩写着「只有 services 能碰
   系统」，检查却只管一个入口**。改成 `patterns` 后整族都拦，窗口控制也搬进了 `desktop.ts`。
2. **质感在组件内，布局在父级**。`SlotButton` 只认 `--slot-h`/`--slot-w`，不写死尺寸；
   父级用 `.rail-foot { --slot-w/--slot-h: calc(30px * var(--fs-scale)) }` 传。`VerticalSlider`
   同理：默认值是侧栏规格（轨道 34 / 格 62 / 图标 15 / 字 14），父级要换尺寸就覆写
   这五个 `--vs-*` 变量。图标一律走 `--icon-size`（见 §2.4-15）。
   原理：父组件 scoped 样式能命中子组件根元素。
   `SlotButton` 另有 `seal` 变体：印面常驻、字压在印上，用于**主操作**——一屏只该有一枚。
   它变的是「印在不在」，与「有没有 text/icon」的形态正交，所以不叫 `variant`、不改尺寸。
   `size`（`md` 26 / `lg` 31）是**变量之上的预设**，不是第二个尺寸入口：
   `lg` 只声明 `--slot-h` 与 `--icon-size`，`md` 故意不写规则——不给它声明，
   默认高度才轮得到继承父级的 `--slot-h`（侧栏 footer 就是传 30px）。给 `md` 补一条规则
   会把那份继承盖掉，侧栏那格会无声退回 26px。
   第三档 `sm`（24px）2026-11-02 删掉：与 `md` 只差 2px，在开发页并排读不出高低，
   业务页零使用——**分辨不出的档位不是「更多选择」，是噪音**。

    **页头动作只用 `md`，不用 `lg`**（2026-11-03）。`--page-head-h` 不是常数，是
    「padding 19 + 标题行高 + 1」算出来的（1 档 45.3、1.1 档 47.8），而页头是 `min-height`：
    按钮比它高就把页头撑大。`lg`（31 + 19 = 50）三档字号全都超（50 / 53 对 45.3 / 47.8），
    页头比左栏牌记高 5px，底下那道通栏账线跟着下移，与内容区、与没有按钮的页面全部错开一格。
    `md`（42.9 / 45 / 47.6）三档都低于自然高度，页头高度才只由令牌决定。
    要更大的按钮先改令牌——那叫「页头整体变高」，不该由某一页自己长高。

    **按钮有两种材质，按「这块地方的语言」分，不是按心情挑**：

    | 组件          | 材质                                 | 用在哪                                                     |
    | ------------- | ------------------------------------ | ---------------------------------------------------------- |
    | `PressButton` | **凸**：一块压印纸，按下去压回纸里   | 页面里的动作——页头、面板、表单（捉鬼页、角色页已是这一套） |
    | `SlotButton`  | **凹**：按钮本体是槽，悬停落一枚朱印 | 左栏底部那两枚工具、开发页的槽按钮演示、占位页             |

    **朱面不是另一套按钮，是同一块纸换成朱色**：传 `tone="seal"`（2026-11-03 从
    `PressButton` 收进 `PressTile`）。朱面的棱必须自己一套——`PressTile` 的棱是按纸调的，
    亮色下那条 82% 奶白的顶线压在纸上等于没画、压在朱红上却是塑料高光，底棱的暖黄棕
    也对朱红反向（详见 RECORD 第 30 小批）。所以 `tone-seal` 换了块面三态、四条棱、
    内容影，`PressButton` 只剩内层字色（`--on-seal`）。

    **需要「一块朱红」的地方一律用它**——主操作按钮、满级的门派字印——不要在业务样式里
    再写一份 `box-shadow`：两份配方迟早变成两个朱。字印这类不可点的块要一起传 `still`：
    悬停变亮、按下回弹是「按我」的承诺，长在点不动的块上就是骗人去点。

    **读数也有自己的一块「凹格」：`NumTag`**（2026-11-03，角色卡师门页的等级先要的）。
    它是纸带上挖出来的一小格——淡槽底（45% 的 `--well`）、无边框、**数居中**，
    几何走 `--tag-w` / `--tag-h`，内容走默认插槽（所以「满 180」里的「满」还能单独上朱）。
    与 `PressTile` 正好相反的一枚：左端字印是凸的印，右端等级是凹的格，一行里一凸一凹。

    三条约束：
    ① **它是签，不是输入框**。不接受点击、不给悬停与按下态——加深底色是「这里能填」
    的承诺，而卡上那格填不了。要能填的地方仍用 `NumberField`。
    ② **材质在全局 `.num-slot`，不在组件里**（2026-11-03 收口）。同一副「45% 槽底 +
    上沿影 + 下沿亮线」原先写了三遍（`NumTag`、`SkillEditor` 的 `.lv-field` / `.cap-field`、
    `AttrEditor` 的 `.value-field`），而且已经写出差异：两个 input 用 `background-color`
    长写，`.field` 的顶壁渐变留了下来，`NumTag` 是 `<span>`、从来没有过渐变——
    同一个数在卡上与弹窗里深浅不同。现在都挂 `class="… num-slot"`，材质只此一份。
    **别把它改回 `background-color`**：`background` 简写才是「顺手清掉 `.field` 那层渐变」的那一步。
    **材质与交互分两层**（2026-11-03 晚）：`.num-slot` 只给静息态，悬停 68% 与聚焦
    转实槽挂在 `.field.num-slot` 上——只有能填的格子才该有「这里能点」的承诺。
    卡上的属性读数（`<dd>`）与 `NumTag`（`<span>`）因此能直接套这层材质而不会
    跟着加深；那条「抬高特异性压掉悬停」的补丁也就不需要了。
    ③ 字号、颜色**不归它管**：等级仍由调用方给 `--fs-md + 3` 与 `--num`。
    组件只说「格」，不说「字」。

    两者三形态（只 `text` / `icon`+`text` / 只 `icon`）与两档尺寸（26 / 31）**逐像素同值**，
    并排时基线齐。**同一行不要混用**：一凹一凸并排，读起来是两种器件。
    两枚都别手写 `<button class="...">`——早先那套全局 `.btn`（1px 描边 + 纸底）就是这么
    长出来的第三种，2026-11-02 已整段删掉（先例：第 8 批删 `.icon-button`）。

3. **一个组件要么管状态，要么管样子，不要两个都管**。`SegmentedPills` 管「选一个」，
   格子的质感交给全局 `.bevel-pill` 类——这是范本。
   这里**不包一层 `BevelPill` 组件**：那枚胶囊自带 `aria-pressed`，是「独立开关」的语义，
   放进互斥组会与 `aria-checked` 打架；而一组格子还需要 roving tabindex，
   也不是单枚胶囊能表达的状态。全局类可以被任意组件直接挂上，不必再包一层组件。
4. **新增控件先进开发页的「原子组件」卡**（`views/dev/AtomsSection.vue`），再进业务页。
   那一页（三连击左上角标进入，见 §2.4-19）是这套语言的验收面，不是给用户看的演示页。
   **卡里的 `.note` 只答两件事：怎么用、踩过什么坑**——「当初为什么这么画」属于
   [`RECORD.md`](RECORD.md)，不上页面。一段压在两行内（1024 单列 878 宽实测），
   末行不留孤字（只剩两三个字要回删几个字，别让它断在那儿）。
   **组合件另开一张卡**（2026-11-03，`views/dev/SkillRowSection.vue` 是第一个）：由原子
   拼成、还带业务语义（`level` / `cap` / `off`）的件不塞进原子卡——混进去之后，下一个人
   想「复用」就会以为它只是个排版件。判据是「它 props 里有没有业务字段」，不是行数。
5. **侧栏不滚动，窗口最小高度由它决定**。`AppRail.vue` 是 `overflow: hidden`——
   8 档一旦要滚，拇指就跑出视口，「第几档」的位置感失效。所以高度交给窗口兜底：
   `src-tauri/src/lib.rs` 的 `min_inner_size` 取「较大」字号（`--fs-scale: 1.1`）时的实测需求
   （侧栏 736.2 + 标题栏 39.6 = 775.8 → 取 **780**，默认窗口 1280×820；实测 776 仍不滚、
   772 开始裁底栏，所以 780 是硬下限）。加高侧栏里的东西（多一格、加大格高、底部再加
   一个按钮）必须同步抬这个数，否则最后一格会被裁掉。反过来说，想再压低最小高度只能
   动侧栏自己：格高（`--vs-cell: 62px`，是「图标 15 + 两字竖排 32.2 + 间距」的下限）、
   牌记高度、或底栏那两枚 30px 按钮。
   **注意「最小高度」不等于「默认档刚好填满」**：按 1.1 档定，默认档必然在槽与底栏之间
   留一段空白，那是留白，不是没排完——留白由 `.rail-foot` 的 `margin-top: auto` 吸收，
   底栏永远贴底。
   **栏顶牌记的高度与 `PageHeader` 等值**：两处都取 `--page-head-h`。那枚令牌写的就是
   「padding 10 + `--fs-xl` × 1.15 + 9 + 1px 账线」，改页头的 padding 或标题行高只改它一处。
   （曾经两边各抄一份算式，正是 `RECORD.md` §1.2-H 里反对的那种写法。）否则下面那道槽的起点会在
   50px 栏宽处与页头底边错开一个台阶。**槽顶紧贴这条线**（`.rail-nav` 不设 margin-top）：
   留 6px 时槽顶比右侧横线低半格，接缝处永远差一个台阶。
   **牌记本身不画下边框**：那里放的是直接落在纸上的应用标
   （`assets/mark-ink.png` / `mark-paper.png`，与 `assets/fonts/` 同处，随主题翻面），横线会把它切成一个
   「头部区块」，而上面并不是区块名。
   **标是一块 34px 见方的压印块，宽度与目录槽一致**（都取 `--rail-slot-w`），整条栏读作一列
   而不是「一枚图 + 一条槽」。块本身是 `PressTile`（`components/PressTile.vue`），与工具页的
   图标格**同一块材质**——两处原先各写一套立体，牌记那套（一圈细线框 + 2px 底边）在 34px 下
   读作「贴了张带框的图标」，同一栏里就出现了两种厚度语言。合并的代价与做法见
   [`RECORD.md`](RECORD.md) 的第 16 小批。
   牌记只给三个变量：`--tile-w`（= 槽宽）、`--tile-r`（`--r-2`，与槽的圆角同心）、
   `--tile-drop: 0.85`（工具页那套是按 56px 的块算的，8px 软影落在 34px 下面读作「浮在纸上的
   小卡片」；但栏底色就是 `--paper`，块面与栏底同色，凸起几乎全靠这道影和四条棱撑着，
   所以也不能缩到 0.6——那样只剩 1px 宽的一条，块读作「一张平的浅色方块」）。
   图形占块的 **72%**：图自带 3% 透明边，满铺会贴到块的下沿那 2px 厚度上，
   82% 时仍是「一圈窄边裹着一只字」，读作带框的图标。

    **不可点的块传 `still`**（角色卡辅助技能那 11 个图标格）。悬停提亮、按下凹回纸里
    是「按我」的两条承诺，长在点不动的块上就是骗人去点——「点了没反应」比没有这个块更糟。
    `still` 只关这两条状态，材质一律照旧（棱、落地影、块面），因为它仍然是纸上的一块东西。
    圆角与棱厚**不乘** `--fs-scale`——它们是绝对曲率与绝对厚度，槽那边也没乘，两处一起缩放反而对不上。

6. **给开发与验证用的入口，一律挂「开发者模式」（`useDevMode`）**，不在页面上直接摊着。
   开关在开发页第二张卡。判据是 **「用户真会用的功能」vs「只在没有游戏、没有数据时才用的
   替身」**——后者属于这一层。现在只有一个：捉鬼页右下角的「测试文字」面板；后面的测试工具
   都挂这一个开关，不再各配一个。
   关着时组件**不渲染**（`v-if`），不是 `v-show`：后者只是 `display: none`，停靠点还在 DOM 里，
   tab 与读屏都摸得到，截图里也会被当成一个真功能。
   状态落 `localStorage`（`mh-dev-mode`）：它表达的是「我现在处在这个模式下」，刷新一次掉回关
   等于每次都要先去点一下。这与「高概率区域默认开且不记忆」不矛盾——那条的理由是「记住上次
   会把默认值变成上次」，而这里默认值本来就该是关，记忆不会污染它。

7. **页面自己的数据层放 `views/<页>/<名字>.ts`，读进来的对象一律先归一**。
   角色名册（`views/characters/roster.ts`）是第一个：模块级 `ref` + `useRoster()`，
   与主题、字号同一套写法（§2.3 开头的分层里没有「store」这一层，也不要为此引 Pinia）。
   放 `views/` 而不是 `services/` 的理由：它不是系统能力（不过 `invoke`），换存储时改的是
   它自己那两个读写函数；而「一个能力一个文件」那条说的是 Tauri 命令这一层。

    **读时清洗与保存时清洗是同一个函数**：`normalizeCharacter` 既把 `localStorage` 里的
    旧数据补成合法形状，也在编辑器点保存时跑一遍——空技能行、空装备壳、没有名字的召唤兽
    都在那一步被清掉。两处各写一套「收尾」，迟早一处记得一处忘。
    兜底的原则是**永不抛错、缺什么补什么、坏条目单条丢掉**：它失败的方式很特别，
    只在重启之后才出错，而那时页面已经挂载完，一行 `undefined is not iterable` 就是整页白屏。

### 2.4 样式

现有代码在这块**已经接近满分**（实测：0 处硬编码 `font-size`、0 处硬编码十六进制颜色），
把已有做法固化成条款即可：

1. **颜色只能来自令牌**。禁止 `#rrggbb`、`rgb()`、颜色名。需要的色先用 `color-mix()` 从令牌混。
   **灌朱的控件一律用 `--seal` / `--seal-edge` / `--on-seal` 这一组**，不要直接拿
   `--cinnabar` / `--cinnabar-ink` / `--on-cinnabar` 配面与字。原因：`--cinnabar` 在暗色翻成
   #d0755f 的亮橙红，而 `--on-cinnabar` 同时翻成近黑 #171310，深字压亮红会被红色吃掉；
   所以暗色的面改用 `--cinnabar-ink`、字改用纸白 `--ink`，两个主题统一成「朱底浅字」
   （`tokens.css` 里 `--seal` 那一段有完整推导）。分界是**面还是前景**：
   填充用这一组，把朱当字/线/描边用仍取 `--cinnabar`。
   `--paper` **暗色是深纸**（#1c1912），不是纸白；要纸白取 `--ink`。
   需要**不随主题翻面**的纸白（`color-mix()` 的提亮锚点、画在截图上的标记）取
   `--paper-base`——它是纸白的绝对值，`--paper` 的亮色档就是由它算出来的。
   同理，需要**恒定的暗**（往深里压的锚点，比如朱红块的背光面）取 `--ink-base`：
   `--ink` 在暗色是纸白，拿它去压会让「背光」在暗色主题下变成一条发光的线。
   这两枚是令牌表里唯一允许写绝对色值的地方——别的地方再写 `#000` / `#fff`
   就是又把锚点抄了一份。
   组件里若仍需写暗色覆写，**必须整条写进 `:global()`**：
   `:global(html.dark .sel)` 编出来是 `html.dark .sel`，而 `:global(html.dark) .sel`
   会被编译成只剩 `html.dark`，后半截选择器直接丢掉（构建产物里 grep 一下就能看见）。
2. **字号只能来自 `--fs-*`**，且每个令牌已经乘过 `--fs-scale`。禁止 `font-size: 14px`。
3. **圆角优先用 `--r-1/2/3/pill`，落不进这四档的就地写 px**。账簿方向基本不用圆角。
   侧栏竖滑块（`VerticalSlider.vue`）外框、格、印**共用 `--vs-radius`（`--r-2`，3px）**——
   一处改三处一起变。胶囊（`--r-pill`）现在只留给三档滑块、分段胶囊这类横向控件。
   **这条原先写的是「只能来自这四档」**，全仓审查时发现套不上，于是改条款而不是改代码：
   现有六处裸值里有三种真实需求是这四档表达不了的——滚动条滑块的 `10px`（必须跟着
   10px 轨道宽走，套 `--r-pill` 成药丸、套 `--r-3` 成方角）、细线的 `1px`、圆形的 `50%`。
   为它们各造一档，等于把「一个值一个令牌」摆回来；那和 `--sp-*` 十档是同一个错误。
   判据：**这个值会不会被第二个地方用到**。会，就进令牌；不会（曲率由某个具体尺寸决定），
   就地写并加一行注释说明它跟着谁走。
4. **间距就地写 px，不做刻度**。2026-11-01 删掉了 `--sp-1…10` 十档：它们只被引用过
   2 次（`.frame` 的 20px、当时还在的 `.btn` 的 6px），其余八档一次没用上。一套 80% 没人
   用的刻度比没有更糟——它让人以为「选令牌」比写 `gap: 8px` 更正确，而表里的值从没在任何
   界面上被验证过。现在写 `gap: 8px`，一眼看得出意图；真到了「间距必须统一」那天再定。
   （`.btn` 那套平面按钮已在 2026-11-02 整体删掉，现在只剩 `SlotButton` 与 `PressButton`
   两种材质，界线见 §2.3-2。）
   **例外只有「等值契约」**——同一个值被三处以上引用，说明它不是布局现场决定的：
   ① 页面留白 `--page-pad`（16px）：页头左右 = 内容区四边。2026-11-02 之前是两处各写
   一份（页头 16、内容区 `12px 16px 18px`），结果上边比左右窄 4px、下边多 2px——
   四边没有一个面同宽，卡片顶边离页头线比离左缘近。现在 `.page-head`、`.page-content`、
   捉鬼页的浮动测试面板都引这一枚，改一次三处一起变。
   ② 区块内边距 `--block-pad`（15/18/18，纸上的主卡）与 `--block-pad-tight`
   （11/14/12，卡内小卡与浮层）：2026-11-02 之前四处分写四套（12/14/13、10/13/12、
   9/11/11、15/18/18），差 1–2px——读者感受不到，维护时多四个数。
5. **结构靠线，不靠阴影**。分区用文武线 `.frame`；列表的行分隔用行级
   `border-bottom: var(--w-hair) solid var(--rule)`。阴影只用于「凸起」的一次性投影。
   **内衬那道细线只有一份定义**：`.frame` 自带，别的区块要同样的内衬就给元素加
   `dual-rule` 类（`.char`、`.gear-tip` 这么用），小尺寸容器要收紧只覆写 `--dual-inset`。
   早先 `.frame` / `.char` / `.gear-tip` 各抄一份，抄到第三遍时已经漂了——浮片写着
   「与卡片同一套」却是 2px 而不是 3px。
   曾经有个全局 `.ledger-lines`（整片 `repeating-linear-gradient` 画满横线），全站零引用，已删——
   真要用「格子纸」，那是**某个列表**的私有样式，写在该组件的 scoped 里，不要再升成全局类。
6. **动效必须走 `--t-*` + `--ease-*`**，位移类动效统一带 `--ease-snap`（回弹）。
   时长按**距离**分七档，不按控件分：`--t-quick` 120（颜色、边框）、`--t-mid` 180
   （淡入淡出）、`--t-press` 200（印面内缩）、`--t-shape` 220（宽高形变）、
   `--t-thumb` 240（滑块走一格）、`--t-slide` 300（竖槽整格跳动，62px 一格）、
   `--t-tip` 90（浮层跟着指针出现）。
   后四档 2026-11-02 才从组件里的裸值提上来（`SlotButton` 220/200、`VerticalSlider` 300、
   `GearTip` 90）：值一个没改，只是给了名字——在此之前条款要求走令牌、代码却写着裸值，
   条款和代码互相打脸。**新写动效先问「它是哪种距离」，再选档，不要新拍一个数。**
7. **`prefers-reduced-motion` 必须有降级**（见 `RECORD.md` §1.3-5）。
8. **令牌只有一个真源**（✅ 已执行）。`src/styles/` 下的三张表是全站唯一来源，全仓没有任何
   样式表副本（2026-11-02 删掉最后一份脱离应用的样张 `design/income.html` 之后，连「样张」
   这条第二入口也不存在了）。以后要做独立设计稿，**引同一份文件，不要复制**——
   需要「记得两边都改」的东西一定会漂。
9. **选中态只换「朱底」，不改字形**。`font-weight`、`font-size`、`letter-spacing`、
   `-webkit-text-stroke` 在选中与未选中之间**必须完全相同**。现状实测：竖版滑块、
   横版三档滑块、分段胶囊三处的选中项计算值一律 400 / 同一字距 / 0 描边，
   七个区块标题（`.ledger-section h2`，设置页 2 张 + 开发页 5 张）也全是 400。
   全站样式表里没有任何 `600` / `700`：`base.css` 只有一条 `h1, h2, h3, h4 { 400 }`
   的合并规则，外加 `.note b` / `.page-title` / `.icon-item b` / `.swatch b` 四处
   显式 400（后三处是把 `<b>` 的浏览器默认加粗压回去），其余一律继承。
   理由有两条：① 文楷本地只有 Regular，`600` 与任何 `text-stroke` 都是浏览器合成，
   会把撇捺糊成块；② 一枚灌朱、带内高光与投影的印本身已经把「选中的是它」说清楚了。
   0.25px 描边尤其要当心——它只把笔画外扩一圈，肉眼读到的就是「这格加粗了」，
   而代码里 `font-weight` 根本没变，查的时候容易找错地方。
   同理，组件里的 `font-weight` 要慎写：scoped 选择器（如 `h2[data-v]`）特异性高于
   全局的 `h2`，一处漏写就会把某个区块顶成合成加粗，而全局表里看不出来。
10. **一组「选一个」＝ 一个 Tab 停靠点**。`radiogroup` + `radio` + `aria-checked`；
    只有当前项 `tabindex=0`，其余 -1；方向键换选项并**把焦点带走**，`Home` / `End` 跳首尾。
    四个控件（侧栏竖槽、三档滑块、两格开关、分段胶囊）统一走
    `src/composables/use-roving-focus.ts`，不再各写一套——此前只有侧栏做全了，
    另两处能 Tab 进每一项，分段胶囊连方向键都没有。组里允许个别禁用项时用
    `isDisabled`，方向键会跨过它而不是卡住。
    导航用 `<nav>` + `aria-current="page"`，**不用** `tablist`：全站没有 tabpanel、
    也没有 `aria-controls`，读屏会宣布「标签页 1/8」然后找不到面板。
11. **凹与凸各只有一处定义：`.well` 与 `.stamp`**。凹槽是金边 + `--well` 底 + 上暗下亮渐变
    - 上沿内影与下沿**亮**高光；印面是底色 + 顶边受光 + 上沿高光 + 落地线与朱色投影。
      两者都写在 `base.css`，控件只写几何（宽高、内边距、圆角、排布），不重写厚度。
      竖起来的槽用 `.well.upright`（暗面换到左壁）；印面的底色走 `--stamp-bg`，
      两格开关「灭灯」换的就是这一个变量。
      **受光一律写像素过渡带（`transparent 9px`），不写百分比**：百分比按元素自身高度解析，
      同一串数落在 23px 的胶囊与 62px 的格上会得出两种宽度——五处印面曾经各拍一套
      （46/46/46/32/15%），改任一处高度就得重调五处。
      改厚度就改那一处，改完五道槽、五枚印同时变；想给某个控件单独调淡，先想清楚是不是约定错了。
12. **令牌不留零引用**。这条在 2026-11-01 反了过来：原先主张「令牌是词汇表，零引用也不删」，
    结果 `--sp-*` 十档里 8 档、`--z-*` 三档、`--overlay` / `--danger-bg` / `--fs-lg` /
    `--fs-amount` / `--w-rule` 全都没有调用方——一年后没人能判断哪些值是验证过的。
    现在的口径：**零引用的令牌直接删，要用时再加**。加一档只花一行，留着十档要一直维护假设。
    **这条同样管类和图标**：`.error` / `.positive`（两个文本色类）和 7 个从没在业务里用过的
    图标（`edit` / `filter` / `camera` / `paste` / `upload` / `calendar` / `clock`）2026-11-02
    一并删了。它们原先靠「词汇表」的理由留着，而那个理由正是这条在 2026-11-01 推翻的东西——
    口径改了、库存却没跟着清，等于把旧答案又抄了一遍。
    真正活着的写法类只剩 `.num`（角色卡的金额列在用）。
13. **展示令牌的页面必须运行时读，不许手抄**。「色板」「字号阶梯」曾经是两份手写清单
    （13 个颜色、8 档 px），`tokens.css` 后来新增的 `--seal` 组一次都没在色板上出现过——
    这就是「需要记得两边都改」的代价。现在两页都走 `views/dev/tokens.ts` 的
    `declaredTokens` / `colorTokens` / `tokenFontSize`：名字从已加载的样式表里枚举，
    值挂到隐藏探针上让浏览器算（判断颜色用的是「套成 `background-color` 读回来」，
    不是 `CSS.supports`——后者只要值里含 `var()` 就返回 true，会把 `--fs-*` 误判成颜色）。
    新增令牌不需要动页面。**任何「文档页」都不要抄代码里的数字。**
14. **一个控件的「皮」放哪里，只看一条：会不会被第二个组件用**。材质与厚度——凹槽 `.well`、
    印面 `.stamp`、凸起 `.bevel-pill`、文武线 `.frame`、区块标 `.section-mark`、`.track-opt`、
    `.dual-rule`、行标签 `.field-label`、表单行 `.form-row`、小签 `.chip` / `.chip-action`、
    元信息 `.meta`——要能被任意组件复用，所以留在全局表。实测（数 `class`
    属性里出现的 `.vue` 文件）：`.well` 5 个、`.stamp` 4 个，`.meta` 4 个、`.chip` 3 个，
    其余几个各 2 个。只被一个组件用的
    就写组件 scoped：`.slot-btn` / `.slot-text` 在 `SlotButton`，`.map-stage` 在 `MapCanvas`，
    `.kit*` / `.col-head` 在 `AtomsSection`（2026-11-02 从全局搬过去的：全仓只有开发页用）。
    判据不是「通用不通用」：再通用的东西，只要只有一个组件用，就该进 scoped。
    （这条判据有过两个版本。2026-11-02 之前它挂在 `design/income.html` 上——一份不经组件的
    静态样张，**只认类名**，所以「样张裸用过的必须留在全局」；样张删掉后没有裸用点了，判据退回
    「会不会被第二个组件用」。历史代价仍值得记着：样张还在时，B 批给 `.well` 拆类要手工补
    15 处 `.bevel-pill` 与 4 处 `.cost-switch` 的 `well`；印面归一那次要改 5 处选中胶囊与
    8 处开关格子。
    **已知的例外**：`.cost-opt` / `.cost-thumb` / `.cost-switch` 三兄弟只被 `CostSwitch` 一个
    组件用，却是全局的——当年为了让样式表只留一份而升上来（那时还有第二处消费）。按现判据它们
    该进 scoped，但迁移要连同类名一起改，收益低；谁动 `CostSwitch` 再顺手评估。）
15. **尺寸只有一个入口：父级覆写变量，组件不认 prop**。图标是 `--icon-size`
    （默认 `calc(14px * var(--fs-scale))`），槽按钮是 `--slot-h` / `--slot-w`，
    区块标是 `--mark-w` / `--mark-h`，竖槽是 `--vs-*`。全站曾经三种并存：`AppIcon` 用 `size` prop 写
    inline px、`SealMark`（已删）也用过 prop、其余走变量——而 inline px 会顶掉默认值、
    也不跟 `--fs-scale` 一起缩放，「较大」档里字号长了而标题栏三枚图标不长。
    判定一条就够：**这个值要不要跟着字号缩放？** 要，就必须是变量。
16. **轨道里的一格是 `.track-opt`**。两格开关与三档滑块的可点区域逐行相同（定位、圆角、
    字色、行高、过渡），只有内边距差 2px；选中字色由轨道的 `--opt-fg` 给（默认 `--on-seal`，
    灭灯时换 `--ink`）。各写一份 `.cost-opt` / `.size-opt` 的结果是两处 `padding` 各自漂。
17. **区块标题前缀是 `.section-mark`（凸起短竖条），不是印章**。原先每块各挂一枚歪 2.5° 的
    朱红方框，块与块之间就被红点压闷了，而「印章」在账本语境里本来就该留给
    「已入账 / 已达成」这类**状态**。标记是恒定的一竖、不带字：它只交代「一块从这里开始」，
    不参与叙事，也就不需要每块编一个字。材质仍走 `--bevel-*`（左沿受光、右沿落暗、下方落地影），
    与 `.well` / `.stamp` 同一光向——这是它读得出厚度的唯一原因。
18. **「标题 + 并排小字」的行不要用 `align-items: baseline`**。`h2` 自己也是 flex 容器，
    它第一个 item 是那枚**空的**标记；按 Flexbox 规范，没有文字的 flex item 基线取自身底边，
    于是 `h2` 对外报出的基线是「标记底边」，11px 的说明文字被拉到比标题文字低 2.5px，
    整行读起来是「小字掉下去了」。`LedgerSection` 改用 `align-items: flex-end`：底边严格重合
    （7 张卡 × 三档实测全 0.00），`h2` 仍是 19 高。**也不要**把 `h2` 退回 inline 排版来修——
    18px 的标记会把行框撑到 20.6，每张卡高 1.6px。

19. **开发用的页面不进左栏**。`/dev`（`views/dev/DevKitView.vue`）在 `router.ts` 里单独挂一条、
    不进 `NAV_ITEMS`，入口是**三连击左栏牌记**。三条约定：
    ① 栏只发事件（`request-dev`），路由由 `App.vue` 决定——`AppRail` 的注释写着「它不知道路由的
    存在」，别破这条；② 这类页面的 `current` 取不到导航项，外壳要给空串，让 `VerticalSlider`
    的 `hasActive` 收起朱印——`useRovingFocus` 的 `indexOf` 找不到值会返回 0，照它画会把朱印
    停在「总览」上，读起来像「你在总览」；③ 判据是**读者**而不是内容量：用户要动的东西留设置页
    （外观、关于），做界面时要查的东西（组件、色板、字号、图标）进开发页。

20. **一叠卡只剩两张就并排，但断点由内容宽度算，不写 `@media`**。`.stack-pair` 只给 `.stack`
    换轴：`repeat(auto-fit, minmax(420px, 1fr))`。420 是设置页最宽一行（字号 + 三段滑块 + 说明）
    的下限；写死 `1fr 1fr` 再配媒体查询，断点就和内容脱钩了——滑块被压扁、说明掉到第二行
    发生在哪个宽度，没人管得住。并排时两卡的文武线要齐（grid 默认 `stretch`）：短的那张
    下面留白，比两张卡底边错开一截好看；退回一列时每行只有一张卡，`stretch` 自然失效，
    各自按内容高——不需要第二套规则。开发页的卡片列表仍是单列：那四张卡高度差得远，
    并排会拉出两个大洞。

    **同一条也约束卡内的网格**：开发页 `.atoms-kit` 要「五件排成 2 + 2 + 1」，用的是
    `repeat(auto-fit, minmax(480px, 1fr))` 而不是 `repeat(2, 1fr)` + `@media (max-width: 1080px)`。
    原先那对写法把同一件事判断了两次：一次按内容要不要折行，一次按视口猜。
    480 与 `.stack-pair` 的 420 **不是同一个数，也不是同一个理由**：420 是「一行装得下」，
    480 是「演示行不折」。2026-11-02 之前这里写的是「`CostSwitch` 那条说明会断出『件。』
    两个字」——那天开发页的说明文字砍掉一半之后，这条依据跟着失效了，于是重测：
    420 时窗口 1024 排两列、各 442 宽，**槽按钮的 `md` / `lg` 两枚会折成上下两行**，
    而那两枚的用途就是「同一行看出 5.5px 的高度差」。所以 480 保留，依据换成这一条。
    **同的是判断方法（按内容量），不是阈值。**
    五件之后最后一行只剩 `PressTile` 一格、右边空着，**不再为它调列宽**：那格内容是三块并排
    的方块，本来就不满宽；把第四件硬拉成三列会让前四格的说明全部重排，为了一格空白去动
    四格的断行，不划算。

    **工具列表的图标格是唯一两条都特殊的一处**：`repeat(auto-fill, 92px)`。
    空轨道这一层用 `auto-fill` 而不是 `auto-fit`：后者会把空轨道折叠掉、剩下的 `1fr` 长开，
    于是只有一件工具时那一枚被抻成横贯整行的长条，读起来像详情页；`auto-fill` 保留空轨道，
    格子宽度与列数都稳定，加工具时只是往里填、填满一行再往下换行。
    轨道这一层又写死 92px、不给 `1fr`：图标格是「一枚一枚摆上去的」，宽度由 56 的图标块
    决定，拉伸出来的不是格子而是按钮。判断方法仍是「按内容量算」，只是这里的量是
    「一枚图标加一个名字」，不是一个能长出上限的段落。

21. **「按下即选值」与「拖动关过渡」不能同时生效**。竖槽原先把两件事都写在 `pointerdown` 里：
    先置 `dragging`（`.dragging` 把 `transition` 关成 `none`），紧接着 `pick()`——点击是在
    过渡被关掉的那一刻选中的，朱印只能瞬移，点得越准越像没有动画。现在分两条路：
    **纯点击在 `pointerup` 才选值**（那时过渡还开着，印从原位滑过去），指针越过 4px 阈值
    才认作拖动、此后选值跟随指针。阈值不是防抖的花样：它把「手抖 1px 的点击」留在点击那条路上。
    判据不是 CSS 里有没有 `transition`——真点击要能数出中间帧（实测 300ms 内 36 个不同位移、
    40ms 时印正压在相邻两格上），拖动期间 `transitionDuration` 必须是 `0s`。

22. **焦点环全站只有两种：朱环与墨环**。`--ring`（`2px solid --cinnabar`）给纸底上的控件，
    `--ring-inv`（墨 45%）给朱底或紧邻朱色的控件——红底画红环等于没有环；默认偏移
    `--ring-offset`（2px），**唯一的负值是 `VerticalSlider` 的 -2px**（34px 宽的槽上
    向外撑一圈会盖住邻格），那一处单写并注明理由。
    2026-11-02 之前有八处各写一份：颜色四样（朱 / 墨 45% / 墨 55% / 印面 45%）、
    线宽两样（1px **虚线** / 2px 实线）、偏移四样（3 / 2 / 1 / -2）。虚线换成实线是有意的：
    虚线是浏览器的默认手感，而这套语言里所有记号都有厚度，一个由短划组成的环读起来
    像「临时画上去的」。
    焦点环画在**哪个元素**上也有一条：可点的容器里包着一块压印块时，环画在块上
    （跟随块的圆角），不在容器上——`PressButton`、工具页图标格、装备格三处一致。

23. **说明文字只有三档，带框小签只有一枚**。按「读者要不要读它」分，不按字号分：

    | 类      | 用途                 | 规格                                  |
    | ------- | -------------------- | ------------------------------------- |
    | `.note` | 块级说明，要读       | `--fs-xs` + 1.72 行高（`blocks.css`） |
    | `.hint` | 行内提示，扫一眼     | `--fs-sm`                             |
    | `.meta` | 元信息，找的时候才看 | `--fs-mini` + `--muted` + 1.6 行高    |

    `.meta` 不写 `margin`、不写 `letter-spacing`：前者属于父级节奏，后者取决于它旁边站的
    是什么（标签 0.14em、状态 0.04em）。2026-11-02 之前第三档散在**十个地方**各写一份
    （`.field-note` / `.status-meta` / `.detail-tag` / `.head-age` / `.tip-kind` /
    `.tip-foot` / `.gear-meta` / `.char-sub` / `.test-tag` / `.engine-warn`），
    字号颜色都一样，只有 margin 在 5–9px、行高在 1.6–1.72 之间游走。

    小签（门派、技能等级、地图上的「小鬼」、测试样例）统一 `.chip`：`--rule-2` 描边 +
    `--r-1` + `--fs-mini` + `1px 5px`；**可点的另加 `.chip-action`**（`2px 6px` + 悬停洇
    一点朱），内边距大 1px 是为了让指针落在框内任意处都算命中。原先四处各写一份，
    边框圆角字号一个不差，只有内边距在 0/1/2px 之间漂。

24. **卡内页签是 `SteppedSlider` 的 `as="tab"`，不是一排胶囊，最多六格**。
    六个分区页签曾经是六枚 `.bevel-pill` 铺在 `.pill-group` 板上，2026-11-02 换掉：
    六枚并排读作「六个独立开关」，而它们实际是**一条轨道上的六个停靠点**——换页签时
    视线跟着那枚朱印走，比「哪一枚变红了」快。同一个控件（`SteppedSlider`）因此有了两种语义，
    差别只在 ARIA：`as="tab"` + `prefix` 出 `tablist` / `tab` / `aria-selected`，
    以及每格的 `id` 与 `aria-controls`（命名约定 `${prefix}-tab-${值}` / `${prefix}-pane-${值}`）。
    **几何一行没改**——`N 格等分 + 印按格位移` 只在一处实现，分头写就会漏出那个 2px 的百分比基准。

    格宽 = `(卡宽 450 − 两侧外边距 40 − 内边距 4 − 边框 2) / 6 ≈ 67.3`（卡宽 2026-11-02 从 360
    放大到 450，见 `CharactersView` 的 `.roster`；左右外边距由卡根的 `--card-pad-x` 给，
    当天从 14 提到 20）；最长的「召唤兽」三个字在 1.1 字号档
    占 46，余量 21px。**再加第七个就得改文案或改成两行**——这个数是量出来的，
    不是起点，而且它跟着卡宽与 `--card-pad-x` 走：两者一改就要重算，
    CSS 能自适应不代表装得下。

    高度同理不给 prop，走 `--step-pad-y`：默认 3（格子 23、整条 29，行内开关用），
    卡内页签条给 6（格子 29、整条 35）。21px 的格子读作一条分隔线，与下面的账页
    抢不出层级——2026-11-02 用户提「高度有点小」后改的，编辑器的页签条同步，
    同一控件不能一薄一厚。

25. **锚定浮片的落位只有 `useAnchoredTip` 一处**。「贴右侧 → 放不下翻左侧 →
    两边都放不下贴边，纵向再夹回视口」这套规则原本写在 `GearTip` 里，加召唤兽浮片时
    抽成 composable（§2.4-14 的判据：现在就有第二个组件在用）。
    同一时刻最多一张浮片，**宽度统一 240**——一宽一窄会读成两套东西。
    新增浮片复用它，不要再手写一份 `place()`。

26. **表单里的格子是全局 `.field`（凹的），数字格走 `NumberField`**。
    输入格与 `.well` 是同一个光向：底取槽色（`--well`）而不是纸色，加一道内侧上影，
    再加一圈细边——**只用细边的输入框在亮色下读作「贴在纸上的白方块」**（同色底，
    对比只剩 1px 线）。高度 `calc(26px * var(--fs-scale))`，与 `PressButton` 的 `md`
    同一条算式：表单里「加一行 / 删一行」的按钮就挨着输入框，高差 2px 整行就是歪的。
    焦点**不画 `outline`**，改换边色 + 复述内影——外框是方的，会压在 `--r-2` 的圆角上；
    这与按钮的焦点环是两件事（那是「键盘停在这枚按钮上」）。

    数字一律走 `NumberField`：它用 `:value` + `@change`（失焦才写回），不用
    `v-model.number`。后者每敲一个字符就写回父级再渲染回来，光标会跳到末尾，退格删空时
    值立刻变 0、没法清空重输。**「上限」这类可选数字传 `zero-as-empty`**：0 在那一格表示
    「没填」，屏幕上摆一个 0 会被读成「上限就是 0」。

    行是 `.erow`（flex + gap 6 + 相邻行距 5）；**行内的文本格子给固定宽度，不要 `flex: 1`**
    ——一撑满，后面的数字就被推到行尾，中间空出大半行，读起来是「一列空白」而不是
    「一个项目配一个数值」（修炼那 10 行就是这么暴露的）。同一个表单里第一列（技能名 /
    修炼项 / 召唤兽名）**统一 200**，四个分区来回切时起点不会左右跳。

27. **进度条不叫滑块，也不复用 `SteppedSlider`**。`MeterBar` 与它是同一套凹槽语言
    （`.well` 槽 + 一段朱色），但**没有落点、不能拖**——滑块说的是「选了哪一个」，
    进度条说的是「走到了多少」。共用一个外观的代价是用户会去拖它。
    两条硬规矩：① 分母未知时 `percent` 传 `null`，轨道空着且**不写 `aria-valuenow`**
    ——写了就是「确定值 0%」；② 填充**不挂 `.stamp`**，印面那套（外投影 + 9px 受光带）
    是给 23px 以上的块调的，压在 10–14px 的条上只剩一圈毛边。
    ③ 高度只走 `--meter-h`（默认 10，角色卡的经验条给 14），**不加 `size` prop**——
    与 §2.3-15 同一条：尺寸由父级变量给。

28. **空数据上屏只有两种处理，「留一片白」不在其中**。判据是**这个标签自己有没有信息**：

    - 标签本身说明了这一格是什么（属性行的「气血」、装备页的「特技」）→ **保留标签，
      值给一个淡「—」**。整行只剩点线和空档时，「没填」和「值恰好很短」读起来一样。
    - 标签只是个容器（门派 `chip`、整行副题、分区注脚）→ **整块不渲染**。一个空的
      胶囊边框比没有更像「这里坏了」；一行空 `<p>` 会撑出一段说不清来源的留白。

    这条是被新建的空角色卡逼出来的：空白卡上同时出现了「20 行点线配空档」「空胶囊」
    「四行空注脚」三种，一眼看去像渲染失败。改完再截图，空卡才读作「还没填」。

29. **游戏里固定的表，结构写进代码，表单只填值**。「属性」那五组（资源 / 名望 / 战斗 /
    加点 / 潜能）就是这种表：游戏面板上它长什么样是定死的，用户要做的只是照抄数字。
    所以 `ATTR_GROUPS` 决定组名、行与顺序，`normalizeCharacter` 按它**重建**，
    表单里没有加行、删行、改标题。第五组「潜能」（乾元丹 / 潜能果）标了 `wide: true`，
    是唯一占整行的组——见 §30 末。

    判据是**数据是不是游戏给的**：是（属性、修炼项、装备 12 格）→ 结构写进代码；
    不是（技能表、召唤兽名单，一个号练哪几项本来就不一样）→ 结构留给用户编辑。
    两种都做成「可编辑」的代价不是多几个按钮，而是**数据里可能出现一份结构不对的表**，
    而界面照旧按它渲染——用户看得见错，却没处改。

    修炼是第二个实例（2026-11-03）：`TRAINING_GROUPS` 定两组十项与各自的 cap
    （`任务修炼` / `宠物修炼`；育兽术 35，其余 20），编辑器里只剩十个等级格。
    这两个组名是我们改的（游戏面板上叫「角色自身修炼」「召唤兽控制修炼」，又长又不准：
    前者练的是任务、后者练的是宠物），改完名字**照样写进清单**——写进数据就又要
    允许编辑，而它本来不是用户的东西。

30. **属性行是「凸起的纸带」，厚度是缝给的，不是棱给的**。两条色带都凸
    （`--paper-2` / `--paper` 交替），厚度全靠行间那道 2px。贴住时上块的下暗棱
    正好压在下块的上亮棱上，两笔抵消，整页退回一条平色带（2026-11-02 用无缝反例
    验证过）。1px 也不够，两块会粘成「色带 + 一条暗线」；2px 是这套 26px 行高的
    下限，3px 与它差别不大反而更散。

    色带画在 `.paper-row::before` 上，**不画在行自己的背景**：行只管排版，
    伪元素承担色带与四道棱，两件事互不牵连。这套类收在 `base.css`（2026-11-02 从
    `character-card.css` 的 `.ledger > div` 提上来）：编辑弹窗的属性表也用它，
    两处各写一份时棱色与交替色已经开始各漂。**改纸带只改 `base.css` 那一处。**
    **纸带铺满整列**（`inset: 0`），
    不两端内收——内收与「字在带内」不可兼得：文字没跟着收，右端数字的右缘会直接
    露在带外 5px，用户在 1.1 字号档 + 147% 缩放下一眼就是「字全跑出去了」
    （2026-11-02 按截图实测：带 55–306、字 62–313）。要保住内收只能整块内缩，
    那样行、组头、经验行会各自错开。留白改由行的左右内边距 10 承担，而这个 10
    不是凑的：组头是「竖条 4 + gap 6」，带内文字正好落在 97，与组头文字同一条竖线。

    上下内边距仍是 5，**别加**：那一档实测是「每行多 2px × 20 行 = 40」，
    1.1 字号档立刻翻页。属性区底下那句「只记上限，不记当前值」删掉腾出的高度，
    已经由「潜能」组吃掉了（见本节末），现在 1.1 档只剩 13px 余量，**不要**再回填成
    更大的行距或内边距。

    偶数行的带色**不能直接用 `--paper`**——那就是卡片本身的纸色，带子与卡底同色，
    只剩上下两道棱，读起来是「这行没有纸带」、字浮在外面。往 `--paper-2` 里掺一半
    （`color-mix(in srgb, var(--paper-2) 55%, var(--paper))`），两行都看得出带子、
    奇偶又还分得开，且两色都走令牌、暗色下自动跟着翻。

    棱色在两个主题下各一档（`--hi-ridge` / `--lo-ridge`）：暗色下 `--bevel-hi`
    只有 18% 白，上棱看不见，凸起会反过来读成「嵌进纸里的黑框」。

    **字不压浮雕**。早先这里是「上沿一道纯白高光 + 下沿一道 1px 柔化的落影」，
    2026-11-02 用户反馈「不要浮雕了，感觉有点眨眼」——12px 楷体的笔画本来就细，
    上下各贴一道边等于给每一笔描了一圈亮边 + 灰边；纸带本身已经凸了，字再浮一层
    是两层立体打架。现在只留一道 `0 1px 0` 的贴纸影（不到一成黑），暗色直接撤掉
    ——深底浅字加任何影只会把字读成发光。**加回高光前先想清楚：凸起交给纸带，
    字只负责读。** 行间的 2px 缝与左右内边距 10 是这套排版的固定开销：
    加「潜能」组之后（卡 450 × 620）三档字号实测 `char-body` 内容高 493 / 497 / 491，
    均不出滚动，1.1 档余 25px。

    引线（`.leader`）**不画 `border-bottom: dotted`**。1px dotted 在屏幕上被渲染成
    1×1 的**方**点、间隔只有 1px，左端紧贴名目、右端顶着数值——整行读下来就是一串
    被拉长的省略号，底下还留着下划线的错觉（2026-11-02 用户：「中间的省略号感觉
    不是很好看」）。改用 `radial-gradient` 铺**圆点**：直径 1px、每 5px 一颗、
    两端各让 6px、浓度 60%。**那 6px 是关键**——点不贴着字，视线才不会被拽回标签。
    带高必须给 4px（`height: 0` 上画不出背景，原来的写法靠 border 画在盒外），
    默认 `translateY(-2px)` 让点落在基线容器（`.paper-row` / `.row-label`）里文字的
    x-height 中线；写成 `-5` 会顶到 x-height 上沿，比字高半头。

    **非基线容器要单独对位，且按「名字那一行」算，不按行盒中心算**：师门行是
    「名称 16 + 1 + 等级 14」的竖排、`align-items: center`，默认偏移会把点挂在名字
    下面（覆写成 `-5px`）；召唤兽行相反——行盒 93 而名字在 38，居中后点偏高 3.6
    （覆写成 `+2px`）。换行高或字号这三处都要重算，别指望一个 `translateY` 通吃。

    **最后那组「潜能」通栏**（`ATTR_GROUPS` 里 `wide: true`）：乾元丹 / 潜能果只有
    两项，并排一行读作一笔小计；只占左半格时右边空出半行，会被读成「另一项漏填了」。
    规则在 `base.css` 的 `.attr-group.wide`，卡与编辑弹窗共用一份，列距由容器的
    `--pair-gap` 给（卡 26 / 面板 20）。并排之后还要拆掉两件「上下相邻」的约定：
    `+ .paper-row` 的 2px 上缝（会把右边那格往下推 2px，两块纸带底棱错开），以及
    偶数行的浅色（同一行的两格必须同色，否则第二格读成「这格没填」）。

    加这一组的代价是**卡高**：属性页 18 行 → 20 行，1.1 字号档在原 540 高下溢出
    27px（经验条被裁掉半截），`--char-h` 由 540 抬到 580；**2026-11-03 晚属性读数套了淡槽**（`.num-slot`），行高
    28 → 30，1.0 档溢出 6、1.1 档 31，再抬到 **620**——该档余 25、1.0 档约 41。
    **再往属性页加行、或给行内加一层带来内边距的东西之前，先在 1.1 档量**，
    默认档看着还有空不算数。

31. **编辑弹窗的留白给外框，不给内边距**：`--editor-pad-x`（`CharacterEditor.vue`
    的 `.editor` 上，16px），页头、基本信息、页签条、内容区四段全部引它。判据是横向
    四段一起量：实测左缘与右缘都是距面板边缘 17（16 + 1px 边框）。

    **宽度是反算出来的，不是拍的**：内容宽 = 宽 − 2（边框）− 2 × `--editor-pad-x`。
    656 对应 622 的内容区。改宽度或改 `--editor-pad-x` 都要重算这一条，否则属性行
    会跟着一起变宽变窄——而 622 是「数字离标签的断点伸手可及」的那个值。

    这条走过两版，方向是反的，别走回去：第一版是 720 宽的纸 + 内部左右各收 48
    （`.attr-editor` 自己写 `padding: 0 32px`，只有属性页内收、上面三段仍贴 16，
    用户一眼看出错位）；第二版把 32 提到四段共用的变量上，内容宽没变但「弹窗很宽、
    内容挤在中间」，四周留白还不一样（左右 48、上下 14/16）。**第三版才是对的**：
    外框缩到 656、留白回到 16，内容宽度一分没变，四边呼吸一致。
    各段各写一个数必然有一处忘改，与卡上的 `--card-pad-x` 是同一个坑。

    内容区的右内边距要再减一条滚动条轨道：`--editor-pad-x` 减去 `--scrollbar-w`
    （外面套一层 `max(0px, …)`）。`scrollbar-gutter: stable` 把轨道算在**内边距里**，
    不减的话内容区恒比页签条窄 10px——左对齐做完，右端缩一截反而更显眼。
    `base.css` 的页面容器是同一条手法，轨道宽必须引 `--scrollbar-w`，
    与 `::-webkit-scrollbar` 同源，别抄字面值。

32. **多格的固定比例写成 grid 的等分列 + `span`，不用 flex + 一串定宽**。编辑弹窗的基本信息
    是「名字 : 等级 : 门派 = 2 : 1 : 1」与「区服 : 帮派 = 1 : 1」（2026-11-03 用户要求）：
    列写 `repeat(4, 1fr)`（**四**条等分轨道），上排 2 + 1 + 1，下排 2 + 2，都 `span`
    在同一组四等份上。原先 `flex` 里「名字 `flex: 1` + 等级 66 + 门派 120」是
    **在某一档内容宽度下碰巧对**：窄一档名字先缩，宽一档多出来的全给名字，
    2:1:1 只是那一刻的读数。

    **别把 `2fr 1fr 1fr` 当成「四份」**——那是三条轨道，跨两格的项目拿到的是
    「2fr + 1fr」＝整条的 3/4，第三格之后没地方放第四个，自动换行。第一版就这么写的，
    页面上弹出三排（名字 + 等级 / 门派 + 区服 / 帮派），用户截图指出来才看见。
    比例要求 N 份时，轨道数就是 N，跨度用 `span` 拼，不要用不同的 `fr` 去凑。

    配套两条：① 每格内部仍是「标签在左、输入格在右」（与 `.form-row` 同一个姿势），
    输入格给 `flex: 1` 吃掉本格剩余宽度，否则它按浏览器默认宽度走，列宽关系立刻作废；
    ② 格子用 `<label>` 包住，点标签等于点输入格——这个点击面积比输入框本身大得多，
    而表单里没有任何额外代价。

33. **值由别处决定的字段，显示成文字，不要再画一个输入格**。门派技能的名字来自
    `game/data/schools.json`（选了门派就有那七项，见 `schools.ts` 的 `schoolSkills`），
    上限是同一份表里的 `cap`——两者都不该出现在输入框里。
    凹槽的意思是「这里可以写」，写不了却画成可以写，比少一个格子更糟：用户会去试，
    试完发现改不动，就开始怀疑整张表是不是坏了。
    同一条也适用于「只读的编号」「算出来的小计」：**只显示，不上 `.field`**。
    要保住的只有两件事——同一列的起点、同一行的基线，所以 `.name-text` 仍是那 200/一行高，
    只是没有边框与内影。

34. **下拉不用原生 `<select>`，用 `SelectField`**（`components/SelectField.vue`）。
    原生那枚在 Windows / WebView2 上永远是系统外观（自带边框、灰底、字号不跟主题），
    放进这张纸里就像贴错的一块金属片——与「不做 `<input type="range">`」是同一条理由。
    `SelectField` 的三段各有出处：触发条直接用全局 `.field`（与旁边输入格同一个凹槽，
    并排不打架）、纸片用 `--paper` + `--shadow-lift`（与装备 / 召唤兽浮片同一枚影子）、
    当前项用朱字 + 3px 朱色短竖条（与 `.section-mark` 一个说法，不另造一枚勾）。

    两条易错的实现细节，改它之前先读：
    ① **焦点始终留在触发条上**（`aria-activedescendant` 指当前高亮项），列表项不接管焦点——
    否则 Tab 会走进列表、弹窗的焦点环要重新算一遍。
    ② `Esc` 收起列表时**必须 `stopPropagation`**：它常长在弹窗里，而弹窗自己在 `document`
    上听 `Esc`（关整张纸）。不拦的话「关下拉」会把正在填的表单一起关掉——实测过。

    ③ **浮层不许出裁剪容器**。纸片的 `min-width: 168` 是按「别看省略号」定的，而触发条
    在门派那格只有 114，左对齐时右端必然伸出弹窗——`.editor` 是 `overflow: hidden`，
    伸出去的部分被齐刀切掉（边框、影子一起没）。做法是先量最近一个 `overflow != visible`
    的祖先，左对齐放不下就改成**右对齐到触发条**（`shift = rect.width − listWidth`），
    再兜一次左端。实测门派那格：纸片 655–823，弹窗 184–840，留 17。

    ④ **别用 `scrollIntoView` 滚浮层里的列表项**。它的 `inline` 默认是 `nearest`，
    会把**所有**可滚祖先一起滚——包括 `overflow: hidden` 的弹窗（照样能被程序滚动）。
    高亮项正好压在弹窗右边界外时，`.editor` 被横向滚了 14px，左边「名字 / 区服」标签
    与左边那一格「属性」全部被切，看上去像布局被挤坏（用户 2026-11-03 报的就是这个）。
    要滚就只滚列表自己：拿 `offsetTop / offsetHeight` 跟 `scrollTop / clientHeight`
    比，直接写 `scrollTop`。

    ⑤ **纵向也要找位置：下方不够就翻到触发条上方**。③ 只管左右；排在弹窗底部的行
    （辅助技能最后几行）向下只剩二三十像素，8.5 行的纸片被 `overflow: hidden` 切得
    只剩第一项。做法是拿同一个裁剪框算上下两侧的余量，`高度 > 下方 && 上方 > 下方`
    时给纸片挂 `.up`（`top: auto; bottom: calc(100% + 4px)`）。两边都放得下时不翻——
    向下是默认，符合「从控件下面长出来」的预期。

    ⑥ **值来自固定名录的字段，用下拉而不是输入框**（`schools.json` 的门派、
    `skills.json` 的辅助技能名都是这种）。手敲只有三种结果：错字、同音字、表里没有，
    而卡片按名字查图标——错一个字那一格就没图，还不报错。与门派下拉同一条兜底：
    **表外的老数据保留一项**（`XX（不在表里）`），否则下拉显示成「未选择」，
    看着像值被清空了，用户一保存就真没了。

35. **凡是自己滚动的容器，右内边距都要减一条滚动条轨道**（`max(0px, calc(内边距 − var(--scrollbar-w)))`）。
    `scrollbar-gutter: stable` 把轨道常驻在内边距**之外**，内容盒的右缘因此恒比同级的非滚动
    元素缩进 `--scrollbar-w`——左端对上了，右端会短一截。已按这条改过的三处：
    `base.css` 的页面容器、`CharacterEditor` 的 `.editor-body`、角色卡的 `.char-body`
    （2026-11-03 用户截图：「切换页签的条和下面的内容右边没对齐」）。

    判据写在容器上、不写在滚动条上：**滚动条的宽度由 `::-webkit-scrollbar` 决定，
    而 `--scrollbar-w` 是它唯一的源**（`tokens.css` §一），所以内边距里引变量、不抄 10。
    `max(0px, …)` 不能省：内边距收到比轨道还窄时（卡的 20 → 10 就快到了），负值会让
    滚动条压到边框上。

    **滚动容器里不要写 `scrollbar-width` / `scrollbar-color`**。它们是 CSS 的「标准」
    属性，Chromium 121 起一旦出现，该元素就**不再套用全站那套 `::-webkit-scrollbar`**——
    `--scrollbar-w` 的宽度、`--scrollbar-thumb` 的三个状态一起失效，滑块退回系统灰条。
    `SelectField` 的纸片原先写着 `scrollbar-width: thin`，就是这个原因（2026-11-03 用户：
    「下拉框的滚动条没有用我们的优化」）。

    要「更细」不用它：`::-webkit-scrollbar-thumb` 的 `border: 3px solid transparent`
    已经把滑杆收成 4px。要「更清楚」就换**深一档的现成令牌**（`--scrollbar-thumb-hover`），
    别新造颜色——小浮片（168 宽的纸片）里 4px 的浅褐滑杆压在纸色上只有 1.7:1，
    读起来是纸上一道划痕。

36. **游戏事实表进 `public/game/data/`，异步加载只发生在启动那一刻**。门派（21 家 × 7 项 +
    上限）与技能名录现在都是 JSON（`docs/GAME-ASSETS.md` §1 的判据：游戏改版时换文件、
    不改代码）。配套三条，改数据表之前先读：

    ① **一个加载器**。`src/services/game-data.ts` 管类型、形状校验、加载、缓存；加一类实体
    就往它里面加一个 `parse*` 与一个读法，**不要**每类各写一个 `game-*.ts`。
    校验只查形状不查业务——「每家七项」写进校验器，就等于「游戏加了第八项时必须先改代码」，
    正好违反搬出去这件事的初衷；那种断言归测试。

    ② **只在 `main.ts` 里 `await` 一次**，之后全站同步读缓存（`gameData()` / `schoolNames()` /
    `lifeSkills()`）。组件里不许 `fetch`，也不许 `v-if="表还没回来"`：前者让每个页面各有
    一套加载与失败处理，后者把「一次加载」摊成 N 个加载态。副作用是 `schoolSkills()`
    与图标查表仍是同步纯函数，单测不必改成 async。

    ③ **失败退空表**，`loadGameData()` 永不 reject（`main.ts` 因此不用 try）。空表的表现是
    「下拉没有选项、图标查不到」，不是白屏——`GAME-ASSETS.md` §1 第 3 条。

    ④ **需要默认值的地方，从表里取，不写死字符串**。新角色的门派取 `schoolNames()[0]`
    （`roster.ts` 的 `defaultSchool()`），并顺手带出那七项技能——写死「大唐官府」等于把
    游戏事实抄回代码，表一换代码就错。也**不要留一个「未选」的空档**：门派决定技能，
    空值在界面上是个选不回来的状态（下拉里没有这一项），用户只会看到一张空表和一句
    「先选择门派」（2026-11-03 用户要求删掉这个选项）。

    测试怎么喂数据：`src/services/game-data.fixture.ts` 直接模块导入那两个 JSON 并装进缓存，
    测试文件一行副作用导入即可。路径字面量只允许出现在这个 fixture 里。

    与 §29 不冲突：那条讲**表单结构**（哪些行、能不能增删）写进代码，这条讲**数据存在哪**。
    JSON 决定「有哪些门派」，代码决定「门派怎么摆」。

37. **「印 + 名称/刻度 + 数值」的行由 `SkillRow.vue` 一处负责**：卡上只读、弹窗里可编辑，
    是同一行。别在两个组件里各写一套——**2026-11-03 收口的原因就是这个**：

    那份解剖原先分别写在 `character-card.css`（`.school-row` 族）与 `SkillEditor.vue`
    （`.school-erow` 族），约六十条声明逐条对应，很快就分叉了：1.1 字号档下卡上的字印 37、
    弹窗里 43，因为一边按行高算、一边写死 `39px × 字号档`。现在四组几何只有一个来源。

    ```css
    /* SkillRow.vue 里，一次 */
    .school-row {
        display: flex;
        align-items: center; /* 三列同一条中线 */
        gap: 10px;
        padding: 4px 10px;
    }
    .school-seal {
        align-self: center;
        aspect-ratio: 1;
        --tile-h: calc(100% - 8px * var(--fs-scale));
    }
    .school-main {
        display: flex;
        flex: 1;
        flex-direction: column;
        gap: 9px;
        min-width: 0;
    }
    .school-val {
        flex: none;
        --tag-w: calc(56px * var(--fs-scale));
        --tag-h: calc(30px * var(--fs-scale));
    }
    ```

    **行高不由这个组件给**：卡上那七行是容器均分出来的（1.0 档 55、1.1 档 54，字放大反而
    更矮），弹窗里得自己钉住 55。但那一页要用 `height: 55px` 而**不是** `min-height`：
    印的 `--tile-h: calc(100% - …)` 要求行高确定，不定的高度会让百分比解析成 `auto`，
    印直接缩成内容大小（改组件时踩过）。

    五条都是踩出来的：

    ① 两层 flex（`dt` = 名称 + 条，`dd` = 大字）各自按整体居中时，数字正好落在字与条之间的
    缝里，读起来像「120 是那条刻度的标签」（实测差 7px）。
    ② **数值列必须定宽**。用 `auto` 时列宽由最宽那行决定（「满 180」比「120」宽一个字），
    没写「满」的行数字窄、刻度就长一截——七行刻度左端参差，像七把长短不一的尺子
    （2026-11-03 用户：「中间的进度条宽度不一致」）。取 `56 × 字号档`：最宽那行
    「满 180」实测 45（32 + 缝 3 + 「满」10），加左右内边距 8 得 53，留 3px。
    66 那一版是按**右对齐**算的——数字贴右时左边空出一大截，看着像没填满的输入框；
    居中之后留白两边均匀，56 就够（同日用户：「师门最多 180，不用这么宽，数字居中」）。
    几何走 `--tag-*` 而不是 `width`——`NumTag` 自己也有一条 `width: var(--tag-w)`，
    同特异性下不押样式注入顺序。
    ③ **`align-items: center`**，不是 `baseline`。这一页要的是「三列一条中线」（用户：
    「左边图标、右边数字、中间进度条加名称，都居中对齐」）；而且字印撑满行高、刻度贴在
    名称底下，本来就找不到一条共同的基线。
    ④ **字印要撑开就只能用 flex**。grid 的两行轨道加起来只有 34px（名称 18 + 缝 9 + 刻度 7），
    `align-self: stretch` 最多撑到 34，够不着「行高减内边距」的 47。flex 的行高由容器给，
    才拿得到整块，`aspect-ratio: 1` 再由高算宽——七行同高同宽，不写死任何尺寸，字号档一变
    自己跟着。
    ⑤ **但别真的撑满**：撑到 47 时块上下只离纸带 4px，整块读作「塞满一行的一格」（2026-11-03
    用户：「太大了，周围边距太小」）。`--tile-h: calc(100% - 8px * var(--fs-scale))` +
    `align-self: center`：1.0 档 39、1.1 档 37，离带子上下各 8、离左缘 10，三边接近。
    内缩量必须乘 `--fs-scale`，否则 1.1 档那一圈呼吸又缩回去半像素。

    左侧那枚字印是 `PressTile`（`still`；满级 `tone="seal"`），卡上 **39 / 37**、
    编辑页 **39 / 38**（见上条：两页用同一个算式，差的那 1px 是两边行高 54 与 55 之差），
    `--tile-r: var(--r-2)`、`--tile-drop: 0.85`。**两页同一个尺寸**（2026-11-03 用户：
    「同步一下编辑页的技能列表样式和角色卡片保持一致」）：上一版弹窗里是 28 固定、
    理由是「印再大就把名称挤窄了」，实际 39 的印在 644 宽的内容区里仍留得下 477 的刻度。
    再上一版编辑页写死 `39px × 字号档`，1.1 档会长到 43 而卡上收到 37——所以才统一成
    同一个百分比算式。块面给
    **不透明的 `--paper`**：纸带底是
    `--paper-2`，`PressTile` 默认的 92% 半透明叠上去只比带子亮一丁点，亮色下凸起几乎全靠影
    （暗色那边默认就是实色，所以同一个块在两个主题里长得不一样）。0 级的行再把块面退回
    半透明那一档——一整块纸白摆在行首，比「练到 60」那块还亮，读起来像「这一项已经记上了」。

    原来写的是「1px 边框 + 四条 inset 棱」，34px 见方读作贴纸：那圈边框把棱的方向盖掉了
    （2026-11-03 用户：「3D 效果不太好」）。边框在 34px 上是一条平均的线，而压印块靠的是
    **不对称**——上、左各 1px 亮，下 2px 暗，再加 3px 硬影与 8px 软影。

    进度用**分段刻度**（一格 20 级：180 就是九格）而不是连续条：这一页要回答「练到哪了」，
    连续条的答案是长度差、得心算；刻度的答案是数格子，120 就是六格满，一眼数完。
    非整十的等级最后一格按比例填，115 也读得出「五格多」。

    一格 = **凹槽 + 里面嵌一截实心**（2026-11-03）：元素自己是槽（`--well` 底、
    `inset 0 1px 2px` 的顶影、底沿一道亮线、外面 1px 灰描边），填充走 `::before`
    （宽 `var(--fill)`、2px 圆角、纵向渐变 上亮 → 主色 → 下暗，再加 1px 内棱）。
    分两层而不是一条横向渐变：横向渐变只答得出「填了多少」，答不出「嵌进去的一截有厚度」，
    而这一批要的正是后者。

    **填充平时是墨，练满那一行才转朱**（2026-11-03 用户：「颜色有点太扎眼」，选的是
    「退墨 · 满级才朱」）。原先不分状态一律朱：一格只有 7px、九格连成一条、卡上一屏七行，
    63 个红块把「强调」均摊得一点不剩。现在平时是 `--ink-2` 62% 掺 `--paper-2`
    （铅笔填的格，不参与配色），`.full` 那一行整条转朱——朱在这一页只剩「达成」一处。
    **别只用描边区分满级**：普通与满级填充同色时，槽那圈朱描边是唯一信号，七行并排
    几乎读不出来。

    满级态五处同一个意思，都只发生在这一行，不另挂签：填充转朱、槽描边转朱、数转朱、
    字印翻朱面、数字旁写「满」。

    **上限不写出来**（2026-11-03 用户：「180 大家默认都知道」）。卡上与编辑页都不再有
    `/180`：七行全是同一个数，占着位置只是噪音。`cap` 仍在数据里——刻度按它分格、
    点刻度按它算档位、满级按它判定——只是不上屏。上限缺席（老数据）时不画刻度：
    没有分母的格子是编出来的。

    编辑页上同一排刻度是**按钮**（卡上是 `<span>`，同一个组件 `SkillTicks` 按
    `interactive` 换标签）：点第 N 格 = 前 N 格全满那一档，
    所以「点第几格」与「画到第几格」必须共用同一套算术（`character.ts` 的 `tickCount` /
    `tickLevel` / `skillTicks`），各算一次迟早会错位。三条配套：

    ① 条只有 7px 高，热区用 `::after { inset: -5px -1px }` 撑开，**不改条高**——
    改条高就把这一页的行高与卡上对不上了；
    ② 指针停在刻度上时整条先按**点下去的结果**重画（前 N 格亮、其余空），
    否则七像素高的格子指哪一格全靠猜；
    ③ `tabindex="-1"` + 容器的 `aria-hidden`：七行 × 九格 = 63 个 Tab 停靠点会把这张表
    变成键盘走不出去的地方，键盘用户走旁边的数字格。

    ④ **编辑页与卡上是同一个组件**（`SkillRow.vue`，2026-11-03 收口）：印 39、
    名称 + 刻度（列内间距 9）、数值格 56 × 30、行内 `align-items: center` 都只有一份。
    两页的差别只剩「行高谁来定」——卡上由 grid 轨道均分，弹窗写 `height: 55px`。

    为什么编辑页也从 grid 改成 flex：grid 的两行轨道加起来只有 32（名称 16 + 缝 9 +
    刻度 7），39 的印与数字格会顶破轨道；而上一版为了让 26 高的输入框居中，
    还得给 row 1 钉一条 `minmax(26px, auto)` 补丁——**尺寸一改，补丁就废**。
    flex 的行高由容器给，三列按中线对齐，没有第二条规则要跟着改。

    数值格的高 **30，比字印矮 9**（2026-11-03 用户连说两次「再小一点」，39 → 34 → 30）。
    39 与字印等高时，右边那块读作「与字印对称的第二个方块」；34 仍嫌厚；30 才回到
    「一条读数被框住」的比例（字 18.5，上下各 5.75）。再往下收字就贴边——
    要更扁得先收字号。行内上下各留 12.5，不撑行高。

    行高 `55px` **不乘 `--fs-scale`**：卡上那七行是容器均分出来的（1.0 档 55、
    1.1 档 54，字放大反而更矮），编辑页跟着放大到 60.5 会让七行多出 44px——
    1.1 档实测溢出 6px，编辑区多出一条滚动条。字印与数字格自己乘档位，行高只认卡上那个数。

    等级格的数字字号也是 `calc(var(--fs-md) + 3px)` + `--num`，满级转朱——与卡上逐条同值。
    卡上多一个「满」字（它是读数，要把状态写出来），编辑页的朱色只表示「到头了」，
    格子照旧能填。

38. **卡上的读数是「数值墨 + 比名目大一档」**；朱只给强调与满级。属性值、技能等级、
    修炼 `11/20`、经验数一律用 `--num`（= 赭），并且比同一行的名目大 1px
    （师门等级再大一档，它是那一页唯一要读的数）。原先它们与名目同色同号，
    二十行属性读下来是一整片匀质的字（2026-11-03 用户：「数字不用黑色了，稍微放大一点，
    用其他颜色表示」）。

    三层不许混：**墨**（名目 / 说明）→ **赭**（读数）→ **朱**（强调 `dd.strong`、
    满级、`.done`）。数值一律朱的话，这三层压成一层，「伤害 512」与「已满」会一样重。

    **卡上与编辑页的数字一律加粗**（2026-11-03 用户分两步：「角色卡片展示的数字全部
    加粗」→「编辑页面里面的数字也同步加粗」）。霞鹜只装了 400 一个字重，700 由浏览器
    合成：笔画描粗、**字宽不变**，所以那格定宽 52 的淡槽、编辑页 60 宽的输入格都不会
    被顶出去（实测五位仍 41.2，无一处 `scrollWidth` 溢出）。

    两处各一条，作用域不同但同义：
    `character-card.css` 的 `.num` + `:deep(.school-val)` / `:deep(.meter-text)`（读到的数）；
    `CharacterEditor.vue` 的 `.editor :deep(.num)`（填进去的数）。
    **仍然不动全局 `.num`**：它还挂在浮片（`GearTip` / `PetTip`，`Teleport` 到 `body`，
    两条 scoped 规则都够不着）与别处零散的小字上，那些地方跟着粗反而分不出主次。
    浮片要不要一起粗另议——它随指针出现，粗会抢正文。
    **单位跟着粗、词不跟**：「136 级」「11/20」整串加粗（「级」是单位），而
    「参战 65」只粗 `65`——签里的「参战」是个词，整枚加粗会让这一行出现两个同重的块。
    唯一没加粗的是装备摘要里的套装串（`天罡 5/5`）：那是「名字 + 件数」的自由文本，
    拆不开，整串变粗会只强调套装、冷落旁边同级的特技值。

    **刻度的填充平时是墨、满级才朱**（2026-11-03，见 §37 那条：一页 63 个红块太扎眼）。
    它不在这三层里——上面讲的是字，这里讲的是「量」；字仍然只有墨 / 赭 / 朱三层，
    没有第四种。苔自此不再灌任何技能进度，只留给**非技能**的两处：修炼那条进度、
    装备浮片的增益字。

    **没填 / 0 级 / 未学** 退回 `--muted`——
    `0/20` 用数值墨时会和「练了一半的 11/20」同样醒目，而它想说的是「还没开始」。

    **编辑页那排数字格同一个赭**（2026-11-03 用户：「太黑了有点扎眼，用角色卡片的颜色」）。
    `AttrEditor` 的 `.value-field` 原先跟着 `.field` 用墨，可这一页不是空白表单，是**照着
    卡上那张表逐格核对**的：同一行数在卡上赭、在弹窗里墨，对照时像两份不同的记录。
    实测定宽 60 的格子里两个主题都取到同一个值（亮 `rgb(138,90,43)` / 暗
    `rgb(196,154,106)`，即 `--num`）。
    卡上那两行朱色的「气血 / 伤害」（`dd.strong`）**在编辑页不跟**：编辑是把十行数一起填，
    挑两行染朱会让人以为只有它们重要；朱留在卡上表示「读的时候先看这两行」。

    **组头右端不报总数**（2026-11-03 用户：「『已满 1/7』这个也删除，多余的这些全部删除」）。
    原先那里写着「已满 0/7」「12/12」，可这两句读卡的人自己数得出来——七行进度条就在
    下面、十二个装备格也在下面，同一个数说两遍；而组头是全页唯一「说完就走」的位置，
    摆一个随时会变的汇总，反而比标题更抢眼。要表达「都练满了」，让那几行自己转朱（§37），
    不要在上面加一行账。

39. **外来图像进纸面前先过一道「纸化」处理**：`filter: sepia(.42) saturate(.72)
contrast(.95) brightness(1.05)` + 外面盖一层纸色纱（`--assist-veil: 38%`，暗色 18%）。
    游戏图标是深底金纹的方图，剧情那几项还是深蓝底——直接贴上来一块块都是「贴纸」，
    而蓝色根本不在这套墨 / 朱 / 赭里（2026-11-03 用户：「原本游戏图标不很好看，
    加点蒙版遮挡一下，同步主题风格」）。

    两件事缺一不可：**纱只降存在感、不改色相**，冷色仍读作冷色；`sepia` 才把它拉进褐调。
    38% 是临界：34% 时深蓝底还看得出是蓝，44% 起图案边缘开始糊、认不出形状
    （图标仍要能认，它不是纯装饰）。暗色 18%：深色纸已经把图标压住了，同一层纱会糊成墨团。

    `<img>` 是替换元素、长不出伪元素，所以外面套一层壳（`.assist-shot`）放纱。
    同样的处理将来用在门派技能图标、装备图标上，一处参数改所有。

40. **`grid-auto-rows: 1fr` 的轨道不会缩到比内容还小，要写 `minmax(0, 1fr)`**。
    `1fr` 的下限是 min-content：七行加起来比这一页高时，轨道不肯缩，整块溢出（师门页实测
    433 / 422，卡内多出一条滚动）。`minmax(0, 1fr)` 才是「均分剩余空间、可以被压」。

    同一族坑：`flex: 1` 的滚动容器还要配 `min-height: 0`，否则它按内容撑开、永远不滚。

41. **`.paper-row + .paper-row` 的 2px `margin-top` 是「纸叠厚度」，不是「行距」**。
    它让相邻两条纸带之间露一道缝，读作「一叠纸」；要的是每一行各自成行（行距）时，
    在容器上写 `row-gap`，并把这个 `margin-top` 归零——两处一起加会叠成 10px 而不自知。

    先用它的地方是师门页：七行挤满一卡时 2px 几乎看不见，七条连成一片，
    「一行一项」得靠进度条去找（2026-11-03 用户：「门派技能列表上下的间距稍微大一些」）。
    改成 `row-gap: 8px` 后行高从 61 收到 54–55（仍比属性行厚一倍多），内容的单行 19
    两端仍有八九像素余量，1.1 档也不溢出（实测缝 8、行高 54、`scrollHeight == clientHeight`）。

    判据：**厚度与行距是两个意思，别共用一个值**。共用了，改厚度就顺手改了行距。

### 2.5 注释

现有注释质量很高——写的是「为什么」和「踩过什么坑」，不是「这行做什么」。这是最重要的
资产之一，要立成条款：

1. **文件头写「这个文件解决什么问题」**，不写「这是 xx 组件」。
2. **反直觉的写法必须写原因**。例：`AppRail.vue` 里 `min-width: 0` 那条、
   `use-theme.ts` 里单例那条——都是「不写下来下次一定重踩」的类型。
3. **不要写「改了什么」**，那是提交信息的活。
4. **不写废话注释**：`// 定义变量`、`// 循环` 一律不写。
5. **代码里留「契约」，历史留在这里**。「当初试过 A、某次截图指出 B、所以现在写 C」是
   §1 的素材，不是行内注释的素材——`git blame` 与提交信息已经存了一份，行内再抄一遍
   只会把 200 行的组件推到 260 行。行内要留下的是那句「不这么写会怎样」：
   「`--bevel-lo` 恒偏黑，用 `--ink` 会在暗色主题翻成提亮带」是契约；
   「早先这里写的是 `--ink`」不是。
6. 中文注释，句号结尾，不用「注意」「小心」这类空话开头——直接说事实和后果。
7. **模板里的中文文案不要手动断行**。Prettier 会按 `printWidth` 折行，而折行点在 HTML
   里渲染成一个空格——「前端不用改。 字号同理」中间就多了一个空格（实测）。
   要强制断句就用 `<br>` 或拆成多个 `<p>`，不要靠源码里的换行。
   同理：一段文案只有一两句时，宁可让它整行超过 100 字符被 Prettier 折，也不要手动
   在两句话中间敲回车。

### 2.6 文档

`src/` 之外该有几份东西，都不长（旧仓的四份加起来 534 行）。**分工按读者分**，
不按内容类型分——同一句「这个值不许硬编码」，给写界面的人和给开工的人，位置不一样。

| 文件                   | 内容                                                         | 什么时候读       | 状态                     |
| ---------------------- | ------------------------------------------------------------ | ---------------- | ------------------------ |
| `AGENTS.md`            | 本机环境硬约束表、验证方式、红线、明确不做的事               | 每次开工         | ✅                       |
| `docs/ARCHITECTURE.md` | 分层、数据流、IPC 边界、crate 划分、数据兼容红线             | 开工前           | ✅                       |
| `docs/CONVENTIONS.md`  | 工程规范条款（基线 / 命名 / 分层 / 样式 / 注释 / 文档）      | 改代码前         | ✅                       |
| `docs/RECORD.md`       | 全仓审查的原始发现 + 十六个小批的落地记录（含否掉了什么）    | 查「当初为什么」 | ✅                       |
| `docs/GHOST-HUNT.md`   | 捉鬼助手：坐标系、ROI、OCR、时序与假坐标口径                 | 动这块功能前     | ✅                       |
| `docs/UI_GUIDE.md`     | 视觉基座、令牌语义、控件契约（「什么时候用它」）、焦点与键盘 | 写界面前         | 暂缺，约定在 §2.3 / §2.4 |
| `docs/PAGE_GUIDE.md`   | 新增一个页面的固定动作清单 + 反模式                          | 写页面前         | 暂缺，清单在 §2.3-4      |

后两份**没有单独建**，因为现在写它们就是把本文件 §2.3 / §2.4 再抄一遍——同一份规矩两处维护，
改一处忘一处。等业务页真的开始铺（第一个真实列表页落地时），再把「页面动作清单」抽出去，
届时它会有代码可对照，写出来才不是空话。

**决定不建的部分**：`CHANGELOG`（改动原因写在提交正文就够了，另养一份必然漂）、
单独的 `STYLEGUIDE`（视觉约定在 §2.4，令牌真源在 `tokens.css`，第三份没有读者）。

`AGENTS.md` 尤其重要：那些环境坑（5173 占用、WebView2 crashpad 占住数据目录、
`git commit -m` 里不能出现某些词、`start.bat` 必须 GBK+CRLF）原先**只存在于
`.workbuddy/memory/`，而那个目录被 `.gitignore` 排除了**——换台机器、换个会话、
或者别人接手，全部丢失。现在它们都在 `AGENTS.md` 里，这是那份文件存在的主要理由。

一条反向要求：**同理，凡是「只在这一台机器上成立」的东西（MSVC 路径、沙箱限制、
代理、字体安装），不要写进本文件**，写 `AGENTS.md`。本文件描述的是换台机器也该成立的规范。

## 4. 明确不做的事

写下来是为了不再每次重新讨论。

| 事项                    | 决定     | 理由                                                                                                                      |
| ----------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------- |
| husky / lint-staged     | 不装     | 沙箱对带管道的子进程不稳定，钩子易误报。校验放 `npm run check`                                                            |
| 组件单测全覆盖          | 不做     | 组件是视觉件，靠 CDP 截图 + 断言几何来验（已在用）；单测只覆盖纯逻辑与 composable                                         |
| CSS 框架（Tailwind 等） | 不引入   | 账簿语言是手写令牌体系，引入框架会带来第二套命名与优先级                                                                  |
| 状态管理库（现在）      | 暂不引入 | 4 个状态用 composable 够了。**触发条件**：出现「跨三个以上组件的共享业务状态」时再上 Pinia，并把这个决定写进 ARCHITECTURE |
| 大改现有命名            | 不做     | 改名冲掉 git blame，收益低于成本。用「新代码守新规」的方式渐进收敛                                                        |
| 全量令牌化间距          | 不做     | 现有裸值数量多、收益低。新代码遵守，旧代码遇到再换                                                                        |
| CHANGELOG               | 不维护   | 改动原因写在提交正文里，再养一份必然漂移（沿用旧仓判断）                                                                  |

## 5. 一句话总结

**设计语言与工程护栏都已成立，剩下的缺口在领域层。**

视觉与组件的那部分（令牌、四件套、控件契约、注释质量）是这个仓最值钱的东西，
规范的作用是把它固化下来别再退回去。工程的那部分已经补齐：`npm run check` 六项、
CI 三个 job、61 条纯函数测试（`ghost-model` / `ghost-parse` / `ghost-hold`）。
还没被网住的是那 6000 行领域逻辑本身——它现在有解析层的回归用例，但截屏与 OCR
这半段仍然只能靠 `cargo test --lib` 与真机验证。
