# 工程规范

> 只写**现在该怎么写代码**：分层、命名、样式语言、控件契约、验收方式。
> 每一批改了什么、否掉了什么，在 [`RECORD.md`](RECORD.md)。
> 章节号保持原样（§2 / §4 / §5），代码注释里的「CONVENTIONS §2.4-20」这类引用不用改。
> **条款编号不重排、不留空号之外的空缺**：删条款时留号，否则代码里的引用会静默指错。

## 2. 规范条款

### 2.1 工程基线

工具链是旧仓验证过的组合，不需要重新选型。

| 用途      | 依赖                                                                               | 配置要点                                                                                                                      |
| --------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 静态检查  | `eslint` 10 + `@eslint/js` + `eslint-plugin-vue` + `typescript-eslint` + `globals` | flat config；`vue/flat/essential`（**不是** `recommended`，那套带 600+ 条格式化规则）；不开风格类规则（交给 Prettier）        |
| 格式化    | `prettier`                                                                         | `printWidth: 100`、`tabWidth: 4`、`singleQuote: true`、`trailingComma: "all"`、`semi: true`、`vueIndentScriptAndStyle: false` |
| 编辑器    | `.editorconfig`                                                                    | 4 空格、`charset = utf-8`、`end_of_line = crlf`                                                                               |
| Rust 格式 | `rustfmt.toml`                                                                     | `max_width = 100`、`edition = "2021"`                                                                                         |
| Rust 检查 | clippy                                                                             | `cargo clippy -- -D warnings`（`unwrap`/`expect` 由人工把关，不靠 lint 全禁）                                                 |

**脚本约定**（与 `package.json` 一致）：

```json
"format":       "prettier --write .",
"format:check": "prettier --check .",
"lint":         "eslint . --max-warnings 0",
"lint:commits": "git log -20 --no-merges --format=%s | node scripts/check-commits.mjs",
"typecheck":    "vue-tsc --noEmit",
"test":         "vitest run",
"check":        "npm run format:check && npm run lint && npm run typecheck && npm run test && npm run check:version && npm run lint:commits"
```

`npm run check` 是前端唯一入口，CI 的 `web` job 跑的就是这一条——**本机绿 = CI 绿**。
但 CI 还有两个 job 不在里面，别以为跑绿就能推：

| job         | 跑什么                        | 提示                                                                                                                    |
| ----------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `rust`      | `cargo fmt --check`           | 本机要单独跑                                                                                                            |
| `rust-test` | `cargo test --lib`（windows） | 前置 `npm ci && npm run build`：`generate_context!` 按 `frontendDist` 读 `dist/`，目录不在直接 panic，而 `dist/` 不入库 |

- **`--max-warnings 0` 不能去掉**：警告不影响退出码，等于检查只打印不拦人。
- **检查必须接进唯一入口**：`lint:commits` 曾经只是独立脚本，于是它自己红了没人发现。
- **`check` 里没有 Rust**：`clippy` 依赖 MSVC 的 `LIB` 与 `PATH`（见 `AGENTS.md` §三），
  混进来会让「一条命令全绿」在这台机器上不成立。Rust 侧单独跑：

```bash
cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings
```

**版本锁定**：`engines` 只在大版本上拦人，`.nvmrc` 写 `22.22.2`、CI 用
`node-version-file: .nvmrc` 读它，两边才跑同一档。

**行尾由仓库说了算**：`.gitattributes` 声明 `* text=auto eol=crlf`，`.editorconfig` 与它一致。
只给 `*.bat` / `*.cmd` 声明不够——源文件会赖本机的 `core.autocrlf`，那是用户级配置、不随仓库走。
症状不是乱码，是**静默**：改一行而 `git status` 显示整篇 M、`git diff` 却是空的。

```toml
# src-tauri/rust-toolchain.toml
[toolchain]
channel = "stable"
components = ["rustfmt", "clippy"]
```

**大户资源必须可再生**。`assets/fonts/LXGWWenKaiScreen.woff2` 是裁过的（GB2312 全集，1.75MB），
别手改：改覆盖范围就改 `tools/font/subset-font.py` 再跑一遍。同目录的 `.full.woff2`（9.84MB 原件）
**必须留在库里**——没有它就再也裁不出第二版，而游戏更新一批生僻地名时一定得再裁。
`public/game/maps/*.webp` 的切图现场已删，属于「不可再生但已定型」，不要再对成品做二次压缩。

**游戏资源集中在 `public/game/`，不进 `src/`**：`src/` 的资源会被打包器改名加哈希，
而资源清单写的是文件名，改名后必然对不上，失败方式是「某张图静默不显示」。
三层的判据、命名、以及哪些「和游戏有关」的东西故意留在代码里（ROI、窗口标题匹配、形近字组、
句式正则）见 [`GAME-ASSETS.md`](GAME-ASSETS.md)。分界线一句话：**会整体替换的是资源，
偶尔改一个数且必须跑测试的是规则。** 游戏内已有的图**从游戏截图切，不手画、不找素材包**。

**性能改动先量基线，量完再改**。`node tools/probe/startup.mjs --exe <路径> --runs 5`
分三段报数（进程→导航 / 导航→FCP / 导航→字体就位）。三条纪律：

- **同一份 exe 做 A/B**，靠 `--browser-args` 传参而不是改 Rust 重编。
- **取中位不取单次**：同机方差能到 2 倍。
- **报数字要报对是哪一段**：`font-display: swap` 之后字体不阻塞首屏，裁字体提前的是
  「字长对了」那一刻，不是 FCP。把两件事混成「启动快了 300ms」就是假话。

**提交规范**：`<type>(<scope>):<中文摘要>`，**只要一行**。type 白名单
`feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert`。
冒号后不加空格（中文摘要贴着冒号读是一行）；校验器对两种写法都放行（`:\s*\S`），
放宽的只是一个空格，不是格式本身。

**不写正文**：提交信息是 `git log --oneline` 里扫过去的一行。为什么这么做、试过什么错路、
量到哪些数，写进 `RECORD.md` 对应那一批。一行装不下 → 这批改动该拆成两次提交，
而不是该写长正文。真的必须交代的后果（例如「旧数据不再兼容」），写 `RECORD.md` 与 `AGENTS.md`。

`npm run lint:commits` 只看最近 20 条；更早的 45 条是旧仓历史，不追溯、不改写。

### 2.2 命名

三条前缀规则，覆盖 `src/` 全部：

| 前缀 / 形态 | 含义                       | 例子                                                                            |
| ----------- | -------------------------- | ------------------------------------------------------------------------------- |
| `App*`      | 应用外壳的一部分，全局唯一 | `AppRail`、`AppIcon`                                                            |
| 功能名      | 通用控件，名字说明它画什么 | `PageHeader`、`PageShell`、`TitleBar`、`SlotButton`、`PressTile`、`PressButton` |
| 业务名      | 只服务于某一页/某一域      | `MapCanvas`、`LedgerSection`                                                    |

`Base*` 前缀**已停用**：最后一个 `BaseCheck` 随清理删除。新基元直接用功能名，不再新增 `Base*`。
这不是「改名计划」，是「不再往里加」——改名冲掉 git blame，收益低于成本。

其余约定：

- 组件文件 `PascalCase.vue`，一个文件一个组件
- **一个 `.vue` 太大时，先拆「样子」和「纯计算」，不要先拆组件。** 同目录允许放
  `kebab-case.css`（`<style scoped src="./x.css">`：选择器与写在 `.vue` 里逐条等价，含 `:deep()`）
  与纯函数模块（如 `components/ghost/map-paint.ts`：入参进、像素出、不碰 Vue）。
  判据是 §2.3-3——拆完之后每个文件只回答一个问题。拆成子组件是最后一步，它会同时引入
  props 契约与插槽，而多数「太大」只是两件事混在一个文件里。
- composable `use-xxx.ts`，导出 `useXxx`
- 类型 / 接口 `PascalCase`，**不加 `I` 前缀**
- CSS 类名 `kebab-case`，BEM 不强制；**层级靠块前缀**（`.rail-item`）而不是嵌套选择器。
  **类名不要求等于组件名**：`.rail-mark`、`.vs-track` 都是块语义命名。
  找组件靠 grep 模板里的标签名，不靠类名。
- 设计令牌 `--<类别>-<语义>`：`--paper`、`--ink-2`、`--fs-base`、`--r-2`、`--t-quick`

### 2.3 组件分层

```
views/          页面 = 路由目标。只做编排：拉数据、拼区块、处理路由参数
components/     有视觉语义的 UI 单元。不引 @tauri-apps/*，不读路由
composables/    跨组件的状态与副作用。单例状态放模块作用域
services/       系统能力唯一出口，一个能力一个文件。页面与组件都不许绕过它调 invoke
types/          （待建）跨组件共享的类型
```

1. **组件不调 `invoke`**。只有 `services/` 能碰系统（`desktop.ts` 管窗口与「关于」、
   `ghost.ts` 管捉鬼读取通道）。ESLint 的 `no-restricted-imports` 把它变成可检查的约束，
   且必须用 `patterns` 匹配 `@tauri-apps/*` 整族——只写 `paths: ['@tauri-apps/api/core']`
   等于只管一个入口，`@tauri-apps/api/window` 照样溜过。
2. **质感在组件内，布局在父级**。`SlotButton` 只认 `--slot-h`/`--slot-w`，父级用
   `.rail-foot { --slot-h: calc(30px * var(--fs-scale)) }` 传；`VerticalSlider` 同理
   （轨道 34 / 格 62 / 图标 15 / 字 14 五个 `--vs-*`）；图标一律走 `--icon-size`（§2.4-15）。
   原理：父组件 scoped 样式能命中子组件根元素。
   `SlotButton` 的 `seal` 变体是「印面常驻、字压在印上」，用于**主操作**——一屏只该有一枚。
   它变的是「印在不在」，与形态正交，所以不叫 `variant`、不改尺寸。
   `size`（`md` 26 / `lg` 31）是**变量之上的预设**：`lg` 只声明 `--slot-h` 与 `--icon-size`，
   `md` **故意不写规则**——不给它声明，默认高度才轮得到继承父级的 `--slot-h`。
   给 `md` 补一条会把那份继承盖掉，侧栏那格会无声退回 26px。

    **页头动作只用 `md`，不用 `lg`**。`--page-head-h` 不是常数，是
    「padding 19 + 标题行高 + 1」算出来的（1 档 45.3、1.1 档 47.8），而页头是 `min-height`：
    `lg`（31 + 19 = 50）三档字号全超，页头会比左栏牌记高 5px，通栏账线跟着下移、与内容区错开一格。
    要更大的按钮先改令牌——那叫「页头整体变高」，不该由某一页自己长高。

    **按钮有两种材质，按「这块地方的语言」分，不是按心情挑**：

    | 组件          | 材质                                 | 用在哪                                                     |
    | ------------- | ------------------------------------ | ---------------------------------------------------------- |
    | `PressButton` | **凸**：一块压印纸，按下去压回纸里   | 页面里的动作——页头、面板、表单（捉鬼页、角色页已是这一套） |
    | `SlotButton`  | **凹**：按钮本体是槽，悬停落一枚朱印 | 左栏底部那两枚工具、开发页的槽按钮演示、占位页             |

    **朱面不是另一套按钮，是同一块纸换成朱色**：传 `tone="seal"`（`PressTile` 提供）。
    朱面的棱必须自己一套——`PressTile` 的棱是按纸调的，亮色下那条奶白顶线压在朱红上是塑料高光，
    底棱的暖黄棕也对朱红反向。所以 `tone-seal` 换了块面三态、四条棱、内容影，
    `PressButton` 只剩内层字色（`--on-seal`）。
    需要「一块朱红」的地方一律用它，不要再写一份 `box-shadow`：两份配方迟早变成两个朱。
    不可点的块一起传 `still`：悬停变亮、按下回弹是「按我」的承诺，长在点不动的块上是骗人去点。

    **读数有自己的一块凹格：`NumTag`**——纸带上挖出来的一小格，淡槽底（45% 的 `--well`）、
    无边框、数居中，几何走 `--tag-w` / `--tag-h`，内容走默认插槽（所以「满 180」的「满」能单独上朱）。
    与 `PressTile` 正相反：左端字印是凸的印，右端等级是凹的格，一行里一凸一凹。三条约束：

    ① **它是签，不是输入框**：不接受点击、不给悬停与按下态——加深底色是「这里能填」的承诺。
    要能填的地方用 `NumberField`。
    ② **材质在全局 `.num-slot`，不在组件里**：同一副「45% 槽底 + 上沿影 + 下沿亮线」
    只此一份，`NumTag`、两个 input、卡上的属性读数都挂 `class="… num-slot"`。
    **必须用 `background` 简写**，它是「顺手清掉 `.field` 那层顶壁渐变」的那一步；
    改回 `background-color` 会让同一个数在卡上与弹窗里深浅不同。
    **材质与交互分两层**：`.num-slot` 只给静息态，悬停 68% 与聚焦转实槽挂在 `.field.num-slot` 上
    ——只有能填的格子才该有「这里能点」的承诺。
    ③ **字号、颜色不归它管**：等级由调用方给 `--fs-md + 3` 与 `--num`。组件只说「格」，不说「字」。

    两者三形态（只 `text` / `icon`+`text` / 只 `icon`）与两档尺寸逐像素同值，并排时基线齐。
    **同一行不要混用**：一凹一凸并排，读起来是两种器件。两枚都别手写 `<button class="...">`。

3. **一个组件要么管状态，要么管样子，不要两个都管**。`SegmentedPills` 管「选一个」，
   格子的质感交给全局 `.bevel-pill` 类——这是范本。
   **不包一层 `BevelPill` 组件**：那枚胶囊自带 `aria-pressed`，是「独立开关」的语义，
   放进互斥组会与 `aria-checked` 打架；而一组格子还需要 roving tabindex。
4. **新增控件先进开发页的「原子组件」卡**（`views/dev/AtomsSection.vue`），再进业务页。
   那一页（三连击左上角标进入，见 §2.4-19）是这套语言的验收面，不是给用户看的演示页。
   **卡里的 `.note` 只答两件事：怎么用、踩过什么坑**——「当初为什么这么画」属于 `RECORD.md`。
   一段压在两行内（1024 单列 878 宽实测），末行不留孤字。
   **组合件另开一张卡**（如 `views/dev/AssistSlipSection.vue`）：由原子拼成、还带业务语义
   （`level` / `cap` / `off`）的件不塞进原子卡——混进去之后，下一个人想「复用」会以为它只是排版件。
   判据是「它 props 里有没有业务字段」，不是行数。
5. **侧栏不滚动，窗口最小高度由它决定**。`AppRail.vue` 是 `overflow: hidden`——8 档一旦要滚，
   拇指就跑出视口，「第几档」的位置感失效。所以高度交给窗口兜底：`lib.rs` 的 `min_inner_size`
   取「较大」字号（`--fs-scale: 1.1`）时的实测需求（侧栏 736.2 + 标题栏 39.6 → 取 **780**；
   实测 776 仍不滚、772 开始裁底栏）。加高侧栏里的东西必须同步抬这个数。
   想再压低最小高度只能动侧栏自己：格高（`--vs-cell: 62px`）、牌记高度、或底栏那两枚 30px 按钮。

    **「最小高度」不等于「默认档刚好填满」**：按 1.1 档定，默认档必然在槽与底栏之间留一段空白，
    那是留白，由 `.rail-foot` 的 `margin-top: auto` 吸收，底栏永远贴底。
    **栏顶牌记的高度与 `PageHeader` 等值**：两处都取 `--page-head-h`（写的是
    「padding 10 + `--fs-xl` × 1.15 + 9 + 1px 账线」）。**槽顶紧贴这条线**：留 6px 时
    槽顶比右侧横线低半格，接缝处永远差一个台阶。
    **牌记本身不画下边框**：那里是直接落在纸上的应用标，横线会把它切成「头部区块」。
    **标是一块 34px 见方的压印块，宽度与目录槽一致**（都取 `--rail-slot-w`），整条栏读作一列
    而不是「一枚图 + 一条槽」。块是 `PressTile`，与工具页图标格**同一块材质**。
    牌记只给三个变量：`--tile-w`、`--tile-r`（`--r-2`，与槽同心）、`--tile-drop: 0.85`
    （工具页那套按 56px 算，8px 软影落在 34px 下面读作「浮在纸上的小卡片」；但块面与栏底同色，
    凸起几乎全靠这道影，也不能缩到 0.6——那样只剩 1px 宽的一条）。图形占块的 **72%**：
    图自带 3% 透明边，满铺会贴到块的下沿厚度上，82% 仍是「一圈窄边裹着一只字」。

    **不可点的块传 `still`**（角色卡辅助技能那几格）。`still` 只关悬停与按下两态，
    材质一律照旧（棱、落地影、块面），因为它仍然是纸上的一块东西。
    圆角与棱厚**不乘** `--fs-scale`——它们是绝对曲率与绝对厚度，槽那边也没乘。

6. **给开发与验证用的入口，一律挂「开发者模式」（`useDevMode`）**，不在页面上直接摊着。
   开关在开发页第二张卡。判据是**「用户真会用的功能」vs「只在没有游戏、没有数据时才用的替身」**
   ——后者属于这一层。现在只有一个：捉鬼页右下角的「测试文字」面板。
   关着时组件**不渲染**（`v-if`），不是 `v-show`：后者只是 `display: none`，停靠点还在 DOM 里，
   tab 与读屏都摸得到，截图里也会被当成真功能。
   状态落 `localStorage`（`mh-dev-mode`）：它表达「我现在处在这个模式下」，刷新掉回关等于每次都要点一下。
   这与「高概率区域默认开且不记忆」不矛盾——那条的理由是「记住上次会把默认值变成上次」，
   而这里默认值本来就该是关，记忆不会污染它。
7. **页面自己的数据层放 `views/<页>/<名字>.ts`，读进来的对象一律先归一**。
   模块级 `ref` + `useXxx()`，与主题、字号同一套写法（分层里没有「store」这一层，也不要为此引 Pinia）。
   放 `views/` 而不是 `services/`：它不是系统能力（不过 `invoke`），换存储时改的是它自己那两个
   读写函数；而「一个能力一个文件」说的是 Tauri 命令这一层。

    **读时清洗与保存时清洗是同一个函数**（如 `normalizeCharacter`）：它既把旧数据补成合法形状，
    也在点保存时跑一遍。两处各写一套「收尾」，迟早一处记得一处忘。
    兜底原则是**永不抛错、缺什么补什么、坏条目单条丢掉**：它失败的方式很特别，只在重启之后
    才出错，而那时页面已挂载完，一行 `undefined is not iterable` 就是整页白屏。

8. **二次确认只有一个入口：`askConfirm()`**。页面不渲染 `<ConfirmDialog>`、也不自己拼遮罩：

    ```ts
    const ok = await askConfirm({ title: '清空所有角色与物价？', confirmText: '清除' });
    if (!ok) return;
    ```

    - 宿主是 `components/ConfirmHost.vue`，在 `App.vue` 里挂**一次**；状态与 `Promise` 在
      `composables/use-confirm.ts`（模块级单例）。页面拿不到、也不该拿到「这个窗开没开」。
    - **宽度、按钮位置、初始焦点都只有一份实现**：宽度是 `ConfirmDialog` 里的 `WIDTH` 常量，
      焦点固定落在「取消」上。「这处窄一点 / 那处不给取消」不是需求，是把同一个窗拆成两个的开始。
    - **叫 `askConfirm` 而不是 `confirm`**：浏览器全局 `window.confirm()` 返回 `boolean`，
      哪个文件忘了 import，`await confirm(...)` 会静静拿到 `undefined`——恒等于「取消」，
      动作永不执行，一条错都不报。换个名字，忘 import 就是 TS2304。
    - 问句带书名号或引号，`note` 写后果（会连带删掉什么、能不能撤回）。这两句由调用方给，
      因为只有它算得出「下面还有 8 条记录」。

9. **消息提示只有一个入口：`notify`**。做完一件事说一句，不等待、不阻塞：

    ```ts
    notify.success('已删除');
    notify.error(result.error);
    ```

    宿主 `NotifyHost.vue` 挂在 `App.vue` 一次，状态在 `use-notify.ts`；页面拿不到
    「屏幕上现在有几条」。

    - **它是「说」，`askConfirm` 是「问」**：问要等回答、后面那句不许跑；说没有返回值，
      写在动作函数末尾即可。两者混用会把「说一声」变成「多一次点击」。
    - **浮层 vs 行内 `.note` 的判据是「这句话要不要留着看」**，不是「重不重要」：
      带路径、要能复制的回执留在行内；「刚才那下成了没有」才用浮层。两秒就消失的东西
      不该承载要抄下来的信息；反过来，要抄的也不该占着一行版面。
    - 三秒自收、同时最多三条（超了挤掉最早那条）、悬停停表、点一下收走。颜色只在左侧
      竖条与图标上，**文字恒 `--ink`**——整句刷成朱红，13.5px 楷体在米白纸上会发糊。
    - 位置、尺寸、动画都在宿主里，一处可改。别在页面里再写一份 `position: fixed` 的提示。
      落在**嵌入槽**里而不是浮层：浮层要处理点击穿透与超时竞争。

### 2.4 样式

1. **颜色只能来自令牌**。禁止 `#rrggbb`、`rgb()`、颜色名。
   **灌朱的控件一律用 `--seal` / `--seal-edge` / `--on-seal`**，不要直接拿
   `--cinnabar` / `--cinnabar-ink` / `--on-cinnabar` 配面与字：`--cinnabar` 在暗色是亮橙红，
   而 `--on-cinnabar` 同时翻成近黑，深字压亮红会被吃掉。所以暗色的面用 `--cinnabar-ink`、
   字用纸白 `--ink`，两主题统一成「朱底浅字」。分界是**面还是前景**：填充用这一组，
   把朱当字/线/描边用仍取 `--cinnabar`。
   `--paper` **暗色是深纸**，要纸白取 `--ink`。需要**不随主题翻面**的纸白（`color-mix()` 的
   提亮锚点、画在截图上的标记）取 `--paper-base`；需要**恒定的暗**（往深里压的锚点）取
   `--ink-base`——`--ink` 在暗色是纸白，拿它去压会让「背光」变成一条发光的线。
   这两枚是令牌表里唯一允许写绝对色值的地方。
   组件里若仍需暗色覆写，**必须整条写进 `:global()`**：`:global(html.dark .sel)` 编出来是
   `html.dark .sel`，而 `:global(html.dark) .sel` 会被编译成只剩 `html.dark`。
2. **字号只能来自 `--fs-*`**，且每个令牌已经乘过 `--fs-scale`。禁止 `font-size: 14px`。
3. **圆角优先用 `--r-1/2/3/pill`，落不进这四档的就地写 px**。账簿方向基本不用圆角。
   侧栏竖滑块外框、格、印**共用 `--vs-radius`（`--r-2`）**——一处改三处一起变。
   胶囊（`--r-pill`）只留给三档滑块、分段胶囊这类横向控件。
   判据：**这个值会不会被第二个地方用到**。会，就进令牌；不会（曲率由某个具体尺寸决定），
   就地写并加一行注释说明它跟着谁走。为滚动条滑块的 10px、细线的 1px、圆形的 50% 各造一档，
   等于把「一个值一个令牌」摆回来。
4. **间距就地写 px，不做刻度**。`--sp-1…10` 已删：十档只用过 2 档，一套 80% 没人用的刻度
   比没有更糟——它让人以为「选令牌」比写 `gap: 8px` 更正确，而表里的值从没在任何界面上验证过。
   **例外只有「等值契约」**——同一个值被三处以上引用，说明它不是布局现场决定的：
   ① 页面留白 `--page-pad`（16px）：页头左右 = 内容区四边，`.page-head`、`.page-content`、
   捉鬼页的浮动面板都引它；② 区块内边距 `--block-pad`（15/18/18，纸上的主卡）与
   `--block-pad-tight`（11/14/12，卡内小卡与浮层）。四处分写四套差 1–2px，读者感受不到，
   维护时多四个数。
5. **结构靠线，不靠阴影**。分区用文武线 `.frame`；行分隔用 `border-bottom: var(--w-hair) solid var(--rule)`。
   阴影只用于「凸起」的一次性投影。
   **内衬那道细线只有一份定义**：`.frame` 自带，别处要同样的内衬就给元素加 `dual-rule` 类
   （`.char`、`.gear-tip` 这么用），小尺寸容器只覆写 `--dual-inset`。
   全局 `.ledger-lines` 已删（全站零引用）：真要用「格子纸」，那是**某个列表**的私有样式，
   写在该组件的 scoped 里。
6. **动效必须走 `--t-*` + `--ease-*`**，位移类统一带 `--ease-snap`（回弹）。
   时长按**距离**分七档，不按控件分：`--t-quick` 120（颜色、边框）、`--t-mid` 180（淡入淡出）、
   `--t-press` 200（印面内缩）、`--t-shape` 220（宽高形变）、`--t-thumb` 240（滑块走一格）、
   `--t-slide` 300（竖槽整格跳动，62px 一格）、`--t-tip` 90（浮层跟着指针出现）。
   **新写动效先问「它是哪种距离」，再选档，不要新拍一个数。**
7. **`prefers-reduced-motion` 必须有降级**。
8. **令牌只有一个真源**。`src/styles/` 下的三张表是全站唯一来源，全仓没有任何样式表副本。
   以后要做独立设计稿，**引同一份文件，不要复制**——需要「记得两边都改」的东西一定会漂。
9. **选中态只换「朱底」，不改字形**。`font-weight`、`font-size`、`letter-spacing`、
   `-webkit-text-stroke` 在选中与未选中之间**必须完全相同**（现状：竖版滑块、三档滑块、
   分段胶囊三处选中项一律 400 / 同字距 / 0 描边）。
   全站没有任何 `600` / `700`：`base.css` 只有一条 `h1, h2, h3, h4 { 400 }` 的合并规则。
   理由两条：① 文楷本地只有 Regular，`600` 与任何 `text-stroke` 都是浏览器合成，会把撇捺糊成块；
   ② 一枚灌朱、带内高光与投影的印本身已经说清「选中的是它」。
   0.25px 描边尤其要当心——它只把笔画外扩一圈，读到的就是「这格加粗了」，查的时候容易找错地方。
10. **一组「选一个」＝ 一个 Tab 停靠点**。`radiogroup` + `radio` + `aria-checked`；
    只有当前项 `tabindex=0`；方向键换选项并**把焦点带走**，`Home` / `End` 跳首尾。
    四个控件（侧栏竖槽、三档滑块、两格开关、分段胶囊）统一走 `use-roving-focus.ts`。
    组里允许禁用项时用 `isDisabled`，方向键会跨过它而不是卡住。
    导航用 `<nav>` + `aria-current="page"`，**不用** `tablist`：全站没有 tabpanel、也没有
    `aria-controls`，读屏会宣布「标签页 1/8」然后找不到面板。
11. **凹与凸各只有一处定义：`.well` 与 `.stamp`**。凹槽是金边 + `--well` 底 + 上暗下亮渐变
    - 上沿内影与下沿**亮**高光；印面是底色 + 顶边受光 + 上沿高光 + 落地线与朱色投影。
      两者都写在 `base.css`，控件只写几何（宽高、内边距、圆角、排布），不重写厚度。
      竖起来的槽用 `.well.upright`；印面的底色走 `--stamp-bg`，两格开关「灭灯」换的就是这一个变量。
      **受光一律写像素过渡带（`transparent 9px`），不写百分比**：百分比按元素自身高度解析，
      同一串数落在 23px 的胶囊与 62px 的格上会得出两种宽度。
12. **令牌不留零引用**。零引用的令牌直接删，要用时再加。加一档只花一行，留着十档要一直维护假设。
    **这条同样管类和图标**。
13. **展示令牌的页面必须运行时读，不许手抄**。色板与字号阶梯走 `views/dev/tokens.ts` 的
    `declaredTokens` / `colorTokens` / `tokenFontSize`：名字从已加载的样式表里枚举，
    值挂到隐藏探针上让浏览器算（判断颜色用「套成 `background-color` 读回来」，不是
    `CSS.supports`——后者只要值里含 `var()` 就返回 true，会把 `--fs-*` 误判成颜色）。
    **任何「文档页」都不要抄代码里的数字。**
14. **一个控件的「皮」放哪里，只看一条：会不会被第二个组件用**。材质与厚度——`.well`、`.stamp`、
    `.bevel-pill`、`.frame`、`.section-mark`、`.track-opt`、`.dual-rule`、`.field-label`、
    `.form-row`、`.chip`、`.meta`——留在全局表。只被一个组件用的写组件 scoped：
    `.slot-btn` 在 `SlotButton`，`.map-stage` 在 `MapCanvas`，`.kit*` 在 `AtomsSection`。
    判据不是「通用不通用」：再通用的东西，只要只有一个组件用，就该进 scoped。
    **已知的例外**：`.cost-opt` / `.cost-thumb` / `.cost-switch` 只被 `CostSwitch` 用却是全局的
    ——按判据它们该进 scoped，但迁移要连同类名一起改，收益低；谁动 `CostSwitch` 再顺手评估。
15. **尺寸只有一个入口：父级覆写变量，组件不认 prop**。图标是 `--icon-size`
    （默认 `calc(14px * var(--fs-scale))`），槽按钮是 `--slot-h` / `--slot-w`，
    区块标是 `--mark-w` / `--mark-h`，竖槽是 `--vs-*`。
    判定一条就够：**这个值要不要跟着字号缩放？** 要，就必须是变量——inline px 会顶掉默认值、
    也不跟 `--fs-scale` 一起缩放。
16. **轨道里的一格是 `.track-opt`**。两格开关与三档滑块的可点区域逐行相同（定位、圆角、字色、
    行高、过渡），只有内边距差 2px；选中字色由轨道的 `--opt-fg` 给（默认 `--on-seal`，
    灭灯时换 `--ink`）。各写一份的结果是两处 `padding` 各自漂。
17. **区块标题前缀是 `.section-mark`（凸起短竖条），不是印章**。印章在账本语境里留给
    「已入账 / 已达成」这类**状态**。标记是恒定的一竖、不带字：它只交代「一块从这里开始」，
    不参与叙事，也就不需要每块编一个字。材质走 `--bevel-*`，与 `.well` / `.stamp` 同一光向
    ——这是它读得出厚度的唯一原因。
18. **「标题 + 并排小字」的行不要用 `align-items: baseline`**。`h2` 自己也是 flex 容器，
    它第一个 item 是那枚**空的**标记；按规范，没有文字的 flex item 基线取自身底边，
    于是 `h2` 对外报出的基线是「标记底边」，11px 的说明文字被拉低 2.5px。
    用 `align-items: flex-end`：底边严格重合，`h2` 仍是 19 高。
    **也不要**把 `h2` 退回 inline 排版——18px 的标记会把行框撑到 20.6，每张卡高 1.6px。
19. **开发用的页面不进左栏**。`/dev` 在 `router.ts` 里单独挂一条、不进 `NAV_ITEMS`，
    入口是**三连击左栏牌记**。三条约定：① 栏只发事件（`request-dev`），路由由 `App.vue` 决定
    ——`AppRail` 不知道路由的存在；② 这类页面的 `current` 取不到导航项，外壳要给空串，
    让 `VerticalSlider` 的 `hasActive` 收起朱印——`useRovingFocus` 的 `indexOf` 找不到值返回 0，
    照它画会把朱印停在「总览」上；③ 判据是**读者**而不是内容量：用户要动的东西留设置页
    （外观、关于），做界面时要查的东西（组件、色板、字号、图标）进开发页。
20. **一叠卡只剩两三张就并排，但断点由内容宽度算，不写 `@media`**。`.stack-pair` 是
    `repeat(auto-fit, minmax(420px, 1fr))`：既能给整页换轴（`.stack.stack-pair`），
    也能只包住该并排的那两张——规则是同一条，不写第二份。420 是「最宽那一行装得下」的
    下限（设置页是字号 + 三段滑块 + 说明）；写死 `1fr 1fr` 再配媒体查询，断点就和内容脱钩了。
    **同的是判断方法（按内容量），不是阈值**——下面卡内网格也用 420，那只是巧合。
    并排时两卡的文武线要齐（grid 默认 `stretch`）：短的那张下面留白，比两张底边错开一截好看；
    退回一列时 `stretch` 自然失效。

    **高度差得远的卡不并**：开发页只并了色板与字号阶梯（两张都只有几行），组件演示与图标
    仍各占一行——并排会把短的那张拉出大片空白，而空白不是「留白」，是「这格没做完」。

    **同一条也约束卡内的网格**：开发页原子卡用 `repeat(auto-fit, minmax(420px, 1fr))`，
    1024 窗口就能排两列。**每格内部的演示行都要按「两列时也放得下」摆**：420 的格内容区
    约 432，最挤的是输入格那排（130 + 72 + 72 + 两处 gap = 288）。原先槽按钮是四枚一行，
    432 会折——折了就看不出「图标带字 / 纯文字」的形态差，所以拆成两行两枚。
    **不要用 `grid-column: 1 / -1` 让某一格吃满整行**：那会在奇数格处留下半行空洞，
    而空洞读起来是「这格没做完」，不是「留白」。

    **工具列表的图标格是唯一两条都特殊的一处**：`repeat(auto-fill, 92px)`。
    空轨道用 `auto-fill` 而不是 `auto-fit`：后者会把空轨道折叠掉、剩下的 `1fr` 长开，
    只有一件工具时那一枚被抻成横贯整行的长条，读起来像详情页。
    轨道又写死 92px、不给 `1fr`：宽度由 56 的图标块决定，拉伸出来的不是格子而是按钮。

21. **「按下即选值」与「拖动关过渡」不能同时生效**。两件事都写在 `pointerdown` 里时，
    点击是在过渡被关掉的那一刻选中的，朱印只能瞬移，点得越准越像没有动画。分两条路：
    **纯点击在 `pointerup` 才选值**（那时过渡还开着），指针越过 4px 阈值才认作拖动、
    此后选值跟随指针。阈值不是防抖的花样：它把「手抖 1px 的点击」留在点击那条路上。
    判据不是 CSS 里有没有 `transition`——真点击要能数出中间帧，拖动期间
    `transitionDuration` 必须是 `0s`。
22. **焦点环全站只有两种：朱环与墨环**。`--ring`（`2px solid --cinnabar`）给纸底上的控件，
    `--ring-inv`（墨 45%）给朱底或紧邻朱色的控件——红底画红环等于没有环；
    默认偏移 `--ring-offset`（2px），**唯一的负值是 `VerticalSlider` 的 -2px**
    （34px 宽的槽上向外撑一圈会盖住邻格），那一处单写并注明理由。
    一律实线：虚线是浏览器的默认手感，而这张纸上的所有记号都有厚度。
    焦点环画在**哪个元素**上也有一条：可点的容器里包着一块压印块时，环画在块上（跟随块的圆角），
    不在容器上——`PressButton`、工具页图标格、装备格三处一致。
23. **说明文字只有三档，带框小签只有一枚**。按「读者要不要读它」分，不按字号分：

    | 类      | 用途                 | 规格                                  |
    | ------- | -------------------- | ------------------------------------- |
    | `.note` | 块级说明，要读       | `--fs-xs` + 1.72 行高（`blocks.css`） |
    | `.hint` | 行内提示，扫一眼     | `--fs-sm`                             |
    | `.meta` | 元信息，找的时候才看 | `--fs-mini` + `--muted` + 1.6 行高    |

    `.meta` 不写 `margin`、不写 `letter-spacing`：前者属于父级节奏，后者取决于它旁边站的是什么
    （标签 0.14em、状态 0.04em）。
    小签（门派、技能等级、地图上的「小鬼」、测试样例）统一 `.chip`：`--rule-2` 描边 + `--r-1`
    - `--fs-mini` + `1px 5px`；**可点的另加 `.chip-action`**（`2px 6px` + 悬停洇一点朱），
      内边距大 1px 是为了让指针落在框内任意处都算命中。

24. **卡内页签是 `SteppedSlider` 的 `as="tab"`，不是一排胶囊，最多六格**。
    它们是一条轨道上的六个停靠点——换页签时视线跟着那枚朱印走，比「哪一枚变红了」快。
    差别只在 ARIA：`as="tab"` + `prefix` 出 `tablist` / `tab` / `aria-selected`，
    以及每格的 `id` 与 `aria-controls`（`${prefix}-tab-${值}` / `${prefix}-pane-${值}`）。
    **几何一行不改**——`N 格等分 + 印按格位移` 只在一处实现，分头写会漏出那个 2px 的百分比基准。

    格宽 = `(卡宽 450 − 两侧外边距 40 − 内边距 4 − 边框 2) / 6 ≈ 67.3`；最长的「召唤兽」三个字
    在 1.1 档占 46，余量 21px。**再加第七个就得改文案或改成两行**——这个数跟着卡宽与
    `--card-pad-x` 走，两者一改就要重算。
    高度不给 prop，走 `--step-pad-y`：默认 3（格子 23、整条 29，行内开关用），
    卡内页签条给 6（格子 29、整条 35）。21px 的格子读作一条分隔线，与下面的账页抢不出层级。

25. **锚定浮片的落位只有 `useAnchoredTip` 一处**。「贴右侧 → 放不下翻左侧 → 两边都放不下
    贴边，纵向再夹回视口」这套规则不要手写第二份。同一时刻最多一张浮片，**宽度统一 240**
    ——一宽一窄会读成两套东西。
26. **表单里的格子是全局 `.field`（凹的），数字格走 `NumberField`**。
    输入格与 `.well` 是同一个光向：底取槽色（`--well`）而不是纸色，加一道内侧上影，
    再加一圈细边——**只用细边的输入框在亮色下读作「贴在纸上的白方块」**。
    高度 `calc(26px * var(--fs-scale))`，与 `PressButton` 的 `md` 同一条算式：表单里
    「加一行 / 删一行」的按钮就挨着输入框，高差 2px 整行就是歪的。
    焦点**不画 `outline`**，改换边色 + 复述内影——外框是方的，会压在 `--r-2` 的圆角上；
    这与按钮的焦点环是两件事（那是「键盘停在这枚按钮上」）。

    数字一律走 `NumberField`：它用 `:value` + `@change`（失焦才写回），不用 `v-model.number`
    ——后者每敲一个字符就写回父级再渲染回来，光标会跳到末尾，退格删空时值立刻变 0。
    **「上限」这类可选数字传 `zero-as-empty`**：0 在那一格表示「没填」。
    行是 `.erow`（flex + gap 6 + 相邻行距 5）；**行内的文本格子给固定宽度，不要 `flex: 1`**
    ——一撑满，后面的数字就被推到行尾，读起来是「一列空白」而不是「一个项目配一个数值」。
    同一个表单里第一列（技能名 / 召唤兽名）**统一 200**，切分区时起点不会左右跳。
    **修炼是例外**：它左右两列各 303，名字必须 `flex: 1` 吃满剩余宽度——303 里没有 200 的余量。

27. **进度条不叫滑块，也不复用 `SteppedSlider`**。`MeterBar` 与它是同一套凹槽语言，
    但**没有落点、不能拖**——滑块说的是「选了哪一个」，进度条说的是「走到了多少」。
    ① 分母未知时 `percent` 传 `null`，轨道空着且**不写 `aria-valuenow`**——写了就是「确定值 0%」；
    ② 填充**不挂 `.stamp`**：印面那套（外投影 + 9px 受光带）是给 23px 以上的块调的，
    压在 10–14px 的条上只剩一圈毛边；③ 高度只走 `--meter-h`（默认 10，经验条给 14），
    **不加 `size` prop**——与 §15 同一条。
28. **空数据上屏只有两种处理，「留一片白」不在其中**。判据是**这个标签自己有没有信息**：

    - 标签本身说明了这一格是什么（「气血」、「特技」）→ **保留标签，值给一个淡「—」**。
      整行只剩点线和空档时，「没填」和「值恰好很短」读起来一样。
    - 标签只是个容器（门派 `chip`、整行副题、分区注脚）→ **整块不渲染**。一个空的胶囊边框
      比没有更像「这里坏了」；一行空 `<p>` 会撑出一段说不清来源的留白。

29. **游戏里固定的表，结构写进代码，表单只填值**。「属性」那五组（资源 / 名望 / 战斗 /
    加点 / 潜能）就是这种表：游戏面板上长什么样是定死的，用户只需照抄数字。
    所以 `ATTR_GROUPS` 决定组名、行与顺序，`normalizeCharacter` 按它**重建**，表单里没有
    加行、删行、改标题。第五组「潜能」标了 `wide: true`，是唯一占整行的组。
    判据是**数据是不是游戏给的**：是（属性、修炼项、装备格）→ 结构写进代码；
    不是（技能表、召唤兽名单，一个号练哪几项本来就不一样）→ 结构留给用户编辑。
    两种都做成「可编辑」的代价不是多几个按钮，而是**数据里可能出现一份结构不对的表**，
    而界面照旧按它渲染——用户看得见错，却没处改。
    修炼是第二个实例：`TRAINING_GROUPS` 定两组十项。组名是我们改的（游戏里叫「角色自身修炼」
    「召唤兽控制修炼」，又长又不准：前者练的是任务、后者练的是宠物），改完照样写进清单
    ——写进数据就又要允许编辑。
    **上限不在这条里**：它不是游戏常量，而是跟号走（帮派与「修炼上限提升」会把它推高），
    所以清单里的 cap 只是默认值，编辑页可改（见 `RECORD.md` 第 94 批）。
    「结构写进代码」说的是**项名与组**，不是上限。
30. **属性行是「凸起的纸带」，厚度是缝给的，不是棱给的**。两条色带都凸（`--paper-2` / `--paper`
    交替），厚度全靠行间那道 2px。贴住时上块的下暗棱正好压在下块的上亮棱上，两笔抵消，
    整页退回一条平色带。1px 也不够，两块会粘成「色带 + 一条暗线」；2px 是 26px 行高的下限。

    色带画在 `.paper-row::before` 上，**不画在行自己的背景**：行只管排版，伪元素承担色带与
    四道棱。这套类收在 `base.css`（编辑弹窗的属性表也用它），**改纸带只改那一处**。
    **纸带铺满整列**（`inset: 0`），不两端内收——内收与「字在带内」不可兼得：文字没跟着收，
    右端数字的右缘会露在带外 5px。留白改由行的左右内边距 10 承担，而这个 10 不是凑的：
    组头是「竖条 4 + gap 6」，带内文字正好落在 97，与组头文字同一条竖线。
    上下内边距仍是 5，**别加**：每行多 2px × 20 行 = 40，1.1 字号档立刻翻页。

31. **编辑弹窗的留白给外框，不给内边距**：`--editor-pad-x`（16px）挂在 `.editor` 上，
    页头、基本信息、页签条、内容区四段全部引它。判据是横向四段一起量：
    左右缘距面板边缘都是 17（16 + 1px 边框）。

    **宽度是反算的，不是拍的**：内容宽 = 宽 − 2（边框）− 2 × `--editor-pad-x`，
    656 对应 622。改宽度或改这个变量都要重算——622 是「数字离标签伸手可及」的那一档。
    别走回另外两个方向：720 宽 + 只在属性页内收 48（上面三段仍贴 16，一眼看出错位），
    或把 48 提成四段共用（内容宽没变，但「弹窗很宽、内容挤在中间」）。

    内容区右内边距再减一条滚动条轨道（`max(0px, …)`）：`scrollbar-gutter: stable`
    把轨道算在**内边距里**，不减的话内容区恒比页签条窄 10px——左对齐做完，右端缩一截更显眼。

32. **多格的固定比例写成 grid 的等分列 + `span`，不用 flex + 一串定宽**。基本信息的
    「名字 : 等级 : 门派 = 2 : 1 : 1」与「区服 : 帮派 = 1 : 1」写成 `repeat(4, 1fr)`，
    上排 2 + 1 + 1、下排 2 + 2，都 `span` 在同一组四等份上。flex + 定宽是「在某一档内容
    宽度下碰巧对」：窄一档名字先缩，宽一档多出来的全给名字，比例只是那一刻的读数。

    **比例要求 N 份，轨道数就是 N**——写成 `2fr 1fr 1fr` 是三条轨道，跨两格的项目拿到
    整条的 3/4，第四格没处放，自动换行（第一版就这么写的，页面上弹出三排）。
    配套两条：每格内部仍是「标签在左、输入格在右」，输入格给 `flex: 1` 吃掉本格剩余宽度
    （否则按浏览器默认宽度走，列宽关系立刻作废）；格子用 `<label>` 包住，
    点标签等于点输入格，这个点击面积比输入框本身大得多，而表单里没有任何额外代价。

33. **值由别处决定的字段，显示成文字，不要再画一个输入格**。门派技能名来自
    `schools.json`（选了门派就有那七项），上限是同一份表里的 `cap`——两者都不该出现在
    输入框里。**凹槽的意思是「这里可以写」**：写不了却画成可以写，比少一个格子更糟
    ——用户会去试，试完发现改不动，就开始怀疑整张表是不是坏了。
    同一条也管「只读编号」「算出来的小计」：只显示，不上 `.field`。
    要保住的只有两件事——同一列的起点、同一行的基线，所以名字格仍是那 200 宽、一行高，
    只是没有边框与内影。
34. **下拉不用原生 `<select>`，用 `SelectField`**。原生那枚在 WebView2 上永远是系统外观
    （自带边框、灰底、字号不跟主题），放进这张纸里像贴错的一块金属片——与「不做
    `<input type="range">`」是同一条理由。

    三段各有出处：触发条直接用全局 `.field`（与旁边输入格同一个凹槽，并排不打架）、
    纸片 `--paper` + `--shadow-lift`（与浮片同一枚影子）、当前项朱字 + 3px 朱色短竖条
    （与 `.section-mark` 一个说法，不另造一枚勾）。

    六条实现细节，改它之前先读：

    ① **焦点始终留在触发条上**（`aria-activedescendant` 指当前高亮项），列表项不接管焦点
    ——否则 Tab 会走进列表，弹窗的焦点环要重算一遍。
    ② `Esc` 收起列表时**必须 `stopPropagation`**：它常长在弹窗里，而弹窗自己在 `document`
    上听 `Esc`（关整张纸）。不拦的话「关下拉」会把正在填的表单一起关掉。
    ③ **浮层不许出裁剪容器**。纸片 `min-width: 168` 是按「别看省略号」定的，而触发条在
    门派那格只有 114，左对齐时右端必然伸出弹窗；`.editor` 是 `overflow: hidden`，
    伸出去的部分被齐刀切掉（边框、影子一起没）。做法是先量最近一个 `overflow != visible`
    的祖先，左对齐放不下就右对齐到触发条（`shift = rect.width − listWidth`），再兜一次左端。
    ④ **别用 `scrollIntoView` 滚列表项**。它的 `inline` 默认也是 `nearest`，会把**所有**
    可滚祖先一起滚——包括 `overflow: hidden` 的弹窗（照样能被程序滚动），左侧「名字 / 区服」
    标签会整片被切，看上去像布局被挤坏。要滚就只滚列表自己：拿
    `offsetTop / offsetHeight` 比 `scrollTop / clientHeight`，直接写 `scrollTop`。
    ⑤ **纵向也要找位置**：下方不够就翻到触发条上方。排在弹窗底部的行（辅助技能最后几行）
    向下只剩二三十像素，8.5 行的纸片被切得只剩第一项。两侧都放得下时不翻——向下是默认，
    符合「从控件下面长出来」的预期。
    ⑥ **值来自固定名录的字段用下拉而不是输入框**。手敲只有三种结果：错字、同音字、
    表里没有，而卡片按名字查图标——错一个字那一格就没图，还不报错。
    **表外的老数据保留一项**（`XX（不在表里）`），否则下拉显示成「未选择」，
    看着像值被清空，用户一保存就真没了。

    **这一套不共用 `useAnchoredTip`**：那个是给「贴着某个元素、宽度固定 240」的浮片的，
    `SelectField` 要的是「不出裁剪容器 + 纵向翻边」，判据不同（§25 说的是浮片，别混）。

35. **凡是自己滚动的容器，右内边距都要减一条滚动条轨道**
    （`max(0px, calc(内边距 − var(--scrollbar-w)))`）。不减的话，窗内滚起来的一瞬间内容整体左移。
36. **游戏事实表进 `public/game/data/`，异步加载只发生在启动那一刻**。门派（21 家 × 7 项 + cap）、
    生活 / 剧情技能表都由 `src/services/game-data.ts` 一个入口加载：`main.ts` 里
    `await loadGameData()` 之后才 `mount`，之后全站同步读 `gameData()` / `schoolNames()` /
    `schoolSkillCap()` / `lifeSkills()` / `storySkills()`；失败退空表、永不 reject。
    **组件里不许 fetch、不许 `v-if="表没回来"`**——半张表上屏比空表更难查。
    测试用 `services/game-data.fixture.ts` 一行副作用导入喂真文件，路径字面量只许出现在那里。
37. **「印 + 名称/刻度 + 数值」的行由 `SkillRow.vue` 一处负责**：卡上只读、弹窗里可编辑，
    是同一行。别在两个组件里各写一套——两族约六十条声明逐条对应，很快就分叉
    （字印一边 37 一边 43，因为一边按行高算、一边写死 px）。现在四组几何只有一个来源：
    `.school-row`（flex + `gap: 10` + `padding: 4px 10px`）、`.school-seal`（`aspect-ratio: 1`，
    `--tile-h: calc(100% - 8px * var(--fs-scale))`）、`.school-main`（`flex: 1` + 列向 `gap: 9`
    - `min-width: 0`）、`.school-val`（`--tag-w: 56` / `--tag-h: 30`）。

    **行高不由这个组件给**：卡上那七行是容器均分出来的（1.0 档 55、1.1 档 54，字放大反而更矮），
    弹窗里得自己钉住 55。那一页要用 `height: 55px` 而**不是** `min-height`：印的
    `--tile-h: calc(100% - …)` 要求行高确定，不定的高度会让百分比解析成 `auto`，印缩成内容大小。

    五条判据：

    ① 两层 flex（名称 + 条 / 大字）各自按整体居中时，数字正好落在字与条之间的缝里，
    读起来像「120 是那条刻度的标签」（实测差 7px）。所以三列统一 `align-items: center`
    ——这一页要的是「三列一条中线」，而且字印撑满行高、刻度贴在名称底下，本来就找不到共同基线。
    ② **数值列必须定宽**。用 `auto` 时列宽由最宽那行决定（「满 180」比「120」宽一个字），
    没写「满」的行数字窄、刻度就长一截——七行刻度左端参差。取 `56 × 字号档`：最宽那行实测 45
    （32 + 缝 3 + 「满」10），加左右内边距 8 得 53，留 3px。数字**居中**而不是右对齐：右对齐时
    左边空出一大截，看着像没填满的输入框。几何走 `--tag-*` 而不是 `width`——`NumTag` 自己也
    有一条 `width: var(--tag-w)`，同特异性下不押样式注入顺序。
    ③ **字印要撑开就只能用 flex**。grid 的两行轨道加起来只有 34（名称 18 + 缝 9 + 刻度 7），
    `align-self: stretch` 最多撑到 34，够不着「行高减内边距」。flex 的行高由容器给，
    才拿得到整块，`aspect-ratio: 1` 再由高算宽。
    ④ **但别真的撑满**：撑到 47 时块上下只离纸带 4px，读作「塞满一行的一格」。
    `--tile-h: calc(100% - 8px * var(--fs-scale))` + `align-self: center`：1.0 档 39、1.1 档 37。
    内缩量必须乘 `--fs-scale`。
    ⑤ **两页同一个尺寸**：卡上 **39 / 37**、编辑页 **39 / 38**（差的那 1px 是两边行高 54 与 55 之差），
    `--tile-r: var(--r-2)`、`--tile-drop: 0.85`。上一版弹窗写死 28、再上一版写死
    `39px × 字号档`（1.1 档长到 43 而卡上收到 37），都是同一个错误的两种长相。

    块面给**不透明的 `--paper`**：纸带底是 `--paper-2`，`PressTile` 默认的 92% 半透明叠上去
    只比带子亮一丁点，亮色下凸起几乎全靠影（暗色那边默认就是实色，所以同一个块在两主题里
    长得不一样）。0 级的行把块面退回半透明那一档——一整块纸白摆在行首，比「练到 60」那块还亮。

    左侧字印是 `PressTile`（`still`；满级 `tone="seal"`）。**不要给它画边框**：34px 见方上
    1px 边框是一条平均的线，而压印块靠的是**不对称**——上、左各 1px 亮，下 2px 暗，
    再加 3px 硬影与 8px 软影。

    进度用**分段刻度**（一格 20 级，180 就是九格）而不是连续条：这一页要回答「练到哪了」，
    连续条的答案是长度差、得心算；刻度的答案是数格子。非整十的等级最后一格按比例填。
    一格 = **凹槽 + 里面嵌一截实心**：元素自己是槽（`--well` 底、`inset 0 1px 2px` 顶影、
    底沿一道亮线、外面 1px 灰描边），填充走 `::before`（宽 `var(--fill)`、2px 圆角、
    纵向渐变上亮→主色→下暗，加 1px 内棱）。分两层而不是一条横向渐变：横向渐变只答得出
    「填了多少」，答不出「嵌进去的一截有厚度」。
    **填充平时是墨，练满那一行才转朱**：一格只有 7px、九格连成一条、一屏七行，63 个红块会把
    「强调」均摊得一点不剩。平时 `--ink-2` 62% 掺 `--paper-2`（铅笔填的格，不参与配色），
    `.full` 整条转朱——朱在这一页只剩「达成」一处。**别只用描边区分满级**：填充同色时，
    那圈朱描边是唯一信号，七行并排几乎读不出来。
    满级态五处同一个意思，都只发生在这一行，不另挂签：填充转朱、槽描边转朱、数转朱、
    字印翻朱面、数字旁写「满」。
    **上限不写出来**：七行全是同一个数，`/180` 占着位置只是噪音。`cap` 仍在数据里
    ——刻度按它分格、点刻度按它算档位、满级按它判定，只是不上屏。上限缺席（老数据）时不画刻度：
    没有分母的格子是编出来的。

    编辑页上同一排刻度是**按钮**（卡上是 `<span>`，同一个 `SkillTicks` 按 `interactive` 换标签）：
    点第 N 格 = 前 N 格全满那一档，所以「点第几格」与「画到第几格」必须共用同一套算术
    （`character.ts` 的 `tickCount` / `tickLevel` / `skillTicks`）。三条配套：
    ① 条只有 7px 高，热区用 `::after { inset: -5px -1px }` 撑开，**不改条高**；
    ② 指针停在刻度上时整条先按**点下去的结果**重画，否则七像素高的格子指哪一格全靠猜；
    ③ `tabindex="-1"` + 容器的 `aria-hidden`：七行 × 九格 = 63 个 Tab 停靠点会让这张表
    变成键盘走不出去的地方，键盘用户走旁边的数字格。

    数值格的高 **30，比字印矮 9**。与字印等高时右边那块读作「对称的第二个方块」；再往下收字就贴边
    ——要更扁得先收字号。行内上下各留 12.5，不撑行高。
    行高 `55px` **不乘 `--fs-scale`**：卡上那七行是容器均分出来的，编辑页跟着放大到 60.5 会让
    七行多出 44px（1.1 档实测溢出 6px，编辑区多出一条滚动条）。字印与数字格自己乘档位。
    等级格的数字是 `calc(var(--fs-md) + 3px)` + `--num`，满级转朱——与卡上逐条同值。
    卡上多一个「满」字（它是读数，要把状态写出来），编辑页的朱色只表示「到头了」。

38. **卡上的读数是「数值墨 + 比名目大一档」**；朱只给强调与满级。属性值、技能等级、修炼等级、
    经验数一律用 `--num`（＝赭），并且比同一行的名目大 1px（师门等级再大一档，它是那一页
    唯一要读的数）。**修炼的 `/20` 不在内**：那是分母、不是成绩，写 `--muted` + `--fs-mini`。
    三层不许混：**墨**（名目 / 说明）→ **赭**（读数）→ **朱**（强调 `dd.strong`、满级）。
    数值一律朱的话，这三层压成一层，「伤害 512」与「已满」会一样重。

    **卡上与编辑页的数字一律加粗**。文楷只装了 400，700 由浏览器合成：笔画描粗、**字宽不变**，
    所以定宽 52 的淡槽、60 宽的输入格都不会被顶出去（实测五位仍 41.2，无 `scrollWidth` 溢出）。
    两处各一条，作用域不同但同义：`character-card.css` 的 `.num` + `:deep(.school-val)` /
    `:deep(.meter-text)`；`CharacterEditor.vue` 的 `.editor :deep(.num)`。
    **仍然不动全局 `.num`**：它还挂在浮片（`GearTip` / `PetTip`，`Teleport` 到 `body`，
    两条 scoped 规则都够不着）与别处零散小字上，那些地方跟着粗反而分不出主次。
    **单位跟着粗、词不跟**：「136 级」「11/20」整串加粗（「级」是单位），而「参战 65」只粗 `65`
    ——签里的「参战」是个词。唯一没加粗的是装备摘要的套装串（`天罡 5/5`）：那是「名字 + 件数」
    的自由文本，整串变粗会只强调套装、冷落旁边同级的特技值。

    **刻度的填充平时是墨、满级才朱**（见 §37）。它不在这三层里——上面讲字，这里讲「量」；
    字仍然只有墨 / 赭 / 朱三层，没有第四种。苔自此不再灌任何技能进度，只留给**非技能**的两处：
    修炼那条进度、装备浮片的增益字。修炼满级时那条**整条转朱**。
    **没填 / 0 级 / 未学**退回 `--muted`——`0/20` 用赭会和「练了一半的 11/20」同样醒目，
    而它想说的是「还没开始」。

    **编辑页那排数字格同一个赭**：那一页不是空白表单，是**照着卡上那张表逐格核对**的，
    同一行数在卡上赭、在弹窗里墨，对照时像两份不同的记录。
    卡上那两行朱色的「气血 / 伤害」（`dd.strong`）**在编辑页不跟**：编辑是把十行数一起填，
    挑两行染朱会让人以为只有它们重要。

    **组头右端不报总数**：七行进度条就在下面、十二个装备格也在下面，同一个数说两遍；
    而组头是全页唯一「说完就走」的位置，摆一个随时会变的汇总，反而比标题更抢眼。
    要表达「都练满了」，让那几行自己转朱。

39. **外来图像进纸面前先过一道「纸化」处理**：`filter: sepia(.42) saturate(.72) contrast(.95)
brightness(1.05)` + 外面盖一层**压暗**的纱。游戏图标是深底金纹的方图，剧情那几项还是深蓝底
    ——直接贴上来一块块都是「贴纸」，而蓝色根本不在这套墨 / 朱 / 赭里。
    两件事缺一不可：**纱只降存在感、不改色相**，冷色仍读作冷色；`sepia` 才把它拉进褐调。
    **纱是暗的，不是纸色**：纸白压在深底图标上是提亮，图标被洗成一片灰白，读作「褪色照片」。
    亮色 `--veil: 22%` 且色取 `--ink-base`，暗色 `18%` 的 `--paper`：两主题**都是压暗**，
    只是暗色的纸本来就深，深底上再叠墨会把图案糊成墨团。
    22% 是三档对照后取的中间：16% 时金纹仍比纸抢眼，30% 起细节开始糊。要再调只改 `--veil`。
    `<img>` 是替换元素、长不出伪元素，所以外面套一层壳放纱。这一整套（压印块 + 壳 + 滤镜 + 纱）
    收在 `views/characters/AssistIcon.vue`：卡与编辑页用同一枚，23 的图配 28 的块。
40. **`grid-auto-rows: 1fr` 的轨道不会缩到比内容还小，要写 `minmax(0, 1fr)`**。`1fr` 的下限是
    min-content：七行加起来比这一页高时，轨道不肯缩，整块溢出（师门页实测 433 / 422）。
    同一族坑：`flex: 1` 的滚动容器还要配 `min-height: 0`，否则它按内容撑开、永远不滚。
41. **`.paper-row + .paper-row` 的 2px `margin-top` 是「纸叠厚度」，不是「行距」**。
    它让相邻两条纸带之间露一道缝，读作「一叠纸」；要的是每一行各自成行（行距）时，
    在容器上写 `row-gap`，并把这个 `margin-top` 归零——两处一起加会叠成 10px 而不自知。
    判据：**厚度与行距是两个意思，别共用一个值**。共用了，改厚度就顺手改了行距。
42. **辅助技能的一项 = 一张小票：图标 ｜ 名字 ｜ 数值签，两列**。卡与编辑页是同一个器件：
    票面（面、四道棱、4px 圆角、一层落影）与票内三列（名字、签、未学退灰）都在 `base.css` 的
    `.assist-slip` 一族里，**高度由使用方给**——卡 42、编辑页 38（那里要塞 26 高的下拉与数字格）。
    - 为什么起一块面：排成网格而没有底也没有边时，一列名字一列数字紧挨着排九行，读起来是
      一条连续的表线，找不到「这是两个技能」的断点。票面把每一项从纸上择出来。
    - 面用 `--well` 掺 `--paper-2`（34%），不用纯 `--paper-2`：与纸同色时只剩四道棱，
      读作「这一格画得比较淡」；深一档才读作「纸上压着一张东西」。
    - 两列而不是一列：一列 17 项 × 42 = 714，卡上可用只有 493。两列各 **198**
      （450 − 左右各 20 − 滚动条占位 2 = 408，减 gap 12 再对半），生活 4 行、剧情 2 行。
    - 名字 12px、色 `--ink-2`：名目比读数淡一档，与属性页同一层级关系。必须
      `flex: 1; min-width: 0`——flex 项默认 `min-width: auto`，长名字会把签挤出去。
    - 编辑页的列距是 **12**，不是 24：加了票面之后两张票之间已经有一道「面 vs 纸」的边界，
      24 会把 299 的票缩到 287，两组反而离得比卡上还远。票负责分隔，`gap` 只管呼吸。

    **编辑页只放四样：图标 / 名字 / 等级 / 删**。上限卡上早就不写、辅助的上限本就随技能表来；
    已学未学在「逐个录已学」的页面上没意义，没学的直接删行。两个字段留在数据里，
    `cap` 仍参与满级判断、`off` 仍让那一格退灰。
    判据：**编辑页的每一格只放「回去之后还要看的东西」**。只在录入那一瞬有用、之后没有任何
    一屏会读它的字段，不该占半行。

43. **修炼一项 = 一条纸带；卡上上下两组，编辑页左右两列**。
    - 卡上：行 **34** × 行距 8，名目 78 ｜ 条 ｜ 数值签 56 × 22。两组各 225、加组间 16 共 466，
      493 里余 27。裸行 18 高时十行只占 318，底下空 180（36%），整页读作「还没做完的表」。
    - 数值签里**只有等级是读数**：上限写成 `/20` 的淡字（`--muted`、`--fs-mini`）。同色同号会让
      「20/20」读成两个并列的数，而上限只是分母。
    - 条 5px、苔色；**满级整条转朱**，与师门刻度、签里的数同一个意思。别用「苔掺朱」去调和
      ——混出来是一根墨绿的条，读作「这条坏了」而不是「这一项满了」。
    - 编辑页：`grid` 两列（各 303、间距 16），一组一列，行换纸带 **40** 高。卡上 34 是因为
      那一格只读、不必点；编辑页要塞 26 高的数字格，上下各留 7 才按得下去。
    - **两列的代价写在明处**：内容从 364 落到约 256，弹窗（六页签共用 656 × 760 定高）底部
      空出一截。这段空白属于「这一页只有五行」，不属于「还没画完」。
    - `.training-row` 同时带 `.paper-row`（纸带材质）与 `.erow`（表单排布），所以三条覆盖都挂在
      `.training-list` 下（0-2-0）：`.paper-row` 的 `baseline` / `padding: 5px 10px`、
      `.paper-row + .paper-row` 的 2px、`.erow + .erow` 的 5px。**同特异性下不押注入顺序。**

### 2.5 注释

注释是这个仓最重要的资产之一：写「为什么」和「踩过什么坑」，不写「这行做什么」。

1. **文件头写「这个文件解决什么问题」**，不写「这是 xx 组件」。
2. **反直觉的写法必须写原因**（`AppRail.vue` 的 `min-width: 0`、`use-theme.ts` 的单例）。
3. **不要写「改了什么」**——一行提交信息与 `git show` 已经说了，注释只留契约。
4. **不写废话注释**：`// 定义变量`、`// 循环` 一律不写。
5. **代码里留「契约」，历史留在这里**。「当初试过 A、某次截图指出 B、所以现在写 C」是
   `RECORD.md` 的素材，不是行内注释的素材。行内要留下的是那句「不这么写会怎样」：
   「`--bevel-lo` 恒偏黑，用 `--ink` 会在暗色主题翻成提亮带」是契约；「早先这里写的是 `--ink`」不是。
6. **中文注释，句号结尾**，不用「注意」「小心」这类空话开头——直接说事实和后果。
7. **模板里的中文文案不要手动断行**。Prettier 会按 `printWidth` 折行，而折行点在 HTML 里渲染成
   一个空格。要强制断句就用 `<br>` 或拆成多个 `<p>`；一段文案只有一两句时，宁可让它整行超过
   100 字符被折，也不要在两句话中间敲回车。

### 2.6 文档

分工按读者分，不按内容类型分——同一句「这个值不许硬编码」，给写界面的人和给开工的人，
位置不一样。

| 文件                   | 内容                                               | 什么时候读       |
| ---------------------- | -------------------------------------------------- | ---------------- |
| `AGENTS.md`            | 本机环境硬约束、验证分档、启动、红线、明确不做的事 | 每次开工         |
| `docs/ARCHITECTURE.md` | 分层、数据流、IPC 边界、目录归属                   | 开工前           |
| `docs/CONVENTIONS.md`  | 本文件：工程规范条款                               | 改代码前         |
| `docs/RECORD.md`       | 每个阶段改了什么、否掉了什么                       | 查「当初为什么」 |
| `docs/GAME-ASSETS.md`  | 游戏资源的判据、目录、命名、替换流程               | 动资源前         |
| `docs/GHOST-HUNT.md`   | 捉鬼助手：坐标系、ROI、OCR、渲染模式               | 动这块功能前     |

**不建的部分**：`UI_GUIDE.md` / `PAGE_GUIDE.md`（视觉约定在 §2.3 / §2.4，令牌真源在 `tokens.css`，
再写一份就是同一份规矩两处维护，改一处忘一处）、`CHANGELOG`（改动原因按批记在 `RECORD.md`，
另养一份必然漂）、单独的 `STYLEGUIDE`。

**「只在这一台机器上成立」的东西不要写进本文件**（MSVC 路径、沙箱限制、代理、字体安装），
写 `AGENTS.md`。本文件描述的是换台机器也该成立的规范。

## 5. 一句话总结

**设计语言与工程护栏都已成立，剩下的缺口在几个还没写的业务页（总览 / 收益 / 账号 / 目标）。**

规范的作用是把这个仓最值钱的东西（令牌、四件套、控件契约、注释质量）固化下来别再退回去。
工程那部分已补齐：`npm run check` 六项、CI 三个 job；单测覆盖纯逻辑、composable 与页面数据层；
Rust 侧 `cargo test --lib` 网住了 SQLite 那一层（`open_at(base)` 不吃 `AppHandle`，
建表幂等 / 读写往返与排序 / 事务整体回滚三条都对着临时目录测得到）。
仍然只能靠真机验证的是截屏与 OCR 那半段——那部分没有可离线的输入。
