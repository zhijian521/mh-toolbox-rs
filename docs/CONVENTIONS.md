# 工程规范

只维护现行规则。目录与数据流见 [架构](ARCHITECTURE.md)，验证见 [测试](TESTING.md)，本机限制见 [协作约定](../AGENTS.md)。
旧条款的过程、示例与测量值见 [历史快照](archive/conventions-through-2026-11-15.md)。章节及条款编号不重排，删除时留号。

## 2. 规范条款

### 2.1 工程基线

- Vue + TypeScript + Tauri；依赖版本、脚本与工具链以配置文件为准。
- 4 空格、100 列、单引号、分号；风格交给 Prettier，ESLint 只负责代码质量，警告必须处理。
- 行尾由 .gitattributes 与 .editorconfig 管理；批处理的 GBK + CRLF 规则见协作约定。
- 提交信息一行 type:中文摘要，可加 scope，不写正文；原因记录在 RECORD.md。
- 功能变更同步维护相关断言，编写和执行分开。验证默认日常，分区选择见 TESTING.md。
- IPC 契约从 Rust 生成 bindings.ts；两张 collect_commands! 同步登记，不手改生成物。
- 资源入口、来源、许可和再生成流程见 GAME-ASSETS.md 及 assets/fonts/README.md；不按历史注释假定资源仍存在。
- 性能优化先记录基线，用同一产物与同一口径比较，保留原始结果，报告中位数；字体加载与首屏绘制不可相加。

### 2.2 命名

三条前缀规则，覆盖 `src/` 全部：

| 前缀 / 形态 | 含义                       | 例子                                                                            |
| ----------- | -------------------------- | ------------------------------------------------------------------------------- |
| `App*`      | 应用外壳的一部分，全局唯一 | `AppRail`、`AppIcon`                                                            |
| 功能名      | 通用控件，名字说明它画什么 | `PageHeader`、`PageShell`、`TitleBar`、`SlotButton`、`PressTile`、`PressButton` |
| 业务名      | 只服务于某一页/某一域      | `MapCanvas`、`LedgerSection`                                                    |

`Base*` 前缀**已停用**：新基元直接用功能名。这不是「改名计划」，是「不再往里加」——改名冲掉
git blame，收益低于成本。其余约定：

- 组件文件 `PascalCase.vue`，一个文件一个组件
- **一个 `.vue` 太大时，先拆「样子」和「纯计算」，不要先拆组件。** 同目录允许放 `kebab-case.css`
  （`<style scoped src="./x.css">`，含 `:deep()` 逐条等价）与纯函数模块（如 `map-paint.ts`：入参进、
  像素出、不碰 Vue）。判据是 §2.3-3——拆完每个文件只回答一个问题。拆子组件是最后一步，它同时
  引入 props 契约与插槽，而多数「太大」只是两件事混在一个文件里。
- composable `use-xxx.ts`，导出 `useXxx`；类型 / 接口 `PascalCase`，**不加 `I` 前缀**
- CSS 类名 `kebab-case`，BEM 不强制；**层级靠块前缀**（`.rail-item`）而不是嵌套选择器。
  **类名不要求等于组件名**（`.rail-mark`、`.vs-track` 都是块语义），找组件靠 grep 标签名。
- 设计令牌 `--<类别>-<语义>`：`--paper`、`--ink-2`、`--fs-base`、`--r-2`、`--t-quick`

### 2.3 组件分层

1. 组件不调 invoke；系统能力仅通过 services/，限制覆盖 @tauri-apps/* 整族。
2. 质感在组件内，布局在父级；尺寸用 CSS 变量传入。页头使用默认尺寸，主操作使用 seal。
3. 状态与材质分别管理；互斥选择组使用统一组件及键盘导航，不重复包装一层视觉组件。
4. 新通用控件进入开发页展示；组合件单列，业务组件不伪装成原子控件。
5. 侧栏不滚动；改变导航尺寸时同步考虑最大字号与窗口最小高度。
6. 调试替身只在开发者模式渲染；持久化功能的演示数据统一由开发页 demo-data.ts 的 buildDemoData 生成，不新增目标／仓库／交易等独立灌数入口。导入整套替换账本，先确认并自动备份，成功后重载；新增持久化功能同步补入这套数据与契约断言。
7. 页面数据层放 views/<领域>/；读取与保存共用归一函数。缺失值补全，坏条目隔离，读取失败不得覆盖原数据。
8. 二次确认只用 askConfirm()；全局 ConfirmHost 只挂一次，取消为初始焦点。弹窗焦点与 Esc 统一走 useModal。
9. 短时回执只用 notify；需长期查看或复制的信息保留在行内，失败不清空草稿。
10. 速记一格一动作；当前指定角色常驻可见，使用单选；旧多人记录仍按原归属读取，不改写历史。
11. 账号按人民币元、梦幻币万分别汇总；收益与账号是独立账本，自动分账仅从收益流向账号。
12. 目标只存定义与手动流水，养成进度现算角色档案；角色多选使用 ID 快照，已有记录不随意切换单位或类型。保存重试不重复变更。
13. 编辑器与历史弹窗通过 components/lazy-dialog.ts 按需加载，快速完成不展示占位窗，慢请求保留取消与失败重试；占位与正式窗同拍交接遮罩及原触发点，不重复出入场，不在页面另造加载浮层。

### 2.4 样式

1. 颜色来自语义令牌；强调、危险、成功、账本正负数各司其职。填色控件成套使用 seal / seal-edge / on-seal。恒定明暗用 paper-base / ink-base。
2. 字号用 --fs-*；令牌已含字号缩放，不重复乘 --fs-scale。
   字体统一使用 --font-ui；“系统默认”走 system-ui／sans-serif，不强行指定某款系统字体或触发下载。系统字体不标为随包 OFL 子集，主题与字号偏好仍独立。
3. 圆角优先 --r-1/2/3/pill；统计票据与队伍小票共用 --r-ticket；特殊形状就地声明。
4. 间距就地写 px，不增加间距刻度令牌。
5. 内容靠层级区分，避免层层描边；卡片与浮层各用对应公共基座。
6. 动效用 --t-* 与 --ease-*；位移使用 --ease-snap，时长按移动距离选。
7. 支持 prefers-reduced-motion；公共降级规则不得被局部动画绕开。
8. 样式唯一真源在 src/styles/；tokens.css 按固定顺序加载令牌与材质分层，base.css 管元素基座，blocks.css 管组合排版。独立 HTML 方案引用同一入口，不复制样式。
9. 选中态改变底色，不改变字重、字号、字距或内容尺寸。
10. 互斥组选项共用一个 Tab 停靠点，使用 radiogroup / radio / aria-checked 与方向键导航。
11. 凹槽与印面复用 .well / .stamp，不复制第二份材质。
12. 令牌不保留零引用项。
13. 开发页令牌展示读取运行时值，不手抄色板与字号。
14. 只在第二处同语义复用出现时提取公共样式；元素基座进 base，组合排版进 blocks。
15. 控件尺寸由父级覆盖约定变量；图标用 --icon-size，不增加等价尺寸 prop。
16. 轨道选项复用 .track-opt，避免开关与滑块各写一份；SteppedSlider 的 #option 插槽可补金额等摘要，仍共用单选状态、落格和键盘导航，不在插槽内嵌交互控件。
17. 区块标题用 .section-mark；印章保留给业务状态。
18. 标题与并排小字使用 center 对齐，避免 flex 标题的 baseline 造成错位。
19. 开发页不加入 NAV_ITEMS；入口由应用角标与开发者模式控制。
20. 短卡并排由内容宽度决定，复用 .stack-pair；不按设备名称设计断点。
21. 拖动时关闭过渡与点击即选值需分开时序，避免点击滑块失去动画。
22. 焦点环复用 --ring / --ring-inv，不能被控件阴影或 overflow 裁掉。
23. 说明、备注与小签使用既有 note / muted / tag 语义，不增设同义组件。
24. 卡内页签使用 SteppedSlider 的 tab 模式；保持分区语义、焦点与方向键行为。
25. 锚定浮层落位统一由 useAnchoredTip 管理，包含翻向、贴边与视口约束。
26. 表单控件用 .field，数字用 NumberField；横向行用 .form-row，垂直字段用 .form-field，双列组用 .form-pair。需要即时保存条件时启用 update-on-input，空数值不添加占位提示。
27. 进度使用专用进度组件，不把 SteppedSlider 当进度条。
28. 空态区分未配置与读数为零；使用既有空态提示或禁用样式，不留下无意义白框。
29. 游戏固定属性与技能结构由规则定义，表单只填值；不增加无效的新增、删除或上限输入。
30. 属性票复用 .slip-row 的棱、影与圆角，不另画分隔缝。
31. 编辑弹窗沿用 ModalShell 留白，分区内部负责滚动；尺寸从公共定义读取，滚动条出现时不改变布局宽度。
32. 多格固定比例用 grid 等分列与 span，避免一串定宽挤压。
33. 派生字段展示为文字，不伪装成可编辑输入。
34. 下拉使用 SelectField，保留旧值及键盘导航，不使用原生 select。
35. 内部滚动区域为滚动条预留空间，避免右侧控件被遮挡；不吞掉外层页面滚轮。
36. 游戏事实表进 public/game/data/，启动时集中加载；解析算法和展示策略留代码。
37. 属性、技能与修炼复用 .slip-row；尺寸按现有档位，名称和数值对齐。
38. 读数使用数值墨；强调和满级才使用强调色，不整片刷色。
39. 外来图像只做一层主题适配，不盖遮挡原图的蒙版。
40. 可收缩的等分网格使用 minmax(0, 1fr)，避免内容最小宽高撑开容器。
41. 行距由容器 gap 管理，不让行自带相互叠加的 margin。
42. 辅助技能编辑只保留图标、名称、等级和删除；新增入口统一为图标加“新增”。
43. 修炼按人物、召唤兽分组，保持对齐；固定项不能删除，等级默认为 0，上限取规则。
44. 门派色仅通过 .character-theme 的变量映射影响角色卡及编辑器，不染原图或复制一套主题。
45. scoped 类名不复用 .stack / .stack-pair / .note / .kit 等全局组合类来表达其他含义。
46. 日期使用 DateField，不使用系统原生日历。
47. 内容卡使用 PaperCard 与 .board；纯色纸面显式传 plain，LedgerSection 透传同一选项，保留公共圆角、棱与阴影。不要在页面用后代选择器覆盖所有 .board；.frame 限浮层，不在卡内叠套文武线框。
48. PressButton 复用 PressTile 材质；大面积使用 wide，主题差异在令牌层维护，不在业务页补渐变。
49. 补记、记录、单价导入导出、首页常用功能自定义等低频辅助操作使用 TextButton，默认无底板、描边或阴影，悬停提示可点击，保留焦点、禁用及完整说明；可选图标，默认 26px 高随字号缩放，局部等高通过 --text-button-h 控制。主操作继续使用 PressButton，不批量迁移无关入口。
50. 弹窗开关统一经 ModalShell／useModalMotion：遮罩轻度虚化背景并与面板分别淡显，面板仅短距离位移，标题／正文／底部操作小间隔淡入；正文不另加位移，不缩放文字，不推迟业务关闭事件。嵌套只进入面板，同拍换窗承接原遮罩，避免背景先亮后暗，加载交接不重复分层入场。时长、间隔、虚化强度和曲线由 token-core.css 的 modal 令牌统一维护。父级卸载时保留真实面板至退场结束，期间面板 inert、遮罩挡点击、背景保持锁滚动，结束后释放栈和恢复焦点。Web Animations 显式响应降动效且取消分层延迟；入场期间不叠加高度动画，后续内容变动合并到下一帧，关闭中断时保留当前高度及分层透明度。初始及返回焦点不带动页面滚动。
51. 液态玻璃支线的滚动容器统一常驻轨道：`src/components/liquid-glass/style.css` 对 `.liquid-app` 全后代与 `glass-sheet::part(body)` 设 `scrollbar-width: thin` + `scrollbar-gutter: stable`。页面大量使用 `auto-fill` / `auto-fit` 网格，滚动条出现／消失会改变内容盒宽度（约 8px），在临界点整排换列、高度又变回去，形成可见抖动（2026-11-22 物价页）。新增页面、弹窗、列表不要另写 gutter，也不要用已废弃的 `overflow: overlay`；刻意隐藏滚动条的容器统一走第 54 条的 `.lg-scroll-hidden`（`.chart-scroll` 是等价的既有写法），否则白留一条轨道。正式版 `base.css` / `blocks.css` 的 `scrollbar-gutter: stable` 与角色卡隐藏滑块是同一问题的两种取向，写需求时先定「要不要看见滑块」。
52. 玻璃弹窗内的 `GlassButton` 不得叠材质文字阴影：引擎按材质把 `--gl-text-shadow` 写到 host 上（`engine/surface.js:247`），`clear` 材质为「白字压亮背景」配了三层黑色柔光阴影（`engine/materials.js:62/75`）；库的 `:host` 用 `text-shadow: var(--glass-text-shadow, var(--gl-text-shadow, none))`，而项目把按钮文字改成深墨后，这层暗影叠在半透明面板上就把小字糊成一团，`variant="plain"` 连底色都关掉、最明显。`glass-button.lg-component` 已在公共样式统一设 `--glass-text-shadow: none`；弹窗容器再给 `--glass-foreground: var(--liquid-ink)`、`--glass-accent-text: var(--liquid-ink)` 与 `letter-spacing: normal`（备份、壁纸、确认、价格编辑器同一口径）。分页沿用物价历史弹窗的 `lg-inline-action` + `shape="circle"` 纯图标按钮配 `aria-label`，不要退回文字按钮。
53. 备份保留只有一个口径：`backup.rs` 的 `BACKUP_KEEP = 5`，日常备份与「替换前」备份**合计**按时间从新到旧留 5 份，不再按类型分设上限；`listed_backups` 同时供 `backups_list` 与 `backup_restore` 使用，保证「列得出来」＝「能恢复」。`prune_backups` 只认两个自动备份前缀，排除符号链接、旧版原件与 `.db` 原库快照，用户手工放进 `backups/` 的文件不动；清理尽力而为，删不掉旧文件不让导入失败，也不报成自动备份失败。调整份数时同步 README、RELEASE、ARCHITECTURE、两版设置页与恢复弹窗文案、`backup/tests.rs`；写需求时不要把「列表显示条数」和「磁盘保留份数」当成两件事。
54. 液态玻璃页面主滚动区**隐藏滚动条但保留滚动**：统一挂 `.lg-scroll-hidden`（`src/components/liquid-glass/style.css`），由这个类一次性给出三条声明，缺一不可——`scrollbar-width: none` 关掉原生条、`scrollbar-gutter: auto` 撤掉第 51 条铺的常驻轨道（否则右侧白留 8px）、`::-webkit-scrollbar { display: none }` 兜住旧 Blink／WebKit；选择器用普通类以压过 `:where(...)` 的零特异性。**不许用 `overflow: hidden`**：那会把滚动能力一起关掉，内容就真看不到了；也不要用废弃的 `overflow: overlay`。只挂页面主滚动容器：物价页是 `LiquidApp.vue` 的 `.liquid-content`（按 `route.name` 判断），组件目录是 `.gallery`；内部独立滚动区（弹窗表格、组件演示的小样例）不挂，仍走第 51 条的 thin + stable，读得出「这里还有东西」。后续新增页面直接挂类，不另写一套隐藏规则。滚轮、触控板、键盘与拖动照常可用，隐藏的只是那根条。另：`overflow: hidden` **也是滚动容器**，裁剪型卡片（壁纸缩略图）同样要显式写 `scrollbar-gutter: auto`，否则右侧白留一条 10px 轨道（170px 的卡片内容只剩 158px，缩略图铺不满）。
55. 液态玻璃表单**只有两档尺寸**：默认 44px（`.liquid-app` 的 `--glass-search-height`）与「小一号」32px（`.lg-form-fields`，取 `--lg-form-height`）。筛选行、录入弹窗一律挂这个公共类（物价页 `.price-filters`、编辑器 `.price-editor-fields`、组件目录的输入／日期样例），**不许在页面里再写 `--glass-*-height: 30px` 之类的第三档**。这个类一次性给全 `--glass-search-height` / `--glass-select-height` / `--glass-input-height`，并等比收小搜索框的放大镜（19→16px）与清除按钮（30→24px）——漏掉第一条就会同排控件高度不齐，漏掉零件缩放则 32px 胶囊里塞着按 44px 画的图标。库只在 `glass-button` 上提供 `size="small"`（32/44/52px），`glass-search` 与自封装的 `GlassSelect` **没有 size 属性**，缩小它们只能经这个类。组件目录刻意同时陈列两档，改公共类时一起核对。

56. 玻璃下拉菜单的面板宽度**按内容自适应**：`glassy-liquid` 在 `open()` 里给 `::part(content)` 内联写入 `minWidth: 220px` 与 `width: max-content`，于是只有「全部分类」四个字的菜单也被撑成 220px。项目统一用 `.lg-select-menu::part(content)`（`GlassSelect`）与 `.lg-popup-menu-small::part(content)`（三点菜单）把下限压到 132px，**必须带 `!important`** 才盖得过内联样式；宽度本身仍交给 max-content，长选项自然撑开，上限保留库内联的 `min(320px, 100vw - 16px)`。触发器更宽时覆盖 `--lg-select-menu-min`（录入弹窗两列网格设 190px），**不要从外部写 `width`**：库量完 `offsetWidth` 会把面板宽写成像素值，外部再插一条 width 只会和开场动画的尺寸打架。

57. **不许给 `<glass-sheet>` 传名为 `shadow` 的 prop／attr**：库把 ShadowRoot 存在实例字段 `this.shadow`（`dist/components/sheet.js:116`），而 Vue 对自定义元素会把「元素上已存在的同名属性」直接写成 DOM property（`'shadow' in el` → `el.shadow = value`）。`themed()` 的材质循环曾把预设里缺省的 `shadow: undefined` 一起透传，ShadowRoot 被覆盖成 undefined，`connectedCallback` 调 `adoptStyles(this.shadow)` 抛 `adoptedStyleSheets of undefined`，面板停在 **0×0**，所有走 sheet 的弹窗（物价历史等）看得见 DOM 却打不开。修法在 `src/components/liquid-glass/index.ts`：`target === 'sheet'` 跳过 `shadow`，并且**任何 undefined 的材质键都不传**；面板阴影由 `updateMaterial('sheet')` 经 `part(sheet).set` 设置。给玻璃自定义元素加材质字段前，先确认它没占用库的实例字段名。

#### 总览作为后续页面的参考

设置页沿用四区按内容换列，外观与数据的标签／控件／说明统一使用领域内 SettingsRow；控件按可用宽度换行，不改变字号或另画材质。清除独立分区，必须保留不可撤销、不会自动备份的说明。关于页优先展示版本、数据位置和字体，标识与运行环境可折叠；低频许可链接使用 TextButton。

隐藏开发帮助按组件预览／设计令牌／图标目录／调试数据分组，普通导航不增加入口。纯内存演示与写入当前账本的工具分开；切组保留演示状态，不执行导入。令牌与图标从各自真源读取，展示说明不写死数量。

沿用展示层级与交互契约，业务计算和页面布局仍由所属领域决定，不要求各页复制总览版式。

完整柱状图的系列色统一经 chartColor 浅染后混入透明色，基础不透明度为 65%；柱体、图例和悬停色标共用，3D 棱面继续从该颜色派生。不要给整个图表或柱体容器叠 opacity，以免连带降低数字、刻度和标签清晰度。

在线角色键按内容自适应宽度，最大不超角色区，所有排数沿用相同的常规最小高度，不按便签高度测量拉伸；长名在窄区允许自然换行。已无业务使用的材质变体连同演示和主题特判一起移除，不为保留历史方案而维护空 API。

同一领域出现两处真实相同展示时，可在领域目录封装组合件。总览的 ShortcutFace 组合公共 PaperTag、图标、名称与分类颜色，尾部操作走插槽；排序注册、点击与存储不放进展示组件。公共 PaperTag 也承载账号快捷记账内容：纸面与底纸分别镂空，孔壁及深浅双棱的断续压痕只作装饰，语义容器和焦点不参与裁剪。跨领域只共享外壳与材质，不共享业务字段、点击或金额计算。

账号快捷记账按可用宽度自然收列，不限制总列数或行数，单卡保留合理宽度上限。最近记录由 AccountRecentRecords 负责展示和回传原记录，页面负责筛选、截取有限条最近记录、编辑与保存；通过条数和内部滚动上限控制高度，避免把并排图表拉出大块底部空白。分类与角色／渠道分层，金额固定在右侧，全文保留在悬停和可访问名称。业务组合不登记为开发页原子组件，也不为样式相近而合并总览队伍记录与收益速记。

读取中、读取失败、未配置与数值为零分别展示；读取失败不显示正常零值、笔数或旧数据图表，局部失败保留其他可读内容。聚合页为每个错误提供明确来源恢复入口；恢复仍由领域页面原 LoadNotice／SaveNotice 执行，尊重保存队列及草稿保护。快捷入口的用户顺序和明确清空必须保留，新增默认入口不能覆盖已有偏好。

总览负责跨领域摘要和导航，收益负责产出速记与上线，账号负责收支、交易与对账。新增功能先确定所属领域，不在三个页面同时增加完整操作区；总览新增工具入口接入既有可自定义功能库。主页面优先放摘要和高频操作，低频明细沿用历史／仓库入口，分析内容需要收纳时按业务区块组织。折叠、删字段或合并主操作需结合使用场景确定，不用字号缩小代替信息取舍。

账号概览与历史的币种标题、笔数提示、金额单位及方向色由 account-summary.ts 的 accountSummaryBooks 统一派生；页面只提供各自已筛选的记录，统计组件仅展示。不要在两个调用方分别维护同一组三项读数。

穿戴出售的后端快照比较允许旧档缺省字段与归一后补全的零／空默认值等价；投影只用于比较，不改写原成交资料。有值字段、编号和数组顺序仍参与核对，不以忽略全部新增字段的方式放宽校验。

### 2.5 注释

注释是这个仓最重要的资产之一：写「为什么」和「踩过什么坑」，不写「这行做什么」。

1. **文件头写「这个文件解决什么问题」**，不写「这是 xx 组件」。
2. **反直觉的写法必须写原因**（`AppRail.vue` 的 `min-width: 0`、`use-theme.ts` 的单例）。
3. **不要写「改了什么」**——一行提交信息与 `git show` 已经说了，注释只留契约。
4. **不写废话注释**：`// 定义变量`、`// 循环` 一律不写。
5. **代码里留「契约」，历史留在改动记录**。「当初试过 A、某次截图指出 B、所以现在写 C」是 `RECORD.md`
   的素材，不是行内注释的素材。行内要留的是那句「不这么写会怎样」：「`--bevel-lo` 恒偏黑，用
   `--ink` 会在暗色主题翻成提亮带」是契约；「早先这里写的是 `--ink`」不是。
6. **中文注释，句号结尾**，不用「注意」「小心」这类空话开头——直接说事实和后果。
7. **模板里的中文文案不要手动断行**。Prettier 会按 `printWidth` 折行，而折行点在 HTML 里渲染成
   一个空格。要强制断句就用 `<br>` 或拆成多个 `<p>`；一段文案只有一两句时，宁可让它整行超过 100
   字符被折，也不要在两句话中间敲回车。

### 2.7 小共用函数：一件事只写一份

同一件小事在几个窗口里各写一遍，改一处另一处就静默落后。已有公共入口如下——
新增同类逻辑前先 grep，已经有家的就去改那一家（§2.6 同一条口径）。

- 下拉选项遇到名录之外的旧值，统一用 `src/components/select-options.ts` 的 `withCurrentOption` 保留当前值；不要在门派、装备属性等各写一份补选项逻辑。
- 属性与修炼按行名查找，统一用 `character.ts` 的 `findAttrRow` / `findTrainingRow`；OCR 草稿和快速修改不各自展开分组。
- 修改窗的初始输入聚焦统一用 `focus-input.ts`，保留各窗口自己的目标选择器。
- 字段契约只从**自己的模块**取：装备相关的类型与常量在 `gear.ts`、召唤兽在 `pets.ts`，`character.ts` **不再** `export *` 转出一份。同一个类型有两个入口时，改一处另一处静默落后，而类型是同一份所以编译也不报错。
- 卡内六分区的页签选项只有一处：`character.ts` 的 `PANE_OPTIONS`。卡片与编辑器不要在组件里各自 `PANES.map(...)`——那还会在每次渲染新建数组，把滑块的 `values()` 一起换掉。
- 角色完整修改、单件装备与单只召唤兽的尺寸共用 `editor-metrics.ts` 的 `EDITOR_W` / `EDITOR_H`，均为定高，长详情在卡内滚动；装备与召唤兽目录共用 `blocks.css` 的 `character-choice*`，头像材质复用 `PressTile`。角色卡与修改窗的读数字重统一由 `.character-theme` 管理。
- 日期与时刻落成字符串只有两处：日期走 `services/format.ts` 的 `dateText`（收 `Date` 也收毫秒），时刻走 `services/clock.ts` 的 `timeText`（补零由同文件的 `pad2` 承担）。不要在窗口里再写一份 `padStart(2, '0')` 去拼 `YYYY-MM-DD` 或 `HH:mm`——这类函数改一处，另一处就静默落后，而它们都长得对。
- 表单页脚复用 `FormActions`，业务保留关闭保护、保存与重试回调；起止日期复用 `DateRangeField`。分组标题用 `GroupHead` 的 `as` 保留标题层级。分页统一用 `RecordPager`：左右箭头翻页、最多七档页码，首尾常驻、省略号前后跳五页，当前页用印面及 aria-current，单页隐藏；复用 PressButton／PressTile 和图标注册表，保留业务标签与摘要插槽。页数及数据切片仍由业务计算，不引入第二套 UI 库。
- 收益历史、上线记录与账号历史共用 `blocks.css` 的 `record-history`、`record-table-frame`；表格只有内部滚动，外框与表头固定；四种状态保留同一滚动宿主：有数据、筛选无匹配保留可见外框，首次无数据或读取失败使用 is-empty 将边框和底板透明化，提示在剩余内容区居中，失败不绘制旧表格。收益历史与上线记录额外共用 `record-roles`、`record-role-*`，角色使用紧凑单行 SteppedSlider，长名省略且保留完整提示，金额不随角色筛选缩减；账号保留多维下拉筛选。搜索、日期和汇总口径由业务保留。
- 仓库浏览与历史表格的固定内容外框共用 `record-content-frame`／`record-table-frame` 的同一规则，只有内部列表滚动；外框两侧与工具栏、页脚留白对齐。筛选复用 `record-filters`，结果数及已选数归页脚；仓库重置使用 TextButton。账号历史默认只展示日期／限宽搜索，六项下拉通过主题色 PressButton 展开，下拉与单个日期框共用宽度、自然换行；重置用普通 PressButton，两按钮置工具栏右侧。收起后保留已选条件摘要和数量，不清空条件或重置分页。汇总复用 StatStrip folded 左侧纸脊，按币种分别列出收入、支出和差额，紧凑留白且不叠同义统计卡。
- 仓库管理的全部包含在仓物品和已售出快照，已售出保持只读。买卖选择均包含穿戴装备和携带召唤兽；补记买入保留原编号与归属，卖出确认记账时按编号解除角色归属；穿戴选取仍排除已占用物品。装备只按下拉部位筛选，关键词只用于召唤兽，隐藏条件不参与装备过滤；顶部分类滑块按内容定宽。图标悬停不位移，状态小签使用常规字重；状态不改变整格边框或背景，下方复用收益固定价格的 NumTag 小签，已穿戴用 moss、已售出用 ochre、未穿戴用 muted；勾选态及键盘焦点仍独立保留。
- 新建装备／召唤兽买卖的关联区同时提供录入与选择，两入口共用原草稿及选取窗；成功确认才替换关联资料，取消保留原值。临时物品来源只在输入契约传递，不落盘：录入买入新增库存，选择买入仅关联原库存编号；选择卖出移出库存，录入卖出只保存成交快照。已有库存选择须核对快照，旧交易关联保持只读，保存／重试和删除卖出回仓仍走同一事务。
- 出售穿戴物品时，账号、库存和角色解除归属由同一账号交易队列负责；待保存期间禁止另写或重读名册。Rust 仅允许本次新增卖出、分类和当前快照匹配的物品解除归属，普通删除仍保留穿戴保护；三域在同一 SQLite 事务提交。浏览器交易恢复日志可带角色快照，名册读取前先恢复；删除卖出仅回仓，不恢复穿戴关系。

- 本地读取与跨窗口同步使用同一解析器；同步失败保留当前内容并暂停写回，完整数据或明确删除后解除读取错误，不把残缺列表当空库。
