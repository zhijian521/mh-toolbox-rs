## 依赖追踪与保留理由

- 外观：AppearanceSection → useTheme／useFontFamily／useFontScale → 本机偏好及根属性 → styles 令牌。保留单例与现有字体／主题范围，没有新增主题、字体或材质副本。
- 账本：DataSection／BackupHistory → useBackups、data-files → persist 写队列与生成 IPC → Rust backup.rs、store。服务中导出、导入、恢复及清除均保留等待写队列的入口；恢复先核对可恢复列表，再校验备份并走 replace_backup。此次仅追踪相关入口，未重审全部事务与文件处理细节，不修改服务、Rust、数据库或真实账本。
- 更新：AboutSection → UpdateCheck → updates.ts → GitHub 正式 Release；下载仍经 desktop.openExternal。已有手动触发、十秒超时、离线错误、正式版本与项目下载地址校验，本批没有足够理由重写。
- 开发数据：DevDataSection → demo-data → 各领域 store 的原追加／替换和 flush／retry。开发模式仅控制测试入口，与模拟数据写入无关；原替换操作继续先确认。此次不调用任何数据生成函数。
- 资源与测试：图标继续来自 components/icons.ts，演示继续消费公共控件和真实令牌；07-settings／08-tools 已维护入口、分组、搜索和返回保留状态的烟测断言，未执行。无需新增资源或 Rust 命令。

## 反馈调整：统一模拟账本

用户要求删除图标搜索及目标、仓库、交易的独立示例入口，并确认统一模拟数据采用“替换全部账本，导入前自动备份”。以下内容取代前文的搜索及分散追加方案。

- 图标目录直接遍历 ICON_GROUPS，删除输入、过滤状态与搜索断言。
- DevDataSection 仅保留开发测试开关及一个模拟账本导入入口；删除 importDemoGoals／importDemoWarehouse／importDemoTrade 和旧的逐 store 替换函数。
- buildDemoData 集中生成 v2 完整账本：四种角色状态、物价走势、近两周及更早收支、双币种账号与买卖快照、普通养成／组合／存钱／装备／自定义目标、在仓与穿戴资产、已结束上线、速记单价与点卡设置。统计数量由数据生成，不另写一份数量表。角色及资产固定编号，目标和记录只引用模拟角色；售出不在库存，原资料保留在成交快照。
- 确认后 dataImportPayload 等待写队列；新命令 data_import_payload 解析当前信封后复用 replace_backup，校验和备份均在事务替换前。备份失败不开始替换，事务失败沿原逻辑回滚；不调用旧版转换、不逐表保存。浏览器禁用该入口。
- 成功后复用 settings/data-notice 将回执与备份位置带到设置页并重载领域单例；回执只读取一次。外观偏好不属于账本，不受替换影响；真实用户提醒和非账本偏好不由模拟数据重置。
