### 2.2 每个模块都要回答的十二个问题

| 维度 | 精确检查点 | 完成依据 |
| --- | --- | --- |
| 业务语义 | 输入、单位、边界、统计区间、来源、派生值与历史记录是否一致 | 给出至少一个正常例和关键边界例；引用现行规则 |
| 展示必要性 | 每块内容是否服务当前任务，是否重复、过时或只有技术解释 | 每块标记保留／合并／移到详情／删除及理由 |
| 操作路径 | 主操作是否明确，重复确认、跳转、手工输入能否消除 | 写出典型任务的前后操作步骤；不隐藏失败恢复 |
| 组件与主题 | 同语义是否复用，颜色、字、材质、状态是否来自同一入口 | 列出公共组件映射；例外有业务理由 |
| 状态完整性 | 初始、加载、空数据、无结果、编辑、保存中、失败、重试、只读、过期结果 | 按适用状态逐项检查；不以默认截图替代 |
| 数据可靠性 | 读失败保护、并发保存、引用、删除、重试幂等、原子性、迁移 | 跟踪完整数据路径；错误不得写成空库 |
| 生命周期 | 挂载、卸载、切页、隐藏、关闭、重启、睡眠恢复是否正确 | 每个定时器、监听、订阅、后台线程都有所有者与停止规则 |
| 性能 | 首次与后续、计算与排队、主线程与后台、长时间运行 | 有明确计时边界；无数据时写“待测”，不猜瓶颈 |
| 安全与隐私 | 输入边界、路径、SQL、外链、CSP、调试钩子、截图及日志 | 针对实际入口列威胁和保护；不套与本地应用无关的清单 |
| 可用与无障碍 | 窄窗、大字号、键盘、焦点、读屏标签、深浅色、降动效 | 公共控件定义完整行为；真实交互问题有复现路径 |

| 可维护性 | 职责、依赖方向、公共出口、死代码、资源、文档 | 按职责判断拆分；不以文件行数和抽象数量评分 |

### 2.3 审查结论必须分清事实与建议

- **确认缺陷**：有文件位置、触发条件和错误结果；需测量的问题另附原始数据或标记“待复现”。
- **规范偏差**：指出违反哪一条现行契约，以及影响哪些页面；不能仅凭个人偏好认定。
- **可选改进**：明确收益假设、成本和保留现状的理由，未证明收益前不强行实施。
- **符合要求**：写明已经检查的范围；不为凑优化数量改稳定代码。
- **未完成／不适用**：写清缺少的证据或不适用原因。没有跑动态验证不能宣称运行行为完全通过。

问题优先级：`P0` 数据破坏或关键安全问题；`P1` 关键功能不可用、明显错误结果、漏提醒或严重卡顿；`P2` 稳定复现的流程／一致性／维护问题；`P3` 有收益但可后置的整理。计划内任务的顺序不等同于已经发现这些等级的问题。

## 3. 必须保持的业务与系统边界

1. 数据目录固定 `%APPDATA%\mh-tool-rs`，identifier 不变，卸载保留数据。不能为重构改变存储位置或重建用户账本。
2. 收益与账号是独立账本；自动分账只按现行方向流转。人民币元与梦幻币万分别计算，不跨币种直接相加。
3. 角色、仓库、资产、收益及账号的跨域操作按现有事务契约执行。不得用多个独立保存伪装一个原子操作。
4. 读取失败、残缺数据、跨窗口同步失败不得触发空值覆盖。保存失败保留用户草稿，重试不得重复记账或重复移动资产。
5. 新版 SQLite 是当前业务真源。旧版导入集中、单向、保留原件；导入前备份，失败不破坏当前库，不产生向旧版的反向镜像。
6. 系统调用仅由 `src/services/` 暴露。IPC 类型源于 Rust，两张命令登记表一致，`bindings.ts` 为生成物，不手工修改。
7. 页面切换和退出应用是不同生命周期。封妖离开页面应继续提醒；退出应用后的持续运行不在现有需求中，不通过偷偷常驻进程扩展范围。
8. 封妖首次无偏好时地图全关；用户手动选择后持久化，下次恢复选择。保存地图不等于自动启动监听；不重新引入角色等级、测试通知、官方规则按钮或折叠“更多设置”。最近提醒沿用既定简洁卡片方向。
9. 规则、模型、资源的优化不能悄悄改变游戏事实、识别阈值含义或历史数据解释。优化识别速度同时约束误识别、漏识别和结果可解释性。
10. 所有测试运行继续遵守真实数据快照与完整还原规则。开发版、浏览器替身、生产构建各自能证明的范围要分清。

## 11. 性能专项工作包与指标

### 11.1 已有能力与尚未证明的部分

源码已具备 OCR 引擎单次初始化和启动后预热、共享互斥引擎、窗口捕获、ROI、画面未变跳过、监听基线／去重、Rust 后台通知等能力。优化应从这些真实路径出发，不把它们当作尚未实现的功能重新建设。

封妖当前循环目标约 900 ms，页面状态约 1200 ms 轮询；捕获路径存在最长约 1200 ms 的取帧等待。循环目标不是端到端延迟保证，页面轮询也不是系统通知触发路径。当前 `ocr_ms` 包含当轮前段处理，不能直接标为模型纯推理时间。实际耗时与争用程度尚未测量。

### 11.2 统一指标与建议目标

以下数字是**待基线后确认的初始候选目标**，不是对当前机器的承诺，也不是已测结果。精确硬件、构建、图像尺寸、DPI、模型线程数和数据规模随基线一并记录；达不到时先找耗时来源，再确定可行目标。

| 用户体验 | 计时／质量口径 | 初始候选目标 | 必测场景 |
| --- | --- | --- | --- |
| 点击有反馈 | 输入到按钮状态、加载态或结果首次可见 | 普通常用操作尽量在 100 ms 内有反馈 | 无任务、OCR 忙、后台监听同时开 |
| 截图 OCR | 图片已解码可提交 → 可核对草稿可见；另记上传／解码 | 热路径 p95 候选 ≤ 2 s，按图片类型分组再确认 | 属性、技能、修炼、辅助、装备、召唤兽；多图队列 |
| 封妖及时性 | 有效新公告在源画面可见 → Rust 提交通知 | 单独运行 p95 候选 ≤ 2.5 s；并发 p95 候选 ≤ 4 s | 前台截图／捉鬼争用、遮挡、多个地图、连续公告 |
| 通知正确性 | 应提醒事件、漏报、误报、重复数 | 标注样本内无漏报／误报／重复为候选验收门槛；不能外推到所有现场 | 基线、滚屏、重复图、停启、改筛选、不同字色 |
| 系统弹窗可见 | 通知提交 → OS 实际展示，单独记录 | 先测；受 Windows 设置影响，不与提交时延混为一项 | 开发／安装版、正常通知设置、勿扰限制 |
| 启动与切页 | 进程启动、导航、FCP、首屏可操作分别记录 | 先记录 p50／慢样本，再设预算；不以空壳 FCP 代替就绪 | 冷／热启动、数据量、字体、OCR 预热同时运行 |
| 大列表／图表 | 筛选／分页／悬停到渲染完成；观察长任务 | 常用输入不明显卡顿；长任务按 > 50 ms 标记定位 | 明确标注的典型量、增长量、极端量 |
| 长时间监听 | 线程／句柄／工作集／CPU／队列长度随时间 | 无持续增长趋势、无重复任务；具体预算基线后定 | 30 分钟观察，必要时指定 2 小时耐久 |
| 测试效率 | 同分区同条件墙钟、启动／准备／执行／恢复分段 | 首轮候选总耗时下降 ≥ 30%；保护覆盖与稳定性 | 冷／热各分开，记录失败与重试，不只挑最快一次 |

p95 需要足够样本：热路径优先采 100 次左右的代表性事件；少于此数量时报告样本数、分布和最大值，不把少量样本的 p95 当稳定结论。冷启动成本单列，可先采 5～10 次观察波动。系统真实公告数量不足时，用固定输入重放分析计算链路，另保留真机端到端观察；二者分别报告。

### P01 OCR 引擎、排队与图像处理

- **范围**：`ocr_paddle.rs`、`ocr_image.rs`、`ocr.rs`、前端 OCR 服务与图像预处理；所有实际调用者。
- **采样拆分**：模型冷加载、引擎锁等待、图像解码／缩放／复制、IPC 编解码、检测、方向分类、识别、解析、草稿渲染。只能测总推理时就如实记录，不伪造子阶段。
- **已知争用点**：截图 OCR、捉鬼与封妖共用序列化引擎。检查模型占用、前后台任务公平性、队列上界、取消与过期结果；不能只测单任务热识别。
- **优化候选**：模型与线程参数、输入尺寸、ROI、减少无意义像素复制、分段取消、前台反馈、按任务特性的有界队列；按采样选择，不一次全上。
- **并行方案取舍**：多个引擎／并发推理需要比较 p95、CPU、内存、识别质量与后台公平性，不能假设线程越多越快。用户提交的多张有效截图不得套用直播流“只留最新帧”而丢失。
- **完成条件**：同一标注样本的准确性不回退；冷／热、单独／并发数据分别给出；UI 可取消且结果归属正确，旧任务不长时间饿死新任务。

### P02 捕获、后台监听与通知时延

- **范围**：`window_capture.rs`、`screen.rs`、`ghost.rs`、`fengyao.rs`、前端状态服务与通知提交入口。
- **链路采样**：源事件／帧时间 → 取帧 → 裁剪／哈希 → 等 OCR → 推理 → 解析／去重 → 通知提交；为轮次或任务分配可关联标识，避免混合旧帧。
- **捕获审查**：WGC 最新帧选择、未变跳过、帧年龄、轮询间隔、纹理／内容尺寸、窗口关闭、最小化、DPI 和尺寸变化、恢复重试、资源释放。遮挡与最小化分别定义，不能等价处理。
- **调度候选**：连续画面仅保留最新有效待处理帧、过期结果丢弃、有界积压、前后台公平；先测事件推送替代状态轮询是否有价值，系统通知时延不能归咎于页面轮询。
- **正确性保护**：首次基线、去重和地图过滤不为追求快而删除；恢复后不误把旧公告当新公告；通知记录成功与提交失败分清。
- **完成条件**：单独／并发／长期运行的延迟和漏误报均有记录；源公告出现到提交的口径可信，停启与异常恢复正确；Windows 勿扰抑制另列，不标成 OCR 漏报。

### P03 启动、路由、列表、图表与资源渲染

- **范围**：启动骨架、规则／数据加载、路由懒加载、弹窗加载、各域聚合、搜索排序、图表与图片／字体。
- **审查**：重复加载、渲染期新建稳定数组、深层 watch、全量重复计算、同步大 JSON／像素工作、图片解码、失效缓存、图表事件频率和路由卸载。
- **优化候选**：复用已存在请求缓存和只读派生、正确失效、批量刷新、只在需要时加载；只有测量证明列表过大才做虚拟化，不把所有小列表升级为复杂基础设施。
- **采样要求**：复用 `tools/probe/startup.mjs`，分清进程到导航、导航到 FCP、可操作、字体完成；字体资源完成不能直接加到首屏时间上。发布与 debug 构建不混比。
- **完成条件**：首屏和操作指标改善，数据更新仍即时正确；预热不抢占首屏造成卡顿，缓存不产生过期价格／进度；不靠移除错误提示或延后必要数据伪装更快。

### P04 长时间运行、资源释放与最小诊断

- **范围**：后台线程、OCR 队列、捕获设备与帧、轮询／事件订阅、图片对象／Blob、窗口、缓存、日志。
- **审查**：连续切页、开关监听、开关弹窗、批量 OCR、睡眠恢复后的工作集、句柄、线程、队列和日志增长；识别暂时缓存与泄漏的差别。
- **实施方向**：只增加定位当前问题所需的低开销分段计时、任务标识和有界诊断；默认不保存原始截图与整段系统消息，不新建独立监控平台。
- **完成条件**：有界缓存和队列、明确释放路径、失败退避；停止后资源下降或稳定在可解释范围。采样输出足够定位慢在采集、排队、推理还是通知，不让用户看技术面板才能完成日常任务。

## 12. 工程、资源与交付工作包

### R01 依赖、编译配置、CI、安装与升级

- **范围**：`package*.json`、锁文件、Vite／TS／ESLint／Prettier／Vitest 配置、Rust manifest／lock／toolchain／build.rs、Tauri 配置、`start.bat`、打包脚本、NSIS hook、`.github/workflows/`。
- **审查**：依赖实际用途、锁定理由、模型／DLL 定位、开发与发布差异、运行环境、重复构建与重复检查、失败日志、版本同步、离线启动和安装后通知身份。
- **体验优先候选**：当前 release 存在 `opt-level = "s"` 的体积导向配置，可在同一环境对比吞吐导向配置；保留 LTO／线程／链接策略的实测取舍，不直接假定改为最高优化就更快。
- **保留边界**：`custom-protocol`、SQLite bundled、模型／字典／运行时、字体许可、卸载保留账本、identifier 与数据目录。遵守 Windows 工具链既有锁定原因，不自动升最新大版本。
- **完成条件**：安装版在无开发服务器的环境可用，OCR／字体／通知／备份资源齐全；更新和卸载不破坏数据。CI 去掉重复工作需能说明剩余门槛覆盖同等风险。
- **未来指定验收**：构建或安装专项只在用户指定时执行；不以本地 dev 运行代替生产 CSP、DLL 和安装身份验收。

### R02 游戏规则、图片、字体、模型与许可

- **范围**：`public/game/` 全资源与事实表、`assets/`、`src-tauri/models/`、图标／头像映射、资源服务、加工脚本、资源说明与许可。
- **审查**：来源、许可、再生成入口、重复／无引用资源、引用大小写、缺图回退、规则版本、异步加载失败、缓存与旧值；地图坐标和尺寸数据同时检查。
- **事实源审查**：技能、修炼、属性、养成费用、活动、封妖场景等事实只维护一处。代码中的解析策略与事实表分开，不把算法硬塞进 JSON 或把规则散回页面。
- **体验取舍**：图片、字体、模型可保留较大版本换清晰度／准确性／加载流畅；删除或压缩必须说明对使用的影响，不以节省安装字节作为唯一理由。
- **完成条件**：每种分发资源有来源／许可／生成方式；页面规则与资源映射一致；缺失或读取失败可恢复；不删除运行时动态引用、模型字典或许可文件。

### R03 文档、开发帮助、死代码与工程卫生

- **范围**：全部现行文档与根说明、开发帮助、脚本入口、忽略／行尾／编码配置、确认无引用的手写代码。
- **审查**：过时命令、示例参数、功能描述、重复标准、无效链接、调试历史混入规范、固定断言数和过期截图；公共控件样例是否真实覆盖状态。
- **实施方向**：契约回原规范，原因回 RECORD，历史回 archive；本计划保留进度和结果链接。先验证引用与动态入口再删代码或资源，不清本地运行目录。
- **完成条件**：新同事可从现行文档找到功能／测试／发布入口；同一规则只有一份真源；新增公共 API 有样例，文档不声称未运行的验证通过。

### R04 覆盖核对与阶段验收

- **范围**：第 2.1 节全部范围、第 5 节 43 个工作包、问题台账、变更和验证证据。
- **执行**：回查是否有遗漏路由、弹窗、全局任务、服务、Rust 模块、资源和脚本；按模块追踪“审查过／改过／静态检查过／动态验收过”，不混合状态。
- **完成条件**：每个包有结论和未解决项；P0／P1 若存在不得无说明搁置；保留现状有依据，优化有前后对照。精简页面、测试效率、模块边界与体验性能均有各自结果。
- **阶段验证**：如用户要求全量检查，再按 AGENTS 一次执行完整清单，并复用相同产物的既有结果；否则交付静态审查与明确标记待验的成果，不能写成全量验收完成。
- **收口产物**：实际修改范围、性能／测试测量报告、仍待验项目、后续维护原则；不因此新增业务功能或发布版本。

## 13. 每个工作包的实际执行流程

### 13.1 固定七步

1. **定边界**：确认用户选定的包、本批目标、工作区他人改动、可修改范围；需要联动时说明原因，不要求逐个例行确认。
2. **一次读齐**：批量读取目标实现、引用、现有契约与相关断言，避免同文件多轮整读；先定位事实再编辑。
3. **列结论**：每个问题写“证据 → 触发 → 影响 → 最小改法 → 风险”。对无需修改的部分也给范围明确的结论。
4. **小批实施**：公共契约先试点，文件尽量一轮改完；变更不跨多个无关目标。发现更大问题登记，不失控扩大。
5. **同步断言与文档**：行为变化补必要逻辑／烟测断言，删除功能删过期断言；既有测试足够时不机械加镜像测试。编写不等于执行。
6. **按档位验收**：日常仅静态审查；指定验证只跑指定范围；实际调试失败时先解决当前问题，不顺手扩成整套。记录产物、样本和限制。
7. **交付与进度**：更新本文件状态或结果链接，说明到哪看；用户要求时用一行 `type:中文短语` 提交，提交本身不触发额外验证。

### 13.2 批次边界与回退

- 优先以“一个公共契约的两个调用方”“一个业务任务”“一个已定位瓶颈”作为一批，不按任意行数拆分，也不把 43 包合成一次重构。
- 页面精简、公共 API、数据结构／迁移、性能配置分别交付，便于定位影响和单独回退。
- 回退只针对本批改动；不覆盖用户或其他任务的未提交文件。数据变更另外设计兼容与恢复，不能认为 Git 回退可以还原真实账本。
- **20 分钟没有可交付结果时先汇报当前证据、已完成部分和阻塞点。** 同文件第三次编辑／整读、第二次构建或“再量一次”的念头出现时，先检查是否失去范围控制。
- 不预估整项目精确天数。先完成前几批记录实际投入，再调整；每次会话应能独立交付并明确下一项。
