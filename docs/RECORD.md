分三批，每批独立验证、独立提交。**不要合并成一次大重构。**

### 角色页细化（2026-11-03，第 43–59 批）

十七批集中在同一个页面，几乎每条都来自一次点测反馈。

- **页头高度**（第 43 批）：诊断对了一半，错在「高度不该由按钮决定」——`--page-head-h` 是算出来的，
  页头是 `min-height`，`lg` 三档全超（→ §2.3-2）。
- **弹窗**（第 44 批）：用户给的 2:1:1 是**列宽比例**，不是「谁先缩谁后缩」；改成四等分轨道后
  上排 2/1/1、下排各 2，正好铺满。格子改 `<label>`，点名字就能聚焦。删「更新时间」——手抄的字段。
- **门派下拉**（第 46–48 批）：原生 `<select>` 的问题不在配色，在浮层由系统绘制。
  第 48 批看到的「下拉挤压布局」是两件事：浮层 `absolute` 撑大了滚动容器（容器一滚，
  左边标签被切掉半个字），以及 `scrollIntoView` 会把整个弹窗滚歪——后者在注释里写明为什么不能用。
- **事实表进 `public/game/data/`**（第 49 批）：加载仍是同步纯函数，组件里没有一处
  `v-if="表没回来"`（启动时 `await` 后才 `mount`，→ §2.4-36）；切图脚本也改成读 JSON，
  否则等于把搬出去这件事说回去一半。
- **辅助技能**（第 51–56 批）：56 裸图 → 40 压 48 块；辅助 / 剧情分两块；四列改五列；
  图标过一道「纸化」。蒙版试过 `grayscale + multiply`（只是把深蓝换成深灰）、纯纸色纱
  （亮色下洗成灰白），最后是 `sepia` + 压暗的纱。
- **修炼两组改名并锁只读**（第 58 批）：改的不只是名字，是「谁来决定这一页的结构」——
  组名写进清单之后，它从「用户的数据」变成「游戏的表」（→ §2.4-29）。

- **第 61 批**定的形态：字印 ｜ 名称 + 九格刻度 ｜ 等级，**刻度只铺名称那一列**

- 刻度改「凹槽里嵌红条」。连带一个后果：填充换朱之后满级不能再靠填充色区分，改成整条转朱 + 槽描边转朱。

### 旧仓的定位：参考读物，不是兼容目标（2026-11-04）

用户：「我们可以参考旧项目，但是不用兼容旧项目，我们是一个全新的项目。」

这条不是新规矩，是把同日早些时候已经落在**数据层**的那句话（`AGENTS.md` 红线 6：不做
SQLite → JSON 反向镜像；`backup.rs` 的模块注释：不读 v1 的 `data.json`）扩到**逻辑层**。

被否掉的是「差分 harness」。原先的设想：把旧仓 `src/renderer/domain/` 的 6391 行纯函数
（`createDomain({ gateway })`，不碰 DOM、Node 里能跑）连同旧仓自带的 3956 行领域测试当作
oracle，新实现逐字段比对。它的价值是真的——能抓住肉眼验不出、但答案不一样的口径差：
`splitAmount` 把 100 万平分 3 人时，尾差给排在前面的人，得 **34 / 33 / 33**，而不是
`33.333…` 四舍五入成 `33.33 × 3`（少 0.01 万）。

否掉的理由不是「不值」，是**目标变了**：差分的前提是「旧答案就是答案」。我们要的是一个新
项目——同一个问题两边答案不同时，该问的是「**哪个对**」，而不是「旧的是多少」。而且差分
会把每一次有意改口径都判成回归，等于把旧仓的选择固化成新仓的红线，与「全新项目」正相反。

于是：旧仓照旧读（字段清单、口径上的坑、文案与交互），但**不写兼容层、不读旧档、测试写新版
自己的期望**。这条写进 `ARCHITECTURE.md` §5——它是边界，不是一次实现选择。

### 第 97 批补三：滑块、多选分账、间距、压印块（同日）

用户四条：「①今日/近七天/本月 用多档滑块组件；②记给用分段胶囊但支持多选；
③统计卡片和物品速记中间没有间距；④物品速记每个块用压印按钮组件」。

**① 统计范围 → `SteppedSlider`**（多档滑块）。原来用的是 `SegmentedPills`——一组互斥
胶囊，能选但读不出「这是一条轴上的三档」。滑块用同一批令牌画凹槽与朱印，宽度由调用方给
（组件只画到内容宽）：`264px`，三格等分 86，字短的那格不被挤。

**补：宽度 264 → 216（三格 72）**（用户：「每个胶囊宽度稍微减小一点」）。86 一档时，一条
滑块比它右边那三个统计数还抢眼——它是过滤器，不是这一屏的主角；72 仍够最长的「近七天」
两侧各留 15 的余量。一格一档的宽度由使用方给宽度来定（组件按 `flex: 1` 等分），
所以下次再调只动 `.range-slider` 这一个数。

**② 记给 → 支持多选，语义是「分账」**。新组件 `TogglePills`（`components/`）：

- **圆角用默认的 `pill`（`--r-pill` = 999px，两端全圆头），不是 `sm`**（用户：「记给角色的
  按钮使用胶囊形状」）。一开始按「贴进方角结构就用小圆角」的旧规矩传了 `sm`，实测读成一排
  方头小按钮——它旁边全是方角的统计格与纸边，小圆角落在同一族里就看不出「这是可以按下去的」。
  全圆头才把「印」的语义说出来；`.pill-group` 的承载面 3px 内衬让外壳跟着变成同一弧度的槽。

- **不改造 `SegmentedPills`**：那是 `radiogroup`，九个里选一个，读屏念「选项，三之一，
  已选中」。多选是 `group` + 每枚 `aria-pressed`（读屏念「切换按钮，已按下」）。ARIA 不能
  靠一个 prop 兼——`role="radio"` 配「可多选」会把状态念反，而「选了谁」在这里是账本口径。
  材质一字不写地复用 `base.css` 的 `.pill-group` / `.bevel-pill`，只留状态与键盘。
- **键盘没有复用 `useRovingFocus`**：那个的方向键**顺着把选项选中**（单选组的约定）。
  放进多选组会变成「左右键从头翻到尾，一路把经过的每一格都按下去」。所以它自己管：
  整组一个 Tab 停靠点、左右键只移焦点、空格/回车切换；焦点记在组件自己的下标上，
  不跟着「第一个选中项」走（否则按两下就跳回原处）。
- **选 N 个号 = 写 N 条、金额平分**（`splitAmount`，余数按币补给排在前面的人）。
  1000000 分 3 人是 333334/333333/333333，总额一分不差。没用 `total / n`：那会少 1 币，
  而账本里「少一点」不报错，攒几十条后再也查不出是哪几条造成的。
- **不写成「一条记录挂多个角色 id」**：按人合计时要么整条算给每个人（翻 N 倍），
  要么把分摊规则搬进查询，而删一条时说不清撤的是谁的份。

**③ 间距**：统计条与速记之间原本是 0（只有筛选行自己写了 `margin-bottom`），两张纸的边
直接叠着。改成外层 `.stack` 一根 `gap: 12px`——**间距不再靠「每块记得给自己加下边距」**，
以后再加一块不写样式也是 12。

**④ 物品格 → `PressTile`**。上一轮我判断「不换」，理由是 59 格落影会读成一面凸起的墙；
用户明确要用压印块，照做，并把密度调对：`--tile-drop` 0.7（默认 1 是给单个块调的）、
格间 6 → 9。

**这一处试错两轮，记下来**：块面先取「paper 掺 24% `--bevel-hi` 提亮」——在白纸上只亮
3–4 阶，肉眼读不出来，59 格并排仍是一整片，只剩一圈棱在讲话；后来照角色卡装备块与物价卡
的做法取 `--paper-2`（**比纸略暗**），悬停返回 `--paper`。纸上要读出一块东西，靠的不是
「更亮」——上面已经没有比纸更亮的纸——而是略深的块面 + 上亮下暗的棱 + 落地影。
`hit` 的朱边也从 `border` 改成 `::before` 画一圈：`PressTile` 的四条棱是叠出来的 inset 阴影，
往它身上压 outline 会把最下面那道厚边盖掉。

**「不指定」的转译踩了一脚**：第一次写成「只要结果数组含空串就把它过滤掉」，实测
「点不指定」完全无效（按之前不指定亮着，点它 = `[..., '']`，过滤后角色还在）。
真正的判据是**按之前它亮不亮**：亮着 → 新按下的是某枚角色；没亮 → 刚按下它，清空全部。
四种操作实测：单选、加选、按不指定、取消最后一枚，全对。

**组件库与规约**：`TogglePills` 进了开发页「原子组件」（十二件 → 十三件，连数一起改）；
`CONVENTIONS` §2.3-10 补「多选 = 分账不是翻倍」与「『不指定』是空数组」两条。

验证：`vue-tsc` / `eslint` 干净，`vitest` 19 文件 **262 用例**（+5：平分尾差、除得尽、
零人、可复现、回执句），`npm run build` 通过。截图实测亮色 / 暗色 / 900 宽 / 多选点击
（两枚同时朱底 → 清单 +2 条各 2.25 万 → 提示「已记 70武器 · 4.5 万 → 2 个号平分」）。

### 第 97 批补四：物品格子只留图标（同日）

用户：「物品速记里面不显示名称，只显示图标和价格，下面没有价格的就只显示图标」。

验证：`vue-tsc` / `eslint` 干净；截图核过亮色 9 列、暗色、900 宽 5 列、1.1 字号档（价格

### 第 97 批补五：右侧留白的真因是类名撞车（同日）

用户：「现在屏幕放大的时候，右侧有空白，没有撑满」。

**不是收益页的网格算错，是 `.stack` 这个名字已经被占了。** `blocks.css` 里有一个全局
`.stack`（设置页与开发页那「一列卡」），它带 `max-width: 1240px`——那一条是给**说明文字页**
写的：「再宽只会让说明拖成一条长线」。收益页的外层也写了 `.stack`，于是两个规则合并生效：
scoped 只往选择器上加一个属性，**拦不住同名的全局规则**。窗口窄于 1306 时两页一模一样，
所以这个错一直没露；1600 宽实测内容卡在 1240，右边空出 294。

改法是换名（`.income-stack`）而不是去掉全局那条上限：说明页确实不该铺满 1600 宽，问题在于
两个不同意图的东西共用一个名字。判据写进 `CONVENTIONS` §2.4-45——**这个类名在
`src/styles/` 里有没有**，有就说明它已经有主。

顺手把物品格也交回给网格自己定尺寸：

- **列宽下限 72 → 88**。72 那档是上一轮「去掉名字」之后临时定的，块一窄，9 的缝就显得比块
  还重，一整片读作「撒开的碎纸」。88 之后块宽由 `auto-fill` 天然锁在 88–112 之间，窗口变宽

  1900 宽 15 列（块 89），缝恒为 9。
- 中途试过「`1fr` 列 + 块 `max-width: 96` + `justify-items: center`」：块是被摁住了，

验证：`vue-tsc` / `eslint` 干净；四个宽度实测（900 / 1180 / 1600 / 1900）列数、块宽、缝宽

### 第 97 批补六：今日速记改成「图标 × 次数」（同日）

用户：「今日速记优化一下，不要列表这汇总了，可以直接还给总结，一个图标 × 20 这种，
一眼可以看清的」。

原来是逐条流水（时间 / 名字 / 角色 / 金额 / ×）。聚合之后反而更贴这一页的动作：速记是
**连点**，一天点十几次同一件物品很正常，逐条列会出现二十行长得一模一样的「定魂珠 4.6 万」；
二十行里数不出「二十」，一格 `×3` 一眼就是。**名字、时间、角色、金额都没有丢**，它们进了
`title` 与读屏标签（`定魂珠 · 3 条 · 13.8 万（点一下撤掉最近一条）`）——与物品格同一条取舍。

- **`groupByItem`（`income.ts`）**：按 `kind|名字` 分组，返回 `count` / `total` / `lastId`。
    - **同名的收入与支出不合并**：合并会把两个方向抵消成 0。
    - **排序按条数降序**，金额只用来定平手。这一栏回答的是「今天都点了些什么、各点了几下」，
      点 20 次的定魂珠哪怕便宜也是主旋律；按金额排会让高频的便宜货沉底。
    - `lastId` 取 `createdAt` 最大的那条 —— 撤销撤的一定是「刚记的那一下」。
- **点一格 = 撤一条**，不是整格清空。清空看着更快，但它把「多点了一下」和「点了二十下要
  全撤」当成同一件事；撤一条、再撤一条，`×20 → ×19 → ×18` 自己数得清。
- **样子必须与左栏不同**：左栏是压印块（凸起的纸，点一下记一条），这里只有浅底 + 1px 边、
  **没有厚度也没有落影**，指上去边线转朱（「点掉它」）。长得一样的话手会按错方向。
- 一屏三列（每格 83×65，实测五格等高）：右栏 300 宽扣掉内衬，三列刚好托住 34 的图标；
  两列时每格会剩一大片空，而「一眼看清」靠的正是**一屏装得下多少种物品**。
- 图标靠**名字反查** `quick-items.json`，不在记录里存 id：`IncomeEntry.item` 是用户看得见的
  那串字，改物品清单时旧账仍读得懂。反查不到就退回文字兜底（截图里的「金香玉」就是清单外
  的名字）——图可以缺，账不能看不出是什么。

**一处功能退化，用 `title` 补回来**：聚合之后「这笔记给了谁」在界面上看不见了，而那排
「记给」胶囊会停在最后一次的选择上——换号忘了切，后面几条就全进了上一个号，本来正是靠
清单里的角色小字兜的。所以 `ItemGroup` 多带一个 `whoIds`（去重），拼进 `title` 与读屏标签
（「记给 归ω岚、小雷」）：归属从「看得见」降级为「指得到」，不是丢掉。找不到人仍写
「已删角色」——账不清人。

验证：`income.test.ts` 19 → **24 用例**（合并与 `lastId`、收发不合并、按条数排、空名归到
「未记物品」、`whoIds` 去重且未指定不占位）；`vue-tsc` / `eslint` 干净；截图核过亮色、
暗色（小格边界与朱色 ×N）、空态、点一格撤一条（`×3 → ×2`，提示「已撤掉 定魂珠 一条 ·
还剩 2 条」）。

### 第 97 批补七：格子几何定稿 + 价格签 + 历史收益（同日）

用户一天之内连收了七道，全在「一格长什么样」和「历史怎么看」这两件事上。

**一、物品格：三轮才定下来，块从 92 宽收到 44 见方**

    88 宽 × 62 高（92×62，图标 34 含价）   ← 被否：「图标偏上，下面以及左右空白」
    → 74 宽 / 76 高 / 图标 40（块内两行居中）← 被否：「压印按钮小一点包住图标即可」
    → **44 见方 / 图标 32 + 价格在块外**     ← 定稿

第一轮的病根不在数值：`.press-content` 只有 max-content 宽（`PressTile` 根是
`place-items: center`），价格文字只在中线附近，块再宽也没用；同时 `justify-content:
flex-start` 把图标顶上沿，下方留白全堆在价格行下面。第二轮把价格装进块里，块就必须跟着
「图 + 价」定高，于是永远比图标大一圈——**块里装「图 + 价」的路线本身错了**。

定稿把两件事拆开：块只负责图标（`--tile-w/h: 44px` 写死，不随列宽伸缩），价格是块下面的
一枚 `NumTag` 淡槽签（`--tag-h: 15`，与票面行 sm 档同一个 1.5 倍比例）。`min-width: 44`
与块同宽。于是「凸起的一块纸 + 纸上挖出的一格」，一凸一凹。没定价就**整行不渲染**
（`v-if`），块靠 `align-content: start` 贴顶，整排图标仍在一条线上。

列宽同步 88 → 74 → **50**（用户：「左右间距还是有点大」），缝 `6px 4px`（行距不动：块下面
还有价签，再压就贴着上一排的落影）。1600 宽下 22 列、块间距约 11（原 19.6）。

顺带：朱边与朱点从 `.item` 挪到 `.item.hit .item-tile`——`.item` 现在含块下面那行价，
圈整条会把「4.6万」一起框进去。

**二、单价连写**：`moneyText` 给的是「4.6 万」，那个空格是给表格列对齐用的；窄签里白占
半个字，还让「万」看着像另一样东西。抽 `compactAmount` 只做 `.replace(' ','')`，
**不动 `moneyText`**（物价表、差额列要那个空格）。

**三、今日速记：按「物品 + 单价」分组，两列网格收尾**

分组键 `kind|名字` → `kind|名字|金额`，`ItemGroup` 加 `amount`。只按名字合并时，浮动价
（金币、代练）会挤进一格，而一格只能印一个价，它不代表组里任何一条。

格子换了四版：浅底细边小格 → `PressTile` + 价格签（`×N` 与签同行，居中）→ 两行两列网格
（签被 `×N` 推向左边、中心错开，用户：「让图标和价格对齐，×X 放在整体后面」）→ **三列 +
第一列定宽 56 + `×N` 跨两行挂在右侧**。56 的来由：最长签「128.5万」在 `--fs-mini` 下约
53，`auto` 会让每格的 `×N` 落在不同水平位置。

**四、历史收益：四版**

    一天一行 + 点开逐条      ← 否：「角色看不清」
    按角色合计表 + 逐条全展开 ← 否：「没法看前几天的收益」
    一天一行、行内挂角色      ← 否：「下面表格可以修改或者删除某一项」
    **日期筛选 + 当天流水表 + 改/删**  ← 定稿

前三版都在解决「怎么看」，第四版才说全：**还要能改**。而「一天一行」的汇总压掉了单条的
id——没有身份就改不了、删不掉。所以顶层必须回到流水，汇总退到顶部一行（笔数 / 净额 /
当天各号小计）。数据层因此新增 `updateEntry`（只开放金额 / 物品名 / 记给谁；日期与方向
不给改）。删除走 `askConfirm`，改不走：改能再改，删不能撤回。

**五、踩到的三处**

- `display: flex` 不能挂在 `td` 上：单元格不再是 table-cell，整张表的列宽计算跟着乱。
  物品格与操作列都在 td 里包一层 span。
- `SelectField` 把空串当「没有值」，用空串表示「不指定」会让触发条退回 placeholder。
  改用只存在于这一层的哨兵值 `__none__`。
- `entries` 是 `ref`：改对象字段不触发依赖（数组没变），改完界面不动。`updateEntry`
  换整个数组。

顺带：`dayText`（今天 / 昨天 / 11月4日 / 跨年才带年份）进 `income.ts`，「昨天」走
`daysAgo` 而不是字符串减一；`item-icons.ts` 抽出「物品名 → 图标」的懒建表（`TodayDump`
与历史窗共用，各建一份会出现「今天有图、历史没图」）。

验证：`income.test.ts` 24 → **28 用例**（新增不同价分开 1 条、`dayText` 3 条）；
`vue-tsc` / `eslint` 干净；19 文件 271 用例全绿。

### 第 98 批：装备页照游戏面板重排（2026-11-04）

用户给了一张游戏「人物装备」面板的截图：「参考这个，中间暂时放空白」。

**先出三套样张再动手**（`.runtime/gear-lab/`，临时目录，验收后删）：①同位格 4 × 4；
②左右两列纵队 + 中央竖幅；③账目式 12 张横票。用户选 ①，并当场校正了位置——第一版把
主件放进了顶行，真实位是**顶行四灵饰、左列头 / 武器 / 腰带、右列项链 / 衣服 / 鞋子、
底中玉魄且"阳在左、阴在右"**（上一版写反了）。没有这一步，落地的会是一张"看着像、
位置全错"的网格。

#### 位置与清单分成两张表

`GEAR_SLOTS` 是**存储顺序**（录入、`normalizeGear` 重建、JSON 都按它），
`GEAR_LAYOUT` 是**版式坐标**。合成一张的代价在这一批里很具体：校正位置要动 `GEAR_SLOTS`，
而那个数组是存档契约——挪一格就等于让所有已存角色的第 9 位变义。

位置属于「游戏里固定的表」（CONVENTIONS §2.4-29 的判据），写进代码，不给编辑入口：
玩家对面板的记忆就是位置，换一次要重新学一遍。

#### 格子从「凸块」改成「凹槽」

旧版是 `PressTile`（凸起的一块纸），判词是「材质与工具页的图标块同一块」。这一批改掉，
理由不是好看：**装备格是「往里放」的槽**，凸块读作「已经拿出来摆着的一件」，方向相反。
现在用全局 `.well` 的四件套，只把顶壁渐变从 62% 收到 46px（109 高的格子上 62% 是 67px
的一大片灰；`.field` 对同一个问题给的是 14px）。焦点环随之从块上移到格子自己身上，
CONVENTIONS §2.4-22 的列举同步改了。

**槽里的图标仍包一层 `IconTile`**（用户同日：「装备图标外面包裹一层，类似于师门辅助这样」）。
第一版是彩色方图直接躺在槽里，看着像贴了张图；包上 54 的压印块之后才是「槽里放着一件」。
凹槽 + 凸块在这套语言里不是矛盾——`.slip-row` 那张凹票里也是这么叠的。

没图的武器与玉魄走 `PressTile` + 首字，**照 `SkillRow` 的现成写法**（`IconTile` 与一块压印块
二选一），没有给 `IconTile` 加插槽：中途试过，那等于把「空块」与「块上首字」两种画法收进通用
组件，而那一块的块面与字色是业务语义（师门朱色 = 这枚是替身，告警；装备淡墨 = 这类图还没切，
常态），组件只管材质。尺寸 54、块面 `--paper-2` 归调用方给。

### 第 100 批：三份数据层收拢成一份骨架（2026-11-04）

物价表、角色名册、收益账是**同一套写法的三份手抄**：读档分浏览器 / 桌面两条路、读失败挂

其中「首次启动把 `localStorage` 搬进 SQLite、搬成功才改名留底」那一段，物价与名册**连注释
都在解释同一件事**。

抄三份没出事，是因为每份都被人从头读过一遍。账号页与目标页要抄第四份时不会——而这类漂移
的表现不是报错，是「某一页的数据被空表覆盖」，等用户发现时原数据已经没了。

#### 抽出来的两个函数

`src/services/persist.ts`：

- `createPersist({ label, loadError, writeError, writeLocal, writeRemote })` → `persist()`：
  读失败拒绝写、浏览器写本地、桌面版异步写库，**并且排队**。
- `migrateLegacy({ storageKey, label, imported, readLegacy, saveAll, markImported })` →
  返回「这次是不是首次启动」。三态判据（`null` 不搬）、搬成功才动源数据、留底失败不能抛，
  三条都跟着搬过去，不再各写一遍。

**规则不跟着搬**：归一、排序、种子数据、`storage` 事件监听仍在各自的 store 里。骨架只回答
「怎么落地」。放在 `services/` 而不是某一页下面，是因为它跨页且直接编排 `localStorage` 与
`invoke`——`ARCHITECTURE.md` §4 的目录表已补这一行。

#### 顺带修掉的真问题：物价与名册没有写队列

收益账第 97 批就为「连点」写过一版队列（`saving` 链），理由是「两次写同时在路上，各自带着
发出那一刻的快照，先发后到就丢一笔」。同样的写法，物价与名册**没有**这条链——记价本来就是
连点（记完一件顺手记下一件），而 `pricesSave` 是异步 IPC。这不是理论风险，是三份实现里
只有一份想到了。

收拢之后三处一致，且快照在**执行时**取（不是排队那一刻），排队中的多次写拿到的是最新那份。
`desktop.ts` 每个命令都自己兜异常，链上仍加了 `catch` 保底：一旦漏出 reject，后面的 `.then`
全不执行，写入会从此静默停摆。

#### 两条防「假通过」的措施

1. **不用 `el.click()`**。合成 click 绕过命中测试——元素被浮层盖住、被 `pointer-events: none`

2. **收页面侧报错**。懒加载 chunk 404、Vue 渲染异常不会在界面上出红字，只进控制台。

#### 五条护栏

1. **连接重试 15s + 每个请求 20s 超时**。原来窗口一关，promise 永远悬着，脚本既不报错也不退出。
2. **环境问题与断言失败分开**：退出码 0 / 1 / 2，端口不通时直接给「先 `start.bat --force debug`」。
3. **`reload()` 用 `performance.timeOrigin` 判新文档**，导航窗口期的求值错误吞掉重试。
4. **就绪判据从「正文 > 10 字」改成「`.page-title` 等于页名」**。工具页整页只有 4 个字，
   旧阈值曾把它判成假红。
5. **失败自动截图**（最多 12 张）+ 报告落盘，隔天回看不用翻终端历史。

#### 断言 52 → 66，新增的都是「内存里绿、库里没落」防不住的那类

**开头先对账**：进角色页与物价页，把「页面上的条数」与 `characters_load` / `prices_load`
的行数比一遍，对不上就停在预检、一条测试数据都不写。这条是血的教训——见下面「踩到的坑」。

- 角色：建完**重载**再断言还在；删完再重载断言真没了。
- 物价：记价后重载断言 7.25 还在卡片上；删完数量核对。
- 收益：连点两笔后重载断言笔数没回落（第 100 批写队列的真场景）。
- 工具：直接改 hash 到 `#/dev`，验懒加载 chunk 到不到（7 张卡）。
- 设置：导入与清除的确认窗都在**系统文件对话框之前**。导入那一段放最后——确认窗要是坏了，
  系统窗会挡住整个 WebView，后面每一步都连坐。

#### 自收尾，而不是「跑完请你还原」

能自己收的全收：带 `E2E` 前缀的角色与物品、测试临时设的单价（右键 → 清除）、字号档位，
以及**测试写进去的流水**——历史窗的行是 `createdAt` 倒序，最新一条同物品记录一定是刚记的，
删「最新 n 条」删的是位置，不是猜测。

收不了的交给快照：开头自动 `snapshot()`，结尾把 `db restore <id> --yes` 打出来。`restore`
的三条硬约束写在代码里：应用在跑就拒绝（覆盖会把 WAL 写坏）、不带 `--yes` 只打印计划、
动手前把现状另存成 `before-restore-<时间戳>`。

#### 踩到的坑

- **报告里的分节耗时错了一轮**：`section()` 只记开始时间、汇总时用 `Date.now()` 算，
  于是每节都显示「到汇总为止」，首跑打印 204s，真实 46s。现在上一节在开下一节时收口。
- **旧脚本按文本「10万」点速记格**——那是用户的单价，不是物品名，用户改了价就点不到。
  现在按 `aria-label` 前缀（`60武器，`）定位，并区分「已有单价直接记」与「先问单价」两条路。
- **dev 里改一个文件，就能让 store 变成空表**：`roster` / `prices` 是模块级单例，`loadRoster`
  只在 `main.ts` 跑一次；Vite 热更新把模块重新求值之后，内存里是空数组、库里还是满的。
  这时第一次 `add()` 就是整份 `characters_save([新角色])`——4 个角色当场被顶掉
  （2026-11-04 实测，靠快照救回）。脚本侧已经用「开头对账」堵住；**应用侧还缺一道闸**：
  `createPersist` 只挡了「读失败」，没挡「模块被重算、还没读过库」。待定。
