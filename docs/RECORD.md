### 角色页细化（2026-11-03，第 43–59 批）

十七批集中在同一个页面，几乎每条都来自一次点测反馈。

- **页头高度**：诊断对了一半，错在「高度不该由按钮决定」——`--page-head-h` 是算出来的，页头是
  `min-height`，`lg` 三档全超（→ §2.3-2）。
- **弹窗**：用户给的 2:1:1 是**列宽比例**，不是「谁先缩谁后缩」；改成四等分轨道后上排 2/1/1、下排各
  2。格子改 `<label>`，点名字就能聚焦。删「更新时间」（手抄的字段）。
- **门派下拉**：原生 `<select>` 的问题不在配色，在浮层由系统绘制。「下拉挤压布局」其实是两件事：浮层
  `absolute` 撑大了滚动容器（容器一滚，左边标签被切掉半个字），以及 `scrollIntoView` 会把整个弹窗
  滚歪。
- **事实表进 `public/game/data/`**：加载仍是同步纯函数，组件里没有一处 `v-if="表没回来"`；切图脚本也
  改成读 JSON，否则等于把搬出去这件事说回去一半。
- **辅助技能**：56 裸图 → 40 压 48 块；辅助 / 剧情分两块；四列改五列；图标过一道「纸化」。蒙版试过
  `grayscale + multiply`（只是把深蓝换成深灰）、纯纸色纱（亮色下洗成灰白），最后是 `sepia` + 压暗纱。
- **修炼两组改名并锁只读**：改的不只是名字，是「谁来决定这一页的结构」——组名写进清单之后，它从
  「用户的数据」变成「游戏的表」（→ §2.4-29）。
- **卡上读数改用 `--num`**：墨是名目、赭是读数、朱是强调，三层不混。**删页脚说明**删的是**字段**，
  不是那三个 `<p>`——只删 DOM 的话下次还会被填回来（「携带 4 / 7」写死之后，删掉一只召唤兽仍报旧数）。

  第一条，不同类保留）并写单测盯住。

### 旧仓的定位：参考读物，不是兼容目标（2026-11-04）

用户：「我们可以参考旧项目，但是不用兼容旧项目，我们是一个全新的项目。」

这条不是新规矩，是把同日早些时候落在**数据层**的那句话（不做 SQLite → JSON 反向镜像；不读 v1 的

### 第 97 批补六：今日速记改成「图标 × 次数」（同日）

用户：「不要列表这汇总了，一个图标 × 20 这种，一眼可以看清的。」

### 第 100 批：三份数据层收拢成一份骨架（2026-11-04）

物价表、角色名册、收益账是**同一套写法的三份手抄**：读档分浏览器 / 桌面两条路、读失败挂 `loadError` 并
拒绝写、整份异步写回、失败落 `writeError`。其中「首次启动把 `localStorage` 搬进 SQLite、搬成功才改名
留底」那段，物价与名册**连注释都在解释同一件事**。抄三份没出事，是因为每份都被人从头读过一遍；账号页
与目标页要抄第四份时不会——而这类漂移的表现不是报错，是「某一页的数据被空表覆盖」。

- **抽出两个函数**（`src/services/persist.ts`）：`createPersist` → `persist()`（读失败拒绝写、浏览器写
  本地、桌面异步写库、**并且排队**）；`migrateLegacy` → 返回「是不是首次启动」（三态判据 `null` 不搬、
  搬成功才动源数据、留底失败不能抛）。**规则不跟着搬**：归一、排序、种子数据、`storage` 事件仍在各自
  的 store 里，骨架只回答「怎么落地」。
- **顺带修掉的真问题**：收益账第 97 批就为连点写过队列，理由是「两次写同时在路上，先发后到就丢一笔」；
  物价与名册**没有**这条链——而记价本来就是连点，`pricesSave` 是异步 IPC。这不是理论风险，是三份
  实现里只有一份想到了。收拢后三处一致，快照在**执行时**取。链上仍加 `catch` 保底：一旦漏出 reject，
  后面的 `.then` 全不执行，写入会从此静默停摆。

### 第 109 批：月历纸片离开弹窗的裁剪上下文（2026-11-05）

用户一张截图：「日期选择被切割了，没展示完全」——月历只露出三行半，下面连同「回到今天」一起
没了，而弹窗本身看起来很正常。

**根因不是尺寸，是裁剪上下文。** `ModalShell` 的 `.modal-body` 是 `overflow-y: auto`（历史窗的
流水会长，正文必须能滚），它同时就是一道裁剪边界；纸片是 `position: absolute` 长在触发条下面，
超出正文高度的部分被齐刀切掉。历史窗只有两条流水时正文约 260 高、月历约 300 高——所以它永远
差那三行。这个坑 `ModalShell` 自己的注释里写过（`scroll: false` 就是为它准备的），但那条路对
历史窗走不通：内容确实会长。

**改法：纸片 `Teleport` 到 body、改 `fixed`。** 控件自己离开裁剪上下文，顺带任何弹窗、任何
滚动卡片里放它都不会再被切。落位由 `placePanel()` 按触发条的视口坐标算：横向右端出界就整体
往左收，纵向下不够就翻上去，两边都不够才夹进视口（宁可盖住触发条，也不许跑出屏幕）；滚动与
resize 用 rAF 节流重新量——`fixed` 元素不会跟着滚动容器走，不重量就悬在原地指着一块空白。

连带三处必须一起改，漏一个就出问题：

- **`z-index` 20 → 85**。它现在与弹窗遮罩（80）是 body 下的兄弟，不高过遮罩就整块看不见；
  仍低于提示层（90）——「刚刚那下成了没有」比一张没选完的月历更急。

  一查 `panel.contains(active)` 为假就把焦点拽回窗内第一个控件——用户从月历离开会突然跳到标题旁
  那枚按钮上。

### 第 110 批：历史窗给高度下限，滚动交给表格（2026-11-05）

用户：「历史弹窗加个高度吧，不然高度太低不好看；列表太多了可以滚动」。原来的窗跟着内容长，
两条记录时只有约 385 高、配 720 宽像一张扁纸条。

**先试了定高 620，被否。** 定高把「矮」换成了「空」：两条记录占不满，下面留出近 400 的空白，
读起来像还没加载完——比原来的矮更难看。所以改成**下限**：`min-height: min(520px, 100vh − 48px)`。
记录少时它托住一个体面的高度，记录多时自己长，长到 `max-height` 之后再滚。**定高和下限的差别
不是数值，是「空出来的那部分该由谁来定」**。

**`ModalShell` 加两个 prop**（`minHeight`、`fill`），都不传就是原来的行为：

- `minHeight` → `--modal-min-h` → `.modal-panel { min-height: … }`；
- `fill` → 正文变成纵向 flex 容器 + `overflow: hidden`，滚动交给调用方内部那个容器。表格类窗要
  这个：筛选条与汇总行钉在顶上，一天三十笔时翻到底想换个日期，不必先滚回顶部。

历史窗的对应改动是 `表格包进 .log-scroll`（`flex: 1` + **`min-height: 0`**——flex 子项默认的
`min-height: auto` 会被内容顶开，写多少高度都拦不住它把窗撑长），表头 `sticky` 吸顶。

**三处细节是踩出来的，不是设计的**：

- **表头的线用 `box-shadow` 画，不用 `border-bottom`**：sticky 元素滚动时边框跟着内容走，
  读起来像一条悬在两行之间的线。背景必须是不透明纸色，半透明时下面的行会从表头里透出来。
- **滚动条占的那 10px**：`.modal-body-fill` 让出 `16 − --scrollbar-w`，`.log-scroll` 配
  `scrollbar-gutter: stable` 让轨道常驻——两边一抵，表格右缘与页脚对齐（实测 983 / 983），
  而且记录从 1 条变 20 条时表格不会横向跳一下。试过「负外边距 + padding」，那会把轨道一起推出
  内衬，反而错开 10px。
- **行高 4 → 7**（行高约 34）：4 的时候两枚 26 高的操作按钮把行撑得比字高出一截，四边留白不匀，
  整张表读作「一条条挤在一起」。这也是「高度太低」的一半——用户说的不只是窗，也是行。

**验证**：`npm run check` 六项全绿（23 文件 / 287 用例）；`npm run e2e` **89 通过 / 0 失败 /
15 提示 / 64.1s**，控制台零报错。新增两条断言都量结构、不造假数据：① 窗高 ≥ 500（两条记录
也不缩成一小块）；② 正文「自己不滚」而表格「自己滚」（`bodyOverflow === hidden` 且
`boxOverflow === auto`）——后者才是 `fill` 的契约。另外用探针在 27 行（克隆 DOM，刷新即消）下
量过：可滚、表头吸顶、面板定在 772（`max-height`）、表格右缘与页脚对齐。

### 第 112 批：账号页落地，人民币与梦幻币两本账（2026-11-05）

用户要「做账号页，参考下旧项目的功能和样式」。旧仓那三件（`AccountsPage` /
`AccountEditor` / `AccountRecords`，1399 行）读完之后，照着它的**功能**做、按新仓的**语言**
重画。动手前先问了两件事，答案决定了数据模型：**双币种全量（照旧仓）**、**不要手续费、
保留交易渠道**。

**一、为什么是两张表，不是在 `income_entries` 上加一列**

收益页记的是「打金产出」（按物品、梦幻币、无渠道），账号页记的是「钱包进出」（按分类与渠道、
两种币）。共表之后每一行都要回答「这行的 amount 是万还是元、有没有渠道」，而这两个判断
漏一次就是把某一笔按错单位算——不报错，只是总数悄悄不对。两张表各自字段固定，
`account_entries` 多出 `currency` / `category` / `channel` 三列，收益表一列不动。

`amount` 的单位**跟着 `currency` 走**：`rmb` 存元、`cash` 存原值（万 × 10000，与收益页、
物价同口径）。统一成一种单位反而会出现「1 元 = 1 万」这种中间态，而两本账从不相加，
本来也没有统一的必要。

**二、两本账绝不合成一个「总收支」**

页面上并排两张卡（收入 / 支出 / 差额 / 笔数），`accountStats(entries, currency)` 只数本币种。
旧仓的注释写得很对：「把元和新台币式的万混加在一起没有意义」。这条在代码里就是那个
`if (one.currency !== currency) continue`。

**三、金额的两个精度**

人民币收到**分**、梦幻币收到**整数**（`quantize`）。这不是顺手取整：浮点尾巴
（`46000.000000001`）会让同额的两笔在汇总时差一点点，差值落在小数第 15 位时人只会看到
「总数不对」。人民币保留两位则是因为它有分——把 30.5 记成 31 就是替用户改账。

校验一律**先换算、再判正**：反过来会让 `0.00001` 万过关、落成 `0`，而 `0` 在
`normalizeEntry` 里是「丢掉」——用户点了保存、提示说记上了、重启后那条不见了。
（同一个坑第 97 批在收益页踩过一次。）

**四、快捷记账十一个块**

记账号收支的难处不在金额，在**四个字段要对**：方向 / 币种 / 分类 / 渠道。连着点四个下拉，
点错哪个都不会报错。所以按「这个游戏里钱的所有走法」摆成十一个块：藏宝阁买卖装备与召唤兽、
点卡的两条路（官方充值花人民币、游戏内买卡花梦幻币）、游戏币买卖、养成投入、游戏产出、
兜底的其他。点一下把四个字段填好，只差金额。

是同一件事。入口的 hint 写「游戏内 · 梦幻币 · 一次性」——它是给懒得逐件速记的那天用的，

### 第 115 批：目标页落地，三种目标一张卡（2026-11-05）

八页里最后一块。用户先要「研究旧仓的目标功能，给个方案」，看完 HTML 样张后定了三条：
**存钱先手动**、**装备就是「买了几件，买了就完成」**、**全部角色用快照，删角色时要提示**。
旧仓那套（`domain/goals.js` 452 行 + 六个组件 2307 行）读了，照着口径抄，界面按新仓的语言重画。

**一、三种类型，两种算法**

养成读角色档案（每次打开现算），存钱与装备记流水（累加）。共用一张 `goals` 表、一个
`goalSummary`，区别只在「数从哪来」。这决定了三件事：

- **不存进度**。档案是唯一真源，目标只是「许了什么」。存一份「进度」就等于存了第二份真源，
  两边一旦不同步，界面上就会出现「档案 21 级、目标说 23 级」。
- **状态是推出来的**。`current >= target` 即达成——装备买够件数就是完成，不需要再点一次
  「标记完成」。删掉最后一笔流水就自动回到进行中。旧仓那套 `status` + `doneAt` +「恢复进行」
  是为「提前结案」留的口子，这次没有那个需求；多一个可写字段，就多一条能被写坏的状态。
- **超额封顶、未达成最多 99%**。`current = Σ min(target, value)`：一个号练到 40 不能替另一个
  号的 10 抵账。这两条不是新发明，是旧仓 `goalSummary` 里最值得照抄的两句——它们让卡片上的
  数回答的是「每个人到没到」，而不是「加起来够不够」。

**二、快照，以及删角色时那半句话**

「全部角色」在建目标那一刻抄成 `members: [{id, name}]`。后加的人不进来（目标许的是
「这几个人练到多少」），名字一起抄（人删了之后那行还得读得出是谁）。

删角色时如果被 N 个目标引用，确认窗里把那几个目标的标题列出来——不说的话，用户是回到目标页
才发现「5 个角色达标」变成了「4 个」。删掉之后成员行保留、标「已删除」、**不计入分母**：
分母里留一个永远补不上的人，目标永远到不了 100%。

**三、装备就是「买了几件」**

用户原话：「就一个进度，购买了就完成，几件装备几个进度」。于是装备卡上第一枚按钮是
**「买了一件」**，点一下 +1，不弹窗——买完就完成的那一下不该穿过一张表单。买满那一刻自动
盖章，筛选从「进行中」切到「全部」，否则卡片就在点完的瞬间从眼前消失（第一次走查就是这么
发现的，用户会以为记丢了）。

**四、走查里改掉的四处（都是自己的 bug）**

- **弹窗里存的是整条目标**，写回后外面那个对象是旧的：流水窗里刚记的一笔不进「当前」。
  改成弹窗只记 id、目标从 store 现查。
- **回车不提交**。`PressButton` 是 `type="button"`，表单没有提交键，浏览器不做隐式提交。
  三个表单（新建 / 记一笔 / 更新养成）各接一次 `keydown.enter`；新建那张只认 `INPUT`，
  否则在下拉纸片里按回车会把目标建掉。
- **卡片没有纸片边**。`.goal` 只写了 `background: var(--paper)`，而页面底色就是 `--paper`，
  整张卡读起来像一段浮在纸上的字。补 `.frame`（与账号页的卡同一个外壳）。
- **达成后卡片消失**。默认筛选是「进行中」，第 3 件买完那一下卡片就没了。`announce()` 在
  「刚达成」时把筛选切到「全部」。

另有一处是**测试自己错**：`.log` 这个类名卡片上的「最近三笔」也在用，流水窗一数就是 6 条。
给窗里的行改名 `.log-row`——不是测试迁就实现，是这个名字本来就该更具体。

**五、范围**

按用户定的三条，这一批**不接账号账本**（存钱仍手记流水）。账本记的是钱包进出，目标问的是
攒够了没有，口径没对齐之前硬接，会把充值也算成进度。接的时候要先定「算净额还是算余额、
从哪天起算、按不按角色分」。

排序也没有手动拖：进行中在前、有期限的按近的在前。旧仓的拖拽 + 方向键换来一条看不见的
`sortOrder` 与一整块拖放代码，而目标的自然读法是「快要到期的、还差得多的先看」。

- 换过去的：`LedgerSection`（八页的区块）、账号的 `filters` / `book`、目标的 `goal`、捉鬼的
  `map-card` / `side-block` / `detail-block`、角色卡 `.char`。
- **`.frame` 没有删，收窄成浮层专用**（角色编辑器、捉鬼测试面板）：盖在纸上的东西仍是线框。

**三、斜对角渐变与纸色（三轮反馈才定稿）**

卡片底色从纯色改成「左上偏光 + 135° 斜向渐变」两层，与角色卡的门派浅染同向，全站的纸朝同一个光源。
幅度调了三轮——用户每次都是在真界面里看出来的，光靠算阶数判断不了：

| 轮次 | 亮色      | 暗色      | 用户原话                                   |
| ---- | --------- | --------- | ------------------------------------------ |
| 一   | 4 / 8     | 14 / 12   | 「亮色下渐变不明显，暗色两个斜角对比太大」 |
| 二   | 4 / 12    | 7 / 6     | 「还是有一点差距过大」                     |
| 三   | **3 / 9** | **4 / 4** | 「亮色可以取不那么白的」                   |

第三条不是渐变，是**卡面纸色**：亮色从纯纸白 `--paper`（#f8f3e6）换到 `--paper-2`（#f2ead6）。
纯纸白压在台面 `--well`（#e7dcc0）上太白，一张张读作「打了灯的板子」；`--paper-2` 正好是
「纸 → 台面」的中间档，纸的温度还在又不刺眼。**没有新造色号**，它就是「比纸深一档的纸」。

落地方式是加一个 `--board-paper`：`.board` 亮色取 `--paper-2`、暗色换回 `--paper`，底色与渐变

换成它——否则角色卡会比其他卡白一档，一眼看出不是同一张纸（这一天最后改的就是这处）。

暗色的左上偏光一路收：100% → 62% → 54%，只负责把左上角提亮半档。

### 第 121 批：给写盘补第二道闸——「还没读过库」不许写（2026-11-05）

用户：「先处理 AB」。

**缺口长什么样**：`services/persist.ts` 的闸只认 `loadError` 非空。那说的是「读了但失败」，
管不到「读这件事根本没发生」。`npm run dev` 里改一个文件，store 模块被 HMR 重算、模块级单例
回到空数组，而 `loadPrices()` / `loadRoster()` 只在 `main.ts` 启动时跑过——这时 `loadError`
是空串，界面看起来正常，点一下「记价」写下去的就是「整份空表 + 这一件」。第 103 批在名册上
实测丢过 4 个角色，靠库快照救回；当时给烟测补了「开头对账」，应用侧一直敞着。

**做法**：`PersistOptions` 加 `loaded: Ref<boolean>`，五个 store（物价 / 名册 / 收益 / 账号 /
目标）在读档成功后置真；`persist()` 在 `!loaded` 时拒绝写入。两条闸各管一件事，都留着：
`loadError` 说「这一次读坏了」，`loaded` 说「还没轮到你写」。

**为什么在 store 里置位，不在 persist 里自己判断**：只有读档那一侧知道「跑完了」，persist 拿到
的只是一个函数引用。所以五处各加一行——这也是这个设计最脆的地方，漏一处就等于那个 store
永远不能写，于是**每条读档分支都要覆盖到**：浏览器路径里「没存过」也算读过（空表是结论，
不是失败），桌面路径在 `loadError.value = ''` 旁边置位。

**文案单独写一句**：「这一页还没读到数据，刷新一次再记」。不用旁边那条「检查一下磁盘空间」
——那条说的是磁盘，会把人引到完全无关的地方去。

**测试**：`persist.test.ts` 补两条（没读过 → 一个字节都不写、且提示里不许出现「磁盘」；
读过 → 照常写），`prices-store.test.ts` 补一条 store 级（只 import 不读档就 `addItem`，
内存里有、库里没有）。单测从 382 → 385。

**已知取舍**：dev 里 HMR 之后第一次保存会被拒，要刷新一次。生产没有 HMR，读档一定先于任何
一次点击，所以这条闸在发布版里永远不会触发——它是给「代码被热替换」这个只在开发时存在的
状态兜底的。

**验证**：`npm run check` **27 文件 / 385 用例全过**；`npm run e2e` **150 通过 / 0 失败**。

**版本**：`tauri-specta` 只有 rc（最新 `2.0.0-rc.26`），且 crate 文档要求 specta 系**全部用 `=`
钉死**，否则下一次 rc 一发就编译不过。所以 Cargo.toml 里三条都带 `=`：
`tauri-specta =2.0.0-rc.26` / `specta =2.0.0-rc.26` / `specta-typescript =0.0.13`。

**接法**：`lib.rs` 的 `command_table()` 用 `collect_commands!` 返回一个 `Builder`，

`collect_commands!` 里出现一个未定义符号就整表编不过。

**三个必须显式改的默认值**（都写在 `command_table()` 的注释里）：

| 默认值                               | 为什么不行                                                           | 改成                                                                |
| ------------------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------- |
| i64 一律拒收（怕 JS 精度丢失）       | 时间戳 / 句柄全是 i64，不放开整个导出直接报错                        | `dangerously_cast_bigints_to_number`                                |
| 错误模式 `Result`（返回 `{status}`） | 前端每个调用点都要读 `status`，等于重写一遍                          | `ErrorHandlingMode::Throw`（Err 即 reject，与原来的 `invoke` 一致） |
| —                                    | `serde_json::Value` 的 `Type` 实现挂在 specta 的 `serde_json` 特性上 | 开特性                                                              |

**改到的文件**：17 条命令加 `#[specta::specta]`；`AppInfo` / `PriceItem` / `PricePoint` /
`IncomeEntry` / `QuickPrice` / `IncomePayload` / `AccountEntry` / `ImportSummary` / `ClearSummary` /
`WindowInfo` / `Roi` / `ProbeResult` / `TextLine` 加 `specta::Type`；前端 `desktop.ts` 删掉五个
`<T>` 泛型（类型改由契约给），`ghost.ts` 一并换成 `commands.*`。

**生成物入库，但不参与格式与 lint**：`src/services/bindings.ts` 21 KB，每次 debug 启动重写。
`.prettierignore` 与 `eslint.config.js` 各加一条——生成器用 tab 与不带引号的键，交给 prettier
只会每跑一次窗口就产生一份无意义的 diff。

**契约测试重写成三层对账**（6 → 7 条）：Rust `collect_commands!` → `bindings.ts` 里的
`__TAURI_INVOKE("名字")` → 前端 `commands.xxx(`。新增两条正是原来抓不到的那两种：
**生成物落后**（改了 Rust 没起过窗口，类型看着对、调下去 command not found）与
**前端又写回裸 `invoke`**。后者判之前要先去注释——`desktop.ts` 的注释里就写着
「原先这里逐个手写 `invoke<T>('prices_load')`」，那是解释不是调用，第一版就这么假红了。

**一处差点写错的结论**：`TextLine.score` 生成的类型是 `number | null`，我先以为是
`#[serde(default)]` 造成的、删掉它就好了——删完再生成，还是 `number | null`。真正的原因是
**specta-typescript 对所有浮点数的规矩**：JSON 装不下 `NaN` / `Infinity`，serde 会把它们写成
`null`，所以浮点一律渲染成可空。删 `default` 另有理由（这个结构没有 `Deserialize`，`default`
只影响读；留着它反而让生成物多出一对 `_Serialize` / `_Deserialize`），但**与可空无关**，
注释里把两件事分开写清了。收窄放在 `ghost.ts` 的边界上（`score: line.score ?? 0`），
不让一个理论上存在的 `null` 渗进整条渲染链。

`npm run e2e` **150 通过 / 0 失败 / 15 提示**，控制台零报错——这一条最要紧：17 条命令全部

**一、单价为什么单独一份文件**

整本账的导出已经包含 `quickPrices`，但用它改价目是错的工具：为了改一个价，得先导一份

**二、分工：Rust 管文件，前端管合并**

- 导出：前端把内存里的价目递进命令（内存那份就是真值，每次改价都已整份落盘），Rust 只

  是白走一步。
- 导入：Rust 弹「打开」、看大小（4 MB 上限）、认信封、逐条校验（`itemId > 0`、价是有限

  `persist()`）。这样「导入」这条路上不存在「库里改了、内存没改」的中间态。
- 合并语义：**同一件物品以文件为准，文件里没有的保持现状**。单价是价目表不是账，把文件里

### 第 130 批：原子组件卡写死高度、两栏分滚、目录改成一张表（2026-11-06）

用户：「原子组件 这个卡片，高度直接设置死吧，然后左右两边分开滚动。并且优化下 原子组件

**一、`LedgerSection` 多一个 `height`（写死高度）**

上一批只有 `max-height`：它管「长了不超出」，管不住「短了缩回去」。而这张卡切组时内容高矮
不同（「选择」六件 vs「提示」一件），卡高跟着跳，它上下那些卡全在动。`height` 是同一件事的
另一头——高度恒定，切组纹丝不动。两者互斥，`height` 优先。

写死之后 **`section-body` 自己不滚**，否则卡片里会有一圈滚动条、内容里再套两圈。它退回纯容器，
`tabindex` 也不给（这一层不再可滚，把 Tab 停靠点挂在这里等于给一个按不动的滚动区）。开发页
四张清单卡仍用 `max-height`（内容多就滚、少就矮，那是清单该有的样子）；只有原子组件这张用
`height="60vh"`。

**二、两栏各滚各的**

`.atoms-split` 撑满 body（`height: 100%` + `min-height: 0`，grid 子项不给 `min-height`
就会被内容顶开、`overflow` 永不触发），`.atoms-nav` 与 `.kit` 各 `overflow: auto`。
结果：目录右缘那道竖线钉在原处，右栏滚到底也不会把目录一起带走——左栏本来就是「我在哪一组」

右栏 564 / 404（滚）；把 `--section-h` 临时压到 120 复验：nav 168 / 56、kit 564 / 56、
body 56 / 56——三处各自滚，互不牵连。切到「提示」组再量，卡仍是 468。

卡的内边距里，内容宽度不变。色板、图标、字号、票面行四张卡一并受益——它们都用这条。

八款同一份数据、同为 132 列宽：账线（当时的现行）、极简无框、书籍目录、朱印序号、
折角书签、压印块、竖槽拨档、胶囊条。点任意一行八张卡同步，右上可切亮暗与字号。
能一次比出来，靠的是**同一选中位置**——各卡独立选的话，比的是八种颜色搭配而不是八种结构。

三处是在样张里才发现要修的：

- **折角书签**只 `clip-path` 切角时，切角露出的是卡面，与行底几乎同色，等于没切 →
  补一枚小三角（比行底暗一档 + 斜边线）才读得出「折了一角」。
- **压印块**最初与卡面同色，只靠内棱，五块糊成一片 → 行底提亮到 `paper-2` 混 `paper-base`
  （84%），再加一道下沿暗边。
- **胶囊条**最初只有选中那枚是药丸（未选中的格是透明的），与竖槽拨档看不出区别 →
  未选中也给淡底 + 一缕细边，五枚药丸才成立。

**二、落地：`.atoms-nav` 从「一列 + 右缘竖线」变成「一条凹槽」**

|                | 之前（第 130 批）                         | 现在                                                      |
| -------------- | ----------------------------------------- | --------------------------------------------------------- |
| 边界           | 右缘一道 1px 竖线 + `padding-right: 12px` | 槽本身：`--well` 底 + `inset 0 1px 3px` 内阴影 + 6px 圆角 |
| 行高           | 32，无隙（gap 2）                         | **27，无隙**（槽内 3px padding，五行 141）                |
| 行壳           | 1px 透明描边 + 3px 圆角                   | 无描边 + 4px 圆角                                         |
| 选中           | `--well` 55% 底 + 细框 + 2px 朱线         | **朱印**：`--seal` 底 + 顶上一条内高光 + 下方投影         |
| 悬停           | `--well` 45%                              | `--paper` 24%（槽里浮起一层纸）                           |
| 名字与件数之间 | 一道 1px 账线                             | **撤掉**，件数 `margin-left: auto` 靠右                   |

撤账线的理由：槽已经画出了左右边界，再横一道线，一格之内就是两条线在抢。
样张里那版没有账线，落地也照它——**别在落地时把样张里没有的东西加回去**。

**三、三个必须写的细节**

1. **`align-self: start`**。grid 子项默认 `stretch`，槽会被拉到整列 404 高，下面空出
   两百多像素的空槽。那不是控件，是一块没画完的底。槽只有 141，浅色下看得出来，暗色下
   更明显（一大片 `--well` 比卡面深）。
2. **朱底上的焦点环换 `--ring-inv`**。`--ring` 是朱色，画在朱印上等于没有环；而目录整组
   只占一个 Tab 停靠点，这一环恰好出现在「当前这一格」上——正是最容易被误认为「没焦点」
   的地方。与 `SegmentedPills` 的选中格同一条规矩。
3. **悬停不许比选中更重**。悬停只是「槽里浮起一层纸」（24% 的纸色），选中才是印。
   两者都做底色时，鼠标划过就像已经切过去了（第 130 批之前犯过这个错，那次是 hover 与
   on 同为 `--bg`）。

字仍然不动字重：文楷只有 Regular，600 是浏览器合成，会把撇捺糊成块；「选中的是这一格」
由这枚朱印说完。

- 量的数（1280 × 780）：卡 **468**（不变）、槽 **132 × 141**（五行 27 + 槽 6）、槽不滚、

- 键盘：`ArrowDown` 换组后焦点跟到新格（`document.activeElement` 是 `.nav-item.on`），

- 亮 / 暗各截图：暗色下槽比卡面深、朱印是亮橙红压深字（`--on-seal`），与 PressTile 一致。

### 第 132 批：左栏改用全局 `.well` / `.stamp`，边距放开（2026-11-06）

用户两句：「3D 效果不是很明显，优化」「3D 效果可以参考下我们其他 3D 组件，菜单项的
上下左右边距稍微大一点，别太挤」。

**一、为什么第一版 3D 不明显：手写了一套本该复用的材质**

第 131 批的槽与印是我现写的：槽 = `--well` 底 + 一道上内阴影；印 = 朱底 + 上沿高光 +
一道软影。而 `base.css` 里早就有一整套：

| 类              | 给什么                                                    | 谁在用                             |
| --------------- | --------------------------------------------------------- | ---------------------------------- |
| `.well`         | 金边 + `--well` 底 + 上暗渐变 + 上沿内影 + 下沿**亮**高光 | 输入格、槽按钮、胶囊轨道、两格开关 |
| `.well.upright` | 竖槽：暗面挪到**左壁**、顶影加深、右侧一道反光            | 侧栏竖槽（`VerticalSlider`）       |
| `.stamp`        | 朱底 + **9px 像素受光带** + 上沿高光 + 落地线 + 朱色投影  | 滑块拇指、胶囊选中、槽按钮悬停     |

差的正是那几件：`.stamp` 的受光带是**像素**（9px）而不是百分比，底部一整段渐变到
`--bevel-lo`（背光面），再加一条 1px 落地线——这三样合起来才是「一块按进纸里的印」。
我手写的那版只有「上亮 + 软影」，缺背光面与落地线，所以读作贴纸。

改法：`<nav class="atoms-nav well upright">`，选中格同时挂 `on` 与 `stamp`，
`.atoms-nav` / `.nav-item.on` 里**一行深度都不写**，只留几何与字色。
这也回到那条规矩：**凹槽只有一处真源，改厚度只改 `base.css` 那几行。**

**二、一个必须绕开的坑：scoped 会把 `.stamp` 擦掉**

`.nav-item { background: none }` 在 scoped 里编译成 `.nav-item[data-v-x]`，特异性比全局
`.stamp` 高一档——朱底会被整条抹掉，只剩印面那层渐变浮在槽上（截图里是一块半透明的红雾）。
改成只有**未选中**才擦底：

```css
.nav-item:not(.on) {
    background: none;
}
.nav-item:hover:not(.on) {
    background-color: color-mix(in srgb, var(--paper) 42%, transparent);
}
```

悬停也必须带 `:not(.on)`，否则选中项被划过时，悬停那层淡纸会盖住朱印。

**三、边距（用户：「稍微大一点，别太挤」）**

|          | 131 批 | 现在        |
| -------- | ------ | ----------- |
| 槽内衬   | 3      | **5**       |
| 格高     | 27     | **32**      |
| 格间     | 0      | **2**       |
| 行内左右 | 7 / 8  | **10 / 12** |
| 五行合计 | 141    | **178**     |

178 仍在 404 里（字号 1.1 时 194），槽照样铺满、下面那截是「这一栏的底」。

**四、铺满这件事是上一轮做的，这一轮才看出它为什么不够**

131 批已经把 `align-self` 从 `start` 改成 `stretch`，但**光有底色铺满还不够**：
`--well` 与卡面只差一档，一大片平色读作「一块浅色板」。这一轮补上的是 `.well` 的
**金边**（1px `--rule-2` 80%）与 **左壁暗**（`.upright` 的水平渐变），左栏才真正成为
「一列凹进去的侧栏」——分区靠的不是面积，是**边缘**。

**验证**

- `npm run check` **32 文件 / 416 用例全过**；`npm run build` 通过。
- 量的数（1280 × 780）：卡 **468**、切到「提示」组后仍 **468**；槽 **404**（铺满）、
  行高 **32**、行距 **2**、槽内衬 **5**、行左内距 **12**；槽底 = `--well`（rgb 231,220,192）、
  槽边 1px `--rule-2` 80%、未选中行透明。
- 亮 / 暗各截图，左栏 3 倍放大核对：金边 + 左壁暗 + 上影 + 下沿亮边四件齐；
  朱印有 9px 受光带、背光面与落地线，与右栏那排 `.bevel-pill` 是同一套物理。
- **烟测未跑**：纯展示结构。

### 第 133 批：原子组件左栏改成主侧栏那套——槽 + 滑动朱印（2026-11-06）

用户：「感觉都不太行，你直接复制，我们现在项目整体的 左侧菜单栏吧，只不过要把菜单项从竖的
改成横的」。

前两轮绕了路：132 批在处理「阴影收口」，还做了八版边缘样张；131 批做了八款菜单风格样张，
用户选了「竖槽拨档」。两轮都在**调这一处的手写参数**，而项目里早有一个跑了很久的答案——
主侧栏 `AppRail` 里的 `VerticalSlider`。这批就是把它搬过来。

**一、三样东西一一对应**

| 主侧栏                                           | 这一栏                                           | 出处            |
| ------------------------------------------------ | ------------------------------------------------ | --------------- |
| `.vs-track.well.upright`                         | `.atoms-nav.well.upright`                        | 全局 `base.css` |
| `.vs-thumb.stamp`（绝对定位、`translateY` 滑动） | `.nav-thumb.stamp`                               | 同上            |
| `.vs-cell`（图标 + 竖排两字，格 62）             | `.nav-item`（图标 + **横排**两字 + 件数，格 34） | 本组件          |

格高 34 而不是 62：那边 62 是「图标 15 + 间距 7 + 两字竖排 32 + 字距」撑出来的，
这里横排，34 就够。槽宽仍是 132（主侧栏 34），因为它是一列目录而不是 34 宽的窄条。

**二、真正换掉的是「印」的挂法，不是参数**

上一版（131/132 批）让**选中的那一格自己挂 `.stamp`**。两个后果：

1. 得靠 `.nav-item:not(.on) { background: none }` 绕开 scoped 特异性压掉全局 `.stamp`
   的坑（132 批为此写过一段注释）——一个选择器为了「别踩到别人」而加条件；
2. 「选中的是哪一格」变成了「哪一格挂了 stamp 类」，切换瞬间是**旧印消失 + 新印出现**，
   没有位移。而主侧栏那一枚是滑过去的。

改成独立拇指层之后两件事一起没了：格永远透明（`background: none` 可以放心写，
因为朱底根本不在这一层），切换是一次 `translateY` 过渡（`--t-slide` / `--ease-snap`，
与 `VerticalSlider` 同一条曲线）。**「选中的是哪一组」收回成一处：印在哪。**

**三、组号换成图标**

照主侧栏的样子：图标在左、标签在中。五组的图标按「手上那个动作」挑，与组名同源：

| 组   | 图标     | 为什么            |
| ---- | -------- | ----------------- |
| 选择 | `check`  | 勾选 = 挑定一个   |
| 输入 | `edit`   | 铅笔 = 填一个值   |
| 操作 | `play`   | 播放 = 让它跑起来 |
| 读数 | `growth` | 折线 = 读出来的数 |
| 提示 | `info`   | 圆圈 i = 提示     |

`KIT_GROUPS` 加 `icon: IconName` 一栏（类型来自 `components/icons.ts`，拼错在 `vue-tsc`
就红，不会等到界面上是一个空图标）。组号 `01–05` 由此撤掉——主侧栏没有编号，
编号在这一栏里也只是「目录的目录」，五组本来一眼数得完。

**四、尺寸**

槽内衬 4、格高 34、格间 3、行内左右 12 / 11、图标 15、图标与字间距 9（都乘 `--fs-scale`）：

- 五行合计 `8 + 34 × 5 + 3 × 4 = 190`，字号 1.1 时 206，仍在 404 里；
- 槽 `align-self: stretch` 照旧铺满整列（130 批那条要求），底下那截空槽是「这一栏的底」；
- `overflow: auto` 留着当退路：真加到十组时它自己滚，不会顶出卡片。

**验证**

- 量的数（1280 × 780）：卡 **468**、槽 **404 铺满**、格 **34**、格间 **3**、印高 **34**；
  点「提示」后印顶 **489** = 第五格顶 **489**（`translateY` 落点精确到整格，不差半像素）。
