# 游戏资源规范（GAME-ASSETS）

> **一句话**：凡是「梦幻西游本身长什么样、有什么东西」，进 `public/game/`；
> 凡是「我们怎么读它、怎么判断」，留在代码里。
>
> 目的只有一个——游戏改版时，**换文件，不改代码**。

## 1. 判据：什么东西算「游戏资源」

三条全部满足才进 `public/game/`：

1. **内容变了，我们的代码一行都不用改**。换一张底图、加一个门派，改的是文件与清单，
   不是 `.ts`。做不到这条，说明它其实是逻辑。
2. **内容来自游戏，不是我们编的**。门派名、地图名、坐标域上限、任务句式——这些是
   客观事实，游戏更新就变；而「高概率区域画 24% 红」是我们的设计决定，不是游戏事实。
3. **丢了它，应用应该「少一块」而不是「崩掉」**。资源缺失要退化成空状态；
   缺了就跑不起来的东西是依赖，不是资源。

反向判据更好用：**「游戏改版后我需要改代码吗？」**——要改的，就是代码。

## 2. 目录

```
public/game/
├── README.md        往哪放、怎么换（给改资源的人看）
├── maps/            地图底图 + 清单
│   ├── maps.json
│   └── *.webp
├── icons/           游戏内图标（技能 21、剧情 11、特技 69、门派技能 147）+ README
│   ├── *.webp
│   ├── items/       速记物品 59 张（`item-<id>.png`，id 即单价表的键）
│   └── gear/        装备 83 张（`gear-<部位>-<序号>.webp`，7 个部位，60 级以上）
└── data/            游戏事实数据 + 资源清单
    ├── icons.json   图标「文件 → 名字」清单（生活/剧情/特技，`slice.py` 生成，不手改）
    ├── school-icons.json 图标清单（门派技能，`slice-school.py` 生成，不手改）
    ├── gear-icons.json   图标清单（装备，`slice-gear.py` 生成，不手改）
    ├── schools.json 门派 21 家 + 每家的七项门派技能 + 上限（`cap`）
    ├── skills.json  生活技能 21 项、剧情技能 11 项（有序名录，下标即图标序号）
    ├── quick-items.json 速记物品 59 件（固定价 38 / 浮动价 21）+ 图标文件名
    └── *.json       以后：装备、道具
```

三个子目录各有一份 README 写「放什么、怎么命名」。这份文档写**规则本身**。

那三份 README 会随 `npm run build` 一起进 `dist/`（合计约 4KB）——这是有意的：
它们是给「半年后往这里丢一张 png 的人」看的，放在目录里才会被看到，放在 `docs/` 里
只会被忘掉。4KB 换一条规则可见，划算。

## 3. 三条硬规则

### 3.1 放 `public/`，不放 `src/`

Vite 会把 `src/` 里的资源**改名加哈希**（`aolaiguo-a1b2c3.webp`）。游戏资源必须
**文件名稳定**：清单里写的是文件名，替换后要还能对上。`public/` 是 Vite 唯一
「原样拷贝、不改名」的目录。

代价：不经打包器优化、没有缓存指纹、拿不到 `import` 的类型检查。对一批**会随游戏
版本整体更换**的文件，这个代价划算。

### 3.2 目录只在代码里写一次

清单里**只写文件名**，目录由加载函数拼：

```ts
// src/services/ghost-maps.ts
const MAP_DIR = `${import.meta.env.BASE_URL}game/maps/`;
```

```json
{ "id": "aolaiguo", "name": "傲来国", "img": "aolaiguo.webp" }
```

不写 `"img": "/game/maps/aolaiguo.webp"`。原因不是洁癖：目录名会重复进 20 条记录，
换一次目录要改 21 处，**漏掉的那一条只有运行到那张地图时才会 404**——而那时页面
一切正常，只是不显示底图。

同理，`import.meta.env.BASE_URL` 不能省。写死 `/game/maps/` 在当前的 `base: '/'` 下
等价，但换子路径部署时会整体失效，且没有任何报错。

**已知例外**：四个测试文件里有 `import mapsFile from '../../public/game/maps/maps.json'`。
那是模块解析，路径必须是字面量（换成变量就读不到 JSON 了），改目录时按 IDE 的全局替换
一次改完即可。除此之外，**同一个文件里不许再写第二个路径常量**——
`ghost-maps.test.ts` 因此改用 `readFileSync`，让目录只出现一次。

### 3.3 文件与清单同目录

`maps.json` 和那 20 张 webp 必须住在一起。这是**唯一能保证「改一份忘一份」的窗口期
只有一次编辑动作**的办法：加一条记录却忘了放图，`npm run check` 当场失败——
`src/services/ghost-maps.test.ts` 有四条断言盯着这件事：**缺图**（清单有、目录没有）、
**孤儿图**（目录有、清单没有）、**`img` 带了目录**、**id 重复**。四条都读真实目录，
不是手搓的假清单——假清单只能证明「假的东西对」。

不要为了「JSON 归 JSON、图片归图片」把它们分到两个目录——那是按文件类型分，
而资源是按**改动时一起改**分的。

## 4. 命名

| 对象     | 规则                                               | 例                                                 |
| -------- | -------------------------------------------------- | -------------------------------------------------- |
| 图片文件 | `<id>.webp`，id 用拼音小写，与清单一致             | `xiliangnvgou.webp`                                |
| 图标文件 | `<类目>-<id>.webp`；一个实体多个图标时带子类与序号 | `school-datang.webp`、`school-skill-datang-1.webp` |
| 数据表   | `<实体复数>.json`                                  | `schools.json`                                     |
| 记录 id  | 稳定唯一；**显示名可以改，id 不要改**              | `datang`                                           |

文件名会进 URL，所以只用 `[a-z0-9-]`。中文名放清单的 `name` 字段——游戏改译名时
只改 JSON，不动文件。

### 4.1 图标：从游戏截图切，不另找素材

技能图标、特技图标这类**游戏内已有的图**，一律从游戏截图切出来，不手画、不找第三方素材包：

- 手画的图在游戏改版后必然对不上，而**截图就是当前版本的真值**；
- 第三方素材包的图标集与本客户端的版本未必一致，混进去没人分得清哪个是哪个。

切图脚本三个，按面板形态分：

- `tools/game-icons/slice.py`——4 列 × 3 行的卡片网格（生活 / 剧情 / 特技），靠检测找格子；
- `tools/game-icons/slice-school.py`——竖排 7 行的门派面板（**只取左边那一列师门技能**，
  中间那一列的师门法术不收），横向固定坐标、**纵向每格量底边**，名字与 `schools.json`
  做集合比对；
- `tools/game-icons/slice-gear.py`——百科典藏「装备」页，3 列 × 4 行、**列表可滚动**：
  列固定、行靠投影检测，滚动露出的半行（高 < 70）丢掉，重叠行按 `rows` 声明只取一次。

前两者统一成 96×96、**图标铺满画布不垫背景**；装备那批**保留游戏卡片底**（图形与卡片底
同色系，抠底会把白衣挖空，详见 `public/game/icons/README.md`）。三者各写自己的清单
（`icons.json` / `school-icons.json` / `gear-icons.json`）——分开写是因为两份清单若共用一个
文件，后跑的脚本会把对方的分组整段覆盖，且不报错。

**别给图标「补成正方形」**：门派技能本体是 60×57~59，补那几像素若填黑色，就成了上下各
一条黑边，看着正像图标被截断（踩过一次）。直接按 96×96 缩放，各向异性 1~3% 看不出来。

**底边必须逐格量，不能补整数像素**：同一批 21 张截图里，最后六张（女魃墓、天机城、花果山、
东海渊、九黎城、弥勒山）的图标列比前十五张高 1px，它们的最底下一行是**「描边 + 米黄底」
混出来的半透明行**（亮度比上一行高 7~50 级），而前十五家那一行是本体自带的深色描边
（比上一行低 10~23 级）。半透明行落在 96px 图上就是用户两次指认的那道黄边。

- 先试过 `dy: -1` 手工补偿——没用：半透明那行换成哪个整数位置都在，只是把黄边从 1 行
  挪到另 1 行。
- 现在 `body_bottom()` 逐格找"描边 → 米黄底"最陡的那次变亮跳变，**跳变行比上一行亮就丢掉
  它**。两类相差 17 级，不是勉强分开的。
- 结果：前十五家 59 行、后六家 57 行，各家 7 格完全一致；147 张末行亮度最高 49（此前 88）。
- `assert_no_pale_edge()` 作为兜底留着（末行亮度 > 130 报错），但真正起作用的是上面那条。

| 处理过的坑                                             | 做法                                                       |
| ------------------------------------------------------ | ---------------------------------------------------------- |
| 末行只有 1 项，那一行检测不到                          | 按相邻**最小**间距外推 3 行；外推位置没图标就跳过          |
| 某些页其中一列图标偏亮，检测不到                       | 同上：外推而非依赖全检出，否则首尾平均会把间距算成两倍     |
| 游戏给选中项画了一圈金框，会被裁进来                   | 掩膜里按颜色剔掉金框，再对框边缘复查一次、有金边就内缩 2px |
| 导出的图标外面套了一圈米黄（用户原话「一圈都有黄边」） | 不垫背景、图标铺满画布；再按**色偏**把边缘残留的卡片底剥掉 |

前三条都试过「阈值调一调就好」，都不行——**间隙处的投影值正好等于阈值**，
而且浅色图标与金色图标的亮度分布相反，一刀切必然顾此失彼。

序号命名（`skill-01`）与名字表的对应由 `src/services/game-icons.test.ts` 盯着：
**第 n 个图标的名字必须等于名字表的第 n 项**。错位不会让任何别的东西变红，只会表现为
「强身术配了冥想的图」——而图标都是纹样，没人能一眼看出。

## 6. 故意留在代码里的游戏耦合点

这些东西确实「和游戏有关」，但**不该进 `game/`**。判断依据见每条的理由——
核心是：搬进 JSON 就要异步加载，而它们服务的是纯函数与单测。

| 常量                                            | 位置                                | 是什么                                                        | 为什么不搬                                                                                                           | 什么时候必须回来看                             |
| ----------------------------------------------- | ----------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `DEFAULT_ROI`                                   | `src/services/ghost.ts:98`          | 任务栏在截图中的位置（右 6、宽 215、上 200、高 400、放大 2×） | 它是 `reportTask` 的默认参数，同一条链上全是同步纯函数；异步化会让 `ghost-*.test.ts` 全变成 async                    | 游戏改 UI 布局、分辨率适配变化                 |
| `TITLE_HINTS`                                   | `src-tauri/src/ghost.rs:138`        | 窗口标题匹配串 `["梦幻西游", "mhtab"]`                        | 在 Rust 侧参与窗口枚举，跨语言读 JSON 要加一次文件 IO 与解析；且改它必须重跑冒烟测试                                 | 客户端改名、五开工具换代                       |
| `CONFUSABLE`                                    | `src/services/ghost-maps.ts:81`     | 形近误读组 `['碗腕', '子孑']`                                 | 每条都来自真机实测，是**纠错规则**不是数据；新增一条必须配一条断言                                                   | 出现新的稳定误读、换了 OCR 模型                |
| 任务句式正则                                    | `src/services/ghost-parse.ts`       | 小鬼/大鬼的两种句式与全半角逗号                               | 句式知识已经编码成正则，拆成数据只能得到一张「正则表」，不如现在可读                                                 | 任务栏文案改版（如加了新任务类型）             |
| 角色页演示数据                                  | `src/views/characters/mock.ts`      | 一个假角色的属性、技能、装备                                  | 它是**版式填充物**，不是游戏事实表；里面没有一行逻辑                                                                 | 接真实识别结果时，把**属性组**同样搬进 `data/` |
| `GEAR_SLOTS` / `GEAR_SPECIALS` / `GEAR_ACTIVES` | `src/views/characters/character.ts` | 装备 12 个部位、69 个特技、18 个特效                          | **下一批该搬的表**：它们是游戏给的名单，与门派表同类；眼下还留在代码里是因为 `gear.test.ts` 与图标清单都按数组下标对 | 加 `data/gear.json` 时一起搬，别只搬一半       |

**分界线**：数据「会整体替换」→ 进 `game/`；「偶尔改一个数、且改完必须跑测试」→ 留代码。
前者是资源，后者是规则。

**已经搬过一轮**（2026-11-03）：`schools.json`（门派 + 门派技能 + 上限）与 `skills.json`
（生活 / 剧情名录）原本是 `views/characters/schools.ts` / `skills.ts` 里的 TS 常量。
搬走的判据就是上面那条：加一个门派、改一个技能名，代码一行都不用改。

## 7. 替换流程

### 换一张底图

1. 覆盖 `maps/` 下同名 `.webp`（**尺寸与比例必须和原图一致**，否则坐标换算整体偏移）；
2. 刷新页面。清单没变就不用动 `maps.json`。

### 加一张地图

见 `public/game/README.md` 的三步。要点：`img` 只写文件名、`maxX/maxY` 是走一遍
四角量出来的真实坐标域、跑 `npm run check`（测试读真实清单，缺图当场失败）。

### 换一批数据表

数据表是**异步加载**的，但异步只留在边界：`src/main.ts` 里 `await loadGameData()`
成功之后才 `mount`，之后全站用同步的 `gameData()` / `schoolNames()` / `lifeSkills()` 读缓存
（`src/services/game-data.ts`）。所以换 JSON 不需要动任何组件——**只要结构不变**。

1. 改 `data/*.json`（加一条门派就加一个对象，`skills` 仍是七项、`id` 仍是拼音小写）；
2. `npx vitest run src/services/game-data.test.ts` —— 形状、条数、id、重名都在这里盯；
3. 刷新页面即生效。

**不许**在组件里 `fetch`，也不许给消费方加 `v-if="表还没回来"`：那会把「一次加载」
变成「每个页面各有一套加载态」，紧接着就是各有各的失败处理。

### 补一批图标

1. 进游戏打开对应的目录面板（生活技能 / 剧情技能 / 特技特效 / 师门技能），**一页一张截图**，
   原分辨率、别经过聊天软件压缩；
2. 把图放进 `tools/game-icons/slice.py` 的 `PAGES` 列表（门派面板放进 `slice-school.py`
   的 `PANELS`），写清每页应有几项；
3. `python tools/game-icons/slice.py`（门派面板用 `slice-school.py --check` 先校名字，
   再跑不带参数的那条写文件）——数量对不上会直接报错退出；
4. 看一眼 `data/icons.json` / `data/school-icons.json` 里新加的名字对不对（脚本从
   `data/skills.json` / `data/schools.json` / `character.ts` 读名字，读不到会报错，不会静默写空）；
5. `npm run check`。

### 游戏大版本更新时（检查清单）

按这张表过一遍，一次改完：

- [ ] `maps/`：新场景有没有加、旧场景坐标域有没有变（地图扩充/改版）
- [ ] `data/`：门派、技能、等级上限有没有调
- [ ] `icons/`：技能 / 特技名字有没有增删（改了要重切，序号会整体错位）
- [ ] `ghost.ts:98` 的 `DEFAULT_ROI`：任务栏位置/尺寸/缩放有没有变（用探针截一帧量，别目测）
- [ ] `ghost-parse.ts` 的句式：任务栏文案有没有改（尤其「去」「的」「附近」）
- [ ] `ghost.rs:138` 的 `TITLE_HINTS`：客户端标题写法有没有变
- [ ] `CONFUSABLE`：换版本后有没有新的稳定误读

## 9. 怎么验证没违反本规范

