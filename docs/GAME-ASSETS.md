# 游戏资源规范（GAME-ASSETS）

> **一句话**：凡是「梦幻西游本身长什么样、有什么东西」，进 `public/game/`；
> 凡是「我们怎么读它、怎么判断」，留在代码里。
>
> 目的只有一个——游戏改版时，**换文件，不改代码**。

## 1. 判据：什么东西算「游戏资源」

三条全部满足才进 `public/game/`：

1. **内容变了，我们的代码一行都不用改**。换一张底图、加一个门派，改的是文件与清单，
   不是 `.ts`。做不到这条，说明它其实是逻辑。
2. **内容来自游戏，不是我们编的**。门派名、地图名、坐标域上限、任务句式——这些是
   客观事实，游戏更新就变；而「高概率区域画 24% 红」是我们的设计决定，不是游戏事实。
3. **丢了它，应用应该「少一块」而不是「崩掉」**。资源缺失要退化成空状态；
   缺了就跑不起来的东西是依赖，不是资源。

反向判据更好用：**「游戏改版后我需要改代码吗？」**——要改的，就是代码。

## 2. 目录

```
public/game/
├── README.md        往哪放、怎么换（给改资源的人看）
├── maps/            地图底图 + 清单
│   ├── maps.json
│   └── *.webp
├── icons/           游戏内图标（技能 21、剧情 11、特技 69）+ README
│   └── *.webp
└── data/            游戏事实数据 + 资源清单
    ├── icons.json   图标「文件 → 名字」清单（脚本生成，不手改）
    └── *.json       门派、技能、装备、道具
```

三个子目录各有一份 README 写「放什么、怎么命名」。这份文档写**规则本身**。

那三份 README 会随 `npm run build` 一起进 `dist/`（合计约 4KB）——这是有意的：
它们是给「半年后往这里丢一张 png 的人」看的，放在目录里才会被看到，放在 `docs/` 里
只会被忘掉。4KB 换一条规则可见，划算。

## 3. 三条硬规则

### 3.1 放 `public/`，不放 `src/`

Vite 会把 `src/` 里的资源**改名加哈希**（`aolaiguo-a1b2c3.webp`）。游戏资源必须
**文件名稳定**：清单里写的是文件名，替换后要还能对上。`public/` 是 Vite 唯一
「原样拷贝、不改名」的目录。

代价：不经打包器优化、没有缓存指纹、拿不到 `import` 的类型检查。对一批**会随游戏
版本整体更换**的文件，这个代价划算。

### 3.2 目录只在代码里写一次

清单里**只写文件名**，目录由加载函数拼：

```ts
// src/services/ghost-maps.ts
const MAP_DIR = `${import.meta.env.BASE_URL}game/maps/`;
```

```json
{ "id": "aolaiguo", "name": "傲来国", "img": "aolaiguo.webp" }
```

不写 `"img": "/game/maps/aolaiguo.webp"`。原因不是洁癖：目录名会重复进 20 条记录，
换一次目录要改 21 处，**漏掉的那一条只有运行到那张地图时才会 404**——而那时页面
一切正常，只是不显示底图。

同理，`import.meta.env.BASE_URL` 不能省。写死 `/game/maps/` 在当前的 `base: '/'` 下
等价，但换子路径部署时会整体失效，且没有任何报错。

**已知例外**：四个测试文件里有 `import mapsFile from '../../public/game/maps/maps.json'`。
那是模块解析，路径必须是字面量（换成变量就读不到 JSON 了），改目录时按 IDE 的全局替换
一次改完即可。除此之外，**同一个文件里不许再写第二个路径常量**——
`ghost-maps.test.ts` 因此改用 `readFileSync`，让目录只出现一次。

### 3.3 文件与清单同目录

`maps.json` 和那 20 张 webp 必须住在一起。这是**唯一能保证「改一份忘一份」的窗口期
只有一次编辑动作**的办法：加一条记录却忘了放图，`npm run check` 当场失败——
`src/services/ghost-maps.test.ts` 有四条断言盯着这件事：**缺图**（清单有、目录没有）、
**孤儿图**（目录有、清单没有）、**`img` 带了目录**、**id 重复**。四条都读真实目录，
不是手搓的假清单——假清单只能证明「假的东西对」。

不要为了「JSON 归 JSON、图片归图片」把它们分到两个目录——那是按文件类型分，
而资源是按**改动时一起改**分的。

## 4. 命名

| 对象     | 规则                                   | 例                   |
| -------- | -------------------------------------- | -------------------- |
| 图片文件 | `<id>.webp`，id 用拼音小写，与清单一致 | `xiliangnvgou.webp`  |
| 图标文件 | `<类目>-<id>.webp`                     | `school-datang.webp` |
| 数据表   | `<实体复数>.json`                      | `schools.json`       |
| 记录 id  | 稳定唯一；**显示名可以改，id 不要改**  | `datang`             |

文件名会进 URL，所以只用 `[a-z0-9-]`。中文名放清单的 `name` 字段——游戏改译名时
只改 JSON，不动文件。

### 4.1 图标：从游戏截图切，不另找素材

技能图标、特技图标这类**游戏内已有的图**，一律从游戏截图切出来，不手画、不找第三方素材包：

- 手画的图在游戏改版后必然对不上，而**截图就是当前版本的真值**；
- 第三方素材包的图标集与本客户端的版本未必一致，混进去没人分得清哪个是哪个。

切图脚本：`tools/game-icons/slice.py`。它按 4 列 × 3 行的网格切、统一成 96×96、
**图标铺满画布不垫背景**，并重写 `data/icons.json`。

| 处理过的坑                                             | 做法                                                       |
| ------------------------------------------------------ | ---------------------------------------------------------- |
| 末行只有 1 项，那一行检测不到                          | 按相邻**最小**间距外推 3 行；外推位置没图标就跳过          |
| 某些页其中一列图标偏亮，检测不到                       | 同上：外推而非依赖全检出，否则首尾平均会把间距算成两倍     |
| 游戏给选中项画了一圈金框，会被裁进来                   | 掩膜里按颜色剔掉金框，再对框边缘复查一次、有金边就内缩 2px |
| 导出的图标外面套了一圈米黄（用户原话「一圈都有黄边」） | 不垫背景、图标铺满画布；再按**色偏**把边缘残留的卡片底剥掉 |

前三条都试过「阈值调一调就好」，都不行——**间隙处的投影值正好等于阈值**，
而且浅色图标与金色图标的亮度分布相反，一刀切必然顾此失彼。

序号命名（`skill-01`）与名字表的对应由 `src/services/game-icons.test.ts` 盯着：
**第 n 个图标的名字必须等于名字表的第 n 项**。错位不会让任何别的东西变红，只会表现为
「强身术配了冥想的图」——而图标都是纹样，没人能一眼看出。

## 5. 不放在这里

| 东西                    | 正确的家                   | 为什么                                          |
| ----------------------- | -------------------------- | ----------------------------------------------- |
| OCR 模型与字典（16MB）  | `src-tauri/models/`        | PP-OCRv4 通用模型，与游戏版本无关；走 Rust 打包 |
| 字体、印章、应用图标    | `assets/`                  | 品牌资产，不随游戏更新                          |
| 界面图标（tabler 那套） | `src/components/icons.ts`  | 是**界面语言**的图标，不是游戏里的图标          |
| 测试样例、演示角色数据  | 跟着用它的页面（`views/`） | 为立版式/跑单测而生，不是游戏事实               |
| 解析正则、ROI、纠错表   | `src/services/`            | 是「怎么读」，见下一节                          |

## 6. 故意留在代码里的游戏耦合点

这些东西确实「和游戏有关」，但**不该进 `game/`**。判断依据见每条的理由——
核心是：搬进 JSON 就要异步加载，而它们服务的是纯函数与单测。

| 常量           | 位置                            | 是什么                                                        | 为什么不搬                                                                                        | 什么时候必须回来看                        |
| -------------- | ------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `DEFAULT_ROI`  | `src/services/ghost.ts:98`      | 任务栏在截图中的位置（右 6、宽 215、上 200、高 400、放大 2×） | 它是 `reportTask` 的默认参数，同一条链上全是同步纯函数；异步化会让 `ghost-*.test.ts` 全变成 async | 游戏改 UI 布局、分辨率适配变化            |
| `TITLE_HINTS`  | `src-tauri/src/ghost.rs:138`    | 窗口标题匹配串 `["梦幻西游", "mhtab"]`                        | 在 Rust 侧参与窗口枚举，跨语言读 JSON 要加一次文件 IO 与解析；且改它必须重跑冒烟测试              | 客户端改名、五开工具换代                  |
| `CONFUSABLE`   | `src/services/ghost-maps.ts:81` | 形近误读组 `['碗腕', '子孑']`                                 | 每条都来自真机实测，是**纠错规则**不是数据；新增一条必须配一条断言                                | 出现新的稳定误读、换了 OCR 模型           |
| 任务句式正则   | `src/services/ghost-parse.ts`   | 小鬼/大鬼的两种句式与全半角逗号                               | 句式知识已经编码成正则，拆成数据只能得到一张「正则表」，不如现在可读                              | 任务栏文案改版（如加了新任务类型）        |
| 角色页演示数据 | `src/views/characters/mock.ts`  | 一个假角色的属性、技能、装备                                  | 它是**版式填充物**，不是游戏事实表；里面没有一行逻辑                                              | 接真实识别结果时，把门派/技能抽进 `data/` |

**分界线**：数据「会整体替换」→ 进 `game/`；「偶尔改一个数、且改完必须跑测试」→ 留代码。
前者是资源，后者是规则。

## 7. 替换流程

### 换一张底图

1. 覆盖 `maps/` 下同名 `.webp`（**尺寸与比例必须和原图一致**，否则坐标换算整体偏移）；
2. 刷新页面。清单没变就不用动 `maps.json`。

### 加一张地图

见 `public/game/README.md` 的三步。要点：`img` 只写文件名、`maxX/maxY` 是走一遍
四角量出来的真实坐标域、跑 `npm run check`（测试读真实清单，缺图当场失败）。

### 换一批数据表

数据表是**异步加载**的。换 JSON 之前先确认消费方已经是「加载完再渲染」而不是
同步 import——现在还没有表，第一次做的时候就把这条定下来，别让每个消费方各写一个
`v-if`。

### 补一批图标

1. 进游戏打开对应的目录面板（生活技能 / 剧情技能 / 特技特效），**一页一张截图**，
   原分辨率、别经过聊天软件压缩；
2. 把图放进 `tools/game-icons/` 的 `PAGES` 列表，写清每页应有几项；
3. `python tools/game-icons/slice.py` —— 数量对不上会直接报错退出；
4. 看一眼 `data/icons.json` 里新加的名字对不对（脚本从 `skills.ts` / `character.ts`
   读名字，读不到会报错，不会静默写空）；
5. `npm run check`。

### 游戏大版本更新时（检查清单）

按这张表过一遍，一次改完：

- [ ] `maps/`：新场景有没有加、旧场景坐标域有没有变（地图扩充/改版）
- [ ] `data/`：门派、技能、等级上限有没有调
- [ ] `icons/`：技能 / 特技名字有没有增删（改了要重切，序号会整体错位）
- [ ] `ghost.ts:98` 的 `DEFAULT_ROI`：任务栏位置/尺寸/缩放有没有变（用探针截一帧量，别目测）
- [ ] `ghost-parse.ts` 的句式：任务栏文案有没有改（尤其「去」「的」「附近」）
- [ ] `ghost.rs:138` 的 `TITLE_HINTS`：客户端标题写法有没有变
- [ ] `CONFUSABLE`：换版本后有没有新的稳定误读

## 9. 怎么验证没违反本规范

```bash
# 1. 运行时有没有把目录写死在代码里（应只剩 MAP_DIR 一条，外加 4 个测试的 import 字面量）
grep -rn "game/" src --include="*.ts" --include="*.vue"

# 2. 清单与文件是否一一对应（缺图 / 孤儿图 / img 带目录 / id 重复）
npx vitest run src/services/ghost-maps.test.ts src/services/game-icons.test.ts

# 3. 全量质量门（上面那条也在里面）
npm run check
```

第 2 条不是可选的「额外检查」——它是 `npm run check` 的一部分。新增一类游戏资源
（比如 `data/` 里第一张表）时，照着这个文件补一组同样的断言：**规范里承诺的保障，
必须有一条会红的测试撑着，否则它只是愿望**。
