# 封妖助手

## 范围

Windows 桌面工具，通过 Windows Graphics Capture 捕获选定游戏或独立聊天窗口，仅对框选区域运行随包 PaddleOCR。支持窗口被遮挡、助手切页或最小化时继续读取；不读取游戏内存、网络协议，不执行游戏操作。

监听在 Rust 线程运行，页面只展示状态和设置。关闭应用即停止；重新打开不自动开始。首次使用场景全部关闭，手动选择后记住地图、窗口标题及消息选区；窗口句柄每次重新查找，复用选区前核对窗口尺寸。游戏最小化、画面全黑、窗口关闭、捕获失败或尺寸变化时明确显示暂停/错误，不把旧文本显示成新读数。恢复读取先重新建立基线。

## 页面与后台

入口为“工具 → 封妖助手”。首屏直接展示窗口、消息区域与全部场景开关，不设置角色等级；首次使用场景全关，已选地图自动保存，下次启动恢复。点击“开始监听”时优先查找保存的窗口或唯一独立聊天窗口；缺少选区则直接显示框选画面，点击“完成并开始监听”后启动。没有地图或游戏窗口时给出明确原因。窗口选择使用紧凑宽度，最近三条提醒使用首页常用功能同款压印块显示场景与时间；识别原文放在“识别详情”。框选画面仅在设置区域时显示，完成框选或开始监听后收起。

点击“开始监听”后可直接返回工具列表或进入其他页面；路由离开仅清除页面状态轮询，不停止 Rust 捕获任务，Windows 通知也不依赖当前页面。监听中回来会读取后台已选场景、选区和监听状态；只有“停止监听”或关闭应用才结束任务。

## 规则与识别

场景名称与别名的唯一事实表为 public/game/data/fengyao.json，来源为官网“挖宝封妖”；表中等级只保留来源事实，监听不按等级筛选，所有场景由用户手动开启。首版不提醒妖王、妖风四起预告。

用户选择游戏或“梦幻西游 聊天窗口”，框选包含频道签和换行正文的系统消息区，保持频道展开且停在最新消息。建议只框最新几条公告，整窗识别可能慢于消息滚动。窗口尺寸改变后需重新框选；移动不影响相对选区。

停止任务留下的选区仅作历史快照，重进页面以最新保存的选区为准；游戏未打开时修改地图保留上次选区。窗口放大超过帧池纹理尺寸时暂停读取，不裁成旧尺寸继续识别。

OCR 文字框按行中心和横坐标拼接，兼容单独识别和合入正文的“系统”频道签。只接受系统频道放妖句式（挖塌/放出 + 妖怪/妖魔 + 已选场景），玩家聊天与普通奖励公告不触发。OCR 误读、消息滚动过快、被选区裁断会漏读，不承诺全量捕获。

启动首帧只建立旧消息基线。同场景十秒内只弹一次，重复来源在持续显示或短时间再次出现时合并；四字以上玩家名容忍一次增删或替换，短名字只精确匹配。离屏十五分钟后才允许同源再次提醒。这会合并同一玩家或短时密集的放妖，避免 OCR 细微差异导致重复弹窗。

## 提醒与数据

新公告命中后直接从 Rust 发送 Windows 通知，最近提醒保留在本次应用会话中。发送失败显示行内状态；系统勿扰可能抑制弹出。提醒仅表示读到刷妖公告，不能判断妖怪是否仍在。

截图仅用于本地选区预览，OCR 原文和最近提醒只驻留内存，不写入账本、不上传。地图选择、窗口标题及选区保存在本机偏好中，不保存窗口句柄；读取失败暂停覆盖原设置，写入失败显示原因且不影响本次手动监听，不修改角色档案。前端系统调用仍统一经过 src/services/fengyao.ts；IPC 类型由 Rust 生成。

相关逻辑断言在 src-tauri/src/fengyao.rs，偏好读写边界断言在 src/services/fengyao.test.ts，页面精简与路由生命周期烟测位于 tools/e2e/sections/08-tools.mjs（以 IPC 替身隔离真实监听）；真实窗口捕获、频道布局与提醒需要定向真机复现，模拟文字不能替代实际 OCR。
