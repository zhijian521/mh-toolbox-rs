# 测试与验证范围

默认日常开发不自动运行验证。用户指定测试时选择相关范围；只有明确要求全量检查才执行整套。
触发规则、Windows 环境与完整清单以 [AGENTS.md](../AGENTS.md) 为准。

## 测试放在哪里

| 类型     | 归属                             | 负责什么                                      |
| -------- | -------------------------------- | --------------------------------------------- |
| 前端逻辑 | 模块旁的 *.test.ts               | 归一、算法、数据层、composable 与共享展示逻辑 |
| 工程工具 | scripts/、tools/ 下的 *.test.mjs | 打包资源、测试选择、资源加工规则              |
| 后端     | Rust 模块内或 store/tests.rs     | 真 SQLite、迁移、事务、备份与系统能力         |
| 窗口烟测 | tools/e2e/sections/              | 真鼠标、IPC、保存、取消、重载持久化           |
| 视觉验收 | tools/probe/cdp.mjs              | 截图、主题、字号、溢出与几何对齐              |

不把现有单元测试集中搬进 tests/。业务夹具留在对应模块或 tools/e2e/fixtures/，不混入 public/game/。
纯逻辑、真存储和真窗口不能互相替代；只修改排版时优先维护对应烟测几何断言，不写重复 CSS 实现的单测。

## 根据改动推荐范围

```sh
npm run test:recommend
npm run test:recommend -- --base=HEAD~1
```

默认读取暂存、未暂存和未跟踪文件；--base 还包含基准提交至当前工作区的差异，重命名前后路径均参与判断。
入口只打印分区单测、窗口烟测与 Rust 范围，不执行任何测试，不改变工作区或账本。
匹配规则在 scripts/test-impact.mjs，收益口径包含账号与首页联动，父烟测分区覆盖重复子项。

纯文档不推荐测试；配置、依赖和未知路径会显式提示人工判断，不静默回退到全量。
结果是路径层面的起点，不能判断实际调用变化或代替下面的联动表；公共组件仍需追加使用页面。
得到建议后仅在用户指定验证时执行，烟测仍须遵守快照与还原要求。

## 按业务选择单元测试

```sh
npm run test:scope -- --list
npm run test:scope -- ocr
npm run test:scope -- income,accounts
npm run test:scope -- goals -t 养成
```

支持逗号合并分区并去重，分区后的选项透传给 Vitest。未知或空范围报错，不回退到全量。
角色、收益、账号、物价与目标分区均包含共享加载及业务只读契约；公共加载改动同时覆盖这些领域。

选择真源为 [scripts/test-scopes.mjs](../scripts/test-scopes.mjs)，新增测试需有分区归属；归属断言随 tooling 分区维护。

| 分区       | 主范围及直接联动                               |
| ---------- | ---------------------------------------------- |
| characters | 角色、OCR、目标回写与首页角色读数              |
| ocr        | 截图识别及装备、召唤兽、技能、游戏规则解析     |
| income     | 收益、上线、账号自动分账、首页与金额格式       |
| accounts   | 账号、自动分账、收益及上线口径、首页与金额格式 |
| prices     | 物价与速记单价导入                             |
| goals      | 目标、名册回写、成长历史与首页目标读数         |
| overview   | 首页聚合、队伍近况与快捷入口                   |
| tools      | 活动、闹钟、捉鬼服务与地图逻辑                 |
| ui         | 公共组件逻辑、偏好与通用 composable            |
| settings   | 偏好、旧版导入、更新与数据服务                 |
| core       | 启动、服务层、导入、存储与模拟数据             |
| assets     | 游戏规则、资源、装备图标与图标加工             |
| release    | Windows 依赖资源与检查更新                     |
| tooling    | 测试分区、烟测选择及归属断言                   |

单个文件可直接运行 npm run test -- src/…/xxx.test.ts；npm run test 仍执行全部单元测试。
分区是常见改动的起点，涉及下表公共边界时追加相应范围，不以分区命令代替依赖分析。

## 按改动追加联动

| 改动                       | 追加范围                                                     |
| -------------------------- | ------------------------------------------------------------ |
| 名册结构、归一或角色 ID    | characters、goals、overview；涉及存储则追加 core 与 Rust     |
| 收益、上线、点卡口径       | income、accounts；确认跨天、历史修改、幂等同步与关闭排队     |
| 金额格式或图表公共逻辑     | income、accounts、overview、ui                               |
| persist、导入、备份、清除  | core 与对应 Rust 模块；真窗口的数据节或受影响页面重载        |
| IPC 命令、参数、返回字段   | core 的 ipc-contract；两张命令表与生成绑定同步，追加后端测试 |
| 主题、字体、公共样式与控件 | ui 及使用页面；要求视觉验收时检查明暗、字号、焦点与溢出      |
| 游戏规则或资源清单         | assets 及使用该规则的 characters、ocr、tools 等分区          |
| Rust 系统能力或打包依赖    | 对应 Rust 模块；release；系统交互需真 Tauri 窗口             |

修改功能同步更新相关断言，删除功能同步删断言。写断言不代表自动执行；交付明确实际运行范围。

## 后端定向范围

仅修改某个 Rust 模块时，可在配置好本机编译环境后使用 Cargo 名称过滤，例如：

```sh
npm run test:rust -- store::
npm run test:rust -- backup::
```

过滤按模块或用例名匹配，范围由实际改动决定；存储结构变更同时考虑备份、导入与 IPC，不能只测一个写入函数。
生成绑定或返回类型变化需追加前端契约测试。Rust 环境与全量 fmt、Clippy 要求见 AGENTS.md。

### 云端与系统环境测试

GitHub Actions 的 check 保留前端整套检查、Rust 格式与 Windows 后端测试。
云端仅用完整测试名排除 `ocr::tests::pipeline_runs_on_a_synthetic_frame`：
托管镜像不保证 Windows 系统中文 OCR 引擎可用。排除项写入任务摘要，其他失败照常阻断。

本机 `cargo test --lib` 仍运行该项；需要定向验证时，在支持中文 OCR 的 Windows 环境执行：

```sh
npm run test:rust -- ocr::tests::pipeline_runs_on_a_synthetic_frame -- --exact
```

该项只检查 Windows OCR 备用链路，不代表随包 PaddleOCR 的识别效果。
前台游戏实验仍按源码 ignore 标记手动执行；云端通过不替代真窗口与正式安装包验收。

## 窗口烟测分区

先启动 debug 真窗口，再按需要执行：

```sh
npm run e2e -- --only=角色/截图
npm run e2e -- --only=角色/截图/辅助
npm run e2e -- --only=角色/装备
npm run e2e -- --only=角色/装备/原图
npm run e2e -- --only=收益
```

页面分区：导航、角色、物价、收益、账号、目标、设置、工具、收益日期、数据、收尾。
首页编排与页面导航使用“导航”分区。收益范围包含收益日期。--skip 只支持完整页面，不允许跳过角色子流程的数据前置。
选择在连接窗口前校验，未知名称直接失败。

| 角色子分区    | 执行内容（均含新建、编辑与删除测试角色） |
| ------------- | ---------------------------------------- |
| 角色/基础     | 角色基础流程                             |
| 角色/截图     | 属性、师门、辅助、修炼截图与连续换图     |
| 角色/召唤兽   | 空列表截图建档、召唤兽编辑与重载         |
| 角色/快速修改 | 截图、召唤兽前置，再测各快速入口         |
| 角色/装备     | 召唤兽前置，再测装备详情与截图           |
| 角色/统计     | 召唤兽前置，再测全角色统计               |
| 角色/成长历史 | 修改后的成长记录与重载                   |

截图可继续选择：属性、师门、辅助、修炼、草稿、换图。师门包含属性前置，以建立对应门派；
草稿包含属性与辅助前置，用于验证固定技能、已有辅助技能的删除与取消。
装备可继续选择：入口、快速修改、批量、原图。各场景均包含召唤兽与装备入口前置；
批量还包含快速修改，确认原有属性、备注与截图保留。原图覆盖基础总值、熔炼、重复属性、套装、特性、零值备注，以及阴阳玉魄同图、标题漏字、奇袭百分号、共用命魂属性与取消不落盘；玉魄解析同时保留实际 OCR 转录夹具。

场景文件分别位于 tools/e2e/sections/characters/ocr/ 与 equipment/；编排入口只负责选择与顺序，
共用原图上传由 characters/screenshot.mjs 管理。修改某个场景时维护该文件断言及 selection.mjs 中的前置。

角色整页或全量选择仍按原顺序运行全部流程。前置定义在 tools/e2e/selection.mjs；
新增流程时同时维护前置与清理条件，不用跳过初始化来缩短时间。

预检与数据库快照始终执行；分区烟测同样会写真实数据。运行完关闭应用，按输出的快照 ID 还原；
即使失败也要还原。不能把自动删除 E2E 条目当成整份恢复，账本的真实数据必须保持原样。

## 编写与维护

- 用稳定 aria-label 或类名定位；点击使用真实鼠标事件，不能用 el.click() 绕过命中测试。
- 写入后重载再确认；控制台错误算失败，预期错误的豁免写在调用处并说明原因。
- 页面单例用 importLoaded() 获取已加载模块，避免导入无时间戳路径产生第二份状态。
- Rust 存储测试用临时真实库验证事务与回滚，不 mock SQL。
- 同一份代码的结果复用，不因 Review 或提交重复执行；运行期间不编辑源码或烟测，避免 Vite 重载污染结果。
- 测试数量以实际输出为准，文档不固定数量，不把未运行的断言写成已通过。

全量命令、真窗口快照恢复、生产 CSP 与截图探针前提统一见 AGENTS.md §一、§五，不在此复制第二份操作清单。
