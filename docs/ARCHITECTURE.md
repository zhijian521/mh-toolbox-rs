# 架构

> 回答「东西该放哪、数据怎么流、哪些边界不能破」。视觉与规范不在这里（见
> [`CONVENTIONS.md`](CONVENTIONS.md)），本机环境不在这里（见 [`AGENTS.md`](../AGENTS.md)）。
>
> **现状**：前端已成型，SQLite 数据层已落地（`src-tauri/src/store.rs`），账本进出在
> `src-tauri/src/backup.rs`（导出 / 导入 / 清除）；八页**都有内容**（目标页是第 115 批补上的
> 最后一块）。
> 总览采用 B 今日工作台：顶部为全队今日读数，中部为可自定义的常用功能与待推进目标，队伍卡按号展示最近上线、最近收益和账号最新收支，并可查看档案；下方为七日收益与本月双币种收支。
> 读数复用收益、账号、上线及目标业务口径，收益净额不重复扣点卡，不跨币种或跨账本相加。
> 队伍卡采用紧凑的三块浅槽，只保留角色名称、门派、等级及最近记录。team-activity.ts 各账本索引一次，收益与账号按业务日期、同日创建时间取最新项，账号收入与支出分别取一笔、各自保留币种；上线按 startAt 取最近一段，历史多人段沿用 ownersOf。首页不新增账本或编辑器。
> 快捷入口经 useRouteAction 消费一次性 action 查询参数，在角色、账号、收益、物价、目标与闹钟页打开已有界面；首页不重复放业务表单。入口目录在 overview/shortcuts.ts，工具从 TOOLS 派生；默认八项，可搜索添加、移除与排序。顺序经 services/home-shortcuts.ts 存为本机 localStorage 偏好，不进入账本备份；保存失败保留草稿。角色分区入口先选角色再打开原编辑器。
> 完整档案用 character 查询参数定位并聚焦名册卡片；角色 updatedAt 仅在新增、修改时记录，旧档不补造历史时间。
> 账号页（2026-11-05，第 112 批）是**第二本账**：它记钱包进出（人民币按元、梦幻币按万），
> 与收益页的「打金产出」分开两张表（`account_entries` / `income_entries`）。两张表而不是
> 加一列：共表就要在每一行上猜「这行是万还是元、有没有渠道」，猜错一次汇总就错。
> 目标页（2026-11-05，第 115 批）是**第三种读法**：它不存进度，只存「许了什么」——手动目标
> 的进度来自自己的流水，养成目标的进度**现算**自身角色档案。所以它是账本的读者，不是第四本账。
> 上线计时（2026-11-11，第 145 批）是**收益页的第二种输入**：它记「玩了多久」（`online_sessions`），
> 与「卖了多少」（`income_entries`）分开两张表——时长要按天切、点卡按号数摊，塞进收益流水就得
> 在每一行上猜「这行是货还是时间」。点卡口径（单价 + 是否计入）单独一行 `online_settings`，
> 不塞 `meta`：`meta` 只放库状态，单价是业务数据，清除时要跟着清。
> 两本账之间只有**一条单向的汇**：`views/accounts/daily-sync.ts` 每天把「速记净额」与「分摊点卡」
> 写进账号账，`source: 'auto'` 标出来源、稳定 id 让重复同步不叠加。账号账不反推收益账。同步仅替换受影响日期，启动从真源补齐全部日期；历史修改、删除收集旧、新日期，关闭窗口前排空防抖队列。
> 账号概览由 `AccountsView` 统一区间、角色筛选；`AccountCharts` 展示两币种走势与整行的角色分类收支堆叠图，
> `account-analysis.ts` 负责纯筛选、分组和跨年月聚合。`AccountRecords` 承载全量历史，复用收益历史的表格与分页，
> 其上叠加同一个 `AccountEditor`；自动记录只查看并转到收益真源，手记用 `usePersistedSubmit` 保证重试不重复新增。
> 金额格式和主题来自公共令牌与柱图组件，不引入新图表库。`AccountFlowCard` 共用角色、渠道的币种切换，`AccountBarChart` 支持渠道分组柱与角色分类堆叠柱；
> 渠道图表在左、最近记录在右等宽并排，卡片沿用收益页的无渐变纹理。
> 账号、收益金额共用 `services/format.ts` 的 `ledgerMoneyText`，按元 / 万最多显示两位小数；
> 手工输入使用相同精度，历史原值与自动分账、计时计算保留原精度。
>
> 每段上线保存 `cardCost` 快照，开关仅决定新段；旧库首次加列沿用升级前口径，旧 JSON 缺字段默认计入。
> **一段计时只属于一个号**（2026-11-11，第 146 批）：`startOnline` 给每个号各开一条，
> `stopOnline([id])` 只停那一个。以前是「一组人共用一段」（`roster` 记全部在线的人），
> 于是想加第三个号只能整组停掉重开——用户明确否掉了这个模型。`roster` 字段留着只为读老数据，
> `ownersOf` 仍会把多人段摊开；点卡在多人段上按人数分摊，时长**不分摊**（每人都挂了这么久）。
> **「此刻」与「趋势」是两个区块**（2026-11-11，第 147 批）：点上那行从左往右是
> 点卡设置在左（开关在单价前）、今日时长与消耗在右，全在 `views/income/OnlineBar.vue`
> （夹在统计条与速记之间）；下排为可横滚的在线胶囊（一枚一个号、整枚可点即结束该号），
> 右端固定「补记 / 记录」。`OnlinePanel.vue`（页尾，卡名「每日走势」）只剩走势范围与两张分组柱图；范围是两档滑块
> （近一周 7 天 / 近一月 30 天），不再是胶囊。
> 读数共用 `useMinuteNow`，按分钟和窗口恢复更新；视图只读派生，自动同步单独订阅时钟更新进行中成本。
> 走势图按共同角色表分配颜色与柱面纹理，再过滤当前日期范围内的空系列，不限制为六个角色。
> 角色整体、快速修改与收益、账号弹窗提交共用 `usePersistedSubmit`：业务变更只执行一次，失败保留草稿，重试只调用 store 写盘，
> 成功后关闭。新建角色模式在打开时固定；账号旧金额在未编辑时保留原值，展示精度不反向改账。
> 历史收益、上线记录和账号历史共用分页逻辑、`components/RecordPager.vue`、筛选汇总空态与表格规则，
> 删除确认和落盘由 `useConfirmedRemoval` 防连点。角色选项归 `characters/character-options.ts`，各页只选择是否含全部、未指定。
> **收益页只记今天**（2026-11-11，第 149 批）：页顶那条「今日 / 近七天 / 本月」整条删掉，
> 统计条只算 `entriesOn(today)`、参照退回昨天。理由是这条账的写入入口（速记、今日速记）
> 本来就只写今天，滑块只是换个区间去**看**已经写进去的东西——而看别天有页头的「历史」窗
> （它自己的日期区间筛选仍然保留，走 `income.ts` 的 `entriesIn`）。滑块与速记口径不一致
> 会让人以为「选了本月，这一笔记的是本月」。走势卡的横轴是展示用的，与这条记账口径无关。
> 单价不在界面上直接改：
> 它是一枚可点的签，点开 `CardPriceDialog.vue` 改（与物品速记「右键改价」同一个做法），
> 口径句（每小时几、折多少币、算不算进账号收支）也就近写在那扇窗里。
> 分开的判据是时态，不是版面——一条卡只回答一个问题，否则看图要先滚过一排按钮；
> 反过来把三格读数留在趋势卡里，用户就得上下滚着对读「开关 / 读数 / 单价」这同一句话。
> **全站卡片只有一种材质**（2026-11-05，第 116 批）：内容区的卡一律是 `components/PaperCard.vue`
> → `base.css` 的 `.board`（台面上的一张纸），页面由 `PageShell` 的 `surface` 铺台面托住。
> `.frame` 那套文武线收窄成**浮层专用**（角色编辑器、捉鬼测试面板）。这不是纯样式约定：
> 「卡片」从此是一个组件而不是一段 class，新页要一块内容区时不该自己拼 `border + background`。
> 带「计划」字样的段落是动手前定好的边界，不是对现状的描述——写在这里的意义是第一次写
> 领域代码的人不用自己发明一套。

## 1. 分层

```
┌──────────────────────────────────────────────┐
│ views/        路由目标。拉数据、拼区块、读路由参数  │
│ components/   有视觉语义的 UI 单元。不调 invoke    │
│ composables/  跨组件状态与副作用。单例放模块作用域  │
│ services/     系统能力的唯一出口（一个能力一个文件）│
└───────────────────────┬──────────────────────┘
                        │ invoke（只有这里能过界）
┌───────────────────────┴──────────────────────┐
│ src-tauri/    Tauri 壳：窗口、命令、能力配置       │
│   └─ crates/  （计划）领域层，与壳解耦             │
│        mh-domain   纯逻辑，无 IO，可被 #[test] 全覆盖 │
│        mh-store    SQLite 读写与迁移              │
└──────────────────────────────────────────────┘
```

规则只有一条真正硬：**渲染层不直接引 `@tauri-apps/*`**。ESLint 的 `no-restricted-imports`
拦住 `components/`、`views/`、`composables/`，要系统能力就往 `services/` 加一个函数。窗口三键
在这条线上，截屏与 OCR 也是。

**一个能力一个文件**，不堆进 `desktop.ts`：那个文件管「应用外壳」（版本信息、外链、窗口三键），
`ghost.ts` 管「读游戏画面」，两者唯一的共同点是都过 invoke。堆一起就看不出「哪些命令服务于
哪块界面」。存储搬运在 `storage.ts`，账本与单价文件在 `data-files.ts`，截图识别在 `ocr.ts`。

## 2. 数据流

```
页面 ──调用──▶ composable / services ──invoke──▶ Rust 命令 ──▶ 领域层 ──▶ 磁盘
  ▲                                                        │
  └────────────────── 返回值（camelCase）◀──────────────────┘
```

- **契约是一处真源：`tauri-specta` 生成的 `src/services/bindings.ts`**（第 122 批）。命令表在 `lib.rs`，
  字段名、参数与返回类型都由 Rust 的 `specta::Type` 派生**生成**到 TS，
  不再两边手抄、也不再靠 `#[serde(rename_all = "camelCase")]` 加上记忆力对齐。
  `bindings.ts` 是**生成物**：每次 debug 启动重写，别手改；`prettier` 与 `eslint` 都把它排除在外。
  `collect_commands!` **按平台写了两份**（`#[cfg(windows)]` / `#[cfg(not(windows))]`）：加命令
  必须两份都加，漏掉非 Windows 那份在本机完全看不出来——`ipc-contract.test.ts` 会红。
- **数据进出走 `backup.rs`**：`data_export` / `data_import` / `data_clear` 管的是「离开这台机器
  的那个文件」——`format` + `app` + `exportedAt` 的信封、`backups/` 下的自动备份、导入前校验；
  `quick_prices_export` / `quick_prices_import` 是同一套信封的窄口径，只装速记单价。
  **它不碰 SQL**：读写库一律回落 `store.rs` 的普通函数，不在那里写第二份查询。两条语义：
  **导入 = 整体替换**（动手前把当前数据导一份到 `<数据目录>\backups\`，路径随回执给用户）；
  **清除 = 清掉七张业务表**，`meta` 一个字不动（`schemaVersion` 在那儿）。旧版 `data.json`
  （`schemaVersion: 10`，角色结构完全不同）**不在这个入口范围内**：不做转换或反向镜像；
  这里只认自己的信封，不认识就拒绝、不猜。
- **前端状态**：业务与偏好使用模块级状态（主题、字体、字号、应用信息、路由、开发者模式、角色名册、物价表、收益
  账、账号账、目标），另有两个瞬时 UI 单例（`use-confirm` / `use-notify`）写法相同但不落盘。
  **不引 Pinia**——触发条件见 `AGENTS.md` §七。名册与物价表都已跨三个组件（页面、卡片、弹窗），
  但用的是与主题、字号同一套「模块级 `ref` + `useXxx()`」，没有第二套机制。
- **写盘时机**：先更新内存，再排队整份写 SQLite；保存回执与收表单等待本领域的 `flush()`，失败保留错误与重试入口。导出、导入、清除和系统关窗等待 `flushPendingWrites()`，关窗失败时由用户选择保留窗口或放弃改动退出。
- **六份数据层的落盘是同一份实现**（`src/services/persist.ts`）：`createPersist` 管「读失败
  拒绝写 / 浏览器写本地 / 桌面异步写库 / 连续写排队 / 可等待结果与 pending 状态」。第 100 批从三份手抄收拢成一份，第 112、
  115 批新增的账号账与目标直接照用——此前只有收益账做了写队列，物价与名册连点两次会丢后一笔。
  **归一、排序、种子数据、`storage` 事件仍归各页的 store**，骨架只回答「怎么落地」。
- **日期**：页面范围、目标期限与日历共享 `useToday()`，午夜更新，在焦点、可见性或页面恢复时重新对时；最后一个消费者卸载时清理计时器和监听。
- **业务数据的 `localStorage` 路径仅用于浏览器**（`npm run dev`、探针）——没有 Tauri 宿主，
  `hasDesktop()` 为假，六个 store 直接走本地分支。早先它还是「旧版 Electron 数据的来源」
  （`migrateLegacy` 搬一次、老键改名 `*.migrated` 留底）；2026-11-04 起不接老数据，
  整套迁移连命令一起删了，见 §3 数据目录。主题、字体、字号、闹钟和首页快捷入口属于本机偏好，桌面版也使用 `localStorage`，不随账本导出。

字体独立选择由 `use-font-family.ts` 单例维护，挂载前恢复 `mh-font-family` 并设置根属性 `data-font`；缺失或非法值使用原有文楷。字体族只在 `tokens.css` 中定义，界面与 Canvas 共用 `--font-ui`，字体加载完成后地图重绘。五种字体随包提供，固定来源、许可与子集生成方式见 [assets/fonts/README.md](../assets/fonts/README.md)。

## 3. 磁盘与兼容红线

| 项         | 事实                                                                   | 为什么不能改                                                                                                                                                              |
| ---------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据目录   | `%APPDATA%\mh-tool-rs`（`lib.rs` 的 `data_dir_path()`）                | 全局唯一真源。2026-11-04 与旧版 Electron 分家（原共用 `mh-tool-v2`），**换名是硬切不搬家**：旧目录一概不接，新目录从空库开始，那条一次性迁移已随兼容链一起删（第 107 批） |
| identifier | `com.zhijian.mhtoolbox.rs`                                             | 必须与旧版 appId 不同，否则 Windows 把两个安装包当一个应用互相覆盖                                                                                                        |
| 卸载       | `deleteAppDataOnUninstall: false`                                      | 卸载重装不该丢账                                                                                                                                                          |
| 镜像       | **不做** SQLite → JSON 反向镜像（2026-11-04 用户定）                   | 升级单向：旧版打不开新版的账。换来「一份数据只有一个真源」，不必维护双向转换；要带走数据用设置页的手动导出                                                                |
| 本地开发   | `vite.config.ts` 的 `server.host` 与 `devUrl` **都必须写 `127.0.0.1`** | Node 把 `localhost` 解析成 `::1`，Vite 只监听 `[::1]:5173`；WebView2 走 IPv4，报 `ERR_CONNECTION_REFUSED` → 白屏，而浏览器打开是好的                                      |
| 打包       | `Cargo.toml` 的 `[features] custom-protocol` 不能删                    | `tauri dev` 用 `--no-default-features` 关掉它才连 devUrl；缺了它两种构建产物一模一样，`tauri build` 的包仍去连 devUrl，装到没起 dev server 的机器就白屏                   |

## 4. 目录归属速查

| 要加的东西       | 放哪                                                                                         | 不该放哪                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 新页面           | `src/views/`，然后在 `src/navigation.ts` 加一项                                              | 不要改 `router.ts` 的数组——它从 `NAV_ITEMS` 生成                                                                  |
| 工具的子页       | `src/views/tools/`，然后在 `src/tools.ts` 加一项                                             | 不要进 `NAV_ITEMS`——工具越加越多，一件一格会把左栏撑成一列                                                        |
| 新控件           | `src/components/`，先加进 `views/dev/AtomsSection.vue` 验收                                  | 不要为一次性用途新开组件                                                                                          |
| 承载内容的卡片   | `components/PaperCard.vue`（`as` 定标签、`face` 定纸色），材质只在 `.board` 一份             | 不要自己写 `border + background + box-shadow` 拼一张卡：抄到第四份必然与 `.board` 漂移，厚度改一处也不跟着变      |
| 新系统能力       | `src/services/<能力>.ts` 一个函数 + Rust 一个 `#[tauri::command]`                            | 不要在组件里 `invoke`；也不要全塞进 `desktop.ts`                                                                  |
| Rust 领域逻辑    | 当前按 `src-tauri/src/` 的业务模块组织，跨宿主复用时再提取 `crates/mh-domain`                | 不要为了目录计划新建空 crate，数据事务仍由存储层管理                                                              |
| 前端的纯规则     | `src/services/`（如 `ghost-parse.ts`），不碰 IO                                              | 不要塞进 composable——那里一有 ref 就不好单测                                                                      |
| 跨页的数据层骨架 | `src/services/persist.ts`：`createPersist` 管落盘与排队                                      | 不要在每页的 store 里重抄——抄到第四份必然漂移                                                                     |
| 跨窗口同步       | `src/services/storage-sync.ts`：`onStorageSync` 只收「什么时候该重读」                       | 不要把 `event.key === null` 那套判断抄回 store——收益与物价各抄过一遍，边界迟早漏一处                              |
| 跨页的呈现口径   | `src/services/format.ts`：金额折万 / 日期文本（`moneyText`、`todayText`、`fromWan`…）        | 不要让一页去引另一页的模块；那是「记账口径」不是「物价」                                                          |
| 页面自己的数据层 | `src/views/<页>/<名字>.ts`（如 `characters/roster.ts`）：单例状态 + 纯函数 + 单测            | 不要塞进 `services/`——那不是系统能力；也不要写进 `.vue`                                                           |
| 一页的两块规则   | 纯函数与被它服务的 store 同目录（`income/online.ts` + `online-store.ts` + `online.test.ts`） | 不要为了「都在收益页」把它们并进 `income.ts`——那一份已经有 551 行，两者的坏条目判据也不同                         |
| 跨页的写入口     | `views/accounts/daily-sync.ts`：只写账号账，且只写 `source: 'auto'` 的那几条                 | 不要在收益页里直接 `addEntry`——手记与自动同步混在一起，第二次同步就会写重复或删掉用户手记                         |
| 开发期工具       | 页面内的放 `views/dev/` 旁边（如 `tokens.ts`）；跨页面的放 `scripts/`                        | 不要放进 `src/components/`                                                                                        |
| 真窗口烟测       | `tools/e2e/`：`cdp` 连窗口、`ui` 说人话的动作、`assert` 报告、`db` 库快照，用例在 `smoke`    | 不要再写 `probe-xxx.mjs`；也别并进 `tools/probe/`——那边每轮从零导航。**新功能的断言加进 `smoke.mjs`，同一个提交** |
| 图标源图         | `assets/icon/app-icon-1024.png` 是 `tauri icon` 的输入；生成脚本在 `scripts/icon/`           | 不要手改 `src-tauri/icons/` 里的产物                                                                              |
| 游戏资源         | `public/game/`（`maps/` `icons/` `data/`），规则见 `docs/GAME-ASSETS.md`                     | 不要放 `src/`——会被改名加哈希，清单里的文件名就对不上                                                             |
