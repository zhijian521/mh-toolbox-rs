# 架构

回答目录归属、数据流与系统边界。样式与控件契约见 [工程规范](CONVENTIONS.md)，本机操作及红线见 [协作约定](../AGENTS.md)。

## 1. 分层与目录

| 目录              | 职责                                            |
| ----------------- | ----------------------------------------------- |
| src/views/<领域>/ | 页面编排、业务组件、模型与数据层；测试放模块旁  |
| src/components/   | 跨页面视觉组件与无业务归属的展示逻辑            |
| src/composables/  | 可复用状态与副作用；单例放模块作用域            |
| src/services/     | 系统能力唯一出口、持久化骨架与生成 IPC 绑定     |
| src/import/       | 旧版数据集中转换，页面只接收当前结构            |
| src/styles/       | tokens 设计令牌、base 元素基座、blocks 组合排版 |
| src/types/        | 全局声明与模块增强；业务类型留在所属领域        |
| src-tauri/src/    | 窗口、IPC、SQLite、备份、截图与 OCR             |
| public/game/      | 游戏资源与事实规则；不放进 src/ 参与哈希改名    |
| tools/            | 烟测、探针与资源加工工具                        |
| scripts/          | 工程检查、分区测试与打包脚本                    |
| docs/archive/     | 历史快照，不参与现行规则维护                    |

业务功能在原领域内聚，出现第二个真实调用方才提取公共实现；不建立空目录或为尚未出现的多宿主需求拆 Rust crates。

### 启动与按需加载

Windows 在访问账本、建窗和预热 OCR 前独占数据目录中的 app-instance.lock，句柄随进程退出释放；重复启动聚焦原窗口并退出，不删除锁文件，也不把权限错误当作重复启动。

先绘制标题栏与加载页，再加载规则、业务数据与历史对账，最后开放业务路由。单个领域读取失败保留恢复与写入保护；
启动失败保留重试入口。首屏完成再通知后台预热 OCR，提前识别仍使用同一 OnceLock。
编辑器与历史弹窗经 components/lazy-dialog.ts 首次打开时加载，复用请求及组件；180ms 内完成不挂载占位窗，慢请求保留取消和重试。已显示的占位窗在正式窗挂载同一拍立即移除，通过一次性 MODAL_HANDOFF 交接背景及原触发点；后续子窗正常叠层，不把已移除的加载按钮当作关闭后的焦点目标。

ModalShell 统一使用 useModalMotion 承接开关动画。modal-mask 负责事件与叠层，modal-backdrop 独立压暗，面板只做透明度和短位移；同拍替换将旧背景当前透明度交给新遮罩，旧面板继续退场，嵌套背景保持隐藏。因调用方通过 v-if 卸载整份弹窗，遮罩的 VNode 移除钩子接入 Vue 渲染器，保留真实节点至 Web Animations 退场结束，不复制表单或 Canvas，不延迟关闭事件；useModal 在退场后释放弹窗栈、锁滚动和焦点，退场中的键盘与面板均不再触发操作，初始及返回焦点使用 preventScroll。useModalSize 在入场中只更新尺寸基线，后续 DOM 更新合并到一帧，关闭时保留动画当前高度。开关专用时长与曲线由 token-core.css 维护，降动效单独读取系统偏好。

全局弹窗采用景深浮现和轻量分层：一级 backdrop 轻度虚化背景，面板短位移淡入，直属 modal-head／modal-body／modal-foot 只做小间隔透明度动画，正文不引入定位变换。快速关闭先冻结分层当前透明度，再整体退场；加载交接省略再次分层。降动效将时长降至 1ms 且延迟归零，浏览器不支持背景虚化时保留原遮罩。材质强度及动效参数集中在 token-core.css。

## 2. 数据流

```
页面 ──调用──▶ composable / services ──invoke──▶ Rust 命令 ──▶ 领域层 ──▶ 磁盘
  ▲                                                        │
  └────────────────── 返回值（camelCase）◀──────────────────┘
```

- **契约是一处真源：`tauri-specta` 生成的 `src/services/bindings.ts`**。命令表在 `lib.rs`，
  字段名、参数与返回类型都由 Rust 的 `specta::Type` 派生**生成**到 TS，
  不再两边手抄、也不再靠 `#[serde(rename_all = "camelCase")]` 加上记忆力对齐。
  `bindings.ts` 是**生成物**：每次 debug 启动重写，别手改；`prettier` 与 `eslint` 都把它排除在外。
  `collect_commands!` **按平台写了两份**（`#[cfg(windows)]` / `#[cfg(not(windows))]`）：加命令
  必须两份都加，漏掉非 Windows 那份在本机完全看不出来——`ipc-contract.test.ts` 会红。
- **数据进出走 `backup.rs`**：`data_export` / `data_import` / `data_clear` 管的是「离开这台机器
  的那个文件」——`format` + `app` + `exportedAt` 的信封、`backups/` 下的自动备份、导入前校验；
  `quick_prices_export` / `quick_prices_import` 是同一套信封的窄口径，只装速记单价。
  **它不碰 SQL**：读写库一律回落 `store.rs` 及其子模块的普通函数，不在那里写第二份查询。物价、收益、账号及上线的 SQL 分别位于 `store/prices.rs`、`income.rs`、`accounts.rs`、`online.rs`，角色与仓库联动位于 `store/character_assets.rs`；命令、类型、建表迁移和跨领域事务由 `store.rs` 统一编排。两条语义：
  **导入 = 整体替换**（动手前把当前数据导一份到 `<数据目录>\backups\`，路径随回执给用户）；
  **清除 = 清掉全部业务表**，`meta` 一个字不动（`schemaVersion` 在那儿）。旧版 `data.json`
  （`schemaVersion: 10`，角色结构完全不同）**不在这个入口范围内**：常规导入不做转换或反向镜像；
  这里只认自己的信封，不认识就拒绝、不猜。旧版专用入口通过 `src/import/legacy.ts` 集中转换 v10 数据，页面只消费当前结构；文件读取和原件留存由 `backup.rs` 负责，提交复用同一备份与事务替换函数。
- **首次旧版导入**：启动先调用 `legacy_startup_read`，仅在首次检测且全部业务表为空时读取 `%APPDATA%\mh-tool-v2\data.json`；有旧数据才加载转换模块，复用设置页的转换与导入服务。`meta.legacyStartup` 保留检测结果，清空后不重复检测；自动导入在立即事务中再次判空，数据与成功标记一并提交。全部领域随后读取导入结果，再开启日常对账；业务页面绘制后弹出成功或失败提示，失败仍可从设置页手动导入。旧文件不修改、不回写。
- **日常备份与恢复**：主窗口创建后启动独立备份线程，使用独立数据库连接，每五分钟检查一次，按至少 24 小时间隔生成，与替换前备份**合计**只保留最近 5 份（`BACKUP_KEEP`），较早的自动清理；取数复用 `store::backup` 的同一读事务。`backups_list` 与 `backup_restore` 共用 `listed_backups`，只列出／只接受本地日常和替换前 JSON 中最近的 5 条。设置卡与恢复窗口通过 useBackups 共用读取状态，直接显示最近日常备份时间与异常，读取失败不冒充空列表，不阻断正常读写。
- **备份容量**：新版账本导出、导入和恢复使用缓冲流读写，不设仅用于导入的 16 MB 上限，避免完整 JSON 字节与账本对象同时驻留。替换前仍校验信封、记录并备份原账本；旧版原文经过 IPC 转换，独立保留 16 MB 限制。
- **活动提醒**：活动 ID 与开场时刻共同关联场次，日历和闹钟共用活动周期算法，按月活动持续循环。重复设置同一场次复用已有提醒；同名旧手动闹钟不推测关联。帮战及非帮战周统一按该周末周日的月份与次序归属，活动须本帮开启时仍提示条件。
- **成长历史**：记录位于角色 JSON 的可选 `growthHistory`，由 `roster.update` 统一比较保存前后值生成，目标回写使用同一入口；草稿不覆盖已有历史。旧版历史只在专用转换模块归一，随角色备份与恢复。
- **检查更新**：`services/updates.ts` 仅在用户点击时查询 GitHub 正式 Release，处理无版本、限流与网络失败，下载通过已有外链服务打开本仓 Release 页面。更新请求通过 CSP 放行 `https://api.github.com`。
- **玻璃界面壁纸**：设置页的目录取自[梦幻西游官方壁纸站](https://xyq.163.com/bz/)，随应用分发名称和图片路径。缩略图和原图通过 `services/xyq-wallpapers.ts` 从官方 CDN 在线读取，使用 `no-store` 和临时 Blob URL。偏好只记所选原图地址，启动时无法读取则显示内置壁纸。
- **前端状态**：业务与偏好使用模块级状态（主题、字体、字号、应用信息、路由、开发者模式、角色名册、物价表、收益
  账、账号账、目标），另有两个瞬时 UI 单例（`use-confirm` / `use-notify`）写法相同但不落盘。
  **不引 Pinia**——触发条件见 `AGENTS.md` §七。名册与物价表都已跨三个组件（页面、卡片、弹窗），
  但用的是与主题、字号同一套「模块级 `ref` + `useXxx()`」，没有第二套机制。
- **写盘时机**：先更新内存，再排队整份写 SQLite；保存回执与收表单等待本领域的 `flush()`，失败保留错误与重试入口。导出、导入、清除和系统关窗等待 `flushPendingWrites()`，关窗失败时由用户选择保留窗口或放弃改动退出。
- **业务状态只读输出**：各业务数据层对页面公开深层只读视图，写入回执和查询结果也不泄漏可变记录；修改通过领域方法，编辑器先生成独立草稿。角色保存重新归一以隔离草稿，目标成员和跟踪配置复制后保存。错误状态仍由启动及写队列维护。
- **各业务数据层的读取共用 load-data.ts**：统一浏览器/桌面分支、错误状态和加载完成标记；解析、默认值及演示种子仍在领域内。读取开始即暂停写入，失败保留当前内存数据，成功应用完整结果后恢复写入；空表与读取失败明确区分。
- **读取恢复**：业务页和历史窗口共用 LoadNotice / useLoadRecovery 提供就地重读；同一数据源共用读取状态，关窗或切页不释放在途请求。存在待保存数据、写入错误或编辑草稿时禁止覆盖式重读。读取失败不展示为首次使用或零汇总，重试期间保留错误与写入保护。
- **各业务数据层的落盘是同一份实现**（`src/services/persist.ts`）：`createPersist` 管「读失败
  拒绝写 / 浏览器写本地 / 桌面异步写库 / 连续写排队 / 可等待结果与 pending 状态」。各领域共用队列，避免连续写入覆盖。
  **归一、排序、种子数据、`storage` 事件仍归各页的 store**，骨架只回答「怎么落地」。
- **日期**：页面范围、目标期限与日历共享 `useToday()`，午夜更新，在焦点、可见性或页面恢复时重新对时；最后一个消费者卸载时清理计时器和监听。
- **业务数据的 `localStorage` 路径仅用于浏览器**（`npm run dev`、探针）——没有 Tauri 宿主，
  `hasDesktop()` 为假，各业务数据层直接走本地分支。主题、字体、字号、闹钟和首页快捷入口属于本机偏好，桌面版也使用 `localStorage`，不随账本导出。

主题样式统一从 `src/styles/tokens.css` 加载，应用与独立预览共用入口，顺序为：

- `token-core.css`：字体选择、基础语义、尺寸与动效。字号与基础行高由两套界面共用的 `token-typography.css` 提供。
- `token-categories.css`：物价、工具与门派分类色。
- `token-themes.css`：六套主题的配色及根变量。
- `materials.css`：公共控件材质，在实际元素上求值。
- `theme-materials.css`：主题材质覆写与兼容降级。

分层保持原声明顺序、选择器与变量名，不使用额外级联层；依赖局部染色的配方不提升到根节点。

字体独立选择由 `use-font-family.ts` 单例维护，挂载前恢复 `mh-font-family` 并设置根属性 `data-font`；缺失或非法值使用原有文楷，旧黑体值 sans 映射为 system。保留随包文楷、资源圆体，另有“系统默认”使用 system-ui／sans-serif，由操作系统提供字体，无字体下载。界面与 Canvas 共用 `--font-ui`，圆体字族与资源入口集中在 `rounded-font.css`；地图监听根属性和字体加载事件，切换系统字体也会重绘。关于页区分系统来源与随包 OFL 子集。随包文件的来源、许可与子集生成方式见 [assets/fonts/README.md](../assets/fonts/README.md)。

公共 PaperTag 只承载插槽内容、镂空双孔、孔壁、薄纸层与断续压痕；深浅双棱材质在 materials.css，几何在组件，配色及尺寸由 CSS 变量传入。首页 ShortcutFace、账号快捷记账及开发页直接复用，不让业务字段进入外壳。

### 业务联动

- 独立仓库位于 views/warehouse/，账号页、角色页与首页常用功能通过延迟加载的 WarehouseDialog 打开同一仓库。装备和召唤兽拥有稳定物品编号，详情与截图识别复用角色表单；管理、卖出多选与买入草稿共用入口，WarehouseItems 统一图标、勾选态和属性浮层。卖出选择在确认时统一回传，筛选与翻页保留勾选，取消不改调用方草稿。角色物品通过 warehouseId 关联，旧记录按角色及位置稳定编号，新物品保存时生成独立编号。已穿戴或携带的物品以角色资料为读写真源，仓库展示只读投影；未穿戴以仓库为真源，已卖出以成交快照为真源。角色完整修改与单件修改均可从仓库选取，装备按部位单选，召唤兽支持多选；选择只改草稿，取消不改变归属。同一物品不能重复穿戴，已穿戴项不能直接修改仓库资料、删除或卖出，需先从角色卸下或移除。保存名册时同事务同步库存并留存换下及被删角色的物品，失败锁住联动并仅重试落盘；浏览器预览使用名册与库存恢复日志。不修改 IPC 参数与导出信封版本。仓库纳入启动加载、整份导入导出、日常备份和清空。账本信封 v2 包含 warehouse，读取兼容 v1 缺省空仓库。
- 装备与召唤兽买卖可选关联仓库。买入草稿在记账时入仓，卖出校验所选物品仍与仓库一致后出仓；账号写队列经 account_trade_save 同事务保存账目与库存，失败保留同一笔内存变更并锁住仓库，重试只落盘。交易快照保存在账号记录中，库存后续修改不改历史；已关联记录不能更换方向、分类或物品，修改金额不变更库存。仓库的已卖出视图从卖出快照派生，只读展示，同一物品取最新卖出并排除在仓物品。删除关联卖出记录时，同事务归还物品；已有库存不覆盖，仍由较新卖出记录持有的物品不重复归还。删除买入或普通账目不改库存。SQLite v7 为账号补充快照列；浏览器预览用恢复日志保证两份数据最终完整写入。账号快照与仓库均等待游戏规则后读取。

- 收益固定单价按物品名称联动物价卡片：设价、改价和导入单价会复用或新建卡片并追加历史，物价当前记录更新或删除回写固定单价；补记旧日期不改变当前价。首次加载为已设价物品补建卡片，同名已有历史优先。收益页清除单价保留行情历史，重载不恢复，后续记录新行情时再次同步。
- 首页读取角色、收益、账号、上线和目标摘要；常规快捷入口通过一次性路由 action 打开原页面功能，仓库入口直接在首页延迟加载共用 WarehouseDialog，由仓库模块管理编辑、截图识别和持久化。默认常用功能包含仓库，已保存的自定义顺序保持，用户可从账号分类自行添加。
- 首页工作台左右并列近一周与近一个月读数；速记净额、在线时长、点卡统计今天及此前六天，进行中目标仍显示当前数量。双币种收支固定按近一个月统计，按日历月向前滚动、月末取目标月最后一日，区间两端计入且截至今天；复用账号账本汇总，不再次叠加已自动分账的收益。
- 首页 OverviewView 负责跨领域读数与区块编排；工作台提供上线、记一笔、仓库，上线和记账沿既有领域路由动作，仓库在首页弹出。OverviewShortcuts 管理常用入口、自定义和角色选择，自定义使用低频 TextButton，仓库入口发出事件交由 OverviewView 的唯一 WarehouseDialog 承接，与工作台共用实例及按需加载缓存；OverviewGoals 展示同一份目标进度。队伍区不放新增／管理按钮，目标区不放全部按钮，角色和目标管理由原领域页面承接；卡片定位与目标空态新增保留。布局样式在 overview.css，区块样式随组件维护。
- StatStrip 的 embedded 兼容模式使用 components/TicketCard.vue，纸面、侧缺口和立体纸边材质集中于 materials.css。面纸通过左右细棱表达上左受光，底纸左右各露 1px、下沿露 2px，两层共用缺口遮罩，无四周模糊投影；装饰外延不改变内容尺寸。固定签头用 --ticket-notch-y；可变签头可用 header 插槽并以分隔线收尾，由组件持有 ResizeObserver 同步票口，卸载或移除签头时清理，只修改遮罩坐标、不回写布局尺寸。开发页保留该外壳的自定义内容示例；组件不进入业务计算。

DevDataSection 将测试开关与统一模拟数据分卡展示，只有一个完整账本导入入口。demo-data.ts 的 buildDemoData 返回新版 v2 信封，集中提供角色、物价、收益、双币种账号收支与交易快照、各类目标、仓库、历史上线、固定单价与点卡口径，使用固定编号及相对日期；角色资产由同一 identifyCharacterAssets／mergeCharacterAssets 归一，售出物品只留成交快照，派生自动账目仍由启动对账生成。确认后经 data-files.dataImportPayload 等待全部写队列，调用 Rust data_import_payload；后端复用信封校验、替换前备份和 store::replace_backup 的单事务，不从各 store 逐表写入，也不借用旧版导入。成功后 settings/data-notice 交接备份回执并重载到设置页，避免旧单例继续操作；浏览器预览禁用导入。后续持久化示例只补这套数据，不另增按钮。

## 3. 数据与打包边界

账号新建交易关联区通过 AccountEditor 的录入／选择双入口管理临时 AccountAssetSource，确认后才替换原草稿；取消不改当前选择，已有交易快照不开放替换。来源随 EntryInput 送入 planAssetTrade，不写入 AccountEntry：draft 买入新增库存、warehouse 买入只关联现有编号；warehouse 卖出移出库存、draft 卖出仅留快照。仓库来源仍核对当前资料，草稿不能冒用已有编号。accounts-store → stageWarehouseTrade → accountTradeSave／本地恢复日志继续一次保存两域，穿戴出售由 stageSoldRosterAssets 按物品编号清空对应装备位或移除召唤兽，交易未落盘时锁定名册写入／重读。Rust save_account_trade 在原事务内仅对本次新增且快照匹配的卖出解除角色归属（旧档缺省零／空字段与前端补全等价，有值字段及数组顺序仍核对），普通库存操作仍保留穿戴校验；浏览器交易日志可携带名册并在角色读取前恢复。删除卖出统一回仓，不恢复穿戴；不新增命令、Schema 或持久化来源字段。

数据目录、identifier、卸载保留数据和单向升级以 [AGENTS.md §六](../AGENTS.md#六红线改代码前必须知道) 为准。
旧版导入是独立、集中、单向的转换入口，常规导入只认新版信封，不猜格式，不回写旧文件。
打包必须保留 custom-protocol；否则安装后的应用仍依赖开发服务。发布流程见 [RELEASE.md](RELEASE.md)。
